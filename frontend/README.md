# 🖥️ Frontend — 관람객이 보는 화면

[← 메인 안내로](../README.md)

**역할:** 전시 QR/URL로 들어온 관람객이 취향을 고르고, 추천·지도·작품 감상을 이용하도록 화면을 연결합니다. 사용자 모바일 웹이 우선이며 관리 화면은 이후 범위에 따라 확장합니다.

## 화면 흐름

```text
전시 진입
  → 취향 선택
  → 관람 시간 선택
  → 추천 작품과 추천 이유
  → 2D 지도·추천 순서
  → 작품 상세·해설·관찰 질문
  → 다음 작품 / 관람 마무리
```

## 백엔드와 어떻게 연결되나요?

| 화면 | 필요한 데이터 | 어디서 받나요? |
| --- | --- | --- |
| 전시 진입 | 전시 ID·이름·작품 목록 | backend API |
| 취향·시간 | 선택한 작품 ID·시간 | 사용자 입력 → 추천 요청 |
| 추천 결과 | 작품 ID·추천 이유·순서 | backend 추천 API |
| 2D 지도 | 평면도·작품 위치·추천 순서 | backend 지도/작품 API |
| 작품 감상 | 제목·작가·검증 해설·출처 | backend 작품 API |

**중요:** 화면에 필요한 JSON 필드·API 경로는 [API 결정 대기 목록](../docs/API-연동-논의.md)을 바탕으로 먼저 합의합니다. 임의 타입을 최종 계약처럼 고정하지 않습니다.

## 첫 작업 순서
1. 실제 사용 화면의 URL·흐름을 [개발 1단계 Notion](https://app.notion.com/p/3fa34713f167804ebb23c251498f3c5a)에서 확인
2. 프레임워크·패키지 매니저가 정해지면 이 폴더에 앱 초기화
3. 전시 → 취향 → 추천 → 지도 → 작품 상세까지 **최소 화면 연결**
4. 실제 API가 준비되기 전에는 샘플/목 응답을 **명확하게 구분**
5. API 연동 후 비회원 이용·새로고침·빈 데이터/에러 화면 테스트
6. 자신의 브랜치에서 커밋 → PR

## 완료 기준
- 모바일에서 화면 흐름이 이어짐
- 작품/전시 ID가 화면 간 일관됨
- API가 없는 부분을 실제 구현이라고 표시하지 않음
- 로컬 실행법, 필요한 환경변수, 검증 결과를 이 문서에 갱신

> **현재 상태 (2026-10-17, `dev/김광권`):** 화면설계서(U-01~U-15, A-01~A-06)를 **React + TypeScript + Vite**로 구현한 화면이 이 브랜치에 올라가 있고, `backend/` API와 연결해 사용자 흐름 전체를 브라우저에서 확인했습니다. **프론트엔드 담당(지성현·김동섭)님의 작업과 겹칠 수 있는 참고용 구현본**이므로, 어느 쪽을 기준으로 합칠지는 팀에서 정합니다. 화면의 작품 데이터는 백엔드 목업 데이터입니다.

## 구현본 (김광권 · 참고용)

> 프론트 담당 팀원 작업과 통합 방식을 정하기 전까지 **참고용**입니다. 실행하려면 `backend/`를 먼저 띄워야 합니다(아래 「백엔드 연결」).

**AI 결과가 보이는 화면**
- **A-04 작품 이미지:** 캡처한 이미지 파일을 올리거나(클릭·끌어다 놓기) URL 입력. 「사용자 화면에 이미지 표시」를 끄면 AI 분석에만 사용
- **취향 태그 8개 통일:** 사용자 취향 카드(U-05) = 관리자 태그(A-04) = AI 태그 — 풍경 · 인물 · 추상 · 빛 · 강렬한 색감 · 차가운 색감 · 따뜻한 색감 · 부드러운 색감
- **A-04 취향 태그:** 「AI 분석 실행」 후 태그 버튼마다 AI 점수(0~1)가 보이고, 「AI 제안대로 켜기」 → 고치기 → 「태그 확정」. 확정하면 그대로 둔 태그는 AI 점수, 바꾼 태그는 켬 1 / 끔 0으로 추천에 쓰입니다. 확정 전에는 켠 태그만 사용
- **A-04 감정·요약:** 감정 6가지 막대그래프(작품 분위기 설명용) + 초보자용 해설 요약 → 확인 후 「확정」. 목록에서 「전시 AI 일괄 분석」·「AI 제안 모두 확정」 가능
- **U-08 / U-10:** 추천 이유 = 고른 카드 중 이 작품에 해당하는 태그 ("'풍경'과 '빛'이 잘 드러나는 작품이에요"). 「작품 해설」 탭은 확정된 AI 요약을 먼저 보여 주고 「공식 해설 원문 보기」 제공, 확정된 감정은 분위기로 표시
- **U-12 아트 영수증:** 오늘 본 작품의 감정 프로필 막대그래프 + AI 취향 해석
- AI 분석 서버(`ai-service`)가 꺼져 있어도 관리자가 켠 태그로 추천됩니다. 예전 버전의 취향(고요한 풍경 등)이 브라우저에 남아 있으면 자동으로 새 태그로 바뀝니다.

**미술관 평면도 (A-05 위치·지도 관리)**
- 「미술관 평면도」에 안내도 캡처를 올리면(클릭·끌어다 놓기) 그 이미지가 원래 비율대로 지도가 됩니다. 바꾸기·삭제 가능, 없으면 전시실 사각형 기본 평면도
- 번호 마커와 「입구」를 **끌어다 놓으면 바로 저장**. 위치가 없는 작품은 목록에서 고른 뒤 지도 클릭 → 「위치 저장」
- 「전시실」 칸에서 이름 변경·추가·삭제 후 「전시실 목록 저장」, 작품별 전시실은 지도 아래 드롭다운
- U-09 추천 경로도 같은 평면도 위에 그려집니다. 경로는 작품 사이를 **직선으로 이은 관람 순서 표시**이며 벽을 피하는 길 안내는 아닙니다
- 비율이 다른 평면도로 바꾸면 마커 위치가 어긋날 수 있어 확인 창을 띄웁니다(좌표는 이미지 기준 퍼센트)

**취향 파악 (U-05) — 그림 1:1 토너먼트**: 그림 1장이 태그 1개예요. 8강 → 4강 → 결승으로 7번 고르면 우승·준우승 태그가 취향이 되고(기본 2개), 결과 화면에서 1개를 더하거나 바꿀 수 있어요(최소 2개, 최대 3개). 「태그로 바로 고르기」도 있어요. 그림은 `frontend/public/taste/`의 `landscape` · `people` · `abstract` · `light` · `vivid` · `cool` · `warm` · `soft` 파일(jpg·png·webp)이고, 바꿔 끼울 수 있어요 (`public/taste/README.txt`).

**로그인 전환 (U-02)** — 로그인한 상태면 「비회원으로 계속」 아래에 「다른 계정으로 로그인 · 로그아웃」. 로그아웃하면 이전 계정의 취향 선택도 비웁니다. U-13 관람기록에도 로그아웃 버튼이 있습니다.

「5. 화면(UI) 설계」 문서의 사용자 모바일 웹(U-01 ~ U-15)과 관리자 데스크톱 웹(A-01 ~ A-06)을
React + TypeScript + Vite로 구현한 프론트엔드입니다.

### URL 설계 (설계서 5.3 외부 URL 진입)

| URL | 화면 | 비고 |
|---|---|---|
| `/exhibitions/:exhibitionId` | U-01 | 전시 입구 QR이 가리킬 주소 |
| `/login` | U-03 | `?redirect=` 로 인증 후 원래 화면 복귀 |
| `/signup` | U-04 | |
| `/history` | U-13 | 미로그인 → `/login?redirect=/history` → 복귀 |
| `/password/reset?token=` | U-15 | 비밀번호 재설정 메일 링크 |

### 화면 전환 규칙 (설계서 5.5)

- 로그인 사용자: U-03 → U-06(저장 취향) → U-07
- 비회원/신규: U-05(취향 파악, 그림 토너먼트 → 태그 2~3개) → U-07
- 추천 없이 보기: U-02 「추천 없이 자유롭게 보기」 → U-16 자유 관람(전시 작품 전체 목록·지도, 입구에서 가까운 순 번호) → 작품을 눌러 U-10 감상 → 「목록으로」 반복 → 「관람 마치기」 → U-12 아트 영수증(관람 방식: 자유 관람)
- U-10 "다음 작품 안내": 남은 작품 있으면 U-09(같은 지도 화면 재사용), 없으면 U-12
- 👍/👎는 선택사항, 누르지 않아도 다음 작품으로 진행
- 작품별 QR은 MVP 범위에서 제외

### 백엔드 연결

화면은 `src/api/client.ts`를 통해 백엔드(`../backend`) REST API를 호출합니다.
개발 중에는 Vite 프록시가 `/api` 요청을 `http://localhost:4000`으로 넘기므로 **백엔드를 먼저 띄워 주세요.**

```bash
cd ../backend && npm install && npm run dev   # 터미널 1
cd ../frontend && npm install && npm run dev  # 터미널 2 → http://localhost:5173
```

- 다른 주소의 서버를 쓰려면: 개발 프록시 대상은 `VITE_API_PROXY`, 빌드 결과물의 API 주소는 `VITE_API_BASE`(예: `https://api.example.com/api`, 이 경우 백엔드 `CORS_ORIGIN` 설정 필요)
- 로그인 토큰은 localStorage(`arti.token`, 관리자는 `arti.adminToken`)에 저장되고, 만료되면 자동으로 지워집니다.
- 추천·AI 답변·비밀번호 재설정은 모두 서버에서 처리합니다. API 목록과 설계 메모는 [`backend/README.md`](../backend/README.md) 참고.
- 데모 데이터를 처음 상태로 돌리려면 백엔드에서 `npm run db:reset`.
