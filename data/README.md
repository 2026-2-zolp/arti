# 🗂️ Data — 전시·작품 정보와 검증 근거

현재 계약은 [W02 개발 계약](../docs/execution-plan/2026-11-07/05-contracts-and-decisions.md)을 기준으로 합니다. 아래 후보 필드/검수명은 초기 논의 기록입니다. 실제 Django는 source_check/approved 등의 확정 계약을 사용합니다. [Git 참조자료](reference/git-captures/README.md)는 검수 전 AI 초안이며 실제 유영국 전시나 승인 데이터가 아닙니다.

[← 메인 안내로](../README.md)

**역할:** 화면과 AI가 참고할 작품 데이터를 관리합니다. **데이터가 맞는지, 그 전시에 실제 등장한 작품인지, 이미지를 쓸 수 있는지**를 구분하는 것이 중요합니다.

## 데이터가 화면까지 가는 흐름

```text
공식 전시/작품 자료
    ↓  출처·사용 조건 확인
작품 3~5점의 기본 정보 정리
    ↓  사실 검증·필드 통일
검수 가능한 JSON/DB 데이터
    ↓  작품 ID를 기준으로 전달
Django API → frontend 화면
```

## 작품 하나에 확인할 정보

| 항목 | 확인 이유 |
| --- | --- |
| `artwork_id`, `exhibition_id` | 추천·지도·해설에서 같은 작품을 찾기 위해 |
| 작품명·작가·제작연도 | 기본 표기 |
| `source_url` 및 확인 날짜 | 정보의 공식 근거 |
| `official_description` | 사실로 검증된 해설 |
| `review_status` | 검수 전/중/완료 |
| 이미지 URL·사용권 상태 | 저작권/재배포 여부 구분 |
| 지도 위치·배치 근거 | 실제 자료인지 시연용 좌표인지 구분 |

위 필드명은 [API 논의사항](../docs/API-연동-논의.md)의 **후보**입니다. 팀이 데이터 계약을 확정하면 맞춰 조정합니다.

## 두 전시 후보

- 화풍 중심: **Radical Harmony** (신인상주의, National Gallery)
- 작가 중심: **유영국: 산은 내 안에 있다** (서울시립미술관)

이들은 검토한 전시 후보입니다. **개별 작품이 실제 그 전시에 출품됐는지는 별도 확인**해야 합니다.

## 검수 기준
1. 원자료 URL 및 확인 일자를 남깁니다.
2. **실제 출품작 여부**를 확인합니다. 소장품 정보만으로 출품 확정 금지.
3. 이미지 사용권·재배포 범위를 확인합니다.
4. 공식 설명·팀 요약·AI 생성 설명을 구분합니다.
5. 지도 위치가 없으면 `mock` 또는 이에 준하는 표시를 합니다.
6. 검수 상태를 `unverified` / `reviewing` / `verified`로 관리합니다.

> **현재 상태:** 정책 문서와 기존 Git 참조 사본·점검/export 도구가 있습니다. 실제 유영국 전시 작품 목록·검수 완료 데이터가 채워졌다는 의미가 아닙니다. 비공개 원본, 개인정보, 재배포 불가 이미지는 커밋하지 마세요.
