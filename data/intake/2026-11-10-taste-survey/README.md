# 취향 조사 10점 비교 초안 v1 — 최종 선정 아님

2026-11-10 사용자 요청에 따라 기존 자료를 대조하고 일반 개발 환경에 **비활성 초안**으로 등록했다. 실제 취향 정답·모델 최적 설정·사람 승인으로 간주하지 않는다. [선정/출처/해시](selection.json), [정렬·쌍 manifest](pool-manifest.json), [비공개 추가 인수 manifest](import-manifest.json), [가설32경로 분석](hypothesis-analysis.json)을 함께 읽는다.

**사용자 추가 확인:** 취향 조사 작품은 아직 최종 선정하지 않는다. 기존 자료뿐 아니라 외부 자료도 동일한 식별·출처·품질·다양성 기준으로 비교한다. 현재 DB의10점과5쌍은 교체 가능한 비활성 비교 초안이다. 후보 등록이나 이번 커밋이 최종 선정 승인을 뜻하지 않는다.

## 재검토와 선정 원칙

- 유영국16점만으로 조사하지 않는다. 기존 Git40점에서9점과 이미 인수한 유영국1점을 참조한다. 유영국 주전시 구성은 바꾸지 않는다.
- 인물·풍경·추상,빛·색감의 대비를 확보하고 같은 태그가 한 쌍 양쪽에 반복되어 무조건 누적되는 구성을 가설 수준에서 피했다. 특정 작가 지식·인지도를 맞히는 시험이 아니다.
- 5번 선택으로8개 특성을 완전히 식별할 수는 없다. 대비축 여러 개가 동시에 달라지므로 한 번의 선택을 특정 태그 선호의 인과 증거로 해석하지 않는다.
- 9점은 과거 개발/보정/평가에 쓰인40점 재사용이다. 이 자료로 측정한 결과를 독립 holdout 정확도나 새로운 일반화 성능으로 발표하지 않는다. 기존 평가 원본·라벨·기준선은 수정하지 않았다.
- 서양 정전화된 회화·남성 작가 비중이 여전히 크고 이미지 해상도·친숙함·좌우 위치도 영향을 줄 수 있다. 범용 취향검사의 최적 표본이라는 주장을 하지 않는다.

## 태그 가설 점검과 개선 대기

가설상 후보 분포는 풍경4·인물5·추상2·빛4·강렬2·차가움3·따뜻함2·부드러움2다. 이는 **모델 분석 결과도 확정 라벨도 아니며 DB tags에는 넣지 않았다.** 촛불 주변의 따뜻함 가설도 작품 전체의 객관적 정답이 아니다.

32가지 선택을 가설로 계산하면 결과 태그 수는5개3경로·6개9경로·7개14경로·8개6경로다. 최상위 동점은16/32경로에 남고 모든 선택에 무조건 나오는 태그는 없다. 따라서 작품 다양성 확보만으로 태그 과다·동점 문제가 해결되지 않는다. 다음 R04-S에서 실제 원시 모델 점수·선택 가중치·추천 변화와 대표 취향 확인 방식을 비교해야 한다. 이 숫자를 사용자 실험·모델 성능으로 발표하지 않는다.

## 현재 일반 개발 DB

`arti-dev`에 마이그레이션0002와 새 API/프론트를 반영했다. 원본16점/이미지16개는 해시까지 그대로 보존했다. 새9점은 비공개 관리 묶음 아래 `source_check`, `show_image=false`, `tag_status=none`, `tags=[]`로 인수했다. 기존 유영국1점을 참조해 조사풀10개를 **revision1·active=false**로 등록했다. 공개 전시/작품/활성풀은0이며 `/api/taste-pool`은 준비부족이다.

일반 API4018·프론트5178은 실행 중이다. 공개 사용 테스트가 가능한 상태라는 뜻은 아니며 검수 전 후보는 관리자/운영 확인 대상이다. 계정·세션·관람 기록을 만들지 않았고 GPT 호출도 하지 않았다.

## 재현과 다음 단계

`python scripts/verify_survey_candidates.py`는 저장된 후보10개/쌍/해시와 가설32경로를 검증한다. 새 체크아웃에 없는 유영국 비공개 이미지 파일은 명시적으로 대기 표시한다. 나머지 Git9점의 해시는 필수다. 인수 manifest는 메타데이터이며 이미지 사본과 DB 백업은 Git 제외 로컬 보존이다.

다음은 외부 후보도 포함한 자료 비교와 미확정 식별·저해상도·사용 범위 보완이다. 현재10점 원시 점수는 탐색용으로 비교할 수 있으나 이 풀에 맞춰 최종 설정을 고정하지 않는다. 사람 승인과 태그 검수 전 공개 활성화하지 않는다. 승인 후에도 운영 명령은 revision·자격을 다시 확인하고 사용자가 공개 활성화를 지시한 경우에만 진행한다.
