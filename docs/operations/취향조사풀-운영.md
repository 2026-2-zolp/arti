# 전시 독립 취향 조사풀 운영

## 무엇을 분리했는가

조사 작품10점/5쌍은 전시와 독립적인 명시적 작품군이다. 작품 원본은 기존 관리자 작품 등록·이미지·검수 절차를 재사용한다. 조사풀은 작품을 참조하며 이미지/설명을 복사하지 않는다. 작품의 전시 FK는 관리 맥락으로 유지하므로, 운영용 비공개 자료 묶음의 작품도 검수 후 조사에 선정할 수 있다. 조사풀에 넣는 것이 실제 전시 출품을 뜻하지 않는다.

추천은 사용자가 접속한 현재 전시의 공개·배치된 작품에 한정된다. 조사용 작품이 추천 전시에 없어도 된다. `/api/taste-pool`이 전역 조회이고 예전 `/api/exhibitions/:id/taste-pool`은 같은 결과의 호환 별칭이다.

## 배포 전 확인

1. 기존 DB/미디어의 정합 백업을 확보한다. 이번 개발은 격리 합성 DB에서만 검증했으며 일반 개발 환경을 자동 변경하지 않았다.
2. 새 API 이미지와 `0002_independent_taste_survey`를 함께 적용한다. 테이블만 추가하고 실제 자료·계정·옛 저장 취향은 자동 변경하지 않는다. `/api/ready`도 조사 테이블 존재를 확인한다.
3. 풀을 지정하지 않은 기존 환경은 `ready=false`가 정상이다. 공개 전시의 첫10점을 자동으로 사용하는 fallback은 없다. 기존 회원은 저장 취향을 재사용할 수 있다. 새 게스트/재조사는 검수된10점 준비 후 가능하다.
4. 예전 게스트 선택 버전은409와 재조사 안내 대상이다. 회원 저장 취향은 서버의 기존 counts/원본 선택을 그대로 재사용한다.

## 선정 파일과 명령

다음 구조의 JSON을 로컬 비공개 경로에 작성한다. `artworkIds`는 정확히10개의 서로 다른 기존 작품 ID다. 아래 ID는 예시이며 실제 승인 자료가 아니다. 배열의 인접 두 항목이 한 쌍이므로 비교 의도에 맞게 순서를 정한다.

```json
{
  "id": "survey-v1",
  "name": "기본 취향 조사",
  "artworkIds": ["work01", "work02", "work03", "work04", "work05", "work06", "work07", "work08", "work09", "work10"]
}
```

구성된 Django 운영 환경 안에서 실행한다. manifest 경로는 **명령을 실행하는 환경에서 읽을 수 있는 경로**여야 한다. Docker에서는 먼저 해당 API 컨테이너에 파일을 전달하고 컨테이너 경로로 지정한다. 키/비밀 환경 파일을 선정 파일에 넣지 않는다.

```text
python manage.py configure_taste_survey --manifest /tmp/taste-survey.json --expected-revision 0
python manage.py configure_taste_survey --manifest /tmp/taste-survey.json --expected-revision 1 --activate
```

첫 명령은 신규 초안 revision1을 만든다. 두 번째는 현재 revision1을 검증하고 revision2로 갱신해 활성화한다. 기존 풀을 수정할 때는 실제 현재 revision을 사용한다. `--activate`를 생략하면 편집 대상 풀은 비활성 초안으로 저장되므로 이미 활성인 같은 풀을 편집할 때는 조사 중단을 고려한다. 다른 활성 풀은 초안 생성으로 바뀌지 않는다. 활성 교체는 하나의 트랜잭션에서 이뤄지고 DB는 활성 풀을 최대 하나로 제한한다.

명령은 작품을 승인하거나 분석하지 않는다.10점 모두 `approved` 원문,확정 태그,표시 허용 이미지가 필요하며 ID/중복/자격/revision 오류 시 전체 롤백한다. DB 직접 편집 대신 이 명령을 사용한다. 이름·순서 변경도 revision을 증가시킨다.

**활성화는 조사 이미지의 공개 결정이다.** 소속 전시가 draft/closed여도 활성·준비된 조사풀 이미지는 공개 미디어 경로로 제공된다. 다른 작품·전시 상세·추천은 공개되지 않는다. 이미지 출처/사용 범위/작품 식별·내용 검수를 먼저 완료한다. 자격이 깨진 항목 하나라도 있으면 전체 조사풀은 준비부족이 되고 조사 이미지 접근 근거도 사라진다. 이미 공개 전시에 속한 이미지의 별도 공개 근거는 유지된다.

## 후속 검토

### 미검수 비공개 초안 등록 (11/10 추가)

후보 검수 전에 순서·소속만 준비하려면 `--allow-unreviewed-draft`를 명시한다. 이 옵션은 기존 작품10개를 참조하는 비활성 풀만 저장하며 작품의 review/tag/show 상태를 바꾸지 않는다. `--activate`와 함께 쓰면 저장 전에 거절한다. 옵션 없이 실행하는 기존 자격 검사는 유지한다.

```text
python manage.py configure_taste_survey --manifest /tmp/taste-survey.json --expected-revision 0 --allow-unreviewed-draft
```

일반 `arti-dev`에는 [실제 후보 선정안](../../data/intake/2026-11-10-taste-survey/README.md)의10개를 revision1·active=false로 등록했다. API/프론트와 마이그레이션0002는 적용했으며 검수/태그/공개 활성화는 하지 않았다. 기존16점은 변경 없이 보존했고 새9점은 source_check·이미지비표시·태그미확정이다. 현재 공개 전시는 없고 신규 취향 조사는 준비부족 안내가 정상이다.

변경 전 DB 덤프·미디어 아카이브와 전후 해시는 Git 제외 `data/private/survey-dev-20261110/`에 보존했다. DB 덤프를 별도 DB로 복원해 기존 행 일치를 확인했고 미디어 아카이브도 원본16파일 해시와 일치했다. 실제 운영 복원 시에는 API 쓰기를 중단하고 별도 복원 대상을 검증한 후 진행한다. 사용자 데이터가 추가된 이후에는 이번 변경 전 백업을 무조건 덮어쓰지 않는다.

조사10점의 다양성·쌍 선정은 아직 실제 자료로 확정하지 않았다. 유영국·인상주의·기존 평가 자료를 자동 적재하지 않는다. 독립 라벨/사람 검수와 R04-S 동점 보조 기준·대표 취향 UI는 별도 과업이다. 현재8태그/빈도 가중치/동점 고정 순서는 이번에 바꾸지 않았다.
