# CLIP·mDeBERTa 로컬 운영 기준

2026-11-09. Django 기본 API와 분리된 분석 서비스의 로컬 운영 기준이다. AWS/고가용성·분산 대기열을 구축한 문서가 아니다. 새 Django는 분석 /analyze만 사용하고 GPT 텍스트·도슨트는 기존 OpenAI 호환 경로를 사용한다.

## 기동과 상태 확인

ai-service 가상환경과 모델 파일을 준비한 뒤 ai-service 폴더에서 실행한다. 현재 검증한 운영 단위는 uvicorn app.main:app --host 127.0.0.1 --port 8001 --workers 1 이다. ARTI_WRITER_ENABLED=false로 Kanana 작성 기능을 끄고, 모델명/파일 경로와 다운로드 방식을 먼저 정한다. 최초 다운로드는 로딩 시간과 구분한다. 이번 실측은 기존 고정 revision 파일·HF_HUB_OFFLINE=1·CPU4스레드였다.

- /health: 프로세스 응답200. modelsLoaded, modelState(not_loaded/loading/failed/ready), analysisBusy, busySeconds를 본다.200만으로 모델 준비/품질을 판정하지 않는다.
- /ready: 모델이 준비됐을 때200, 아직 준비되지 않으면503/Retry-After5다. 준비된 모델이 추론 중인 경우에도200이며 유휴 슬롯 보장이 아니다.
- 기본 PRELOAD=true는 시작 시 한 번 백그라운드 로딩한다. PRELOAD=false면 첫 /analyze가 로딩을 시작하고503을 반환한다. /ready 조회만으로 로딩을 시작하지 않는다.
- 로딩 실패는 failed로 표시하고 다음 요청의 재로딩까지 최소5초를 둔다. 로딩 중 다른 요청은 추가 로더를 만들거나 기다리지 않고503을 받는다.

Django의 /api/ready는 기존 API/DB 준비 상태로 모델 readiness와 다르다. Django ARTI_MODEL_SERVICE_URL은 접근 가능한 내부 분석 서비스 주소로 설정한다. Compose의 localhost는 호스트가 아니므로 호스트 서비스라면 http://host.docker.internal:8001 등의 실제 접근 경로를 선택한다. 일반 arti-dev의 설정/컨테이너는 이번 작업에서 재생성하지 않았다.

## 요청·장애 정책

분석은 프로세스당1건이다. 추론 슬롯이 차 있으면429/Retry-After1로 알리며 모델 작업을 대기열에 쌓지 않는다. 모델 상태/추론 lock은 프로세스 로컬이므로 workers를 늘리면 메모리·동시 추론도 늘어난다. 여러 모델 프로세스/호스트의 전역 제한을 구현했다고 주장하지 않는다. Django 관리자 분석은 기존 PostgreSQL advisory lock으로 요청을 제한한다.

Django는 같은 관리자 요청의 태그·감정에 성공 결과뿐 아니라 실패도 공유한다. 최초 호출이 timeout/503/429이면 다른 분석 필드를 위해 즉시 같은 호출을 반복하지 않는다. 다음 사용자 요청은 새 캐시로 시도할 수 있다. GPT 요약·가이드 경계와 기존 부분 성공 정책은 유지한다. 일부 텍스트 생성만 성공하면 그 부분은 기존 계약대로 suggested 저장될 수 있으므로 ‘모든 필드 전체 원자성’으로 설명하지 않는다.

30초는 분석 서비스 HTTP 한 번의 timeout이며, GPT 요약·가이드 등을 포함한 관리자 분석 전체의 총기한이 아니다. Django의 모델 HTTP timeout은30초이며, 테스트는 지연 주입에서 .05초로 단축해 같은 실패 경로를 확인했다. timeout 뒤 늦은 응답을 백그라운드 DB 작업으로 적용하지 않는다. 원문/버전이 그 사이 바뀌면 성공한 옛 응답도409로 거절한다. 모델 생성으로 confirmed/approved를 자동 설정하지 않는다.

caller가 timeout/연결을 끊어도 동기 native 추론이 즉시 취소되지는 않는다. 실제 계산이 끝날 때까지 모델 슬롯을 유지하고 그동안429를 반환한다. 다른 native 계산을 겹쳐 실행해 메모리를 늘리지 않는다. busySeconds가30초를 넘기는 등 지속 지연은 조사 대상이며 자동 강제취소/워치독 재시작 기능은 없다. native 계산이 멈춘 경우 운영자가 상태와 요청을 확인해 전용 모델 프로세스를 재시작해야 한다.

서비스가 중단되면 연결 실패503, 진행 중 연결이 끊기거나 응답이 잘리면 안전한502 등 명시 오류로 처리한다. 원문 앞부분·가짜 점수·GPT 태그로 성공을 대신하지 않는다. 재기동 후 /ready를 확인하고 명시 재시도한다. 기존 Django DB·미디어 볼륨을 삭제/초기화하지 않는다.

분석 서비스는 내부 주소로만 접근하게 운영한다. 애플리케이션 단일 추론 슬롯은 역방향 프록시/연결 수/요청 크기·인증 같은 배포 보호를 대체하지 않는다. 현재 요청 모델의 이미지/설명 제한은 유지했으며 큰 병렬 입력·AWS 프록시/다중 worker 수용량은 W12/W08 후속으로 확인한다. 레거시 /write를 켰을 때의 동시 자원 보호는 이번 분석 슬롯 범위가 아니므로 새 운영에서는 비활성으로 둔다.
