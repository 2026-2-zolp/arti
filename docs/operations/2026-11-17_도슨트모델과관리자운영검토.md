## 적용 순서와 라우팅 기준

1. **시연**에서 검수된 작품 해설·요약·질문·힌트는 DB 공개본을 표시한다. 입력이 없는 감상과 기존 해설은 모델 연결 상태와 무관하게 이용할 수 있다. 현재 도슨트 모델은 이어 묻기와 근거 부족 처리 검증의 기준선으로 둔다.
2. **모델 재검수**를 시작할 때 동일한 승인 자료와 동일 질문으로 기존 기준선과 Kanana-2를 비교한다. 관리자 초안에서 사실 추가 오류, 근거 불일치, 질문 1~3개·힌트 개수 일치, 재시도 후 확정본 보존을 먼저 본다. 도슨트는 저장된 12건의 질문·평가표로 이어 묻기, 다른 작품 출처 섞임, 근거 부족, 거절 응답과 읽기 쉬운 길이를 비교한다. 실제 운영 선택에는 같은 요청의 p50·p95, 콜드 스타트, 메모리와 요청당 토큰·운영 비용도 쓴다. [도슨트 평가표](../review/docent-2026-11-15/README.md)
3. **작업별 라우팅**부터 적용한다. 관리자 초안과 검증된 단순 요약을 경량 모델 후보로 두고, 문맥을 이어가는 도슨트는 현재 기준 모델을 쓴다. 더 깊은 답변이 필요하면 사용자의 명시적 요청과 승인 근거 수·질문 유형을 활용한다. 근거가 부족하면 다른 모델을 불러도 근거는 생기지 않으므로 등록 자료 안내로 돌아간다. 429·502·타임아웃은 같은 입력의 재시도 기준을 유지한다. 두 공급자 동시 호출이나 자동 난이도 판단은 일관성·비용을 비교한 뒤 판단한다.

Kanana를 배포 후보로 붙일 때는 로드한 모델 개정과 라이선스를 먼저 고정한다. 어댑터의 텍스트 입력·JSON 응답이 호환되는지 로컬에서 확인한 다음, 같은 호스트의 루프백이나 신뢰할 수 있는 내부 HTTPS 엔드포인트로 연결한다. 현재 텍스트 제공자는 임의 내부 HTTP 주소를 받지 않는다. 기존 관리자 **‘이미지도 분석’**은 태그·감정 경로의 도판 입력을 제어한다. 요약·가이드에 도판을 전달하려면 이미지 수신 대상, 사용이 허용된 파일, 사람 검수 단계가 있는 별도 멀티모달 입출력 계약이 필요하다.

## 관리자에서 먼저 필요한 지표와 설정

- 대시보드는 텍스트 AI·태그/감정 설정 상태와 한국 시각 오늘의 도슨트 요청·관리자 분석 요청·AI 응답 오류를 표시한다. “요청”은 앱에서 집계한 HTTP 요청이며 세션이나 과금 건수가 아니다. 연구용 운영 로그는 최근 50개를 표시하고 오류만 볼 수 있다. 시각·작업명·HTTP 코드·요청 ID만 저장한다. 운영 주기와 보관·파기 담당은 배포 단계에서 확정해야 한다. [OWASP 로깅 가이드](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)
- 키는 서버 비밀 설정에서 관리한다. 관리자 화면에서 조정이 필요해지면 서버에서 승인한 모델 ID와 기능별 켜기·끄기 같은 제한된 항목부터 제공하고, 변경자와 변경 시각을 기록하는 방식을 검토한다. 현재 화면은 설정 상태 조회를 제공한다.
- **토큰**은 제공자가 실제로 돌려준 입력·출력·캐시 토큰을 작업별·모델별로 합산한다. 사용량 응답이 빠진 구간은 미수집으로 표시한다. 관리자 분석 한 요청에 제공자 호출이 여러 번 발생할 수 있으므로 HTTP 이벤트와 모델 사용량을 구분한다.
- **비용**은 공식 사용량 대시보드 및 프로젝트별 비용을 기준으로 대조한다. 비용 연동이 필요하면 조직 관리 키를 ARTI 요청 처리 서버와 분리한 집계 작업에 두고 통화·집계 기준·갱신 시각을 함께 표시한다. 운영 로그에 질문, 인증 토큰, 카카오 콜백 쿼리와 결제 자격증명을 넣지 않는다. [OpenAI Usage Dashboard](https://help.openai.com/en/articles/10478918-reviewing-api-usage-and-costs) · [Costs API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs)
