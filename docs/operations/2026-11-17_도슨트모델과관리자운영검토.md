## 적용 순서와 라우팅 기준

1. **시연**에서 검수된 작품 해설·요약·질문·힌트는 DB 공개본을 표시한다. 입력이 없는 감상과 기존 해설은 모델 연결 상태와 무관하게 이용할 수 있다. 현재 도슨트 모델은 이어 묻기와 근거 부족 처리 검증의 기준선으로 둔다.
2. **모델 재검수**를 시작할 때 동일한 승인 자료와 동일 질문으로 기존 기준선과 Kanana-2를 비교한다. 관리자 초안에서 사실 추가 오류, 근거 불일치, 질문 1~3개·힌트 개수 일치, 재시도 후 확정본 보존을 먼저 본다. 도슨트는 저장된 12건의 질문·평가표로 이어 묻기, 다른 작품 출처 섞임, 근거 부족, 거절 응답과 읽기 쉬운 길이를 비교한다. 실제 운영 선택에는 같은 요청의 p50·p95, 콜드 스타트, 메모리와 요청당 토큰·운영 비용도 쓴다. [도슨트 평가표](../review/docent-2026-11-15/README.md)
3. **작업별 라우팅**부터 적용한다. 관리자 초안과 검증된 단순 요약을 경량 모델 후보로 두고, 문맥을 이어가는 도슨트는 현재 기준 모델을 쓴다. 더 깊은 답변이 필요하면 사용자의 명시적 요청과 승인 근거 수·질문 유형을 활용한다. 근거가 부족하면 다른 모델을 불러도 근거는 생기지 않으므로 등록 자료 안내로 돌아간다. 429·502·타임아웃은 같은 입력의 재시도 기준을 유지한다. 두 공급자 동시 호출이나 자동 난이도 판단은 일관성·비용을 비교한 뒤 판단한다.

Kanana를 배포 후보로 붙일 때는 로드한 모델 개정과 라이선스를 먼저 고정한다. 어댑터의 텍스트 입력·JSON 응답이 호환되는지 로컬에서 확인한 다음, 같은 호스트의 루프백이나 신뢰할 수 있는 내부 HTTPS 엔드포인트로 연결한다. 관리자 **‘이미지도 분석’**은 태그·감정 경로를 제어한다. **‘요약·가이드 Luna 생성에 도판 사용’**은 별도 선택이며, 확정 전에 사람이 도판과 원문을 대조한다.

| 담당 | 준비와 인수 |
| --- | --- |
| **Codex에서 진행할 수 있는 일** | 허용된 실행 환경의 사양과 vLLM 적합성을 확인하고, 선택한 Kanana 가중치·개정을 고정한 서빙 명령을 준비한다. 모의 서버로 검증한 요약·가이드 전용 연결에 붙이고, 동일 작품의 JSON 계약, 근거·질문·힌트 품질, 지연·메모리, 확정본 유지와 실패 후 재시도를 비교한다. |
| **시험 조건** | 현재 노트북을 우선 사용한다. 실제 비교가 시작되면 전송 가능 범위가 확인된 작품과 동일한 합성 입력을 준비한다. 서버 설정은 접속 주소, 모델 ID·개정, `/v1/models`의 상태만 기록한다. |

Windows에서 Intel Arc 140V, Ubuntu WSL에서 Core Ultra 7 258V, 메모리 총 15GiB·확인 시 사용 가능 10GiB, `/dev/dxg`를 확인했다. vLLM·Ollama 실행 명령은 WSL PATH에서 확인되지 않았다. Intel iGPU의 공유 메모리 표기와 실제 모델이 할당할 수 있는 메모리는 구분한다. 첫 실행 단계는 3B 또는 1.3B로 CPU 경로의 메모리·첫 토큰 지연을 재고, Intel XPU 드라이버·PyTorch 인식과 불러올 모델 개정의 지원을 확인하는 순서다. 가중치와 런타임 설치 및 추론은 후속 시험에 둔다. [Intel 프로세서 사양](https://www.intel.com/content/www/us/en/products/sku/240957/intel-core-ultra-7-processor-258v-12m-cache-up-to-4-80-ghz/specifications.html) · [vLLM Intel XPU](https://docs.vllm.ai/en/latest/getting_started/installation/gpu/index.html) · [vLLM CPU](https://docs.vllm.ai/en/latest/getting_started/installation/cpu/)

같은 Linux/WSL 안에서 Django도 실행하는 시험의 예다. `VLLM_API_KEY`와 `KANANA_REVISION`은 서버 실행 환경에 설정한다. 모델 서빙과 Django를 다른 컨테이너에 두면 Django의 `127.0.0.1`은 Django 컨테이너 자체를 가리킨다. 그 경우 접근이 제한된 내부 HTTPS 주소를 사용한다. [vLLM 호환 API와 인증 범위](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/)

```bash
vllm serve kakaocorp/kanana-2-3b-instruct \
  --revision "$KANANA_REVISION" --host 127.0.0.1 --port 8010 --max-model-len 4096
```

Django 시험 환경에서 아래 값을 설정하고 API를 다시 시작한다. 현재 도슨트 제공자 설정은 그대로 사용한다. 4096은 짧은 초안 시험용 시작점이며, 실제 입력과 최대 출력의 합이 들어가는지 확인한다.

```dotenv
ARTI_DRAFT_PROVIDER=openai_compatible
ARTI_DRAFT_BASE_URL=http://127.0.0.1:8010/v1
ARTI_DRAFT_API_KEY=서버에_설정한_VLLM_API_KEY
ARTI_DRAFT_MODEL=kakaocorp/kanana-2-3b-instruct
ARTI_DRAFT_TOKEN_PARAMETER=max_tokens
ARTI_DRAFT_JSON_MODE=true
```

요약·가이드만 이 설정을 사용한다. 제공자 모의 429는 그대로 전달하며 공통 도슨트 제공자로 자동 재전송하지 않는다. 현재 방식으로 돌아갈 때는 `ARTI_DRAFT_PROVIDER=default`를 적용한다. `response_format`을 받지 않는 서버라면 JSON 모드 옵션을 끈 시험도 가능하며 Django의 결과 검증은 항상 실행된다. [vLLM 구조화 출력](https://docs.vllm.ai/en/latest/features/structured_outputs/)

### Kanana-2 초안 연결 재현

1. `python backend-django/manage.py test arti.tests.test_provider arti.tests.test_luna_draft_vision --noinput`으로 합성 PostgreSQL에서 실행한다. `L01`~`L03` 원문 파일의 SHA-256을 확인하고 모의 `kanana-2-3b-instruct`에서 요약·가이드 6건, 가이드 형식 오류 `502`, `429`, 응답 지연 `504`, 정상 재요청을 검수한다. 공급자에 보낸 작업과 공개본 보존 검수를 함께 본다.
2. 현재 Ubuntu WSL 기본 환경은 x86_64, Python 3.12.3, 확인 시 사용 가능 메모리 약 10.3GiB다. `/dev/dxg`는 확인됐고 `vllm`·`ollama` 실행 파일은 PATH에서 확인되지 않았다. 첫 추론 전에 3B 공식 가중치 개정을 고정하고 실제 CPU 또는 XPU 초기화와 첫 토큰 지연을 기록한다. 1.3B를 비교할 때는 모델 카드의 사용자 정의 코드 요구와 해당 개정을 함께 확인한다. [3B 카드](https://huggingface.co/kakaocorp/kanana-2-3b-instruct) · [1.3B 카드](https://huggingface.co/kakaocorp/kanana-2-1.3b-instruct)
3. 실제 품질 시험은 L01~L03의 **원문만 입력**을 같은 프롬프트·출력 예산으로 맞추고, 근거 없는 사실 추가와 관찰 질문·힌트 적합성을 평가한다. 도판을 추가한 Luna 시험은 입력 조건을 따로 기록한다. 관람 도슨트나 실제 도판으로 범위를 넓히려면 해당 시험 결과를 확인한다.

#### 원문 비교 실행표 준비

- `python -X utf8 scripts/prepare_draft_model_comparison.py --product-revision <ARTI Git 전체 SHA>`로 L01~L03 원문 해시를 대조한다. 요약·가이드 각각 두 번, 총 **12쌍·24회 요청**의 실행표를 만든다. 평가자에게는 X/Y 응답과 원문만 주고, 모델 대응표와 요청 환경·오류·지연은 진행자가 보관한다. [기존 평가 기준](../review/docent-2026-11-15/Luna_원문과도판_비교평가표.md#채점과-회신)
- 첫 선택인 3B는 공식 개정 `6a5d7889964c4c590299d16e309eabab1f73f8a9`와 약 7GB의 가중치 파일을 확인했다. WSL에 실행기를 준비하고 짧은 테스트 한 건으로 초기 로딩과 메모리·응답 지연을 본다. 3B 실행이 어렵다면 1.3B 공식 개정 `bf4786aa2a1908adce942d53976270132732f720`의 단일 가중치와 사용자 정의 코드 경로를 먼저 검토한다. 가용 메모리는 실제 초기화 때 다시 측정한다. [3B 파일](https://huggingface.co/kakaocorp/kanana-2-3b-instruct/tree/main) · [3B 고정 개정](https://huggingface.co/kakaocorp/kanana-2-3b-instruct/commit/6a5d7889964c4c590299d16e309eabab1f73f8a9) · [1.3B 파일](https://huggingface.co/kakaocorp/kanana-2-1.3b-instruct/tree/main) · [1.3B 고정 개정](https://huggingface.co/kakaocorp/kanana-2-1.3b-instruct/commit/bf4786aa2a1908adce942d53976270132732f720)
- 실제 생성은 추론 환경과 호출 범위가 준비된 뒤 실행한다. Luna는 실제 시험 시 응답 모델 식별자와 시험 시각을 기록한다. 양쪽 모두 원문 버전·요청 설정을 맞추고, 각 초안의 수정 시간과 근거 채점, 기존 공개본 유지 여부를 남긴다.
- 실행표의 X/Y는 모델별로 절반씩 무작위 배정한다. 진행자는 최초 실행표를 비공개 경로에 저장하고 끝까지 같은 대응을 쓴다. 같은 명령에 `--review-template`을 추가하면 모델명·개정·대응표를 뺀 채점표 24행이 나온다. 진행자는 저장한 대응과 시행 ID에 맞춰 생성 결과를 넣고 평가자에게 전달한다. 채점표에는 근거·작업 점수, 인용 근거, 중대 오류, 판정을 적는다.
- `--validate-review <채점표.json>`으로 시행 ID·X/Y 중복, 원문 해시·버전, 누락 행과 점수·판정의 일치를 검사한다. 점수 합 3 이상은 `usable`, 합 2 이하는 `revise`, 중대 오류는 `failed`다. 생성이 실패해 초안이 없으면 0·0점과 `failed`를 쓰고 검수 근거에 응답 코드·요청 ID를 적는다. `pending`은 미완료로 남긴다.

## Luna로 도판을 볼 수 있는지

- 5290에서 쓴 기준 모델은 `gpt-6-luna`다. `ARTI_LUNA_DRAFT_VISION=true`이고 작업의 실제 설정이 OpenAI Luna일 때 A-04에 도판 체크박스가 나타난다. 기본값은 꺼짐이다. 체크하고 요약 또는 가이드를 다시 생성하면 승인된 원문과 저장된 도판을 함께 보낸다. 도판은 PNG·JPEG·WEBP, 최대 2MiB다. 태그·감정, 관람 도슨트, 영수증은 각자의 기존 경로를 쓴다. [Luna 사양](https://developers.openai.com/api/docs/models/gpt-6-luna) · [Chat Completions의 이미지 입력](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)
- Luna 표준 단가에서 입력이 도판 포함 1,500 과금 토큰, 출력이 300 과금 토큰이라는 **가정 예시**는 요청당 약 **$0.00030**, 1,000회 약 **$0.30**이다. 실제 도판 토큰은 해상도·detail·모델별 과금에 따라 달라진다. 이 수치는 실제 ARTI 결제 내역과 품질 측정값을 포함하지 않는다. [Luna 공식 요금](https://developers.openai.com/api/docs/models/gpt-6-luna) · [이미지 비용 계산기](https://developers.openai.com/api/docs/guides/image-cost-calculator)

- 원문만 쓴 경우와 원문·도판을 함께 쓴 경우의 입력 고정, 합성 사례, 점수표와 회신 양식을 마련했다. [Luna 원문과 도판 비교 평가표](../review/docent-2026-11-15/Luna_원문과도판_비교평가표.md)

## 관리자에서 먼저 필요한 지표와 설정

- 대시보드는 도슨트·요약/가이드·태그/감정의 설정 상태와 한국 시각 오늘의 도슨트 요청·관리자 분석 요청·AI 응답 오류를 표시한다. “요청”은 앱에서 집계한 HTTP 요청이며 세션이나 과금 건수가 아니다. 운영 로그는 최근 50개를 표시하고 오류 필터는 서버에서 목록을 자르기 전에 적용한다. 시각·작업명·HTTP 코드·요청 ID만 저장한다. 운영 주기와 보관·파기 담당은 배포 단계에서 확정해야 한다. 항목 일부만 실패했고 HTTP 200인 관리자 분석은 별도 항목 결과로 집계할 수 있다. [OWASP 로깅 가이드](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)
- 현재 관리자 화면은 설정 상태를 보여 주고, 모델·키 교체는 서버 비밀 설정에서 한다. 웹 설정을 개발할 때는 운영 권한 전용 화면으로 분리한다. 기본 선택은 Luna로 두고, 도슨트와 요약·가이드는 각각 승인된 모델·제공자 목록에서 고른다. 호환 제공자는 등록된 HTTPS 주소와 Chat Completions·JSON·토큰 옵션을 서버가 검증한 뒤 목록에 넣는다. 실제 운영자가 입력하는 프로젝트 키는 서버에서 쓰기 전용으로 받는다. 값 저장은 서버 비밀 저장소 또는 DB와 분리된 암호화 키를 사용한다. UI에는 연결 상태·교체 시각만 보여 주고 변경자·작업만 로그에 남긴다. URL 자유 입력, 원본 키 조회, 제공자 자동 전환은 후속 설계 결정으로 둔다. [OpenAI API 키](https://developers.openai.com/api/docs/guides/api-keys)
- **토큰**은 제공자가 실제로 돌려준 입력·출력·캐시 토큰을 작업별·모델별로 합산한다. 사용량 응답이 빠진 구간은 미수집으로 표시한다. 관리자 분석 한 요청에 제공자 호출이 여러 번 발생할 수 있으므로 HTTP 이벤트와 모델 사용량을 구분한다.
- 운영 로그의 **작업·모델별 토큰 사용량**은 설정에 사용한 모델명으로 집계한다. 입력·출력과 캐시 입력을 표시한다. 캐시 입력은 전체 입력에 포함되고, 수집된 `0`과 값 누락을 구분한다. 상세 집계는 해당 계측 도입 뒤의 호출부터 쌓인다. 제공자 청구 내역 대조는 별도 단계다. [Chat Completions 사용량 필드](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- **비용**은 공식 사용량 대시보드 및 프로젝트별 비용을 기준으로 대조한다. 비용 연동이 필요하면 조직 관리 키를 ARTI 요청 처리 서버와 분리한 집계 작업에 두고 통화·집계 기준·갱신 시각을 함께 표시한다. 운영 로그에 질문, 인증 토큰, 카카오 콜백 쿼리와 결제 자격증명을 넣지 않는다. [OpenAI Usage Dashboard](https://help.openai.com/en/articles/10478918-reviewing-api-usage-and-costs) · [Costs API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs)
