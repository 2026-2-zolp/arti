# ARTI 카카오 로그인 첫 연동

현재 구현은 **기존 ARTI 이메일 계정에 카카오를 연결하고, 나중에 같은 ARTI 계정으로 로그인**하는 흐름이다. 마이페이지에서 ARTI 비밀번호로 재확인한다. 카카오에서 돌아오면 서버가 인가 코드를 교환하고 PKCE·state·nonce·ID 토큰 서명과 발급 대상을 검증한다. 카카오 앱 안의 사용자 식별자인 `sub`를 기존 계정에 연결한다. 카카오 이메일을 요청하거나 이메일 일치로 계정을 합치는 단계는 없다. [현재 연동 코드](../../backend-django/arti/kakao_auth.py) · [카카오 로그인 REST 안내](https://developers.kakao.com/docs/ko/kakaologin/rest-api)

팀의 카카오 앱과 시험 주소가 아직 준비되지 않았다. 다음 작업은 앱 소유자와 시험 주소를 정하는 것이다. 기존 구현은 카카오 공개 OIDC 정보에 표시된 `RS256`과 PKCE `S256`을 사용한다. 실제 앱과의 연결 결과는 아래 순서로 확인한다. [카카오 OIDC 메타데이터](https://kauth.kakao.com/.well-known/openid-configuration)

## 1. 시험 주소와 앱 준비

### 첫 연동 분담

- **준억·팀 앱 소유자**가 시험용 카카오 앱과 고정 HTTPS 주소를 정한다. 콘솔에서 카카오 로그인과 OpenID Connect를 켜고 시험 계정을 등록한다. 아래 콜백 주소를 REST API 키에 등록하고, 그 키와 클라이언트 시크릿을 시험 배포의 서버 비밀 설정에 직접 입력한다. 공유할 정보는 공개 가능한 시험 주소, 앱 종류, 콘솔 설정 완료 여부다. [카카오 앱·시험 앱 설정](https://developers.kakao.com/docs/ko/app-setting/app)
- **Codex**는 Django가 읽는 환경변수와 HTTPS 프록시 경로, 마이그레이션, 상태 응답을 대조한다. 모의 환경에서 연결·취소·중복·콜백 재사용·원래 계정과 영수증 유지 및 로그를 재검수한다. 콘솔과 시험 주소가 준비되면 준억이 카카오 화면에서 직접 인증할 수 있는 순서와 통과 기준을 제공한다.
- **ARTI 화면**은 전시 QR 진입 후 비회원 관람을 열어 두고, 영수증 보관이나 지난 기록 열기가 필요한 지점에서 로그인 선택을 제시한다. 기존 회원은 카카오를 한 번 연결한 뒤 이메일·비밀번호 입력을 반복하는 수고를 줄일 수 있다. 신규 관람자의 처음 가입 입력까지 줄이는 카카오 신규 가입은 약관 동의·중복계정·탈퇴·복구 흐름을 정한 뒤 별도로 검수한다.

1. 팀이 관리하는 고정 HTTPS 주소를 준비한다. 브라우저에서 프런트, `/auth/kakao/complete`, `/api`가 같은 호스트로 열려야 한다. HTTPS는 앞단 프록시에서 종료해도 된다. 프록시 뒤 Django로 `/api/auth/kakao/callback`을 전달하고, 프런트 완료 주소는 SPA 진입점으로 연결한다. 공인 HTTPS 주소를 기준으로 진행하며 로컬 LAN 주소로는 현재 ARTI 연결을 켤 수 없다. [ARTI HTTPS 검수 기록](../작업기록/2026-11-16_NginxHTTPS카카오콜백로그.md)
2. 팀 앱이 처음이면 카카오디벨로퍼스에서 팀 소유의 **기본 앱**을 먼저 만든다. 제한된 ARTI 시험 주소와 합성 ARTI 계정으로 첫 연결을 검수한다. 이미 비즈 앱이 있고 별도 키가 필요하면 카카오의 **테스트 앱**을 만들고 실제 시험할 카카오 계정을 해당 앱의 멤버로 추가한다. 테스트 앱과 운영 앱의 연결은 앱별로 취급한다. [앱 관리](https://developers.kakao.com/console/app) · [기본·비즈·테스트 앱 조건](https://developers.kakao.com/docs/ko/app-setting/app#app)
3. 앱 관리에서 **카카오 로그인 → 사용 설정 → ON**, **OpenID Connect → ON**으로 설정한다. ARTI는 이 설정에서 나오는 ID 토큰을 사용한다. 기존 계정 연결 시험은 기본 OIDC 식별자로 가능하므로 카카오 이메일·닉네임 등의 추가 동의항목을 먼저 신청할 필요가 없다. [카카오 설정 안내](https://developers.kakao.com/docs/ko/kakaologin/prerequisite)
4. **앱 → 플랫폼 키 → REST API 키**에서 쓸 키를 선택한다. 해당 REST API 키에 **카카오 로그인 리다이렉트 URI**와 **클라이언트 시크릿**을 설정한다. 예시 HTTPS 호스트가 `staging.arti.example`이면 아래와 같이 등록한다. 요청과 콘솔의 주소는 스킴·호스트·포트·경로·마지막 슬래시까지 같아야 한다. [리다이렉트 URI와 키](https://developers.kakao.com/docs/ko/getting-started/app-key-migration)

```text
https://staging.arti.example/api/auth/kakao/callback
```

## 2. Django 기동과 첫 연결

1. 배포 비밀 저장소나 로컬 Compose의 Git 제외 환경 파일에 아래 값을 넣는다. 프런트 빌드 변수와 팀 채팅에는 비밀 값을 넣지 않는다.

   ```dotenv
   ARTI_KAKAO_CLIENT_ID=콘솔의_REST_API_키
   ARTI_KAKAO_CLIENT_SECRET=해당_REST_키의_클라이언트_시크릿
   ARTI_KAKAO_CALLBACK_URL=https://staging.arti.example/api/auth/kakao/callback
   ```

2. 해당 배포의 DB에 Django `migrate --noinput`을 적용한다. 표준 Compose를 쓰는 경우 배포에 쓰던 환경 파일과 프로젝트명을 그대로 사용해 `migrate` 서비스를 먼저 실행하고 `api`를 재생성한다. 외부 HTTPS 프록시는 같은 배포를 가리켜야 한다. 기존 DB 볼륨을 재사용한다. `GET /api/ready`가 200이고, 브라우저에서 같은 호스트의 `GET /api/auth/kakao/status`가 `enabled: true`인지 확인한다. 이 값은 설정 형식 확인 결과다. 성공적인 실제 연결은 다음 단계로 확인한다.
3. 접근이 제한된 시험 주소에서 ARTI 이메일 계정을 만든다. 이메일로 로그인 → 마이페이지 **카카오 계정 연결** → 현재 ARTI 비밀번호 입력 → 카카오에서 인증 → 마이페이지 **카카오 계정 연결됨**까지 확인한다.
4. ARTI에서 로그아웃하고 로그인 화면의 **연결한 카카오 계정으로 로그인**을 누른다. 같은 ARTI 계정의 취향과 시험 영수증을 다시 열어 확인한다. 두 번째 ARTI 계정에는 같은 카카오 식별자를 중복 연결할 수 없어야 한다. 사용자 취소, 잘못된 비밀번호, 사용한 콜백 재접근도 확인한다.
5. 배포의 프록시·앱 접속 로그와 모니터링에서 콜백 쿼리·코드·토큰이 남지 않는지 확인한다. 성공·취소·실패는 시간, 단계, 상태 코드와 ARTI 요청 ID로 기록한다. `KOE004`는 로그인 사용 설정, `KOE005`는 테스트 앱 멤버, `KOE006`은 REST 키에 등록한 URI, `KOE010`은 해당 키의 시크릿부터 확인한다. [카카오 오류 코드](https://developers.kakao.com/docs/ko/kakaologin/trouble-shooting)

표준 Compose 배포는 저장소 루트에서 아래 순서로 실행할 수 있다. 프로젝트명과 환경 파일은 이미 배포에 쓰고 있는 값으로 바꾼다.

```powershell
$artiProject = '기존-배포-프로젝트명'
$artiEnvFile = '.env.compose'
docker compose --env-file $artiEnvFile -p $artiProject config --quiet
docker compose --env-file $artiEnvFile -p $artiProject run --rm migrate
docker compose --env-file $artiEnvFile -p $artiProject up -d --build api
```

## 3. 운영 적용과 계정 복구

- 운영 앱과 주소에서 같은 절차를 다시 거친다. 앱 변경 시 식별자를 재연결하기 전에 운영 계정의 소유자를 확인한다. 카카오 버튼을 내려야 하면 배포의 카카오 환경값을 비우고 API를 재시작할 수 있다. 기존 이메일 로그인과 ARTI 계정 데이터는 계속 이용할 수 있다.
- 공개 전에 연결 해제, 계정 복구, 탈퇴가 ARTI 연결 레코드·카카오 연결·관람기록에 각각 어떤 영향을 주는지 정한다. 계정 연결 시 보관하는 카카오 식별자와 파기 기준은 약관·처리방침 초안에 반영한다. 카카오 전용 신규 가입은 기존 연결 시험 범위와 별개다. [가입·OAuth 준비안](2026-11-14_가입안내와OAuth준비.md) · [카카오 연결 해제](https://developers.kakao.com/docs/ko/kakaologin/rest-api#unlink)
- 이메일 복구는 별도 설정으로 활성화한다. SMTP와 발송 작업이 준비되면 **메일 소유 확인 → 새 ARTI 비밀번호 설정** 절차로 검수한다. 이미 연결한 카카오로 다시 로그인해 같은 ARTI 회원과 영수증을 여는지도 첫 연동 이후 확인한다. [비밀번호 재설정 검수와 배포 준비](비밀번호재설정_로컬검수와배포준비.md)

## 4. 첫 실제 시험 인수표

| 단계 | 담당과 완료 기준 |
| --- | --- |
| 앱 준비 | 팀 앱 소유자가 앱 종류와 담당자를 정한다. 같은 HTTPS 주소에 콜백과 프런트 완료 경로를 연결하고, 콘솔에서 로그인·OIDC·콜백 등록을 마친다. 회신에는 공개 가능한 시험 주소와 설정 완료 여부를 적는다. |
| ARTI 준비 | 담당자가 서버 비밀 설정을 적용한다. `GET /api/ready`는 `200`, `GET /api/auth/kakao/status`는 `enabled: true`를 확인한다. 앱 키 값은 서버 설정에서만 사용한다. |
| 계정과 영수증 | 기존 합성 이메일 계정의 회원 ID와 시험 영수증 ID를 적는다. 카카오 연결 후 로그아웃하고 다시 로그인했을 때 두 ID가 같아야 한다. 연결 취소와 다른 ARTI 계정의 중복 연결도 확인한다. |
| 로그와 복귀 | 사용한 콜백을 다시 열어 연결이 추가되지 않는지 확인한다. 접속 로그에서는 시간·응답 코드·ARTI 요청 ID를 남긴다. 문제가 생기면 카카오 설정을 비운 시험 배포를 다시 적용하고 이메일 로그인과 영수증 조회를 확인한다. |

팀 앱·HTTPS 주소가 결정되면 첫 두 단계를 진행한다. 첫 카카오 로그인과 실제 SMTP 통합 검수는 각각의 설정이 준비되는 순서에 따라 진행하며, 둘 다 준비되면 비밀번호 재설정 후 같은 카카오 계정으로 재로그인한다.

`7611856`의 모의 HTTPS Chrome이 통과했다. 첫 실제 시험에서는 아래 항목을 채워 모의 결과와 이어서 확인한다. [PR #50 CI](https://github.com/2026-2-zolp/arti/actions/runs/44098945732)

```text
팀 앱 소유자 / 앱 종류 / 시험용 HTTPS 주소 / 배포 커밋
카카오 로그인 / OIDC / REST 키 리다이렉트 URI 등록 완료 여부
ARTI ready·Kakao status / 연결·취소·중복·콜백 재사용 결과
회원과 영수증 ID 유지 여부 / 비밀번호 재설정 뒤 카카오 재로그인 결과 또는 미실행
실패한 단계 / 응답 코드와 ARTI 요청 ID / 이메일 로그인 복귀 결과
```

### 첫 연동에서 막히는 경우

| 관찰한 결과 | 다음 확인 |
| --- | --- |
| 로그인 버튼이 숨겨지고 `enabled: false`가 나온다. | 시험 배포의 세 카카오 환경변수가 같은 앱·HTTPS 주소를 가리키는지 확인한다. 설정을 적용한 API를 다시 기동하고 상태를 본다. |
| 카카오 인증은 끝났고 연결된 ARTI 계정이 없다는 안내가 나온다. | 이전 이메일로 로그인해 마이페이지에서 연결한다. 이어서 로그아웃하고 카카오로 같은 회원과 시험 영수증을 연다. |
| 콜백 재사용 또는 다른 계정에서 완료 시 `KAKAO_INVALID_FLOW` 또는 `KAKAO_ACTOR_CHANGED`가 나온다. | 기존 콜백을 닫고 연결을 시작한 ARTI 계정에서 새 요청을 시작한다. 실패 단계·코드와 요청 ID를 회신에 남긴다. |
