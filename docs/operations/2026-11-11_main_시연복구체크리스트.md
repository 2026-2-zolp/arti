## 시작 전

- [ ] 시연 커밋, 사용할 전시 ID, 시연 주소, DB·미디어 프로젝트 이름을 적는다. 이번 시험은 `fixture-ex01`, 원본 `arti-demo-1111-source`, 복원 `arti-demo-1111-restore`를 사용했다. API는 PC 루프백의 4418/4419에 열고 Chrome 검증 프록시도 루프백에만 열었다. 두 환경의 PostgreSQL과 미디어는 각각 별도 볼륨을 사용했다.
- [ ] 합성 리허설에는 별도의 ignored env, `ARTI_ENV=test`, `ALLOW_TEST_FIXTURES=true`, `ARTI_TASTE_PROFILE_V2_ENABLED=true`를 사용한다. 첫 기동에서 원본 API에만 `python manage.py load_test_fixture`를 실행한다. 백업에서 복원한 대상에는 fixture를 다시 넣지 않는다.
- [ ] `/api/ready`가 200인지 확인하고, `/api/health`에서 도슨트와 작품 분석 설정을 각각 확인한다. `configured`인 경우 실제 시험 질문도 보낸다. 이번에는 별도 루프백 제공자를 사용했다. 실제 GPT를 쓰는 날에는 검수된 자료와 의도한 provider로 질문·응답을 따로 확인한다. [기동 및 합성 자료 안내](프론트인수_PC와휴대폰검증.md)

## 정상 시연과 실패 시 진행

- [ ] 전시 링크 → 취향 작품 5쌍 → 취향 미리 확인 → 30분 선택 → 추천 3점과 이유 → 도면 지도 → 첫 작품을 연다. 취향 선택은 조사풀, 감상 작품은 해당 전시에서 불러오는지 확인한다.
- [ ] 작품해설과 관람가이드를 확인하고, 관찰 질문에서 도슨트로 들어가 관찰 내용을 입력한다. 성공하면 현재 작품·질문의 응답인지 확인하고, 실패하면 입력이 남고 재시도 안내가 보이는지 확인한다. 같은 질문으로 한 번 재시도할 수 있다.
- [ ] 응답이 계속 없으면 관람가이드로 돌아와 나머지 작품과 아트 영수증으로 진행한다. 발표에서 AI 응답을 보여줄 필요가 있으면 미리 확보한 **실행 당시 기록**임을 밝히고 사용한다. AI 응답이 없는 흐름으로도 관람을 마칠 수 있어야 한다.
- [ ] 회원은 반응과 이유를 한 번 남기고 영수증 저장을 확인한다. 비회원은 영수증을 확인하고 서버 관람 기록이 생성되지 않는지 본다. 발표 당일에는 시연 환경과 동일한 휴대폰 또는 PC에서 한 번 더 완주한다.

## DB·미디어 복원과 전환

1. 원본 API 쓰기를 멈춘 뒤 PostgreSQL custom dump(`pg_dump -Fc`), 미디어 tar, 파일별 SHA-256, 커밋을 한 세트로 보관한다. 실제 자료를 인수하는 날에는 공개 범위와 백업 접근 권한을 먼저 확인한다.
2. 새 프로젝트에 **테이블이 없는 DB와 빈 미디어 볼륨**을 준비한다. 같은 PostgreSQL 메이저 버전에서 `pg_restore --exit-on-error --single-transaction --no-owner --no-acl`로 복원한다. 미디어는 manifest에 있는 일반 파일만 풀고 파일 해시와 앱 UID 10001 소유권을 확인한다. [Compose 명령 예시](../execution-plan/2026-11-07/records/backup-restore/2026-11-09/commands.md)
3. 복원한 API를 기동하고 200 준비 응답, 작품·도면 접근, 미검수 작품·보호 이미지 비노출을 확인한다. 같은 회원으로 **새 브라우저 세션**에서 로그인하고 마이페이지에서 과거 영수증을 연다.
4. 기존 관람과 같은 요청은 200과 같은 영수증을 돌려주는지, 같은 관람 ID에 다른 내용은 409인지 확인한다. 다른 회원과 비로그인 사용자의 조회가 각각 403과 401인지 확인한다. 시험 원본과 복원본의 관람·반응 행 수와 내용 해시를 대조한다.
5. 복원본 API와 DB를 재시작하고 준비 응답·행·파일을 다시 확인한다. 원본 전환이 필요할 때만 새 주소를 사용한다. 실패하면 기존 백업과 원본을 보존하고 복원 대상에서 원인을 확인한다. 리허설이 끝나면 시험 프로젝트만 `down`하고 볼륨을 유지한다.
