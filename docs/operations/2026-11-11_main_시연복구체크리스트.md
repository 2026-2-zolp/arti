## DB·미디어 복원과 전환

1. 원본 API 쓰기를 멈춘 뒤 PostgreSQL custom dump(`pg_dump -Fc`), 미디어 tar, 파일별 SHA-256, 커밋을 한 세트로 보관한다. 실제 자료를 인수하는 날에는 공개 범위와 백업 접근 권한을 먼저 확인한다.
2. 새 프로젝트에 **테이블이 없는 DB와 빈 미디어 볼륨**을 준비한다. 같은 PostgreSQL 메이저 버전에서 `pg_restore --exit-on-error --single-transaction --no-owner --no-acl`로 복원한다. 미디어는 manifest에 있는 일반 파일만 풀고 파일 해시와 앱 UID 10001 소유권을 확인한다. [Compose 명령 예시](../execution-plan/2026-11-07/records/backup-restore/2026-11-09/commands.md)
3. 복원한 API를 기동하고 200 준비 응답, 작품·도면 접근, 미검수 작품·보호 이미지 비노출을 확인한다. 같은 회원으로 **새 브라우저 세션**에서 로그인하고 마이페이지에서 과거 영수증을 연다.
4. 기존 관람과 같은 요청은 200과 같은 영수증을 돌려주는지, 같은 관람 ID에 다른 내용은 409인지 확인한다. 다른 회원과 비로그인 사용자의 조회가 각각 403과 401인지 확인한다. 시험 원본과 복원본의 관람·반응 행 수와 내용 해시를 대조한다.
5. 복원본 API와 DB를 재시작하고 준비 응답·행·파일을 다시 확인한다. 원본 전환이 필요할 때만 새 주소를 사용한다. 실패하면 기존 백업과 원본을 보존하고 복원 대상에서 원인을 확인한다. 리허설이 끝나면 시험 프로젝트만 `down`하고 볼륨을 유지한다.

### 2. 관람·기록 생성

1. Chrome에서 `$sourceUrl`에 `/exhibitions/fixture-ex01`을 붙여 열고 **관람 시작하기 → 회원가입**을 누른다. `demo-member@example.test`와 시험 비밀번호를 입력하고, 비밀번호 확인과 약관 동의를 마친 뒤 가입한다.
2. 1/5에서 위쪽 작품을 고른 뒤 2/5에서 앱 상단 **뒤로가기**를 눌러 1/5로 돌아오는지 본다. 작품 이미지를 열면 크게 보기, 각 카드의 **선택** 버튼을 누르면 다음 비교로 간다. 다섯 쌍 모두 위쪽 작품을 선택하고 **취향 미리 확인 → 이번 관람만 적용 → 30분 → 추천 받기 → 2D 지도에서 경로 보기 → 관람 시작하기**를 누른다. 추천 목록·지도·감상 순서는 **검증용 작품 01 → 03 → 05**다.
3. 첫 작품에서 **관람가이드 → 1번 질문으로 대화하기**로 진입한다. 질문 입력에 `그림에서 가장 밝은 부분이 보여요.`를 입력하고 **보내기**를 누른다. 응답 503과 **다시 시도**, 입력 유지가 보이면 재시도 후 상단 **뒤로가기**를 눌러 같은 작품으로 돌아간다. 모의 제공자 재시도 성공은 별도 환경에서 확인한다. [모의 도슨트 재현](../작업기록/2026-11-15_AI도슨트브라우저복구.md#재현)
4. 첫 작품에서 **좋아요 → 색감이 좋아요 → 다음 작품 안내**를 누른다. 2번 작품 카드와 이동 구간을 확인하고 앱 상단 **뒤로가기**로 1번 작품에 돌아간 뒤 브라우저 앞으로가기로 2번 안내를 다시 연다. 새로고침 후에도 안내와 마커가 같은 작품을 가리켜야 한다. 나머지를 감상해 **관람 마치기**를 누르고 저장 성공 표시와 영수증 3점을 본다.
5. 새 영수증 화면 상단에 뒤로가기 화살표가 없는지 본다. 브라우저 뒤로가기에서 종료 확인이 뜨면 **머무르기**를 눌러 같은 영수증으로 돌아간다. **이미지 저장·공유**로 PNG를 받아 열어 보고, **관람 완료 → 마이페이지**에서 기록 한 건을 연다. 과거 영수증의 상단 화살표를 누르면 마이페이지로 돌아와야 한다. 네트워크에서 회원의 첫 저장은 201이고, 복귀로 재전송되면 같은 영수증 ID의 200이다.

### 3. 새 DB·미디어로 복원

원본 명령을 실행한 PowerShell에 이어 붙인다. 2단계에서 생성한 계정 2개와 관람·반응 각 한 건을 재현한다. 덤프와 미디어를 복사한 다음 원본 시험 프로젝트를 내린다. 원본 볼륨은 남기고, 해제된 Docker 네트워크를 확보한 뒤 새 프로젝트를 기동한다. 운영형 검수 기록의 회원 두 명과 관람 두 건은 별도의 합성 백업을 사용한 결과다.

```powershell
$env:ARTI_DEMO_PORT = "$restorePort"
$db = "$dst-db-1"
$hashCommand = 'cd /app/media && sha256sum fixture-public.png fixture-private.png'
$before = docker compose @source exec -T api sh -ec $hashCommand
docker compose @source exec -T db pg_dump -U arti -d arti -Fc -f /tmp/team-demo.dump
docker compose @source exec -T api tar -C /app/media -cf /tmp/team-demo-media.tar fixture-public.png fixture-private.png
docker cp "${src}-db-1:/tmp/team-demo.dump" (Join-Path $dir 'arti.dump')
docker cp "${src}-api-1:/tmp/team-demo-media.tar" (Join-Path $dir 'media.tar')
docker compose @source down
docker compose @restore up -d --wait db
$tables = docker exec $db psql -U arti -d arti -tAc "select count(*) from pg_tables where schemaname='public'"
if ($tables -ne '0') { throw '비어 있는 새 DB가 필요합니다.' }
docker cp (Join-Path $dir 'arti.dump') "${db}:/tmp/arti.dump"
docker exec $db pg_restore -U arti -d arti --exit-on-error --single-transaction --no-owner --no-acl /tmp/arti.dump
docker compose @restore build api migrate
docker compose @restore create api
docker compose @restore run --rm --no-deps -T --user 0 -v "${dir}:/backup:ro" api sh -ec 'test -z "$(ls -A /app/media)" && tar -xf /backup/media.tar -C /app/media fixture-public.png fixture-private.png && chown 10001:10001 /app/media /app/media/fixture-public.png /app/media/fixture-private.png'
docker compose @restore up -d --no-build --wait web
docker compose @restore logs migrate
docker compose @restore exec -T api python manage.py migrate --check
$after = docker compose @restore exec -T api sh -ec $hashCommand
if (Compare-Object $before $after) { throw '복원 미디어 해시 불일치' }
$sql = "select (select count(*) from arti_account), (select count(*) from arti_visit), (select count(*) from arti_visitreaction)"
$expected = docker exec $db psql -U arti -d arti -tAc $sql
if ($expected -ne '2|1|1') { throw "예상과 다른 계정·관람·반응 수 $expected" }
(Invoke-RestMethod "$restoreUrl/api/ready").database
```

복원 `migrate` 로그에서 `No migrations to apply`를 확인한다. 새 Chrome 세션에서 복원 주소의 `/mypage`로 들어가 같은 회원으로 로그인한다. 영수증 한 건을 열어 3점과 좋아요를 확인한 뒤 새로고침한다. 관리자 로그인 뒤 `/admin/members`에서 같은 회원의 관람기록과 `/admin/reactions` 화면의 반응 사유를 대조한다. 공개 `/api/uploads/fixture-public.png`는 200, 비공개 `/api/uploads/fixture-private.png`는 404여야 한다. 관리자 작품 관리의 **검증용 작품 13** (`/admin/artworks/fixture-art13`)에서 이미지 미리보기를 확인한다.

회신에는 **재현 커밋·브라우저·도커 버전, 원본/복원 준비 응답, V2 추천 순서, 직전 작품 복귀, 도슨트 실패 후 복귀, 저장 PNG, 회원 기록과 비회원 저장 요청 수, 미디어 해시 일치**를 적는다. 실패하면 어느 단계에서 어떤 버튼을 눌렀는지와 응답 코드 또는 화면을 함께 남긴다. [운영형 검수 기록](../작업기록/2026-11-15_운영형로컬기동과합성복원.md)

### 복원 후 영수증 접근 권한 확인

회원 영수증이 있는 합성 DB와 미디어를 위 절차로 새 프로젝트에 복원한다. 영수증 보유 회원 A, 같은 복원 환경에서 새로 만든 회원 B, 시험 관리자, 비회원 브라우저 세션을 준비한다. 회원 A의 목록에서 영수증 ID를 기록한다. 모든 요청은 같은 복원 환경의 Nginx 주소에 보낸다.

| 확인 주체 | 실행과 기대 결과 |
| --- | --- |
| 회원 A | `/api/users/<A ID>/visits`에 한 건. `/api/visits/<영수증 ID>`는 200. PC Chrome에서 `/receipt/<영수증 ID>`를 직접 열고 새로고침해도 감상 작품을 확인할 수 있다. |
| 회원 B | 자기 목록은 빈 배열. A의 목록과 영수증 상세 API는 403. A의 영수증 화면 주소를 직접 열고 새로고침해도 안내와 재시도만 표시되고 영수증 본문은 보이지 않는다. |
| 비회원 | A의 목록과 상세 API는 401. 영수증 화면 주소는 로그인으로 이동한다. |
| 관리자 | `/api/admin/members/<A ID>/visits`의 한 건과 `/api/admin/visits/<영수증 ID>` 상세를 A의 조회 결과와 대조한다. 관리자의 토큰을 회원용 `Authorization: Bearer`로 보내거나 회원 토큰을 `X-Admin-Token`으로 보내면 401이다. 비공개 미디어는 회원 주소에서 404, 관리자 주소에서 200이다. |

`e2f8127` 운영형 빌드를 새 Compose 프로젝트로 복원해 위 네 역할을 모두 확인했다. API는 Nginx 경유 응답으로 대조했고, 영수증 주소 직접 진입·새로고침은 PC Chrome에서 실행했다. 복원 회원 A의 시험 비밀번호는 그 복원본에서만 재설정했다. 사용한 합성 백업은 [Compose 복구 기록](../작업기록/2026-11-16_Compose기동실패와Nginx복구.md)에 적힌 자료다.
