## 정상 시연과 실패 시 진행

- [ ] 전시 링크 → 취향 작품 5쌍 → 취향 미리 확인 → 30분 선택 → 추천 3점과 이유 → 도면 지도 → 첫 작품을 연다. 취향 선택은 조사풀, 감상 작품은 해당 전시에서 불러오는지 확인한다.
- [ ] 작품해설과 관람가이드를 확인하고, 관찰 질문에서 도슨트로 들어가 관찰 내용을 입력한다. 성공하면 현재 작품·질문의 응답인지 확인하고, 실패하면 입력이 남고 재시도 안내가 보이는지 확인한다. 같은 질문으로 한 번 재시도할 수 있다.
- [ ] 응답이 계속 없으면 관람가이드로 돌아와 나머지 작품과 아트 영수증으로 진행한다. 발표에서 AI 응답을 보여줄 필요가 있으면 미리 확보한 **실행 당시 기록**임을 밝히고 사용한다. AI 응답이 없는 흐름으로도 관람을 마칠 수 있어야 한다.
- [ ] 회원은 반응과 이유를 한 번 남기고 영수증 저장을 확인한다. 비회원은 영수증을 확인하고 서버 관람 기록이 생성되지 않는지 본다. 발표 당일에는 시연 환경과 동일한 휴대폰 또는 PC에서 한 번 더 완주한다.

## DB·미디어 복원과 전환

1. 원본 API 쓰기를 멈춘 뒤 PostgreSQL custom dump(`pg_dump -Fc`), 미디어 tar, 파일별 SHA-256, 커밋을 한 세트로 보관한다. 실제 자료를 인수하는 날에는 공개 범위와 백업 접근 권한을 먼저 확인한다.
2. 새 프로젝트에 **테이블이 없는 DB와 빈 미디어 볼륨**을 준비한다. 같은 PostgreSQL 메이저 버전에서 `pg_restore --exit-on-error --single-transaction --no-owner --no-acl`로 복원한다. 미디어는 manifest에 있는 일반 파일만 풀고 파일 해시와 앱 UID 10001 소유권을 확인한다. [Compose 명령 예시](../execution-plan/2026-11-07/records/backup-restore/2026-11-09/commands.md)
3. 복원한 API를 기동하고 200 준비 응답, 작품·도면 접근, 미검수 작품·보호 이미지 비노출을 확인한다. 같은 회원으로 **새 브라우저 세션**에서 로그인하고 마이페이지에서 과거 영수증을 연다.
4. 기존 관람과 같은 요청은 200과 같은 영수증을 돌려주는지, 같은 관람 ID에 다른 내용은 409인지 확인한다. 다른 회원과 비로그인 사용자의 조회가 각각 403과 401인지 확인한다. 시험 원본과 복원본의 관람·반응 행 수와 내용 해시를 대조한다.
5. 복원본 API와 DB를 재시작하고 준비 응답·행·파일을 다시 확인한다. 원본 전환이 필요할 때만 새 주소를 사용한다. 실패하면 기존 백업과 원본을 보존하고 복원 대상에서 원인을 확인한다. 리허설이 끝나면 시험 프로젝트만 `down`하고 볼륨을 유지한다.

### 1. 원본 기동과 준비

다음 명령은 실행별로 다른 시험 프로젝트를 만든다. 5232·5233을 이미 쓰고 있으면 블록 안의 `$sourcePort`와 `$restorePort`를 비어 있는 값으로 바꾼다. Nginx만 루프백으로 열고 Django·PostgreSQL은 Compose 내부에서 연결한다.

```powershell
$ErrorActionPreference = 'Stop'
$PSNativeCommandUseErrorActionPreference = $true
$trial = Get-Date -Format 'yyyyMMddHHmmss'
$src = "arti-team-src-$trial"
$dst = "arti-team-dst-$trial"
$sourcePort = 5232
$restorePort = 5233
$dir = Join-Path (Get-Location) "data/private/team-demo-$trial"
New-Item -ItemType Directory -Path $dir | Out-Null
$overlay = Join-Path $dir 'compose.ops.yaml'
@'
services:
  api:
    ports: !reset []
  web:
    image: arti-team-demo-web:${ARTI_DEMO_TRIAL}
    build:
      context: ./frontend
      dockerfile: Dockerfile.static
    depends_on:
      api:
        condition: service_healthy
    ports:
      - "127.0.0.1:${ARTI_DEMO_PORT}:80"
'@ | Set-Content -LiteralPath $overlay -Encoding utf8
$env:ARTI_DEMO_TRIAL = $trial
$env:ARTI_DB_PASSWORD = [guid]::NewGuid().ToString('N')
$env:DJANGO_SECRET_KEY = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
$env:ARTI_ENV = 'production'
$env:ALLOW_TEST_FIXTURES = 'false'
$env:ARTI_TASTE_PROFILE_V2_ENABLED = 'true'
$env:ARTI_LLM_PROVIDER = 'disabled'
$env:OPENAI_API_KEY = ''
$env:ARTI_MODEL_SERVICE_URL = ''
$env:ARTI_KAKAO_CLIENT_ID = ''
$env:ARTI_KAKAO_CLIENT_SECRET = ''
$env:ARTI_KAKAO_CALLBACK_URL = ''
$env:ARTI_DEMO_PORT = "$sourcePort"
$password = 'ArtiDemo1-' + [guid]::NewGuid().ToString('N')
$source = @('-f', 'compose.yaml', '-f', $overlay, '-p', $src)
$restore = @('-f', 'compose.yaml', '-f', $overlay, '-p', $dst)
$sourceUrl = "http://127.0.0.1:$sourcePort"
$restoreUrl = "http://127.0.0.1:$restorePort"
docker compose @source up -d --build --wait web
docker compose @source logs migrate
docker compose @source exec -T -e ARTI_ENV=test -e ALLOW_TEST_FIXTURES=true api python manage.py load_test_fixture

$pool = Invoke-RestMethod "$sourceUrl/api/taste-pool"
if (!$pool.ready -or !$pool.tasteTieV2Enabled -or $pool.pairs.Count -ne 5) { throw '취향 V2 조사풀 확인 실패' }
```

원본 `migrate` 로그에서 8개 마이그레이션 적용, 준비 응답에서 `postgresql`을 확인한다. 두 시험 계정에 쓸 이번 실행 전용 비밀번호는 로컬 PowerShell에서 `$password`를 확인해 입력한다. 검수 회신에는 비밀번호를 넣지 않는다.

### 3. 새 DB·미디어로 복원

원본 명령을 실행한 PowerShell에 이어 붙인다. 2단계에서 생성한 계정 2개와 관람·반응 각 한 건을 재현한다. 운영형 검수 기록의 회원 두 명과 관람 두 건은 별도의 합성 백업을 사용한 결과다.

```powershell
$env:ARTI_DEMO_PORT = "$restorePort"
$db = "$dst-db-1"
$hashCommand = 'cd /app/media && sha256sum fixture-public.png fixture-private.png'
$before = docker compose @source exec -T api sh -ec $hashCommand
docker compose @source exec -T db pg_dump -U arti -d arti -Fc -f /tmp/team-demo.dump
docker compose @source exec -T api tar -C /app/media -cf /tmp/team-demo-media.tar fixture-public.png fixture-private.png
docker cp "${src}-db-1:/tmp/team-demo.dump" (Join-Path $dir 'arti.dump')
docker cp "${src}-api-1:/tmp/team-demo-media.tar" (Join-Path $dir 'media.tar')
docker compose @restore up -d --wait db
$tables = docker exec $db psql -U arti -d arti -tAc "select count(*) from pg_tables where schemaname='public'"
if ($tables -ne '0') { throw '비어 있는 새 DB가 필요합니다.' }
docker cp (Join-Path $dir 'arti.dump') "${db}:/tmp/arti.dump"
docker exec $db pg_restore -U arti -d arti --exit-on-error --single-transaction --no-owner --no-acl /tmp/arti.dump
docker compose @restore build api migrate
docker compose @restore create api
```

복원 `migrate` 로그에서 `No migrations to apply`를 확인한다. 새 Chrome 세션에서 복원 주소의 `/mypage`로 들어가 같은 회원으로 로그인한다. 영수증 한 건을 열어 3점과 좋아요를 확인한 뒤 새로고침한다. 관리자 로그인 뒤 `/admin/members`에서 같은 회원의 관람기록과 `/admin/reactions` 화면의 반응 사유를 대조한다. 공개 `/api/uploads/fixture-public.png`는 200, 비공개 `/api/uploads/fixture-private.png`는 404여야 한다. 관리자 작품 관리의 **검증용 작품 13** (`/admin/artworks/fixture-art13`)에서 이미지 미리보기를 확인한다.
