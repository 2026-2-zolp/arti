# 유영국 전달 자료 검토와 시연 준비 계획

2026-11-09 KST / 코드 기준858b2bb / W06 AC18·AC19 관련 조사. 전달 ZIP과 카톡을 자료로 검토했으며 문서 내부의 설명을 구현 지시나 승인으로 취급하지 않았다. DB 적재·승인·실모델 호출은 수행하지 않았다.

## 판단

**유영국은 시연 후보로 유지할 가치가 있다. 다만 이번 자료는 검수 완료된 전시 데이터가 아니라 인수·내용 대조가 필요한 자료다.** 개별 작품의 일화가 적다는 이유만으로 전시를 바꿀 필요는 없다. ARTI의 초심자 관찰 지원, 취향 추천, 작품해설/관람가이드에서 AI 도슨트로 이어지는 목적에 맞춰 판단한다.

이미지에서 거친 질감/기하학적 색면, 따뜻한 색/차가운 색, 어두움/밝음의 대비가 보인다. 관찰 대화 소재는 충분하다. 반면 단일 작가의 추상·산 계열이라 현재 8개 취향 태그의 분포와 추천 구별력은 별도 검증이 필요하다. 이미지를 보았다는 사실만으로 CLIP·mDeBERTa 성능이나 추천 품질을 통과시키지 않는다.

## 설명 TXT의 성격

공통 작가 정보와 작품별 기본정보/시각적 관찰/해석·상징/작가·시대 맥락/화풍/연관 작품으로 구성됐다. MMCA 참고 링크3개와 확인일2026-11-08이 있으나 **내용 대조 필요**라고 명시돼 있다. 작가 소개, 눈에 보이는 특징, 감상 해석, 미확인 사실이 섞여 있다. 작성 주체와 AI 사용 여부는 확인되지 않았다.

예를 들어 여러 작품에 재료가 유화로 보인다는 추정, 크기·소장처 확인 필요가 남아 있다. 1984년 작품의 동일성도 확인 필요로 적혀 있다. 후기 작품의 인타글리오 기법, 두 작품의 짝 관계, 제목에 담긴 작가 의도 등은 해당 작품별 근거를 확보해야 한다. 색면을 해·달·물로 읽는 감상은 가능하지만 작가가 의도한 정답으로 단정하면 안 된다.

따라서 전체 TXT를 공식 원문으로 저장하거나 관리자 확정 상태로 일괄 가져오지 않는다. 검토 시 ①출처로 확인한 사실 ②검수한 팀 작성 설명 ③관찰 질문 ④가능한 해석/미확인 메모를 구분한다. 팀 작성 설명은 공식 해설 인용과 구별해서 표시한다. 이번 단계에서 별도 거대 콘텐츠 시스템을 만들 필요는 없다.

현재 작품해설/관람가이드2탭 계약은 유지한다. 예시로04번에서 ‘어느 색에 먼저 눈이 가나요?’→‘대각선을 따라 시선을 움직여 보세요’→‘내 생각 이야기하기’를 연결할 수 있다. 사용자의 ‘초록 삼각형이 앞으로 튀어나와 보여요’와 현재 질문을 도슨트에 넘기고 그 관찰을 이어가게 한다. 이는 검토용 관찰 질문 예시이며 승인 콘텐츠/실제 모델 응답 결과가 아니다.

S1은2024년 청주5점 전시이고 S2는2016~2017년 덕수궁 전시다. 이를 섞은16점을 특정 실제 전시의 출품 목록이라고 소개하지 않는다. 시연용 재구성을 택한다면 명확히 표시한다. 실제 전시를 택하면 그 전시의 출품·배치 근거를 별도 확보한다.

## 자료 도착 이후 작업 순서와 통과 기준 제안

기존 Django 실행 일관화와 Git자료 의존분리 결과는 유지한다. 대기계획의 다음 독립 작업인 백업/복원 검증은 여전히 가능하지만 실제 자료 사용 전에 수행하는 것이 좋다. W06 AC18/19는 이번 조사만으로 통과하지 않는다.

1. **W06 식별·출처 인수표:** 16점의 안정된ID/원래 파일명/해시/공식 제목·연도·재료·치수/작품별URL/전시 포함 근거/이용 조건/검토자를 연결한다. 5개 시각 대응은 우선 후보로 삼고 나머지는 대기한다. 통과 기준은 시연에 사용할 모든 항목의 식별·근거가 연결되고 미확정 작품이 승인 목록에 섞이지 않는 것. 이미 확인한5개도 최종 검수를 대신하지 않는다.
2. **설명·가이드 검수:** 핵심3점을 먼저 선정한다. 예:04번 기하학적 구성,08번 반복·방사형 형태,10번 산의 중첩. 사실 설명과 팀 감상/질문을 분리하고 해설·가이드를 각각 검수한다. 통과 기준은 작품별 출처 확인과 관리자 재조회/공개 범위 확인. 최소3점 준비가 W06 전체 통과나3/5/7 모든 추천 경로 준비를 뜻하지 않는다.
3. **자료 보존 후 개발 DB 인수:** 기존 백업/복원 절차를 분리된 시험 환경에서 확인한다. 그 뒤 현재 capture40 전용 importer와 실제 인수표의 차이를 검토해 필요한 최소 적재 기능을 정한다. source_check/draft에서 시작하고 자동 approved/running 또는 실제 좌표를 만들지 않는다. 해시·개수·관계·원본 미변경·재적재 시 검수 정책을 확인한다.
4. **취향 풀·추천 점검:** 실제 사용하는10점/5쌍과3/5/7 추천을 검토한다. 이미지 재사용 여부와 풀 선정 기준을 명시하고 시각 대비가 있는 쌍을 우선한다. current 태그에 맞추려고 없는 인물/감정을 붙이지 않는다. 모델 연동 전에는 사람 검토 라벨을 모델 출력이라고 부르지 않는다. 실모델 연결 후 고정 입력의 출력·시간·실패와 추천 차이를 확인해야 AC19/후속 모델 품질을 평가할 수 있다. 유영국만으로 변별력이 부족하면 취향 파악용 공통 풀과 전시 내 추천 풀 분리를 후보로 검토하되 계약 변경은 따로 판단한다.
5. **W07 실제 모델·전체 여정:** 키·사용 모델을 정할 때 확장 방향과 하네스를 함께 논의한다는 기존 결정을 유지한다. 그 전까지 유료 호출/하네스 구현을 시작하지 않는다. Django의 실제 태그/감정 연동도 남은 과제다. 실제 키 없이 AI 대화를 정상 작동한다고 발표하지 않는다. 이후 선택→추천→지도→해설/가이드→문맥을 이어받는 도슨트→기록과 비활성/오류를 검증한다.

**유영국 유지/교체 판단 시점:** 식별·이용 가능한10점 풀과 핵심3점 콘텐츠를 확보할 수 있는지, 실제 태그/추천이 유의미하게 구분되는지 확인한 뒤 결정한다. 선명도·근거·구별력 문제가 확보 가능한 자료로 해결되지 않거나 시연 일정 대비 보완 비용이 큰 경우에만 대체 전시를 비교한다. 개별 일화가 적다는 사유만으로 교체하지 않는다.

## 자체 관점 검토와 남은 한계

작성자가 기존 검증단의 관점을 적용해 재검토했다. 별도 사람/교수님/모델의 검토를 받았다는 뜻은 아니다.

- 팀/인수: 추가20~40점 수집보다 현재16점의 정확한 출처·판본을 먼저 요청하는 것이 재작업을 줄인다.
- 교수님/주제: 관찰과 질문을 돕는 서비스라는 설명이 가능하다. 추천 성능과 실AI 실행 근거가 아직 없다는 경계를 유지한다.
- 방문자: 추상화에는 정답 찾기보다 짧은 질문이 유용할 수 있다. 이는 설계 판단이며 실제 초심자 사용성 검증은 남아 있다.
