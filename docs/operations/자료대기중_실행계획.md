# 유영국 자료·GPT 키 대기 중 실행계획

2026-11-08 KST / 조사 기준530291a. 사용자가 자료 도착 전에 가능한 작업을 구체화하도록 요청했다. 코드·실행계획을 대조한 후 다음 순서를 권한다. 이 문서는 착수 가능한 작은 작업을 정리한 것이며 W06~W12나 제품 게이트를 완료 처리하지 않는다.

## 1. 최우선 — Django 개발 실행 경로 일관화

**실제 빈틈:** compose.yaml의 frontend는 VITE_API_TARGET=django와 api:8000 프록시를 명시한다. 그러나 frontend/vite.config.ts의 단독 dev/preview 기본 프록시는 localhost:4000(기존 Express)이다. client.ts의 ADMIN_READ도 VITE_API_TARGET이 django일 때만 /admin이다. frontend/.env.example은 없다. 이미 검증한 Compose 흐름이 틀렸다는 뜻이 아니라 팀원의 일반 단독 실행 경로가 새 기준과 다르다는 문제다.

작업 범위:

1. Compose와 호스트 Vite 각각의 공식 실행 방법·주소·API 대상 선택 규칙을 정한다. Django를 새 기본으로 하고 legacy는 명시 선택으로 격리하는 방향을 적용한다.
2. Vite 프록시와 client의 관리자 경로가 같은 대상을 사용하도록 맞춘다. Vite 설정에서 .env 값을 어떻게 읽는지도 확인한다. API 키는 프론트 환경변수에 넣지 않는다.
3. 프론트 설정 예시와 새 개발 안내의 진입점을 제공한다. 기존 Windows/Express 실행 안내는 삭제하지 않고 legacy임을 표시한다.
4. 가상 전시/시험 계정만 사용해 호스트 Vite와 Compose에서 회원·관리자·보호이미지·추천·기록·AI비활성 안내를 확인한다. AI 자동 fallback은 추가하지 않는다.

완료 기준: 새 개발자가 환경변수 없이 또는 공식 예시대로 실행할 때 API 대상/관리자 경로가 어긋나지 않는다. Django 정지 시 Express로 자동 우회하지 않는다. 잘못된 대상 설정을 숨기지 않는다. 프론트13회귀·타입/빌드 및 바뀐 설정의 의미 있는 회귀, 관련 실제 UI를 확인한다. 기존 fixture/볼륨과 legacy 원본은 보존한다.

필요 입력: 없음. 유영국 작품·LLM 키·AWS 계정과 독립이다. 기존 W04/W05 개발 전환의 후속 보완으로 기록하며 새 기능을 추가하지 않는다.

## 2. 기존 Git 자료의 읽기 전용 품질·인수 점검

현재 import_capture_bundle은 ex-capture·40점에 한정된 명시 importer다. 이를 곧바로 임의 전시의 범용 importer로 늘리면 실제 인수 형식을 받기 전에 설계를 추정하게 된다. 먼저 기존 자료를 검사하는 작은 읽기 전용 단위를 만든다.

작업 범위: 기존 exporter/manifest·이미지·해설·태그 파일을 대조해 ID 중복/누락, 경로와 해시, 빈 원문/출처, 초안/검수 구분을 한 보고서로 낸다. 40점과 WikiArt 평가자료를 섞지 않고 누락·경고·차단을 구분한다. 자료의 사실성/이미지 권리를 자동 승인하지 않는다. 기존 검증을 복사해 새 프레임워크를 만들지 말고 재사용한다.

완료 기준: 기존 자료의 실제 점검 결과와 변조/누락 fixture의 실패를 확인하고, DB·파일 원본·승인 상태를 바꾸지 않는다. 나중에 실제 유영국 자료가 오면 채울 manifest 필드와 확인할 부족분이 분명하다. 형식 검사가 사람 검수나 AC18/19 전체 통과를 대신하지 않는다.

필요 입력: 기존 Git 자료만. 실제 작품·출품/출처 확정·사람 검수는 대기로 남긴다. GPT 평가 질문·하네스 구현은 포함하지 않는다.

## 3. 개발 DB·미디어의 로컬 백업/복원 절차 검증

자료가 들어온 뒤 실수로 초기화하지 않도록 미리 준비한다. 기존 migration/재시작 검증과 달리, 여기서는 DB와 대응 이미지의 백업 세트를 별도 환경에서 복원하는 것을 확인한다.

작업 범위: 시험 fixture로만 백업 세트와 파일 해시를 만들고, 새 Compose 프로젝트/새 볼륨에 복원한다. 작품/검수 상태·회원 관람 snapshot·대응 미디어를 대조한다. 비밀번호/세션/개인 자료를 Git/공유 로그에 담지 않는다. 원본 볼륨이나 팀원 로컬 DB를 삭제/덮어쓰지 않는다.

완료 기준: 분리된 복원본에서 관계·기록·파일 해시와 공개 제한이 유지되고, 누락된 미디어를 발견할 수 있다. 원본 미변경과 종료/보존 범위를 기록한다. 이것은 로컬 개발 복구 준비이며 AWS 백업·운영복구·AC17 별도 고유자료 인수 완료가 아니다.

필요 입력: 없음. 운영 DB/세션 전체 이전 방식을 확정하거나 AWS 서비스를 만들지 않는다.
