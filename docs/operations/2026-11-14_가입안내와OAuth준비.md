### 2. 보유·이용 기간과 삭제

계정·저장 취향·회원 관람기록은 [항목별 보유기간 또는 종료 조건]까지 보관합니다. 로그인은 발급 후 최대 14일 동안 유효합니다. 만료된 세션, 접속 기록과 백업의 보유기간은 [항목별 기간]입니다. 보유기간이 끝나거나 처리 목적을 달성하면 [확정한 절차와 방법]으로 지체 없이 파기합니다.

### 3. AI 기능에서 전송하는 정보

AI 기능을 사용할 수 있는 환경에서 도슨트에 질문하면 입력한 질문과 최근 대화, 해당 작품의 설명 또는 선택한 관찰 질문이 AI 제공자에게 전송됩니다. 영수증에서 취향 해석을 요청하면 관람한 작품의 정보, 작품별 반응과 체류 시간이 전송됩니다. 두 요청은 이메일, 비밀번호, 계정 ID와 관람 ID를 별도 항목으로 제공자에게 전달하지 않습니다. 자유 입력에 개인정보를 적으면 질문 내용과 함께 전송될 수 있으니 질문에 개인정보를 넣지 말아 주세요.

AI 제공자의 명칭과 연락처, 처리 위치, 전송 시점과 방법, 제공자의 이용 목적·보유 기간, 전송을 거부하는 방법과 그 영향을 [실제 운영 환경에서 확인한 안내 위치]에서 확인할 수 있습니다.

## 동의 화면과 서버 기록 초안

- **가입 화면 적용** · U-04에 서비스 이용약관 체크 한 항목과 두 전문 보기 버튼을 연결했다. 전문은 입력 화면 위에서 열리며 닫으면 입력값과 체크 상태가 유지된다. 운영 주체·연락처·보유기간은 화면에도 팀 확인 중인 초안으로 표시했다. [가입 화면](../../frontend/src/pages/user/U04Signup.tsx) · [표시 문안](../../frontend/src/data/signupDocuments.ts)
- **저장 적용** · Django `POST /api/auth/signup`은 `termsAccepted: true`와 현재 `termsVersion`을 요구한다. 정상 가입 시 계정·약관 버전과 서버 시각·첫 세션을 한 트랜잭션에 저장한다. `0005_signup_terms_acceptance`는 기존 계정에 동의 기록을 추가하지 않는다. 비교용 Express는 새 화면의 요청을 기록하며 예전 직접 호출은 기존 계약으로 처리한다. 표시 본문을 개정할 때는 프론트와 두 API의 약관 버전을 함께 바꾼다. [Django 가입 API](../../backend-django/arti/member.py) · [마이그레이션](../../backend-django/arti/migrations/0005_signup_terms_acceptance.py) · [Express 가입 API](../../backend/src/routes/auth.ts)
- **후속 기준** · 별도 개인정보 동의가 필요한 경우 기능 시작 시 안내하고, 항목·버전·서버 시각·동의/철회를 기록한다. 현재 가입에서는 약관 동의만 남긴다. 기록의 접근 권한과 보유·파기 기간을 정한다. 로그인 세션의 14일 만료는 만료된 DB 행의 파기 시점과 별개다.
- **기존 계정** · 기존 상태는 ‘기록 없음’으로 보존한다. 새 문서 적용이나 재동의가 필요한 경우 대상·시점·보류 시 제공 기능을 정하고 그 시점의 선택을 남긴다. 변경·철회 이력은 이전 기록을 덮어쓰지 않으며, 접근 권한과 보유·파기 기간을 별도로 정한다.
- **로컬 검수** · Edge 320·375·412px에서 약관·처리방침 열기, 닫기와 포커스 복귀, 입력값 보존, 체크 누락, 버전 불일치, 정상 가입 후 마이페이지 진입을 확인했다. 격리 PostgreSQL에서 합성 가입 3건의 약관 버전 `2026-11-14-draft.1`, 유효한 서버 시각, 세션이 각각 한 건씩 연결됐다. API 회귀는 동의 누락·버전 불일치, 중복 요청, 약관 또는 세션 기록 실패 시 롤백과 기존 회원 로그인을 포함한다. Django 156건과 마이그레이션 검사, 프론트 37건과 프로덕션 빌드, 비교용 Express 39건을 통과했다. 팀 확인 항목의 문구를 확정한 뒤 공개에 사용할 버전을 정한다.

## 카카오 OAuth 도입 준비

1. **범위 제안** · 기존 이메일 계정에 카카오를 연결하고 이후 같은 계정으로 로그인하는 팀 내부 시험부터 진행한다. 이미 로그인한 회원이 연결을 시작하고 기존 비밀번호로 재확인한다. 카카오 앱 단위 회원번호를 ARTI 계정에 고유하게 연결하고 같은 이메일만으로 자동 병합하지 않는다. 기존 계정과 영수증·취향 ID가 유지되는지 확인한다. 신규 카카오 전용 가입은 이메일 없이 가입·복구·연결 해제할 방법과 ARTI 동의 절차까지 설계한 뒤 판단한다. [카카오 앱 단위 회원번호 안내](https://developers.kakao.com/docs/ko/getting-started/faq)
2. **앱·주소 준비** · 팀이 관리하는 기존 앱을 확인하고 소유자·관리자를 정한다. 시험 환경의 고정 HTTPS 주소를 확보해 `https://<시험 호스트>/api/auth/kakao/callback` 형식의 후보 경로를 정한다. 등록한 URI와 인가·토큰 요청의 URI를 동일하게 사용한다. 로그인과 OpenID Connect를 활성화하고 REST API 키와 클라이언트 시크릿은 Django 환경으로 관리한다. 카카오 이메일·프로필 등 추가 동의항목은 이번 연결 시험에서 요청하지 않는 안이다. 카카오 테스트 앱을 사용하려면 비즈 앱과 앱 멤버 조건을 확인한다. 현재 5207 LAN 주소와 임시 공유 터널은 관람 검수에 쓰고, 콜백은 팀이 유지할 수 있는 주소에서 시험한다. [카카오 로그인 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite) · [앱·테스트 앱 설정](https://developers.kakao.com/docs/ko/app-setting/app)
3. **Django 연동안** · 시작 요청마다 브라우저에 결속된 짧은 수명의 일회용 `state`와 OIDC `nonce`, PKCE S256을 사용한다. 콜백에서 일치·만료·재사용 여부와 내부 복귀 경로를 검사하고 서버에서 인가 코드를 교환한다. 공개키로 ID 토큰 서명, 발급자, 해당 앱 대상 여부, 만료와 `nonce`를 검증해 `sub`를 읽는다. 카카오 공개 설정에는 PKCE S256이 명시돼 있으므로 실제 시험에서 정상 교환과 누락·오류 verifier의 거절을 모두 확인한다. [카카오 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api) · [OIDC 토큰 검증](https://developers.kakao.com/docs/ko/kakaologin/utilize) · [카카오 공개 설정](https://kauth.kakao.com/.well-known/openid-configuration) · [OAuth 보안 권고](https://www.rfc-editor.org/rfc/rfc9700.html)
4. **계정 연결·세션** · `(provider, app, subject)`를 유일하게 관리하고 내부 ARTI 계정 ID로 조회한다. 연결 완료는 요청을 시작한 동일 계정에서만 처리한다. ARTI 로그인은 검증된 연결을 확인한 뒤 기존 회원 세션을 발급한다. 브라우저는 동일 출처에서 일회용 교환을 완료하고 카카오 토큰과 ARTI 세션 토큰은 URL이나 로그에 남기지 않는다. 프록시와 Django의 콜백 접속 로그에서는 인가 코드가 담긴 쿼리 문자열을 제외한다. 로그인 용도라면 카카오 토큰은 인증 교환에서만 쓰는 안으로 두고, 연결 해제에 필요한 인증 방식은 운영 담당과 확인한다. ARTI 로그아웃, 카카오 연결 해제, ARTI 탈퇴가 각각 어떤 상태와 데이터를 바꾸는지 정한다. [카카오 보안 권장 사항](https://developers.kakao.com/docs/ko/getting-started/security-guideline) · [카카오 연결 해제](https://developers.kakao.com/docs/ko/kakaologin/rest-api#unlink)
5. **앱 등록 전 구현** · 마이페이지 → 카카오 계정 연결 → 현재 ARTI 비밀번호 확인 → 카카오 인증 → ARTI에서 계속을 누른다. 이후 로그인 화면에서 연결한 카카오 계정으로 로그인하면 같은 ARTI 계정의 취향·관람기록을 불러온다. 연결을 시작한 회원 세션이 바뀌면 연결을 거절한다. 서버는 앱과 회원번호 `sub`의 조합을 계정에 연결한다. 카카오 이메일·프로필을 요청하지 않고, 토큰 교환 응답에서 검증된 회원번호만 연결에 사용한다. OAuth 진행 데이터의 유효 시간은 10분이며, 완료 시 지우고 만료 행은 다음 시작 요청에서 정리한다. [계정 연결 API](../../backend-django/arti/kakao_auth.py) · [마이그레이션](../../backend-django/arti/migrations/0006_kakao_oauth.py)
6. **팀 시험 설정** · 팀 앱에서 카카오 로그인과 OIDC를 활성화하고 HTTPS 콜백 URI를 등록한다. Django에 `ARTI_KAKAO_CLIENT_ID`(REST API 키), `ARTI_KAKAO_CLIENT_SECRET`, `ARTI_KAKAO_CALLBACK_URL`을 설정한다. 웹과 `/api`는 같은 HTTPS 출처에서 제공하며 콜백 등록 호스트도 그 출처와 동일하게 둔다. 앱 키·시크릿·올바른 HTTPS 콜백 경로가 모두 설정된 환경에서만 로그인·연결을 표시한다. 실제 프록시·모니터링에서도 콜백 쿼리 수집 여부를 확인한다. 환경변수 예시는 [Compose 설정](../../.env.compose.example)에 있다.
7. **실연동 통과 기준** · 팀 시험 계정으로 비밀번호 확인 → 연결 → 로그아웃 → 카카오 재로그인 후 기존 계정 ID·취향·영수증을 대조한다. 취소·실패 후 비회원 진행 복귀, 중복 연결, 실제 PKCE 오류 거절, 콜백 재사용, 배포 HTTPS 및 갤럭시·두 번째 기기의 복귀 경로를 함께 확인한다. 공개 전에 개인정보 처리방침에 카카오 회원번호의 처리 목적과 보유·파기 기준을 반영하고, ARTI 연결 해제·카카오 연결 해제·계정 복구·탈퇴의 절차와 담당을 정한다.

### 11/14 앱 등록 전 검수 기록

- **Django와 PostgreSQL** · 격리 DB에 `0006_kakao_oauth`가 적용됐고 모델과 마이그레이션이 일치했다. Django 회귀 166건이 통과했다. 가짜 제공자가 만든 RSA 서명 토큰으로 기존 계정 ID·취향·관람기록 재조회, 같은 이메일의 미연결 계정 처리, 현재 비밀번호·같은 세션 확인, 다른 브라우저·출처, 만료·재사용, 서명·발급자·대상 앱·nonce 검증, 취소와 응답 시간 초과를 확인했다. 코드 교환 요청에서 PKCE S256 challenge와 verifier가 일치했다.
- **브라우저** · Edge 320·375·412px의 모의 API에서 기존 계정 연결, 취소 후 복귀, 카카오 재로그인 후 마이페이지 복귀를 확인했다. 기본 환경의 실제 Django 응답에서는 카카오 버튼이 숨겨졌다. 프론트 테스트 39건과 프로덕션 빌드, Gunicorn 콜백 쿼리 로그 제외, Nginx 설정 문법을 확인했다. 카카오 앱 등록·카카오 서버와의 교환·HTTPS 실기기 검증은 시험 환경 확보 후 진행한다.
