- 추천 3·5·7점을 한 번에 확인할 최소 묶음은 **위치와 검수 근거까지 맞는 작품 7점**이다. 같은 방에 몇 점을 두고, 옆 방 작품도 포함한다. 대표작 2~3점은 도슨트 검수용 해설 출처와 인용할 수 있는 문장 또는 팀 관찰 메모를 함께 남긴다.
- 파일은 같은 작품 번호에 도판과 캡션을 연결하고, 도판의 원본 파일·취득일·원 출처를 보관한다. 애매한 연도·작품 판본과 이용 범위는 `확인 대기`로 쓴다. 사진을 쓸 수 없으면 작품 정보와 공식 자료 링크를 먼저 기록한다.
- 일괄 적재 때는 제공된 도판만 안전한 평면 파일명으로 매핑한다. 예를 들어 `SP01.jpg`의 전체 SHA-256을 구하고 같은 ID의 제목·출처·초안 해설을 현행 `manifest.json`에 기입한다. 기존 인수 명령의 `--dry-run`을 먼저 사용한다. 도판이나 필수 출처가 없는 항목은 이 표에 남겨 순차 인수한다. [인수 계약과 명령](전시자료_비공개인수_v1.md) · [manifest 작성 예시](../../data/intake/2026-11-09-yoo-youngkuk/core3-manifest.json)
- `SP01`의 작품 `id`는 `spain500-review-20261119-01`, 인수 `recordId`는 `spain500-intake-20261119-01`, 도판 `assetId`는 `spain500-asset-20261119-01`처럼 각 번호를 대응시킨다. 도면에는 현장에서 적은 `SP01`을 그대로 쓰고, 등록할 때 작품 ID와 연결한다.

현장에서는 도면이나 손그림 위에 번호만 표시해도 된다. 등록할 때 준억이 같은 도면 버전의 A-05에서 입구·벽·기둥·문·복도와 작품 감상점을 입력한다. 이미지 도면에서는 작품마다 **전시실 선택**과 **위치 저장**을 각각 한다. 숫자를 공유할 때는 좌측 상단을 기준으로 X는 오른쪽, Y는 아래쪽으로 0~100을 쓴다. 공식 도면이 없으면 현장 메모를 팀 검수용 스케치로 옮기고 해당 사실을 표시한다. [A-05 도면과 이동 구조 검수](2026-11-17_A05_팀도면검수.md)

**등록 순서** · 새 비공개 전시 생성 → 작품과 근거 연결 → A-05 원본과 배치 등록 → A·B 경로 미리보기. 취향 조사 작품은 독립 풀에서 관리하고, 이 전시 작품은 전시 안에서 추천할 대상으로 등록한다. 자료 확인과 팀 결정 뒤 공개 단계로 넘어간다.

## 11/19 비공개 합성 등록 리허설

- 새 로컬 PostgreSQL에 전시 `ex-spain500-form-fixture-20261119`와 작품 번호 `SP01`~`SP07`의 합성 입력을 준비했다. `--dry-run`에서 도판 해시 7건을 확인했고 전시·작품 행과 목적지 미디어가 모두 비어 있었다. 실제 인수 후 전시는 `draft`, 작품은 전부 `source_check`와 이미지 비표시였다. 대표 3점의 요약·가이드 초안은 `suggested`로 저장됐다.
- PC Chrome의 A-03 전시명 링크에서 해당 전시의 A-04 작품 7점이 열렸다. 관리자용 도판 응답 7건의 SHA-256이 입력과 일치했다. A-05에서 1000×700 합성 도면을 올리고, 제1전시실 4점과 제2전시실 3점의 소속·좌표를 저장했다. 새로고침 뒤 좌표와 마커 7개가 유지됐고, `SP05`의 **작품 관리로 이동**은 같은 작품 ID의 A-04를 열었다.
- 입구와 문 2개가 있는 복도 구조를 도면 버전 `2`에 저장했다. `SP01→SP02`의 같은 방 경로와 `SP01→SP05`의 방 사이 경로가 미리보기에 표시됐다. 방 사이 경로가 복도의 양쪽을 지나가는 것을 확인했다.
- 도면·배치 저장 전후 비회원 전시·작품 목록은 비어 있었고 상세·이미지·추천 요청은 `404`였다. 도면 저장 후 공개 도면 주소도 `404`, 비회원의 관리자 전시 요청은 `401`이었다. 전시 상태는 `draft`를 유지했다. 입력 묶음·검수 JSON과 A-05 캡처는 Git 제외 `data/private/spain500-intake-rehearsal-1119/`에 있다.
