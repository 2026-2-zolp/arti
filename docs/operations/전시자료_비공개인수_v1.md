# 전시 자료 비공개 인수 v1

2026-11-09 / 기준d3a2f76. [확장 방향](전시작품확장방향.md)의 최소 요구를 현행 Django 모델에 맞춰 구현한다. 기존 capture40 importer는 변경하지 않는다. 이번 도구는 **명시된 시연 재구성 전시와 미검수 팀 초안의 신규 생성**만 지원한다. 공식 전시/권리 승인, 기존 작품의 갱신·병합, 도면·좌표, 모델 추론, 계정 인수는 범위 밖이다.

## 계약과 매핑

입력은 분리된 디렉터리의 manifest.json과 평면 PNG/JPEG/WEBP 파일이다. [실제 핵심3점 manifest](../../data/intake/2026-11-09-yoo-youngkuk/core3-manifest.json)가 전체 필드 예시다. 연구용 inventory.json은 수정하지 않고 이 형식으로 명시 매핑한다.

| 입력 | 저장/검사 |
| --- | --- |
| format/version | arti-exhibition-intake / 정수1. 알 수 없는 필드 거절 |
| exhibition | id·title·subtitle·venue·startDate·endDate·kind·basis. kind=demo_reconstruction만 허용. 기간은 내부 개발용이며 실제 일정 아님 |
| items 식별 | id(DB 작품)·recordId(인수)·assetId(파일). 각각 묶음 내 중복 거절, 제목으로 병합하지 않음 |
| file/sha256 | 안전한 ASCII 평면 파일명, PNG/JPEG/WEBP 기본 signature와 일치하는 확장자, SHA256. symlink/누락/변조 거절 |
| title/artist/year | 현재 작품 모델 필드. 미확정한 재료/치수를 만들어 필드에 채우지 않음 |
| description/source/referenceUrl | 팀 초안 내용·근거 후보·기본HTTPS 출처(하단의 명시HTTP 예외 참고). 서버가 임의 URL을 요청하지 않음 |
| contentOrigin/identityStatus/rightsStatus | team_draft / candidate / unverified. 승인을 입력으로 받을 수 없음 |
| summary/guide | 요약 최대200자, 도입+질문/힌트0~3쌍. 없는 경우 비움. 입력이 있으면 suggested만 저장 |

전시 status=draft, 작품 review_status=source_check·show_image=false, 태그/감정 미생성, 좌표 null·방 없음, 요약/가이드 suggested 또는 none으로 강제한다. 전시 subtitle에 시연 재구성을 붙이고 source에는 인수/asset ID와 식별·권리 대기를 남긴다. 전체 인수 근거와 매핑의 원본은 versioned manifest이며 별도 신규 DB 테이블은 만들지 않는다. 기존 Artwork는 여전히 한 전시에 속하며 M:N 재출품·전시관 원장을 구현한 것은 아니다.

## 실행과 실패 경계

```powershell
docker compose --env-file .env.compose -p arti-dev run --rm --no-deps -e ARTI_LLM_PROVIDER=disabled -e OPENAI_API_KEY= -v "${PWD}/data/private/yyk-core3-bundle-20261109:/intake:ro" api python manage.py import_exhibition_bundle /intake --dry-run
# 원본 보존·dry-run·검증 통과 후 같은 명령에서 --dry-run만 제거해 명시 적재
```

전시/작품ID 또는 목적지 파일이 이미 있으면 동일 해시여도 중단한다. 재실행/기존 승인본 덮어쓰기·강제 reset 옵션은 없다. dry-run은 DB와 파일을 쓰지 않는다. 적재 중 예외는 DB transaction rollback과 이번 호출이 만든 파일만 회수한다. 배포/프로세스 강제 종료나 파일시스템 장애까지 DB와 파일을 단일 원자 트랜잭션으로 보장하지 않으므로 그런 경우 원본/manifest와 대조하고 수동 복구한다. 성공 commit 후 출력 실패는 파일을 지우지 않는다. API/CLI와 동시에 같은 대상 자료를 편집하지 않는 인수 작업 구간에서 실행한다.

묶음은1~200점, manifest1MiB·개별 이미지10MiB·총 이미지100MiB 제한이다. signature 검사는 완전한 이미지 디코딩/안전성/저작권 검증이 아니다. 실제 이미지 육안 대조와 출처/사용 범위 검수는 따로 필요하다. 파일 대소문자·인수ID·assetID의 묶음 내부 중복은 거절한다. 기존 파일은 읽기 비교만 하고 변경하지 않는다.

## 이번 단계의 통과 기준

- S1 콘텐츠: 핵심3점 원본 해시와 후보 메타정보/직접 관찰을 대조하고, 사실/해석/미확정을 구분한다. 질문/힌트가 열린 관찰로 이어진다. 이 자체 검수는 사람 승인 대체가 아니다.
- S2 인수 도구: dry-run 무변경, 잘못된 입력/변조/중복/승인·좌표 주입 거절, 기존자료 보존, 여러 전시 식별 분리, 예외 시 DB/신규파일 회수, commit 후 출력 실패 보존을 실제 PostgreSQL로 검증한다.
- S3 비공개 적재: 실제 개발 DB·미디어를 먼저 보존하고, dry-run→명시 적재→행/파일 해시·공개404·관리자 데이터·재실행 차단·재시작을 확인한다. 추가 계정/태그/감정/배치/승인을 만들지 않는다.

위 기준은 이번 작은 과업의 인수 기준이다. W06 AC18/19·W07·G5의 전체 기준을 낮추거나 완료 처리하지 않는다. 내부 관리자 검수 준비 뒤 권리/식별·공개 상태는 사람이 별도로 결정한다.

## 2026-11-09 추가 인수 모드

기존 전시를 기본 거절하는 동작은 유지한다. 같은 시연 재구성 초안 전시에 **새 작품만** 추가하려면 --append-to-draft와 양의 정수 --expected-version을 함께 명시한다. 없는 대상·running/closed·시연 표시 없는 초안·stale version·기존 작품ID/미디어는 거절한다. 전시의 제목/장소/기간은 입력과 같아야 한다. lock에서 상태/version을 재검사하고 subtitle만 새 묶음의 검수 설명으로 갱신하며 version을1 올린다. 기존 작품 필드/검수/도면/입구/방은 수정하지 않는다. 실패 시 subtitle/version과 신규 행/파일도 복구한다.

```powershell
docker compose --env-file .env.compose -p arti-dev run --rm --no-deps -e ARTI_LLM_PROVIDER=disabled -e OPENAI_API_KEY= -v "${PWD}/data/private/yyk-remaining12-bundle-20261109:/intake:ro" api python manage.py import_exhibition_bundle /intake --append-to-draft --expected-version 1 --dry-run
```

위 예시는 실제 version1 당시 수행 기록이다. 현재 version은2이며 재실행은 기존 작품 충돌로 중단된다. 반복 성공을 위해 ID를 바꾸거나 강제로 덮어쓰지 않는다. 신규 묶음은 현재 version을 별도로 확인하고 사전 보존 후 사용한다. manifest 형식은1로 유지하며 append/version은 실행 옵션이다. 도상 후보는 비교 레코드의 개별 판본/연도를 확정값으로 이식하지 않고 제목/설명/source에 후보를 명시하고 year를 비울 수 있다. 연구용 세부 미확정은 검토표에서 추적한다.
