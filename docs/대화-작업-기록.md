## 2. 지금 시스템 한 장 요약

```
[관리자] 작품 등록 (그림 + 해설)
      │
      ▼
[AI 서버 · Python]
  ├ 취향 태그 8개  ← 그림이 있으면 CLIP이 그림만 보고 판단 (없으면 해설로)
  │                  → 관리자가 확인하고 「태그 확정」
  └ 감정 6개       ← 그림(CLIP) 60% + 해설(mDeBERTa) 40%
                     → 작품 화면 분위기, 아트 영수증에만 사용 (추천에 안 씀)
      │
      ▼
[사용자] 취향 카드 고르기 (카드 = 태그)
      │
      ▼
[백엔드 · Node] 고른 태그와 작품 태그를 비교 → 카드마다 1점 이상 보장
             → 입구에서 가까운 순서로 동선 만들기
```

| 구성 | 기술 | 주소 |
|---|---|---|
| 화면 | React 19 + TypeScript + Vite | localhost:5173 |
| 백엔드 | Node 22 + Express + SQLite (`backend/data/arti.db`) | localhost:4000 |
| AI 서버 | Python FastAPI + CLIP + mDeBERTa | localhost:8000 |

**취향 태그 8개:** 풍경 · 인물 · 추상 · 빛 · 강렬한 색감 · 차가운 색감 · 따뜻한 색감 · 부드러운 색감
**감정 6개 (설명용):** 평온 · 기쁨 · 그리움 · 슬픔 · 경외 · 긴장

## 3. 시간순 상세 기록

### 3-0. 시작: CLIP 코드 설명
- **질문:** "너가 쓴 소스코드 설명해봐"
- **답:** CLIP은 직접 만든 게 아니라 OpenAI가 공개한 모델(`openai/clip-vit-base-patch32`)을 Hugging Face `transformers`로 불러 써요. 그림과 "a calm and peaceful painting" 같은 문장이 얼마나 닮았는지 점수를 내요. 한국어 해설은 다국어 NLI 모델 mDeBERTa가 읽어요. 둘 다 **학습 없이 바로 쓰는 제로샷**이에요.
- **코드:** `ai-service/app/analyzer.py`, `emotions.py`, `main.py`

### 3-1. VS Code(Windows)에서 실행하기
| 문제 | 원인 → 해결 |

### 3-7. 태그와 감정, 기준 통일하기 (`03d87d5` → `6154f86`)
- **질문:** "관리자 태그(풍경, 빛)와 AI 감정(기쁨, 슬픔)을 이어주는 지표가 뭐야?", "이름을 통일해야 되지 않을까?"
- **문제:** 사용자 카드, 관리자 태그, AI 감정의 이름이 서로 달라서 중간에 억지 매핑표가 필요했어요.
- **대안 정리:** [추천 기준 통일 대안](추천-기준-통일-대안.md)
  - A: 감정으로 통일
  - B: **태그로 통일**하고 감정은 설명용
  - C: 둘 다 유지
- **결정:** "기쁨, 슬픔 말고 풍경, 빛, 강렬한 색감처럼 분류하는 게 맞는 것 같아" → **B안 적용** (`6154f86`)
  - 태그 8개를 사용자, 관리자, AI가 똑같이 써요.
  - AI는 태그마다 0~1 점수를 제안하고, 관리자는 「AI 제안대로 켜기」로 받은 뒤 「태그 확정」해요.
  - 추천은 확정된 태그로 계산해요. 확정 전에는 관리자가 켠 태그만 사용해요.
  - 감정 6개는 작품 화면과 아트 영수증 설명에만 써요.
  - 예전 태그(`calm` 등)는 서버를 켤 때 자동으로 바꿔요.

### 3-9. 캡처 40점으로 태그 검증 (`19f3659`, `76e1915`)
- **흐름:** 태그별 추천 작품 5점씩, 총 40점 목록을 받음 → 사용자가 직접 캡처 → Claude가 테두리를 자르고 크기를 줄임(최대 800px) → 검증
- **저작권:** "팀원밖에 안 봐서 올려도 된다"고 해서 이미지도 저장소에 올렸어요.
- **결과:**

| 항목 | 결과 |
|---|---|
| WikiArt 70점: 풍경 / 인물 | 96% (AUC 1.00) / 93% (AUC 0.98) |
| 캡처 40점: 대표 태그 적중률 | 기본 0.5 기준 92% → 기준값 보정 후 95%. 같은 데이터로 정해서 낙관적인 수치이고, 교차검증(LOO)으로는 **88%** |
| 「빛」 태그 | 문장을 바꿔 AUC **.59 → .84** |
| 색감 태그 (픽셀 색과의 상관) | 따뜻한 .56, 차가운 .47, 강렬한 .46, 부드러운 .29 |

- **태그별 기준값** (`ai-service/app/tag_calibration.json`): 풍경 .6, 인물 .55, 추상 .5, 빛 .9, 강렬 .5, 차가운 .5, 따뜻한 .95, 부드러운 .2. 기준값이 0.5로 오도록 점수를 다시 매기므로 백엔드와 화면은 계속 0.5로 판단해요.
- **"지금 하는 게 파인튜닝이야?"** → 아니에요. 문장과 기준값 조정이에요. 파인튜닝(예: linear probe)은 데이터가 더 모이면 하는 후속 과제예요.

### 3-11. 직접 실행해 보는 테스트 전시 (`3869bb5`)
- **질문:** "너가 AI 한 걸로 먼저 해볼까? 내가 실행시켜 볼게"
- **만든 것:** `npm run seed:captures`를 실행하면 「캡처 40점 테스트 전시」(`ex-capture`)를 만들어요. 작품 40점은 검수 완료 상태로 전시실 4곳에 배치돼요.

### 3-14. 검증 지표 다시 보기: 색 태그 점수가 낮은 이유
- **질문:** "0.7 정도는 넘겨야 되는데 따뜻한·차가운·부드러운 색감 점수가 왜 이래?"
- **답:** 0.56, 0.47, 0.29는 정확도가 아니라 **단순 픽셀 계산값과의 순위 상관**이에요. 픽셀 계산이 거칠어서 낮게 나와요. 예를 들어 "밝기 × (1 − 채도)"는 칙칙한 갈색 그림도 '부드럽다'고 계산해요.
- **다시 잰 결과:** 사람 정답 기준 **AUC**(캡처 40점, 정답은 1인 판단)

| 풍경 | 인물 | 추상 | 빛 | 강렬한 | 차가운 | 따뜻한 | 부드러운 |
|---|---|---|---|---|---|---|---|
| 0.94 | 0.97 | 0.98 | 0.84 | 0.92 | 0.95 | 0.88 | 0.88 |

- 같은 정답으로 픽셀 계산의 AUC를 재면 강렬한 0.70~0.75, 차가운 0.99~1.00, 따뜻한 0.79~0.80, 부드러운 0.63~0.64예요. 사람이 느끼는 색감은 AI가 대체로 더 잘 맞히지만, **차가운 색감만은 픽셀 계산이 더 좋았어요**. AI와 픽셀 계산을 섞는 방식은 실험해 볼 후보예요.
- **발표용 정리:** 색 태그는 "사람 정답 대비 AUC 0.88~0.95"를 대표 지표로 쓰고, 픽셀 상관은 "AI가 실제 색을 본다"는 보조 근거로만 써요. 팀 라벨이 오면 다시 재요.
- **보통 기준:** 정해진 공통선은 없어요. AUC는 0.7 이상 쓸 만함, 0.8 이상 좋음이고, 무작위보다 얼마나 나은지, 사람끼리의 일치도와 비교해서 판단해요.
- 「빛」은 이름을 그대로 두고 **CLIP 비교 문장만** 바꿨어요. 어둠 속 광원, 햇빛, 명암 대비를 보게 해서 AUC가 0.59 → 0.84로 올랐어요.
- 노트북 결론 글의 인물 91%, 부드러운 0.30을 실행 결과(93%, 0.29)에 맞춰 고쳤어요 (`feb2e93`).

### 3-15. 점수 계산 과정과 추천 흐름 (설명)
- **질문:** "mDeBERTa가 감정 분석해서 요약하면 CLIP이 참고하는 거야?"
- **답:** 아니에요. CLIP(그림)과 mDeBERTa(해설)는 **서로 참고하지 않고 따로** 분석해요. 마지막에 점수만 60:40으로 섞어요. 요약은 둘 다 아니고 **Claude API**가 따로 만들어요.
- **감정 점수 계산 10단계** (`ai-service/app/analyzer.py`)

| 단계 | 그림 (CLIP) | 해설 (mDeBERTa) |
|---|---|---|
| 판단 | 감정 문장 2개씩과 유사도 → 감정별 평균 → softmax (합 1) | "분위기는 ○○이다"를 감정마다 따로 판단 (0~1) |
| 편향 빼기 | **없음** (보정값은 해설용만 있음) | 감정별 평균 점수를 빼고 가장 낮은 값을 0으로 |
| 정리 | 1위 = 1 → A | 1위 = 1 → B |
| 합치기 | A, B를 각각 합 1로 맞춤 → 그림 0.6 + 해설 0.4 → 1위 = 1 → 최종 | |

  - 예시: 그림은 평온 1위, 해설은 그리움 1위 → 최종은 평온 1.00 · 그리움 .95. 해설의 경외 .80은 편향을 빼서 최종 .30이 됐어요.
- **태그 추천 흐름** (`backend/src/lib/recommend.ts`, `tags.ts`)
  1. (전시 전) AI가 그림만 보고 태그 8개 점수를 매겨요. 관리자가 확정할 때 그대로 둔 태그는 AI 점수, 바꾼 태그는 켬 1 / 끔 0이에요.
  2. (관람) 사용자가 카드를 2장 이상 골라요. **카드 1장 = 태그 1개로 코드에 고정**돼 있고, 카드 그림은 AI가 분석하지 않아요.
  3. 관람 시간을 골라요. 30분 3점, 1시간 5점, 여유롭게 7점이에요.
  4. 작품 점수 = 고른 태그 점수의 평균이에요. 합으로 매겨도 순위는 같아요.
  5. 카드마다 그 태그가 0.5 이상인 1등을 먼저 넣고, 남은 자리는 점수순으로 채워요.
  6. 입구에서 가까운 순서로 동선을 짜요. 그래서 화면 순서는 점수순이 아니에요.
  7. 고른 태그 중 0.5 이상인 것을 이유로 표시하고, 하나도 없으면 "새로운 취향을 넓혀 줄 작품"으로 표시해요.
- **취향 카드 그림:** `public/taste/`가 비어 있어서 지금은 색으로 그린 임시 그림이 나와요. 그림을 넣어도 태그는 그대로이니, **그 태그만 뚜렷한 그림**을 골라야 해요.
- **최소 점수 컷?** 개수를 줄이면 관람 시간과 어긋나요. 1시간인데 3점만 주는 식이 돼요. 그래서 개수는 시간대로 두고 **「내 취향 작품」과 「함께 보면 좋은 작품」으로 나눠 보여 주기로** 했어요 (남은 일 참고).

- **mDeBERTa가 읽는 칸:** 관리자 「작품 해설」 원문만 읽어요. 작품명은 그림도 해설도 없을 때만 읽어요.
- **자유 관람 (U-16):** 취향 추천 없이 둘러보고 싶은 사람을 위해 추가했어요.
  - U-02 「추천 없이 자유롭게 보기」 → 전시 작품 전체 목록과 지도(입구에서 가까운 순 번호) → 작품을 눌러 감상 → 「목록으로」 → 「관람 마치기」 → 아트 영수증(관람 방식: 자유 관람)
  - 기존 감상 화면과 영수증을 그대로 쓰고, 추천 이유 칸만 숨겨요.

### 3-19. 같은 태그 → 같은 추천인가 (검증, 11/01)
- **요구:** 사용자1과 사용자2가 같은 태그를 고르면 추천 작품도 같아야 해요.
- **검증 범위:** 목업 전시에서 태그 2~3개의 모든 조합 × 관람 시간 3가지를 돌렸어요.
  - 같은 선택 반복: **252/252 동일**
  - 같은 태그를 **다른 순서**로 고른 경우: **924건 중 58건(6%)이 달랐어요.** "카드마다 1점 보장"이 고른 순서대로 작품을 가져가서 생긴 문제예요. 토너먼트는 1·2위 순서로 태그가 들어가서 실제로 생길 수 있었어요.
- **수정:** 추천 계산 전에 태그를 고정 순서(태그 8개 순서)로 정렬하고 중복을 제거해요. 수정 후 **924/924 동일**이에요.
- **회귀 테스트:** `backend/test/api.test.ts`에 「같은 태그면 고른 순서와 상관없이 같은 추천」 테스트를 추가했어요. 모든 2~3개 조합 × 순서 × 관람 시간을 확인해요 (백엔드 테스트 34개 통과).

## 4. 자주 헷갈린 개념 Q&A

| 질문 | 답 |
|---|---|
| 태그는 무슨 역할? | 인스타 해시태그처럼 작품에 붙는 이름표예요. 사용자가 고른 취향 카드와 같은 이름이라서 바로 비교돼요. |
| 태그와 감정 모두 그림과 글을 합쳐서 판단하나? | **아니요.** 태그는 그림이 있으면 **그림만** 봐요(색과 구도는 그림이 정확해서). 감정은 **그림 60% + 해설 40%**로 섞어요. |
| CLIP은 그림만 보고도 해줘? | 네. 그림-설명 쌍 약 4억 개로 미리 학습된 모델이라, 우리는 비교할 문장만 주면 돼요(제로샷). |
| 태그 점수는 어떻게 나와? | 태그마다 "해당하는 그림" 문장과 "해당하지 않는 그림" 문장 중 어디에 더 가까운지 보고 0~1 점수로 바꿔요. 0.5 이상이면 해당해요. |
| 해설은 누가 읽어? | **mDeBERTa**예요. 한국어를 직접 읽는 다국어 모델이고, CLIP은 그림 담당이에요. |
| mDeBERTa는 감성 분석 AI야? | 원래는 **문장 추론(NLI)** AI예요. 해설이 "이 작품의 분위기는 그리움이다"를 뒷받침하는지 판단해요. 감정 이름만 바꿔 6번 물어보는 식으로 감정 점수를 얻어요. |
| AI 분석을 안 하면? | 관리자가 직접 켠 태그만으로 추천해요. 확정 전에는 켠 태그를 1, 끈 태그를 0으로 봐요. |
| 사용자 점수는? | 사용자가 고른 카드 태그 = 1이에요. 작품의 그 태그 점수 평균으로 순위를 매기고, 카드마다 그 태그가 0.5 이상인 작품을 최소 1점 넣어요. 그다음 입구에서 가까운 순서로 동선을 만들어요. |
| 이게 파인튜닝이야? | 아니요. 모델은 그대로 두고 문장과 기준값만 조정했어요. |
