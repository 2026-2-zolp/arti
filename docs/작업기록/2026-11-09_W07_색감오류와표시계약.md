# W07 색감 오류와 점수·피드백 표시 계약 검토

2026-11-09 / 출발9f22c6f / dev/임준억. [40점 기준선과 피드백 계획](2026-11-09_W07_40점기준선과피드백계획.md)에 이어 사용자가 동의한 다음 순서의 오류 검토와 표시/계약 구체화를 진행했다. 기존 과업과 마찬가지로 로컬 커밋만 한다.

## 배경·변경 전후

앞선 평가는 vivid 정밀도38.5%/cool50%를 확인했으나 작품별 시각 근거와 표시 규칙이 없었다. 이번에는 [검토 기록](../execution-plan/2026-11-07/records/W07-preparation/ai-review-2026-11-09/README.md)에18건을 원시 점수/라벨 표수/이미지SHA로 연결했다. vivid FP8건,cool FP7/FN3건이다. 원본18장의 비공개 연락판을 확인했고 높은 채도/강렬함·일부 색/전체 인상의 차이를 후속 검수 가설로 남겼다. IKB191의 진한 단색 파랑처럼 모델 출력에 시각 근거가 있어도 사람0/5인 예를 오답으로 단정하지 않고 태그 정의의 합의 항목으로 분리했다.

태그 정의는 포함/제외/판단보류 예시를 보강한 제안이다. 실제 팀 합의나 재라벨링은 아직 없다. 기존 tags.py/모델/threshold/calibration을 바꾸지 않았다. 기존40점에 맞춘 수치 조정으로 성능이 좋아졌다고 보고하지 않는다.

점수·의견·검수 상태의 표시 원칙과 피드백 최소 계약을 문서/JSON으로 구체화했다. 모델0.74는정답확률74%가아니다. 사람 비율은유효판단분모·모르겠음·노출응답률을구분하고0건/소수응답은건수위주로보여주는방향이다. 소수응답10건표시기준은잠정제품정책이며통계적신뢰보장이아니다. guest저장/식별/보관과정식UI계약은후속확정으로남겼다.

scripts/ai_review.py는 개발 검토 자료의 원점수·표수·분류추적 및 표시 예시 검사다. 새 제품 기능이 아니다. scripts/tests/test_ai_review.py는 모르겠음/무응답·소수/0건·불가능건수·모델확률오인·자동학습/승인·버전누락의회귀를검사한다. execution.json에는이기록의범위와미구현상태를추가했다.

## 자체 검토와 검증 루프

시각 검토에서 기존 FP를 자동 오답으로 확정하지 않도록 정의안과 사례 설명을 보완했다. 비율 예시에서는 모르겠음을 제외한 분모가 전체응답과 다름을 명시했다. 운영검토에서는 작품선호/AI평가 구분, model 없는 선호 대상의 not_applicable 버전, guest 미저장·개인정보 최소화·자동반영 차단을 구체화했다.

기술/시니어·데이터/운영·방문자/콘텐츠·팀/교수/평가위원의 관점별 자체 검토이며 실제 외부 승인과 다르다. 최종 자동 검사와 원본 보존 결과는 검토폴더 validation.json에 기록한다. 앞선21개는5.118초에통과했고, 계획 errors0·보호38개/guardrail25/W02 errors0을확인했다. 이후 사례 추적에서 점수/표수/분류의 원자료 재대조 검사를 보강해 다시 검증한다. 제품 코드 변경이 없어 Django/프론트/유료모델 호출은 재실행하지 않았다.

## 통과 범위·후속

이번 과업은 오류18건 추적·정의 제안·숫자/피드백 경계와 자동 검사까지 개발 검토 통과를 목표로 한다. 새 피드백 화면/API·실제 사람 라벨/승인·유영국 품질/G5 통과가 아니다. 불일치 원인 가설을 검증할 독립 라벨과 정의 검토가 다음이다. 검수 전에는 격리 전체 여정 점검도 가능하다. 실제 피드백 기능은 최소 수집·guest·보관 정책을 결정한 뒤 별도 구현한다. 기존 모델/라벨/DB/승인 상태는 유지한다.
