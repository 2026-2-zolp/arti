# 11/15 관람가이드·쉬운 요약에서 도슨트 재시도

- **환경** · 로컬 `9b4ba63`에서 취향 V2 합성 전시를 PC Chrome으로 관람했다. 실제 Django와 격리 PostgreSQL을 사용했다. 관리자 편집 API에서 원문을 유지한 채 합성 관찰 질문 2개, 각각의 힌트, 쉬운 요약을 확정하고 가이드·요약 리비전이 증가하는 것을 확인했다.
- **관람가이드 질문** · 두 번째 관찰 질문의 저장된 힌트를 펼친 뒤 해당 질문으로 도슨트에 들어갔다. 작성한 질문이 502로 실패해도 입력이 남았고, 수동 재시도에서 같은 질문 인덱스와 자료 버전으로 성공했다. 모의 응답을 통해 제공자에게 전달된 근거가 선택한 두 번째 질문임을 확인했다.
- **AI 힌트** · 도슨트에서 별도 질문을 적어 둔 채 ‘힌트 받기’를 눌렀다. 502 뒤 ‘다시 시도’는 같은 힌트 요청과 가이드 리비전으로 성공했다. 방문자가 작성 중인 질문은 보존됐고, 작품으로 돌아오면 펼쳐 둔 저장 힌트가 다시 보였다.
- **쉬운 요약** · ‘AI 요약 보기’ → ‘이 부분 더 알아보기’에서 질문을 보냈다. 502 뒤 원래 입력과 대화 이력이 보존됐고, 수동 재시도에서 같은 요약 본문과 요약 리비전으로 답변이 왔다. 작품 화면에 돌아오면 요약이 계속 보였고 다음 작품으로 이동할 수 있었다.
- **통과 기준** · 세 경로 모두 실패·재시도의 브라우저 요청에 담긴 방문 ID, 질문, 진입 맥락, 이력이 같고 제공자 요청 본문도 바이트 단위로 일치했다. 성공 답변의 서버 출처는 현재 작품, 원문 버전, 근거 유형과 해당 리비전이었다. 실패한 질문은 이력에 추가되지 않았고, 재시도 전에 자동 호출도 없었다. 제품 동작은 기존 구현으로 통과해 모의 제공자와 브라우저 회귀만 확장했다.
- **결과와 범위** · 새 Chrome 경로 3개, 기존 장애·자료 갱신·작품 이동 Chrome 회귀 5건, 프론트 단위 테스트 43건, Django 도슨트·제공자·통합 테스트 44건과 프로덕션 빌드가 통과했다. 기존 429 시험은 가상 시계를 진행한 뒤 버튼이 활성화될 때까지 기다리도록 보완했다. 연속 실행 중 서버의 요청 제한을 만난 기본 장애 시험은 새 모의 서버에서 통과했다. 실제 모델의 답변 품질과 실기기는 보류했다.

## 재현

[기존 브라우저 하네스](2026-11-15_AI도슨트브라우저복구.md#재현)의 격리 환경을 준비하고, [합성 관리자 설정](2026-11-15_AI도슨트응답대기중작품변경.md#재현)을 적용한다. 서버의 `docker run`에 `-e ARTI_DOCENT_ENTRY_TESTS=1`을 추가한다. 실행 셸에 같은 합성 관리자 비밀번호, `ARTI_DOCENT_ENTRY_TESTS=1`과 해당 프리뷰의 `ARTI_REVIEW_BASE`를 정하고 `node frontend/tests/docentRetry.browser.cjs`를 실행한다. 합성 가이드·요약은 종료 때 복원되며 편집 API에 따라 버전은 증가한다.
