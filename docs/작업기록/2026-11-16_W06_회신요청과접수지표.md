회신 원문과 첨부는 팀 비공개 경로에 모은다. 준억이 작품·도판·문안 버전을 대조해 접수 JSON에 옮기고 `python scripts/yoo_core3_receipt.py <비공개-회신.json>`을 실행한다. 서로 다른 검수자의 원본과 이견은 각각 보존한다. 회신에서 파일이나 문안 버전을 확인할 수 없으면 확인 담당과 남은 항목을 적는다. [회신 제출과 JSON 형식](../review/yoo-core3-2026-11-11/README.md#1116-회신-접수-사전-확인)

## 접수 후 볼 지표

- **원 취득 근거 `N/3`** · 원 취득처와 실제 파일 해시를 연결한 작품 수. 광권·준억이 확인한다.
- **현행 문안 `N/12`** · 작품 3점 × 문안 4항목 중 확인한 항목 수. 작성자 외 검수자의 `확인`을 집계하고 `수정`과 `보류`에는 재확인 담당을 적는다.
- **매체별 `N/3`** · 도판 사용 근거를 확인한 작품 수와 `ready-for-review`인 작품 수를 함께 적는다. 예를 들어 교내 2/3에 사용 근거가 있어도 한 작품의 문안이 대기면 적용 검토는 1/3이다. 실제 채택에는 원 취득 근거·도면·해당 매체의 사람 판정이 필요하다.
- **적용 후 연결 `N/채택 작품 수`** · 준억과 시연 운영자가 추천 순서 → 지도 마커·좌표 → 해설·가이드 → 질문의 작품 ID, `sourceVersion`, 가이드 개정 번호를 대조한다. 누락은 건수와 원인을 기록한다. [기존 합성 적용 검수](2026-11-16_W06_회신과시연연결검수.md)

## 합성 회신 실행 결과와 개발 자료

- 현행 문안·교내 회신 `001`, 힌트 누락·발표 회신 `004`, 11/11 이전 문안·교내 회신 `010`의 임시 JSON 세 건을 CLI로 확인했다. 현행 문안 확인은 합성 7/12, 도판 사용 확인은 교내 2/3·발표 1/3, 적용 검토 가능은 교내 `001` 1/3만 나왔다. `004`는 힌트, `010`은 11/13 문안 네 항목이 대기였고 확인된 매체 행은 유지됐다. 실제 회신 지표에는 포함하지 않았다.
- 기존 접수 회귀 8건과 메모리 시험 DB의 합성 API 회귀 2건을 통과했다. 추천·지도·해설·공개 제외와 모의 질문의 작품 참조를 다시 확인했다. 이번 범위에 필요한 검수는 현재 자료로 재현된다.
- 개발팀에는 저장소의 합성 `fixture-ex01`과 W06 합성 회귀 실행법을 제공하면 PC에서 관람·영수증 또는 접수·추천 연결을 재현할 수 있다. 기존 `load_test_fixture`를 별도 시험 DB에서 사용한다. 별도 실제 데이터를 전달할 필요는 현재 검수에서 확인되지 않았다. 실제 도판·문안은 사용 목적의 근거와 팀 판정을 받은 뒤 해당 범위의 자료를 준비한다. [합성 전시 재현 절차](../operations/2026-11-11_main_시연복구체크리스트.md)
