# 네이티브 도면 구간과 초안 모델 분리

`506f1f0`에서 합성 도면 두 종류의 이동 구간을 보완했다. 직접 관람의 시험 옵션과 기존 V2 진입은 그대로 사용할 수 있다. 직접 관람의 실제 전시 적용은 팀 회신 대기다.

## 확인 결과

| 검수 | 결과 |
| --- | --- |
| 기둥이 있는 세로 도면 | 관리자·관람자 화면에서 네이티브 SVG로 방과 기둥을 표시했다. 직접 및 추천 관람의 강조 구간과 전체 선을 검수했다. 선이 기둥 경계에 닿지 않았다. |
| 전시실 두 개와 문 두 곳이 있는 가로 도면 | 등록된 두 문을 지나 복도로 연결됐다. 방 사이 벽과 통로 밖을 지나는 선은 렌더링되지 않았다. |
| 연결 불가 | 문을 막은 단위 검사에서 두 방의 연결이 끊겼다. Chrome에서 작품의 지도 위치가 기둥 안으로 바뀌면 해당 구간 선 없이 안내와 작품 버튼을 표시했다. 기준 도면을 교체하면 예전 합성 연결을 사용하지 않는다. |
| OpenAI 호환 초안 분리 | 별도 모의 제공자 두 곳에서 관리자 요약·가이드와 기존 도슨트가 각각 정해진 주소·키·모델에 도달했다. 초안 쪽 429와 불완전한 설정에서 기존 도슨트로 요청하지 않았고 일치하는 오류를 반환했다. |
| AI 운영 로그 | 도슨트·요약/가이드·태그/감정의 설정 상태를 구분했다. 오류 뒤에 정상 이벤트를 51건 넣고도 오류 필터에서 해당 요청을 다시 찾을 수 있었다. |

도면의 보행 가능 사각형과 벽·기둥은 명시적으로 등록한 합성 데이터다. 등록된 연결점과 작품 위치 사이에서 선분 전체가 보행 영역에 속하고 벽·기둥에 접촉하는지 검사한 뒤, 사용할 수 있는 연결로 최단 구간을 찾는다. 도면 종횡비를 구간 비교에 반영한다. 운영용 도면 등록 화면은 다음 단계다. [구간 계산](../../frontend/src/lib/indoorRoute.ts) · [합성 도면 정의](../../frontend/src/lib/indoorMapFixture.ts)

## 추천 순서를 바꿀 때

작품을 고르는 취향 점수·태그별 후보와 이미 선택한 작품의 이동 순서는 서로 독립적으로 평가할 수 있다. 현행 추천은 마지막 위치에서 가까운 작품을 계속 고른다. 장애물이 없어도 입구 `(0,0)`, 작품 `(2,0)`·`(0,3)`·`(5,0)`에서 이 방식은 총 거리 10.83, 여섯 순서를 모두 비교한 최단 순서는 9.61이다. 벽이 있을 때는 좌표가 가까워도 돌아가는 거리와 접근 가능 여부가 달라진다.

다음 단계는 운영자가 승인한 방·기둥·문·복도와 작품 앞의 접근점을 도면 버전에 묶어 저장하는 것이다. 읽을 수 있는 공간 구조를 SVG로 그리면 관리자와 관람자가 같은 배치를 확인할 수 있다. 운영 연결점을 확보한 전시에서만, 이미 고른 3·5·7점의 구간 거리표를 만든 뒤 입구 출발 기준으로 전체 이동 거리를 비교한다. 방 순서와 접근 가능한 통로 조건을 먼저 적용하고, 그 안에서 열린 경로의 최소 거리를 찾는다. 기존 추천 선택, 관람 중 저장된 순서와 영수증을 유지한다. [OGC 실내 이동 엔지니어링 보고서](https://docs.ogc.org/per/18-089.pdf) · [OR-Tools 관람 순서 비교 참고](https://developers.google.com/optimization/routing/tsp)

## 팀 PC 재현

[기존 직접 관람 준비](2026-11-17_합성전시순서바로보기.md#재현)의 격리 PostgreSQL·미디어 설정에서 `0009_operation_event`를 적용한다. 모델은 `ARTI_LLM_PROVIDER=disabled`, `ARTI_DRAFT_PROVIDER=default`로 두고 `ARTI_MODEL_SERVICE_URL`을 비운다. 팀 검토용 직접 관람은 `ARTI_EXHIBITION_ORDER_DEMO_ENABLED=true`로만 연다.

```powershell
node frontend/tests/runVisitBoundaries.browser.mjs map-variants
node frontend/tests/runVisitBoundaries.browser.mjs exhibition-order
node frontend/tests/runVisitBoundaries.browser.mjs operations
```

브라우저에서 직접 확인할 때는 시험 DB에 기본 fixture를 적재한 후, 아래 명령으로 문과 복도가 있는 도면을 넣고 API와 프런트를 루프백에서 연다. 세로 기둥 도면은 `two-rooms`를 `pillar`로 바꾼다. 전시 경로는 `/exhibitions/fixture-ex01`, 관리자 위치·지도 경로는 `/admin/map?exhibition=fixture-ex01`이다. 시험 종료 후 `restore`로 기본 도면을 적재할 수 있다.

```powershell
$env:ARTI_BROWSER_MAP_VARIANT = 'two-rooms'
& $env:ARTI_TEST_PYTHON backend-django/manage.py shell -c 'from pathlib import Path; exec(Path("frontend/tests/fixtures/mapVariants.py").read_text(encoding="utf-8"))'
```

프런트 빌드·단위 검사 50건과 Django PostgreSQL 검사 201건, 합성 지도·직접 관람·운영 로그·기존 관람 Chrome을 통과했다. 실제 모델·도판 전송과 실기기 검증은 보류했다. [카나나 적용 분담과 OpenAI 도판 비용 검토](../operations/2026-11-17_도슨트모델과관리자운영검토.md)
