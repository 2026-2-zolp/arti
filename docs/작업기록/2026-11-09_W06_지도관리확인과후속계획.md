# W06 관리자 지도·배치 확인과 후속 W 계획

2026-11-09 KST / 기준f181b23 / dev/임준억 / W06·F17·AC18·AC19 관련 부분 과업. 이전 [유영국 식별·출처표](2026-11-09_W06_유영국식별출처표.md) 이후 사용자가 운영자 도면/배치 기능을 실제로 확인하고16점 전시 검토 및 남은 W 과업을 정리하도록 요청했다. 평가위원·시니어 개발자 관점 추가에도 동의했다.

## 배경과 변경 전후

도면/배치가 없다는 말은 현재 유영국 인수자료에 근거가 없다는 뜻이지 제품에 관리자 기능이 없다는 뜻은 아니었다. A05Map→client→Django editing→모델/미디어→recommendations→U09를 읽어 기능을 연결했다. 도면 업로드·전시별 입구/위치/방 소속 저장은 이미 있고, 방 경계 편집·실통로 추출·실측 시간 계산·도면 출처/제공자 정식필드는 없음을 구분했다.

프론트는 도면비율 변경이나 최초 업로드 때만 좌표초기화 확인창을 띄웠고 서버는 모든 업로드에서 좌표를 비웠다. 같은비율 도면교체의 안내 누락을 A05Map.tsx에서 고쳐, 배치작품이 있으면 모든 도면 업로드 전에 확인한다. 기존 삭제확인·서버버전/좌표초기화 정책은 유지했다. 도면 설명도 교체하면 좌표초기화/입구재확인으로 맞췄다.

`backend-django/arti/tests/test_map_management.py`에 실제600×400 합성PNG와 임시미디어·시험fixture만 쓰는6검사를 추가했다. 업로드/재조회/공개·관리자 이미지 접근, 같은비율 교체의 해당전시 좌표초기화/다전시보존, 구버전409와위치보존, 방·입구·위치 저장과 배정방삭제거부, 도면삭제/권한, 저장좌표→추천순서→교체후후보제외를 확인한다. 실제 유영국 이미지는 사용하지 않는다.

## 전시 구성·계획과 검증단

[전시 구성과 동선 검토](../operations/2026-11-09_유영국전시구성과동선검토.md)에 운영자 제공/직접제작 도면의 인수 방식, 실제출품/배치확인과 업로드기능의 차이,16점 준비→보존→적재→배치→선택풀/추천 비교→콘텐츠/평가설계 순서를 기록했다. 핵심3점과 전체16점의 역할, 통로 경로/가정시간의 미검증도 구분한다. 남은 W06/W07/W11/W12/W08/W09/W10을 기존 의존관계와 연결했고 W01~W05는 다시 시작하지 않는다.

execution.json의 asOf/AC18부분증거와 EVALUATOR·SENIOR 관점을 추가하고 persona-scenarios.json에 PS09/PS10 설계사례를 넣었다. 전체 시나리오는 not_run이며 API검사 성공을 실제 브라우저/사람/현장시험이나 AC18전체 통과로 대체하지 않는다. 외부 평가위원/시니어가 실제로 참여했다는 뜻이 아니라 AI검토 역할 추가다.

## 검증 루프

Docker 기본 접근은 권한 오류라 허용된 실행 경로를 사용했다. `arti-w06-map-review`라는 새Compose프로젝트와 별도PostgreSQL/미디어볼륨으로 기존개발자료와 분리했다. 처음 읽기전용 /app bind와 /app/media 볼륨이 충돌해 시험 프로세스 시작이 실패했다. 새 시험이미지에 코드를 포함하고 중첩 bind를 제거해 재실행했다. 이 실패를 제품 테스트 실패로 세지 않는다.

첫 신규5개 포함 전체68개 통과 후, 배치한 좌표가 추천에 연결되는 검사를 추가해 전체69개를 다시 실행했다. frontend는17회귀·TypeScript/Vite빌드 통과. 실제브라우저 확인창 클릭/유영국 DB적재·배치/실제도면·보행시간/실모델 평가는 하지 않았다. 실행·검토·환경 종료 결과는 [검증 기록](../execution-plan/2026-11-07/records/W06/map-review/README.md)에 남긴다.

원본ZIP·기존DB/미디어·legacy는 수정하지 않는다. W06 진행중·AC18/19/G5 미통과, W07실모델/하네스추후논의를 유지한다. 이번 기능 보완·계획 확인 후 로컬커밋만 하며 원격push·PR·AWS생성은 하지 않는다.

검증단 루프에서 방문자 검토가 도면 교체 후 미저장draft 잔존을 필수 지적으로 발견했다. 업로드/삭제 성공 시 임시위치·선택·이전마커를 즉시 비우고, 저장좌표0점이어도draft가있으면확인하도록 보완했다. 확인문에 입구/방 소속 재확인도 넣었다. 프론트17/빌드를 다시 통과하고 방문자 재검토에서 필수 지적 해소를 확인했다. 기술검토의 등록/조회/수정 표현과 DB기동 재현명령 의견도 반영했다.

SENIOR 재검토에서 전시전환 뒤도면요청의늦은응답이현재작품목록을덮는추가필수문제를발견했다. FloorPlanField를전시ID로분리하고 useLayoutEffect수명과mapOperationGate의작업ticket으로은퇴뷰의성공/실패/finally를무시한다. 중복업로드/삭제도차단한다. 지연응답3검사추가후 최종frontend20·타입/빌드를통과했다. 이경우는서버변경이없어PG69를다시반복하지않았다.

최종기술/SENIOR와방문자재검토에서필수지적해소를확인했다. 계획/guardrail검사와보호아카이브38파일보존도통과했다. 시험프로젝트는down으로종료하되볼륨은보존했다. 실제브라우저PS09및W06전체통과는대기다.
