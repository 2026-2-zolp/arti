## 환경 안내와 GPT 연결

**시작 배경**

개발자가 파일 역할과 환경설정을 읽고 직접 키를 설정할 수 있게 안내가 필요했다. 키와 모델이 설정된 뒤에도 텍스트 provider는 비활성이어서 격리 환경에서 실호출부터 확인했다.

**작업과 변경 파일**

- React·Django·FastAPI와 보존 Express 소스에 한글 역할 주석을 보완했다. `.env.compose.example`, `frontend/.env.example`, 루트 `.env.example`과 보존 Express 예시에 연결 범위를 설명했다. [GPT 키 로컬 설정 가이드](../../operations/GPT_API키_로컬설정가이드.md)
- 합성 작품 1점으로 작품 해설, 관리자 요약·가이드, 가이드 맥락 도슨트, 이전 답을 이어받은 후속 대화를 기존 `gpt-6-luna` 설정으로 호출했다. 시험 성공 뒤 비공개 `.env.compose`의 provider를 `openai_compatible`로 맞췄다.

**검증 결과**

Python 43파일의 AST와 TypeScript 77파일의 주석 제외 산출물을 대조했고 프론트 20건·타입·빌드가 통과했다. 실제 GPT 호출 5회가 성공했고 제안 상태에서의 비공개와 합성 자료 확정 뒤 공개를 확인했다. 이 연결 시험의 태그·감정은 고정 합성값이었다. [실제 연결 증거](../../execution-plan/2026-11-07/records/W07-live-smoke/2026-11-09/README.md)

## GPT 품질과 도슨트 답변

**시작 배경**

## 분석 서비스 연동과 실모델 기동

**시작 배경**

GPT 텍스트가 연결된 시점에도 Django의 태그·감정 분석은 503이었다. 기존 FastAPI를 연결하고 HTTP·저장 보호 검증 뒤 실제 가중치의 준비 시간과 자원을 측정했다.

**작업과 변경 파일**

- `model_service.py`가 승인 원문과 서버 보관 이미지를 FastAPI `/analyze`에 보낸다. 파일·응답 크기와 입력 사용 여부, 모델명·점수 범위를 확인하고 리다이렉트·외부 이미지 URL 전달을 막았다.
- `providers.py`와 `editing.py`에서 GPT 텍스트와 분석 제공자를 분리하고 태그·감정이 한 분석 결과를 공유하게 했다. 설정·Compose 예시에 기본 비활성인 `ARTI_MODEL_SERVICE_URL`을 추가했다. [연동 범위와 기준](../../execution-plan/2026-11-07/records/W07-preparation/model-integration/README.md)
- 실제 CLIP·mDeBERTa는 고정 revision을 받아 별도 로컬 FastAPI에서 오프라인 CPU로 기동했다.

**검증 결과**

격리 PostgreSQL 93건에서 분석 저장·실패 보호·HTTP timeout을 확인했다. 실제 모델 3점×2회는 모두 성공했고 반복 결과가 같았다. 준비 5.67초, 호출 1.70~2.19초, 서버 계열 최대 RSS 1,260.87MiB였고 모델 회귀 17건이 통과했다. 이 설정은 기존 개발 표본에서 고른 기준선이며 유영국 독립 라벨로 재검증할 대상이었다. [PostgreSQL 검사 로그](../../execution-plan/2026-11-07/records/W07-preparation/model-integration/postgres-tests.log) · [실모델 측정](../../execution-plan/2026-11-07/records/W07-preparation/model-runtime-2026-11-09/README.md)

## 태그 기준선과 표시 계약

**시작 배경**

기존 40점 다수결 결과만으로 평가자별 차이와 색감 오류를 설명하기 어려웠다. 태그 점수, 사람의 의견, 콘텐츠 승인 상태를 어떻게 읽고 표시할지도 정리가 필요했다.

**작업과 변경 파일**

- `tag_baseline.py`로 기존 40점의 실제 CLIP 원시 점수를 동결하고 기본 임계값 0.5, 현재 보정, 모두 양성 대조군을 비교했다. 개인별·한 명 제외·합의 수준을 따로 집계했다.
- `ai_review.py`와 검토 자료에 vivid 거짓 양성 8건, cool 거짓 양성 7건·거짓 음성 3건을 원점수·표수·이미지 해시와 연결했다. 태그 정의 보완과 불확실·미응답·표시 분모의 처리 원칙을 제안했다. `execution.json`에는 작품 선호와 태그·추천·AI 답변 평가의 구분을 기록했다. [피드백 계획](../../execution-plan/2026-11-07/records/W07-preparation/tag-baseline-2026-11-09/feedback-plan.md)

**검증 결과**

기존 40점에서 기본 임계값 대비 현재 보정의 Macro-F1은 62.6%→71.7%, Micro-F1은 61.7%→73.4%였다. 평가자별 Macro-F1은 60.0~71.2%였다. 기준선 회귀 16건과 색감·표시 검토 21건이 통과했다. 40점은 보정에 사용한 개발 표본이고, 모델 점수는 태그 판정 근거로 표시하는 방향이었다. 독립 라벨·감정 품질 평가·사용자 피드백 구현은 남았다. ## 격리 관람과 모델 장애 복구

**시작 배경**

API와 소수 모델 시험에 이어, 화면에서 관람 맥락이 이어지는지와 분석 장애 뒤 입력·저장이 보존되는지를 확인했다.

**작업과 변경 파일**

- `U09Route.tsx`와 `lib/recommend.ts`에서 가정 거리에 기반한 ‘약 1분’ 표시를 제거하고 저장 좌표를 기준으로 위치를 안내했다.
- FastAPI `runtime.py`, `analyzer.py`, `main.py`에 단일 로딩·추론 슬롯과 준비 상태를 추가했다. Django `providers.py`, `model_service.py`, `editing.py`에서 요청 내 실패 공유, 429·timeout 처리, 늦은 결과의 저장 보호를 보완했다. [모델 로컬 운영 기준](../../operations/모델서비스_로컬운영.md)
- 관리자 `A04Artworks.tsx`, `adminAnalysis.ts`, `client.ts`와 Django `providers.py`에서 성공 시각과 재시도 안내를 제공하고, 응답이 와도 편집 중인 값과 최신 저장값을 보존하도록 했다. [후속 CI 준비](2026-11-09_운영시연준비.md#w-계획과-후속-ci-준비)

**검증 결과**

- 합성 자료로 비회원·회원 각 3점을 완주했다. 실제 GPT 2회에서 이전 관찰이 후속 대화에 이어졌고, 비활성 503에서 질문 입력이 남았다. 새로고침·동일 관람 재전송 뒤 회원 관람과 반응은 각 1건이었다. PG 93건·프론트 20건·빌드가 통과했다. [격리 관람 여정](../../execution-plan/2026-11-07/records/journey/2026-11-09/README.md)
- 고정 가중치 실측에서 로딩 503, 동시 요청 200·429, timeout 뒤 슬롯 유지, 프로세스 중단과 재기동을 확인했다. 저장 보호는 별도 지연 HTTP와 PostgreSQL에서 검증했고 PG 97건·모델 회귀 24건이 통과했다. [모델 운영 안정성 증거](../../execution-plan/2026-11-07/records/W07-preparation/model-operations-2026-11-09/README.md)
- 합성 관리자 브라우저에서 503→429→504→중단 503→재기동 200을 확인했다. 실패 동안 DB 버전과 값이 유지됐고, 복구 중 두 번 눌러도 모델 1회·버전 1회만 반영됐다. 미저장 편집도 남았다. PG 97건·프론트 23건·빌드가 통과했다. [관리자 장애 복구 증거](../../execution-plan/2026-11-07/records/journey/model-fault-2026-11-09/README.md)
