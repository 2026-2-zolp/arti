## 첫 사용자 결함 수정

**시작 배경**

11/9 컨설팅 후 동섭님의 첫 사용자 점검에서 가입 입력과 서버 조건, 관람 복귀, 작품 표시 문제가 드러났다. 광권님이 제안한 태그 동점 처리와, 팀 논의 후 사용자가 승인한 전시 독립 조사 방향을 각각 계획에 연결했다. [팀 의견과 변경 계획](../../execution-plan/2026-11-07/14-team-feedback-2026-11-10.md)

**작업과 변경 파일**

- `member.py`와 `U04Signup.tsx`에서 닉네임을 선택 입력으로 맞췄다. 생략·빈칸·공백을 허용하고, 앞뒤 공백을 제거한 뒤 100자 제한과 타입을 검사한다. 비밀번호 오류와 닉네임 길이 오류도 구분했다.
- `U07Time.tsx`에서 같은 시간을 선택하면 새 관람을 만들거나 추천을 비우지 않고 복귀하도록 했다. 시간이 실제로 바뀌면 기존 확인 절차를 따른다.
- `ArtImage.tsx`와 `U05Taste.tsx`에서 취향 비교 이미지에 `contain`을 적용했다. `U10Artwork.tsx`와 `app.css`에서는 해설 원문과 확정 요약의 문단과 긴 문자열을 처리했다.

**검증 결과**

- Linux·PostgreSQL 17에서 Django 104건, 프론트 24건과 빌드가 통과했다. 첫 Windows 실행의 이미지 파일 정리 오류는 Linux에서 같은 소스로 재검증했다. 가입은 API와 DB에서 확인했다.
- 격리 Chrome에서 세로·가로 작품의 전체 테두리, 해설 문단과 더보기, 같은 30분 선택 시 기존 추천 복귀와 시간 변경 취소를 확인했다. 모바일 화면 크기로 시험했으며 실기기 확인은 후속 범위였다. R06 전체는 진행 중이었다. [검증 기록](../../execution-plan/2026-11-07/records/team-feedback-2026-11-10/validation.json)

## 전시 독립 취향 조사 구현

**시작 배경**

기존 W02 계약은 현재 전시의 작품 10점으로 취향을 조사했다. 팀 논의에서 전시를 바꿔도 공통 작품군으로 취향을 조사하고, 추천은 관람 중인 전시에서 제공하는 방향을 확인했다. [개정 계약](../../execution-plan/2026-11-07/records/team-feedback-2026-11-10/survey-contract.md)

**작업과 변경 파일**

- `models.py`, `survey.py`, `0002_independent_taste_survey.py`에 조사풀과 작품 참조를 추가했다. 단일 활성 풀, 10점·5쌍, 순서·중복·revision을 검증한다. `configure_taste_survey.py`로 등록과 명시적 활성화를 처리한다.
- `views.py`와 `config/urls.py`에 전역 `GET /api/taste-pool`과 기존 전시별 호환 경로를 연결했다. 활성·검수 조건을 모두 충족해야 조사 이미지를 보여준다.
- `recommendations.py`에서 선택 근거와 빈도를 서버가 검증하고, 버전 변경에는 409를 반환하도록 했다. 근거가 있는 태그의 비어 있지 않은 부분집합과 기존 회원 저장값을 지원한다. `client.ts`, `U05Taste.tsx`, `types.ts`에서 전역 조회·준비 부족 안내를 반영했다. [조사풀 운영 안내](../../operations/취향조사풀-운영.md)

**검증 결과**

계약 C1과 구현 C2 기준을 통과했다. 격리 PostgreSQL에서 Django 114건, 프론트 25건과 빌드가 통과했다. Chrome에서 두 전시가 같은 조사풀을 쓰면서 각각 추천을 반환하고, 비활성 풀에서는 준비 부족을 안내하는지 확인했다. 이 단계는 합성 데이터로 검증했다. [구조 검증 기록](../../execution-plan/2026-11-07/records/team-feedback-2026-11-10/survey-validation.json)

## 개발 환경에 후보 초안 등록

**시작 배경**

전시 독립 구조를 격리 DB에서 확인한 뒤, 기존 `arti-dev`에도 새 API와 스키마를 적용하고 실제 후보를 비교할 수 있게 준비했다. 유영국·기존 Git 평가 자료·WikiArt·인상주의 자료의 식별과 검수 상태를 대조해 Git 9점과 기존 유영국 1점을 교체 가능한 초안으로 잡았다. [후보 선정 근거와 미확정 사항](../../../data/intake/2026-11-10-taste-survey/README.md)

**작업과 변경 파일**

- `configure_taste_survey.py`에 `--allow-unreviewed-draft`를 추가해 미검수 후보도 비활성으로 등록할 수 있게 했다. `test_survey.py`에서 미검수 작품의 활성화 거절을 확인했다.
- `data/intake/2026-11-10-taste-survey/`에 식별·출처·해시·쌍별 대비·제외 사유를 기록하고, `verify_survey_candidates.py`로 자료를 검사했다. 기존 캡처의 식별 불일치, 워터마크와 판본 미확정은 자료 이슈로 남겼다.
- 기존 DB와 미디어를 백업한 뒤 일반 개발 환경에 이관 0002를 적용했다. 신규 9점은 비공개 관리 자료로 넣고, 기존 유영국 작품을 참조해 10점·5쌍을 `revision=1`, `active=false`로 등록했다.

**검증 결과**

Django 115건이 통과했다. 일반 개발 DB의 작품 수는 16점에서 25점이 됐고, 기존 16점의 행과 미디어 해시는 일치했다. 백업을 별도 DB에 복원해 원본과 대조했다. 실제 API에서 준비 상태 200, 비활성 풀의 빈 응답, 비공개 상세·이미지 404를 확인했다. 최종 선정과 공개 활성화는 대기였다. [개발 환경 반영 기록](../../execution-plan/2026-11-07/records/team-feedback-2026-11-10/dev-application.json)

## 외부 후보와 추천 민감도 비교

**시작 배경**

10점 초안은 기존 평가 자료에 많이 의존했고, 추상 중심의 유영국 작품군만으로는 다른 전시에서 추천이 어떻게 달라지는지 보기 어려웠다. 외부 후보와 다른 작품군을 넣어 조사 구성과 동점 정책의 영향을 비교했다.

**작업과 변경 파일**

- `survey_candidate_compare.py`에서 Met 자료 15개 중 확보한 이미지 11개를 포함해 고유 이미지 54점을 기존 CLIP·mDeBERTa와 보정값으로 오프라인 추론했다.
- 현행 초안 A, 외부 3점 교체 B, 같은 주제 대비로 재배열한 C를 비교했다. 현행·동점만 AI 보조·대표 3개와 AI 보조·상대 대비 3개의 네 처리 방식을 유영국·기존 혼합·외부 추천군에 적용했다. [비교 보고와 재현 자료](../../execution-plan/2026-11-07/records/W07-preparation/survey-comparison-2026-11-10/README.md)

**검증 결과**

- 추천 3,456조건을 재현했고, 현행 처리 864조건은 실제 Django 추천 함수와 일치했다. 신규 6건을 포함한 스크립트 33건이 통과했다. 일반 개발 DB와 미디어의 전후 상태를 대조했다.
- 최상위 빈도 동점은 A 13/32, B 17/32, C 16/32였다. A에서 동점 보조만 바꿔도 30분 추천 구성이 유영국 7/32, 기존 혼합 14/32, 외부 13/32에서 달라졌다. 이 수치는 추천 변화 빈도이며 만족도는 별도 검증 대상이다. [비교 검증 결과](../../execution-plan/2026-11-07/records/W07-preparation/survey-comparison-2026-11-10/validation.json)

## 후보 대비표와 블라인드 검수 준비

**시작 배경**

모델 비교에서 같은 주제의 두 작품이 공유하는 태그도 함께 누적돼 동점이 남았다. 최종 후보를 고르기 전에 사람이 대비 의도와 표시 품질을 독립적으로 판단할 자료가 필요했다.

**작업과 변경 파일**

- `matrix.json`과 `candidate-contrast-table.md`에 21점의 식별·출처·미확정 사항과 18쌍의 대비 의도·공통 특징·교란 요인을 적었다. 18쌍은 앞서 비교한 13쌍과 검수용으로 제안한 5쌍으로 구성했다.
- `survey_blind_review.py`와 `review-template.html`로 익명 코드·이미지·중립 질문이 담긴 오프라인 HTML을 생성했다. 두 버전은 작품·쌍 순서와 좌우를 반대로 구성했다. 기권과 미응답, 초안 복원과 완료 제출도 처리했다. [검수 진행 안내](../../review/taste-survey-2026-11-10/README.md)

**검증 결과**

신규 11건을 포함한 스크립트 44건이 통과했다. 브라우저에서 21점 확인과 18쌍 진입, 미완료 제출 차단, 응답 다운로드·복원을 확인했다. 파일 복원이 브라우저 권한에 막혀 JSON 붙여넣기 복원을 추가했다. 검수 준비 기준 CP1~CP4를 통과했고, 실제 사람 응답과 최종 선정은 대기였다.
