## 운영 구성과 전체 요청 예산

**시작 배경**

기존 운영 문서는 SQLite 시점의 설정을 담고 있었다. 크레딧 없이 배치할 후보의 비용과 용량을 다시 계산했고, 관리자 분석의 개별 25·30초 제한만으로 전체 요청 시간을 제어하기 어려운 점을 확인했다. [직전 관리자 장애 복구](2026-11-09_모델도슨트검증.md#격리-관람과-모델-장애-복구)

**작업과 변경 파일**

- `06-operations.md`와 운영 결정안에 Django·PostgreSQL, 미디어 보존, 접근 제한·복원 절차를 연결했다. AWS 공식 단가로 EC2 자체 DB, EC2+RDS, Lightsail과 교내 로컬 시연안을 비교했다. 초기 4GB 검토는 이후 저사양 실측으로 갱신했다. [운영 결정안](../../operations/W12_운영구성과예산결정안.md) · [당시 가격과 계산 근거](../../execution-plan/2026-11-07/records/W12/2026-11-09/README.md)
- `Dockerfile.static`, `nginx.static.conf`, `compose.capacity.yaml`에서 정적 웹과 1GB·2GB 격리 시험을 구성했다. `capacity_probe.py`에서 cgroup v1·v2 메모리 수집을 보완했다.
- `budget.py`, `editing.py`, `providers.py`, `llm.py`, `model_service.py`에 전체 60초 예산과 남은 시간 전달, 저장 직전 만료 검사를 추가했다. `test_budget.py`와 `request_budget_probe.py`로 부분 결과 저장과 재시도 경계를 점검했다.

**검증 결과**

- 비용·결정안의 오류 변이 9개를 거절했다. 두 용량 모두 조회·추천·저장·재시작 검사를 통과했다. 50동시 혼합 1,000요청의 p95는 1GB 848.06ms, 2GB 962.47ms였고 OOM과 중복 행은 0건이었다. 1GB는 제한 시연의 최소 시험 후보, 2GB는 여유를 둔 권장 후보였다. 실험은 모델 분리와 외부 빌드를 전제로 했다.
- Nginx→Gunicorn→합성 제공자 경로에서 60.133초에 504가 반환됐고, 저장 스냅샷은 그대로였다. 연결 중단 뒤 서버 처리가 완료될 수 있으며, 이전 버전 재전송은 추가 제공자 호출 없이 409였다. 최종 Django 100건·모델 24건·프론트 23건·빌드가 통과했다.
- 실제 배치는 계정·상한·TLS·접근 제한·복원 검증을 남겨 뒀다. 당시 소형 구성 비용과 AWS Core 검토는 운영 기록에 남겼다. [실측과 재현 근거](../../execution-plan/2026-11-07/records/W12/capacity-2026-11-09/README.md) · [저사양 판단과 AWS Core](../../operations/W12_저사양용량검증과AWS_Core.md)
