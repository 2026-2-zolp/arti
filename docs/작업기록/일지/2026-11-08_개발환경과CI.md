## 텍스트 모델 연결 준비

**시작 배경**

새 Django의 텍스트 호출은 설정과 관계없이 503이었다. 키를 서버에 보관하고, 명시한 경우에만 OpenAI 호환 텍스트 모델을 연결할 설정이 필요했다.

**작업과 변경 파일**

- `arti/llm.py`, `providers.py`, `settings.py`, Compose와 환경 예시에서 `disabled`와 `openai_compatible`을 선택하게 했다. 공통·작업별 모델 설정을 지원하고 키는 Git 제외 서버 환경에 두도록 했다.
- 해설·요약·가이드·도슨트·영수증 해석의 텍스트 요청에 제공자를 연결했다. 승인 원문과 오류 응답 경계를 보완했다. 기존 Kanana는 FastAPI writer와 Express fallback에 남았고, Django의 태그·감정 분석은 별도 과업으로 이어졌다. [설정과 모델 선택 근거](../../operations/AI_설정과모델선택.md)

**검증 결과**

로컬 HTTP 제공자 11건과 통합 429 시험 1건을 포함해 PostgreSQL 63건이 통과했다. 미검수 근거 혼입과 429 상태 유실을 보완했다. 당일 검증 범위는 설정·요청·오류 처리였고 실제 키·유료 호출과 확장·하네스 검토는 후속으로 정했다. [W07 준비 검증](../../execution-plan/2026-11-07/records/W07-preparation/README.md)

## Git 자료 점검과 Express 경로 분리

**시작 배경**

Django를 기본으로 바꾼 뒤에도 구조 안내와 캡처 exporter가 기존 Express 경로에 의존했다. 유영국 자료를 받기 전에 Git에서 복원 가능한 평가 자료의 범위를 확인했다.

**작업과 변경 파일**

- 루트·자료·도구 안내를 현재 Django 실행 경로에 맞췄다. `data/reference/git-captures/`에 원본 Git blob의 바이트와 commit·blob·해시를 연결한 참조 사본을 만들었다.
- `git_materials.py`와 `export_git_captures.py`에서 원본 ID·경로·내용의 읽기 전용 검사와 복원을 공통화했다. 기존 `backend/` 없이도 exporter가 작동하며 원본과 기존 출력은 덮어쓰지 않는다. [현재 구조와 기존 코드의 관계](../../operations/현재구조와legacy의존.md)

**검증 결과**

125개 자산을 감사했다. 캡처 40점, WikiArt 파일 79개, 감정 예시 11건을 구분했고 캡처 경로 차이 40건과 미검수 해설을 기록했다. Windows·Linux 자료 검사 7건, 프론트 17건, actionlint와 기존 exporter 대비 40점 출력·이미지 동일성이 통과했다. 유영국 자료 수령과 작품별 검수는 다음 작업으로 이어졌다.
