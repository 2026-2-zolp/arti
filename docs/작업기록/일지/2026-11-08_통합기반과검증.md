## 개발 계약과 기존 회귀 기준

**시작 배경**

Express의 현 동작을 그대로 옮기면 미검수 공개나 회원 저장 오표시까지 이어질 수 있었다. React와 호환할 계약을 정하고, 기존 구현의 정상 동작과 결함을 재현할 근거가 필요했다.

**작업과 변경 파일**

- W02의 `source-inventory.*`, `contracts.md`, `decisions.md`, `issue-implementation-map.md`에서 React 유지와 Django·DRF·PostgreSQL·Docker 전환을 확정했다. 공개·관리자 조회, 검수 상태와 버전, 취향 빈도와 저장값, 도슨트 맥락, 동일 회원의 미저장 영수증 복구 계약을 구체화했다.
- `cases.json`과 `wire-examples.json`에 시나리오 35개와 전송 예시 6개를 목표 계약으로 기록했다. 무효 회원 인증의 비회원 전환, 버전 불일치, 이미지·출처 변경 시 검수 범위를 정리했다.
- W03의 `regression.test.mts`와 `browser-server.mts`에 Express HTTP·격리 DB·가상 모델 회귀와 React 화면 증거를 추가했다. 화면에서 U07은 시간을 바꾸면 추천을 비우고 다시 요청하는 것을 확인해 기존 reducer 단독 해석을 정정했다.

**검증 결과**

- W02는 소스 65개·API 34개·프론트 호출 51곳·이슈 37개를 대조했고 계약 검사 오류 0건으로 G1을 통과했다. [계약 검사](../../execution-plan/2026-11-07/records/W02/contract-check.json) · [G1 검토](../../execution-plan/2026-11-07/records/W02/gate-review.md)

## Django 기반과 인수 기록 정합화

**시작 배경**

확정 계약을 기존 React에 연결할 수 있도록 조회·추천부터 새 서버로 옮겼다. 검수 전 공개와 자동 데모 계정 같은 동작을 새 환경에서 막고, Docker에서 실행과 데이터 보존을 확인해야 했다.

**작업과 변경 파일**

- `backend-django/config/`, `arti/models.py`, `0001_initial.py`에 PostgreSQL 모델과 관계·유일성 제약, 상태 검사 API를 추가했다. `views.py`, `serializers.py`, `recommendations.py`에서 공개 전시·승인 작품과 관리자 조회를 구분하고 추천 3·5·7점 계약을 연결했다.
- `compose.yaml`, `Dockerfile`, `init_dev_env.py`에서 DB 준비→이관→API 준비→선택적 UI 순서를 만들었다. 관리 명령으로 초기 관리자와 시험 자료를 명시적으로 생성하게 했다.
- 프론트의 `client.ts`, `ArtImage`, `FloorMap`, `useProtectedImage`에 관리자 전용 읽기와 인증 미디어 처리를 추가했다. 빠른 URL 전환의 이전 이미지 정리도 보완했다.
- 후속 문서 감사에서 루트 `README.md`의 옛 안내와 `execution.json`의 중복 상태를 정리했다. `verify_repository_handoff.py`가 당시 6개 커밋 구간과 W04 기준 소스를 검사하게 했고, `verify_compose.py`는 재실행 결과를 별도 이름으로 기록하게 했다. [Django 실행 안내](../../../backend-django/README.md)

**검증 결과**

- PostgreSQL 17.11에서 24건, 프론트 타입·빌드가 통과했다. 빈 기동과 반복 fixture, DB·API 재생성 뒤 건수·미디어 해시 보존을 확인했다. 실제 React에서 합성 전시→추천→지도→원문과 관리자 보호 이미지를 점검했다. 42개 검증 소스 해시를 복원본과 대조해 G3를 통과했다. [W04 구현과 시험](../../execution-plan/2026-11-07/records/W04/README.md) · [계약 차이](../../execution-plan/2026-11-07/records/W04/contract-delta.md) · [G3 검토](../../execution-plan/2026-11-07/records/W04/gate-review.md)
- 후속 문서 감사에서는 계획·원본 38개 보존, 검증기 25건, 고정 소스와 커밋 이력이 통과했다. 회원 저장과 도슨트 등 쓰기 흐름은 다음 W05로 이어졌다.

## 관람 핵심 통합과 G4 인수

**시작 배경**

W04는 조회·추천까지 연결했다. 관리자 편집과 검수, 회원 취향과 영수증, 작품 안내에서 도슨트로 이어지는 흐름을 W02 계약대로 구현해야 했다.

**작업과 변경 파일**

- `editing.py`에서 관리자 편집·파일·분석·선택 확정과 잠금·버전 충돌 처리를 구현했다. 근거 변경 시 재검수하고 다른 확정 산출물은 보호했다. `member.py`에서 본인 인증과 취향 저장을, `recommendations.py`에서 서버 검증 빈도와 저장 취향 재사용을 연결했다.
- `records.py`와 `receiptPayload.ts`, `PendingReceipts.tsx`에서 영수증 본문을 먼저 고정해 저장하고 같은 요청의 중복을 막았다. 만료 회원의 미저장 요청은 같은 계정으로 돌아온 뒤 명시적으로 복구한다.
- `docent.py`, `providers.py`, `visitScope.ts`, U10·U11에서 서버 승인 자료와 실제 진입 질문, 대화·관람 범위를 연결했다. `VisitContext.tsx`와 `visitReducer.ts`에는 오래된 요청과 계정 변경 보호를 반영했다.
- 시험 중 미완료 작품의 체류 시간이 복구 본문에 섞여 400이 났다. 완료 작품만 담도록 수정했다. 브라우저 확인창에서 시험이 멈춘 뒤 `Confirmation.tsx`를 추가해 취소·포커스·경로 전환을 제어했다. U08의 목록 오류 재시도, A04의 확정 충돌 뒤 재조회·재검토도 보완했다.
- `export_git_captures.py`와 `import_capture_bundle`로 Git 캡처 40점의 메타데이터·이미지를 ID와 해시로 대응했다. `checkedAt=null`인 해설은 검수 대기로 가져왔고 전시 draft·작품 source_check·좌표 미입력을 적용했다. 로컬 고유 자료는 원본 보존 후 별도 인수하기로 정했다. [AC17 자료 인수 결정](../../execution-plan/2026-11-07/records/W05/data-intake-decision.md)

**검증 결과**

- 비회원 3점 관람과 회원 3점 저장·재진입을 확인했다. 새 1점 관람의 만료 복구는 취소 시 pending 유지, 확인 후 삭제, 역사 재조회와 DB 1건까지 실제 화면에서 검증했다.
- 관리자 409 뒤 재조회·1점 확정, 원문 변경 후 비공개와 재승인, provider 503에서도 확정값 보존을 확인했다. 추천 목록 오류와 서비스 중단 뒤 화면 복구도 확인했다. [W05 구현과 시험](../../execution-plan/2026-11-07/records/W05/README.md) · [브라우저 관측](../../execution-plan/2026-11-07/records/W05/browser-observations.md)
- PostgreSQL 51건, 프론트 13건·타입·빌드, 이관·Compose가 통과했다. Git 자료 범위의 AC11~17을 확인하고 G4를 통과했다. 로컬 고유 자료, 유영국 실자료와 사람 검수, 실모델·실기기·운영 검증은 후속 범위였다. [G4 판정](../../execution-plan/2026-11-07/records/W05/gate-review.md) · [CI/CD 검토](../../operations/CI-CD_적용검토.md) · [당시 공유 준비](../../operations/원격푸시_검토준비.md)
