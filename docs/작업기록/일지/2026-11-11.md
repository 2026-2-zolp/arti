## 취향 동점 처리와 관람 반영

**시작 배경**

11/10 팀 논의에서 선택 빈도가 같은 태그의 순서가 고정 기준으로 정해진다는 문제가 나왔다. 모델 점수를 보조 기준으로 쓰려면 점수가 어떤 이미지·모델·설정에서 나왔는지 먼저 확인할 수 있어야 했다.

**작업과 변경 파일**

- `provenance.py`와 `tag_scores.py`에서 점수의 출처를 전달·저장했다. `taste_resolution.py`와 `TasteReview.tsx`에서 서버의 동점 계산과 사용자 확인 흐름을 연결했다.
- `records.py`와 `receiptPayload.ts`에서 체류 시간이 같은 작품의 영수증 표시 기준을 관람 순서로 맞췄다.

**검증 결과**

격리 DB와 실제 Django API에서 작품 선택부터 영수증까지 완주하고, 동일 요청의 결과 일치와 중복 저장 방지를 확인했다. 실제 모델과 도슨트 시험의 입력·환경은 단계별 기록에 남겼다. [TP1a~TP4 작업기록](2026-11-11_취향동점처리와관람반영.md) · [동점 계약](../2026-11-11_R04_프론트인수와동점처리계약.md) · [구현 계획](../2026-11-11_R04_동점구현상세계획.md)

## 작품과 태그 검수 준비

**시작 배경**

기존 라벨링 도구는 유영국 16점 전체 응답을 받아야 해서 핵심 3점만 제출하면 초안으로 처리됐다. 우선 세 작품의 태그를 팀원이 각자 판단할 수 있는 제출 경로가 필요했다.

**작업과 변경 파일**

- 소장품 기록을 대조하고, `build_yoo_core3_review.py`와 `yoo_labels.py`에 3점 전용 묶음 생성과 제출 검증을 추가했다.
- `build_team_review_pack.py`와 검수 안내를 작성해 **작품 태그 → 취향 후보 비교 → 콘텐츠 확인**을 한 ZIP에서 순서대로 진행할 수 있게 했다.

**검증 결과**

ZIP 무결성과 합성 응답 제출을 확인했다. 팀원 응답, 최종 조사 작품 10점·5쌍 선정, 이미지별 사용 근거와 공개 범위는 확인 대기다. [핵심 3점 인수 기준](../2026-11-11_W06_핵심3점독립검수인수준비.md) · [팀 전달 묶음](../2026-11-11_W06_팀검수통합전달묶음.md)

## 모바일 리허설과 실기기 관찰

### 격리 Chrome 에뮬레이션

**시작 배경**

느린 연결에서 작품 정보가 오기 전에 도슨트 보내기 버튼이 활성화돼 전송이 중단됐다. 운영 진단에서도 실제로 AI가 설정됐는지 구분할 필요가 있었다.

**작업과 변경 파일**

- `U11AskAI.tsx`에서 작품을 불러오는 중에도 질문을 작성할 수 있게 두고, 작품 맥락이 준비된 뒤 전송을 열었다.
- `views.py`와 제공자 어댑터를 수정해 `/api/health`에 AI 설정 상태를 표시했다. DB 준비는 `/api/ready`에서 확인했다.

**검증 결과**

두 화면 크기에서 관람을 완주했다. 제공자 오류 뒤 입력 보존·재시도, 영수증 중복 방지를 확인했고 Django 152건·프론트 34건이 통과했다. [모바일 리허설과 운영 진단](../2026-11-11_격리모바일리허설과운영진단.md)

**시작 배경**

휴대폰의 터치·시스템 뒤로가기·PNG 저장을 직접 확인하려고 합성 전시를 가입부터 마이페이지까지 사용했다.

**작업과 변경 파일**

두 번째 작품이 화면 아래로 밀렸고 영수증 뒤로가기에서 화면이 반복됐다. 저장 PNG에서는 태그 줄바꿈을 확인했다. 같은 기기에서 수정 후 재확인할 항목으로 남겼다. [실기기 관찰 22개와 개선안](../2026-11-11_갤럭시실기기_관찰과개선안.md) · [수정 후보와 통과 기준](../2026-11-11_실기기피드백_프론트인수.md#1차-수정과-통과-기준)

## 프론트 인수와 브랜치 공유

**시작 배경**

팀 UI 작업과 취향 기능이 같은 화면을 건드려 최신본을 받을 때 선별 기준이 필요했다.

**작업과 변경 파일**

- 성현님 중간 ZIP을 당시 코드와 대조했다. 헤더·오류색·추천 이유 표시는 적용 후보로, 전시 독립 조사 API와 작품 전체 표시는 현재 브랜치 기준으로 기록했다.
- 기존 개발 커밋을 `dev/임준억`에 공유했다. 첫 원격 CI에서 새 체크아웃에 `data/private`가 없을 때 검수 도구가 해당 폴더 자체를 출력 대상으로 받아들이는 문제가 드러나, `scripts/survey_blind_review.py`에서 그 경로를 거절하도록 보완했다.

**검증 결과**

11/11 첫 push CI는 계획·계약 검사에서 실패했고 나머지 세 작업은 성공했다. 프론트 인수 기준과 팀 검증 절차를 문서에 남겼으며, 최신본의 기준 커밋·수정 화면·검증 범위 확인은 대기였다. [첫 CI 실행](https://github.com/2026-2-zolp/arti/actions/runs/42977731964) · [프론트 인수와 CI 기록](../2026-11-11_실기기피드백_프론트인수.md) · [PC와 휴대폰 검증 가이드](../../operations/프론트인수_PC와휴대폰검증.md)
