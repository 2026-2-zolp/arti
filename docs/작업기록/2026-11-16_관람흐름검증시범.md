- 기준 빌드 `1b8b8ee`. Vite 정적 빌드와 합성 API를 사용한 PC Chrome에서 320×640, 360×780, 412×812로 확인했다. U-05의 확대와 선택 분리, U-09의 다음 작품 표시와 지도 펼침·복귀는 동섭님 변경이 반영된 화면을 기준으로 삼았다. [프론트 인수 가이드](../operations/2026-11-13_프론트분담과검증가이드.md)
- PR 템플릿의 ‘관람 흐름’에 화면·환경, 정상 흐름과 다음 행동, 실패나 복귀 후 상태, 확인 대기를 짧게 적는다. 푸시 전 같은 커밋에서 이미 확인한 실행 결과를 사용할 수 있다. [PR 템플릿](../../.github/PULL_REQUEST_TEMPLATE.md)

| 화면 | 정상 흐름과 다음 행동 | 실패·복귀와 남은 상태 |
| --- | --- | --- |
| U-05 · 두 작품 비교 | 긴 제목은 말줄임으로 표시됐다. 세로·가로 합성 작품과 두 선택 버튼이 세 화면 크기의 첫 화면 안에 들어왔다. 선택 버튼을 연달아 눌러도 한 쌍만 진행됐다. | 키보드로 크게 보기를 열면 닫기 버튼에 초점이 갔다. Esc를 누르면 원래 카드에 초점이 돌아왔고 진행은 1/5였다. 다음 쌍에서 뒤로가면 같은 첫 쌍으로 돌아왔다. |
| U-09 · 다음 작품 안내 | 다음 작품 제목·썸네일과 감상 버튼을 찾을 수 있었다. 전체 지도를 펼쳐도 도면의 높이와 감상 버튼 위치가 유지됐다. | 합성 목록 503 뒤 다시 시도 버튼이 첫 화면에서 보였다. 복구 뒤 앞뒤 이동을 거쳐 같은 관람 ID와 감상 기록을 유지했고, 표시된 두 번째 작품으로 이동했다. |

U-05의 둘째 카드를 첫 화면 아래로 미는 시험용 CSS를 잠시 적용했다. Playwright의 `isVisible()`은 참을 반환했지만 화면 좌표로는 선택 버튼을 바로 찾을 수 없었다. 시범 문항이 DOM 표시 여부와 별개로 중요한 행동의 가시성을 확인하는 데 도움이 됐다. 시험용 CSS는 브라우저에서 제거했다.

기존 `frontend/tests/visitCompletion.browser.cjs` 15건도 통과했다. 새 양식에 맞춰 같은 검수 결과를 한 줄로 적으면 `U-09 · PC Chrome 320×640 · 지도 목록 503 → 다시 시도 → 뒤로/앞으로 · 다음 작품 버튼과 기존 관람 유지`다. 실기기의 키보드·터치 확대·OS 공유와 실제 모델 호출은 보류 항목이다.
