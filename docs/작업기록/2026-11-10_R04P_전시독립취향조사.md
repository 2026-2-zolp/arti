# R04-P — 전시 독립 취향 조사

## 맥락과 연결

[이전 R06 기록](2026-11-10_R06_팀의견과첫사용자결함.md)에서 같은 전시10점이라는 기존 W02 계약과 팀 이해 차이를 확인했다. 사용자는11/10 전시 독립 조사 방향과 계약→분리 구현·검증을 승인했다. 실제 조사 자료 선정과 동점 알고리즘은 다음 과업이다. 원격 푸시는 하지 않는다.

## C1 계약 준비

[개정 계약](../execution-plan/2026-11-07/records/team-feedback-2026-11-10/survey-contract.md)을 작성했다. 조사풀/순서/버전과 현재전시추천을 분리하고 기존 작품 참조를 재사용한다. 전시 FK 전면 변경·새 업로드 UI·데이터 자동 공개를 피한다. 운영자 명령은 revision과 자격을 검증하며, 명시적 활성화만 조사 이미지 공개 근거가 된다. 기존 회원 snapshot은 그대로 유지하고 이전 게스트 picks는 버전 충돌 시 다시 조사한다.

역할별 자체 검토에서 기술/시니어는 위조선택·이전 버전·부분집합 호환을, 방문자는 준비부족/재조사를, 운영은 비공개 소속 작품의 조사 이미지와 전시 상세 공개 구분을, 팀/교수/평가위원은 합성 기술검증과 실제 자료 검수 구분을 확인했다. 선택 태그를 전체집합으로 강제하려던 초안은 기존 부분집합 요청을 깨므로, 비어 있지 않은 부분집합 허용·근거없는 태그 추가 거절로 보완했다. C1 자체 준비 기준 통과이며 사람·제품 최종 게이트 통과는 아니다.

다음: 동일 계약으로 구현하고 C2 회귀를 기록한다.


## C2 구현과 변경 전후

기존 공개 조사와 picks 검증은 현재 전시의 ID순10점에 의존했다. 이제 `SurveyPool/SurveyEntry`와 `arti/survey.py`가 전시 독립 자격·순서·버전·5쌍을 검증한다. `0002_independent_taste_survey`는 두 테이블과 양의revision/단일활성/위치·작품중복 제약만 추가한다. 실제 자료/기존 계정의 데이터 마이그레이션은 없다.

`views.py/config/urls.py`에 전역 GET /api/taste-pool과 기존 전시별 호환 별칭을 연결했다. 명시적 활성·준비 조사풀만 소속 전시 공개와 독립적으로 이미지 접근을 허용한다. 전시 목록·상세·추천의 running/approved 범위는 그대로다. 원문검수·확정태그·이미지표시·10점 중 하나라도 깨지면 풀은 전부 비노출이다. ready는 신규 테이블까지 확인한다.

`recommendations.py`에서 새 picks 검증은 전역풀로 전환하고 counts를 서버에서 재계산한다. 선택 근거가 없는 태그 추가는400,풀 버전/준비 변경은409다. 기존 태그 부분집합 요청은 유지한다. 저장 snapshot은 originSurveyId/originSurveyRevision과 기존 originalPoolVersion/originalPicks/originExhibitionId를 함께 보존한다. saved는 기존 계정의 원본 snapshot을 그대로 재사용하며 현재 조사풀로 재검증하지 않는다. 과거 make_pool(works)는 메모리 평가 재현용으로만 남겨 과거 실험을 임의로 바꾸지 않았다.

`configure_taste_survey` 관리 명령은10개 기존ID·순서·기대revision을 검증하고 전체 트랜잭션으로 저장/활성화한다. 관리자 화면의 기존 자료 등록·검수를 재사용하며 새 업로드 화면은 만들지 않았다. --activate 없는 같은풀 수정은 비활성 초안이 된다는 운영 경계도 명시했다.

프론트 `client.ts/U05Taste.tsx/types.ts`는 전역 조회와 서버 provenance를 반영했다. 전시 독립 조사를 안내하고 준비부족은 재시도/이전으로 처리한다. 기존5쌍/8태그/빈도가중치/동점 알고리즘·추천수는 바꾸지 않았다. [운영 안내](../operations/취향조사풀-운영.md)에 적용 전 백업·마이그레이션·빈 풀·선정/활성화·이전 게스트/회원 호환을 기록했다.

## 검증 루프와 판정

[구조 검증 결과](../execution-plan/2026-11-07/records/team-feedback-2026-11-10/survey-validation.json)에 C2의7조건을 연결했다. Linux/PostgreSQL17 전체114건(기존104+신규10),프론트25건(전역API경로 회귀 포함)·TypeScript/Vite빌드를 통과했다. 격리 Chrome에서 비공개/좌표없는10점 조사→현재전시별도3점추천,두 번째 전시의 동일조사,비활성풀 준비부족 안내를 확인했다. 실기기/회원브라우저/실제작품 승인까지 확인했다고 확대하지 않는다.

첫회귀의 합성태그 미확정은 fixture10점에 명시적으로 confirmed를 넣어 해결했다. 프로덕션 자격을 낮추지 않았다. 기존 저장 회귀는 고르지 않은 warm태그를 보내던 사례라 실제warm작품 하나를 고르도록 수정했고, 서버빈도 재계산·부분집합가중치 검증은 유지했다. 새 시험의 잘못된 전시ID와 FileResponse 정리 중 TestCase 연결종료 간섭도 수정했다. DB/API/선택 검증을 mock으로 우회하지 않았다.

기술/시니어는 단일활성·중복제약·revision/위조선택·기존저장을,방문자는5쌍·준비부족·재조사를,운영/데이터는공개범위·비공개출처·원본보존을,팀/교수/평가위원은계획/구현/실제콘텐츠검수의 구분을 자체 검토했다. **C2 구조 기술 기준 통과**이며 R04 모델품질·실제 조사 자료 선정·사람 검수·제품 최종 게이트는 완료하지 않는다.

일반 arti-dev DB/미디어와 GPT 설정은 건드리지 않았다. 일회용 PG와 서버만 사용했다. 현재 일반 환경에는 마이그레이션 적용과 실제 검수 조사풀 구성이 남는다. 자동 fallback 없이 준비부족이 정상이며,명시적 활성화 전 실제 자료는 노출하지 않는다.

## 다음 단계

먼저 조사 작품10점의 선정안을 작성한다. 각 후보의 식별·출처·이미지사용/콘텐츠검수 상태와 쌍별비교 의도를 연결한다. 승인 전에도 후보별 태그분포와 편중은 비공개로 비교할 수 있다. 이어 R04-S에서 동점빈도/선택별가중치/추천차이를 측정한 후 AI점수보조·대표2~3개 변경UI를 채택할지 결정한다. 서버최대3개 제한은 여전히 미채택이다.

계약/C1과 구현/C2는 별도 로컬 커밋으로 보존한다. 원격 푸시는 하지 않는다. 후속 제안도 목적·구체작업/경계·통과기준·산출물/커밋범위·다음단계 순으로 제시한다는 사용자 선호를 커밋작성기준에 기록했다.

최종 자체 검토에서는 두 전시 추천이 비어 있어도 검사에 통과하는 약점을 발견해 두 결과 모두 비어 있지 않도록 검증을 강화했다. 미검수 작품의 명령 활성화 거절도 추가하고 신규10건을 다시 통과했다. 새 마이그레이션 차이 없음,계획/기존계약/가드레일32건/재계획 무결성 검사도 통과했다.
