# 11/16 도슨트 저장 답변 12건 평가 회신 검증

- `289c110` 기준으로 기존 팀 검수의 Markdown 제출표를 재사용한다. 회신 검사에 사용하는 것은 11/09 보완 라운드의 합성 작품 답변 12건이다. 답변 원본과 질문 프로토콜의 SHA-256을 대조하고, 프롬프트 원본 SHA-256은 기존 기록에서 읽어 결과에 표시한다. 기존 답변·질문·평가 원본을 수정하지 않았다. [팀 검수 기준과 제출표](../review/docent-2026-11-15/README.md) · [저장 답변 원본](../execution-plan/2026-11-07/records/docent-baseline-2026-11-09/targeted-results.json)
- `scripts/docent_review_intake.py`는 사례 누락·중복, 판정과 확인 항목, 적용 항목의 0~2점과 평균, 필수 행동·중대 위반·최종 판정의 불일치를 찾는다. 첫 답변 4건은 평균을 내지 않고 후속 4건은 네 항목, 경계 4건은 근거와 명료성으로 계산한다. 회신의 답변 인용 구절이 저장된 문장에 있는지와 인용 뒤에 대조 근거가 있는지를 확인한다. `보류`에는 아직 필요한 자료를 적고 판정 건수에는 넣지 않는다.
- 결과는 사례별 판정·필수 행동·중대 위반·점수의 차이와 기존 평가·다른 검수 의견의 `미열람`, `열람`, `모름`, `미기록` 집계를 표시한다. 미열람은 검수자의 자기 신고다. 중복 별칭이나 버전이 다른 회신은 비교 건수에서 제외하고, 상세 결과에서 원본 파일 순서와 문제 행을 찾아볼 수 있다. 인용·근거의 내용과 이견은 준억과 검수자가 회신 원문을 놓고 대조한다.

## 작성과 재현

1. 작성자 외 팀원이 제출표를 복사해 저장 답변을 먼저 읽고, 검수자 별칭·작성일·평가 자료 SHA-256·열람 여부를 적는다. 근거 칸에는 `저장 답변의 구절 → 대조한 자료`를 적고, 보류라면 `→ 더 필요한 자료`를 적을 수 있다.
2. 받은 UTF-8 Markdown 파일을 비공개 작업 위치에 두고 저장소 루트에서 실행한다. 입력 순서대로 `reply` 번호가 부여된다. 결과를 공유하기 전에 별칭과 회신 번호를 필요한 범위에서만 사용한다.

```powershell
python -X utf8 scripts/docent_review_intake.py data/private/review-a.md data/private/review-b.md
python -X utf8 -m unittest discover -s scripts/tests -p test_docent_review_intake.py -v
```

3. `replies`의 누락·중복·형식 오류는 제출표에서 대조한다. `caseSummary`의 의견 차이는 기존 판정 열람 여부와 함께 확인하고, 필요한 사례는 사람 재검수나 모의 회귀 입력으로 남긴다.

## 검수 결과와 대기 항목

- 합성 회신으로 12건 완성본과 빈 공식 양식, 1.5점 통과 경계, 잘못된 점수·판정·인용, 누락·중복 사례, 보류와 근거, 해시 불일치, 중복 별칭, 열람 상태와 판정 차이를 검수했다. 합성 Markdown 두 파일을 CLI에 넣어 한 건 누락과 이견을 확인했고, 빈 양식은 접수된 판정 0건이었다. 집중 검사 6개와 전체 스크립트 검사 67개가 통과했다. [회귀 테스트](../../scripts/tests/test_docent_review_intake.py)
- 실제 팀 회신과 작품별 독립 판정은 대기다. 실제 작품·W06 채택과 AC20·21은 기존 인수 조건을 따른다. 실제 모델 호출과 실기기는 계속 보류했다.
