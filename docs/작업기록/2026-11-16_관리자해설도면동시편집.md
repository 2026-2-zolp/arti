# 11/16 관리자 해설·도면 동시 편집 검수

- 기준은 `6a3e20a`다. 합성 PostgreSQL 17의 `arti_admin_editing`, 루프백 Django와 제품 프론트 빌드를 사용했다. 독립적인 두 Chrome 세션에서 서로 다른 합성 관리자 계정으로 로그인했다. 실제 모델과 실기기는 보류했다.
- 도면 교체 뒤 최신 작품 목록과 이전 도면이 화면에 함께 들어온 상황에서, 수정 전 작품 좌표 저장이 200으로 처리됐다. 도면 교체가 이미 초기화한 좌표를 이전 도면 기준으로 다시 넣을 수 있었다. PostgreSQL 회귀에서 기대한 409 대신 200을 확인했다. [도면 회귀](../../backend-django/arti/tests/test_map_management.py)
- 위치 저장·해제와 전시실 소속 변경에는 화면의 전시 버전과 작품 버전을 함께 사용한다. 서버는 도면 교체와 같은 순서로 전시 행부터 잠그고 각 버전을 확인한다. 도면 업로드·삭제 요청에는 표시 중인 전시 버전을 `If-Match`로 보낸다. 전시와 작품 목록을 다시 읽는 동안 편집 화면이 대기하며 기존 작품 일반 편집의 입력 형식도 계속 지원한다.
- 원문 저장·가이드 확정·지도 배치가 409로 막힌 뒤 최신 자료를 다시 불러올 수 있다. 확인을 취소하면 그 탭의 미저장 원문·질문·위치를 유지한다. 최신 지도를 불러온 경우 새 도면에서 좌표를 다시 찍고 저장한다. 갱신 이전의 도면을 봤다면 최신 작품 버전을 이미 받았어도 위치가 저장되지 않는다. [두 관리자 Chrome 회귀](../../frontend/tests/adminConcurrent.browser.mjs)
- Chrome에서 두 번째 관리자가 원문을 고치면 작품 공개 조회가 404였고, 새 원문 검수·가이드 확정 뒤 최신 원문과 질문·힌트가 공개됐다. 첫 번째 관리자의 구버전 원문 저장과 가이드 확정은 각각 409였다. 이전 도면의 좌표 저장과 도면 재업로드도 409였다. 최신 도면을 확인하고 다시 저장한 뒤 새 비회원 관람에서 V2 5쌍→30분 추천→지도로 들어가 도면 파일, 마커의 작품명·좌표가 최신 저장값과 일치하는 것을 확인했다. 합성 작품이 조사풀에도 들어 있으므로 원문 수정 뒤 기존 태그를 검토하고 명시적으로 다시 확정했다.
- 격리 PostgreSQL 도면·통합 36건, 프론트 단위 44건과 프로덕션 빌드가 통과했다. 별도 분석용 합성 DB에서 기존 관리자 분석 Chrome의 이전 원문 409→최신 내용 다시 조회→모의 200도 통과했다. [기존 관리자 분석 회귀](2026-11-16_관리자분석중작품변경Chrome.md)

## 재현

1. 별도 루프백 PostgreSQL에 `arti_admin_editing` 합성 DB를 만든다. 합성 DB의 `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `DJANGO_SECRET_KEY`, 별도 `MEDIA_ROOT`를 지정한다. `ARTI_ENV=test`, `ALLOW_TEST_FIXTURES=true`, `ARTI_LLM_PROVIDER=disabled`, `ARTI_TASTE_PROFILE_V2_ENABLED=true`를 사용하고 모델 서비스 URL과 실제 키를 비운다.
2. 잠금 의존성을 설치한 Python과 일회용 관리자 비밀번호를 각각 `ARTI_TEST_PYTHON`, `ARTI_BOOTSTRAP_PASSWORD`에 지정한다. 저장소 루트에서 실행한다.

```powershell
& $env:ARTI_TEST_PYTHON backend-django/manage.py migrate --noinput
& $env:ARTI_TEST_PYTHON backend-django/manage.py load_test_fixture
& $env:ARTI_TEST_PYTHON backend-django/manage.py bootstrap_admin --login-id admin-edit-a --name '합성 관리 A'
& $env:ARTI_TEST_PYTHON backend-django/manage.py bootstrap_admin --login-id admin-edit-b --name '합성 관리 B'
$env:VITE_API_TARGET = 'django'
$env:VITE_API_BASE = '/api'
npm.cmd --prefix frontend run build
```

3. 같은 합성 설정으로 `manage.py runserver 127.0.0.1:5712 --noreload`를 띄운다. 별도 셸에서 `$env:VITE_API_TARGET='django'`, `$env:VITE_API_BASE='/api'`, `$env:VITE_API_PROXY='http://127.0.0.1:5712'`를 지정한 뒤 `npm.cmd --prefix frontend run preview -- --host 127.0.0.1 --port 5713 --strictPort`를 실행한다.
4. 부트스트랩 비밀번호가 설정된 셸에서 실행한다. Chrome 검사는 합성 작품 출처와 AI 비활성을 확인한 뒤 제품 API를 사용한다. 화면에 먼저 도착한 구버전 전시 목록을 재현할 때만 앞서 조회한 목록을 브라우저에 전달한다.

```powershell
$env:ARTI_REVIEW_BASE = 'http://127.0.0.1:5713'
node frontend/tests/adminConcurrent.browser.mjs
& $env:ARTI_TEST_PYTHON backend-django/manage.py test arti.tests.test_map_management arti.tests.test_integration --noinput
```
