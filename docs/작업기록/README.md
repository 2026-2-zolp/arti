## 기록 방법

- **한 날짜에 한 일지**를 기본으로 한다. 제목에 날짜와 기록자를 쓰고, 상단에 기록자와 기준일(KST)을 표시한다. 각 작업은 **시작 배경 → 작업과 변경 파일 → 검증 결과** 순으로 적는다. 변경 파일과 동작은 불릿으로 연결하고, 후속 확인은 일지 끝에 모은다.
- 날짜가 길어지면 먼저 주제별 소제목을 사용한다. 본문이 약 80~100줄을 넘거나 긴 검증 표 때문에 한 번에 읽기 어려울 때는 `YYYY-MM-DD_프론트.md`, `YYYY-MM-DD_운영.md`처럼 **작업 흐름 단위**로 나누고, 같은 날짜의 일지에서 연결한다. 분량 기준은 편집 판단에 쓰는 참고값이다.
- 팀에 그대로 전달할 자료, 독립적으로 검토하거나 승인받을 문서, 재현·인수에 필요한 상세 검증은 별도 파일을 쓴다. 일지에는 결과와 링크를 남긴다. 원시 로그와 검증 증거는 [실행계획의 기록](../execution-plan/2026-11-07/README.md)에 연결한다.
- 후속 변경으로 판단이 바뀌면 그날 일지에 근거를 적는다. 통합 전 과업별 원문은 Git 이력에서 확인하고, 현재 일지에서 각 검증 근거와 관련 문서로 이동한다.
- 카톡이나 구두로 진척·결정·확인 요청을 공유한 날에는 Notion에 짧은 스크럼 요약을 남길 수 있다. 공유 내용, 합의와 확인 대기, 담당과 다음 행동을 기록하고 필요하면 이 일지를 연결한다. 대화가 없으면 Git 일지만 작업일 기준으로 남긴다.
