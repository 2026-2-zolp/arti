# 통합 작업기록

이 폴더는 구현 이유·변경 위치·전후 동작·검증·후속 작업을 누적한다. 상세 원시 로그/판정은 실행계획 records/의 해당 W에 연결한다. 단순 대화 복사나 완료 체크만으로 작업을 기록하지 않는다.

## 기준과 읽는 순서

- [통합 준비 문서](../통합준비문서.md): 전체 맥락·이슈·채택 방향.
- [동섭님 통합 원문](1107_김동섭_(리팩토링전)프론트_백_통합.md): ae0e58e의 원문을 내용 변경 없이 이동.
- [실행계획](../execution-plan/2026-11-07/README.md): 과업·게이트·인수 기준·현재 상태.
- [통합 기준·계획 정리](2026-11-08_00_통합기준과계획정리.md): 브랜치 인수·자료 정리·회고 커밋 방식.
- W01→W02→W03→W04 기록은 해당 커밋에서 순서대로 추가된다. 기록이 없는 미래 W를 완료로 해석하지 않는다.
- [W01 코드 인수·재현](2026-11-08_W01_코드인수와재현.md): 전체 기준 확보와 G0, 실제 자료 이전과 구별.
- [W02 개발 계약](2026-11-08_W02_개발계약확정.md): 실제 코드 대조·정상/실패 예시·수정 경계와 G1.

## 이번 커밋 정리 방식

W01~W04는 이미 수행한 작업을 2026-11-08에 회고 정리해 단계별로 커밋한다. 실제 검증 당시 로그는 보존하며 커밋 날짜/작성자를 과거로 바꾸지 않는다. 원격 `dev/임준억`의 f0c55aa에서 동섭 통합본 ae0e58e를 병합했고 그 병합의 파일 tree가 원본과 같음을 확인했다.

작업기록에는 자신이 포함된 커밋의 SHA를 적어 자기 참조로 계속 바꾸지 않는다. 해당 기록의 최초 추가 커밋은 `git log --follow -- docs/작업기록/<파일>`로 확인한다. 다음 작업기록은 앞 단계의 실제 SHA를 연결한다.

## 매번 남길 항목

1. 수행일/기록일·담당·브랜치·관련 W/F/AC·이전 기록/커밋.
2. 어떤 문제/요청에서 시작했으며 무엇을 유지하고 바꾸려 했는지.
3. 실제 변경 파일/모듈과 변경 전→후 동작.
4. 검사 명령·환경·기대/실제·실패/수정 루프·검토자·한계.
5. 남은 문제/다음 한 작업·원격 반영 여부.

새 과업에서는 이전 기록을 지우지 않고 변경된 결정을 새 기록에서 설명한다. 일시 실패 로그·과거 판단의 정정도 근거를 남긴다.
