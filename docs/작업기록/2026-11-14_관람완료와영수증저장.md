# 11/14 관람 완료와 영수증 저장

- **착수 범위** · `dev/임준억`의 `6611b0e`에서 잔여 계획 과업 6의 다음 작품 안내와 과업 9의 관람 기록 저장을 점검했다. 팀 회신 없이 사용할 수 있는 합성 전시와 PC Chrome으로 재현했다. [잔여 계획](../execution-plan/2026-11-07/15-remaining-work-2026-11-13.md)
- **재현** · 추천 작품이 있는 상태에서 관람을 시작하기 전에 영수증 주소를 열면 회원 기록 저장 요청이 한 건 발생했다. 정상 3점 관람에서는 마지막 작품 감상 시간이 포함됐다. 완료 처리와 시간 누적이 별개였고, 시간 누적은 작품 화면의 종료 처리에 맡기고 있었다.
- **수정** · 관람 전·도중 영수증 주소를 열면 현재 작품 안내로 이동한다. 작품을 표시한 때부터 감상 시간을 측정하고, 완료 버튼에서 마지막 구간의 시간과 완료 작품을 함께 기록한다. 지도나 도슨트로 이동할 때는 직전 구간을 누적한다. 상태가 다른 관람이나 추천으로 바뀐 뒤 도착한 누적·완료 요청은 방문 ID·추천 세대·현재 작품을 확인해 거절한다. 이전 버전의 미완료 영수증이 브라우저 캐시에 남았으면 완료 작품 목록으로 새 영수증을 만든다. 서버에 이미 저장된 기록의 중복·충돌 규칙은 기존 계약을 따른다.
- **자동 검수** · 프론트 40건과 타입 검사를 포함한 프로덕션 빌드 통과. 완료 처리에서 이전 감상 구간을 합산하고, 동일 작품 중복 완료 및 이전 관람의 종료 처리를 막는 회귀를 기존 상태 검사에 추가했다.
- **브라우저 검수** · 합성 API와 360px 회원·412px 비회원 Chrome에서 네 조건 통과. 관람 전·도중 직접 접근은 저장 0건, 3점 관람은 지도 복귀와 두 번째 작품 안내 재진입 후 순서 유지, 연속 클릭에도 한 작품씩 완료, 마지막으로 본 작품의 시간과 영수증 표시 일치를 확인했다. 회원은 이전 미완료 캐시를 채워 둔 상태에서 3점 전체로 저장했고 새로고침하면 동일한 방문 ID와 저장 본문을 다시 사용했다. 비회원은 기록 저장 요청이 없었다. 영수증 재해석과 PNG 회귀 6조건도 통과했다.
- **재실행** · `npm --prefix frontend run build`로 빌드하고 `npm --prefix frontend run preview -- --host 127.0.0.1 --port 5219`로 실행한다. `ARTI_REVIEW_BASE=http://127.0.0.1:5219`와 설치된 Playwright 모듈 경로 `PLAYWRIGHT_MODULE`을 지정한 뒤 `node frontend/tests/visitCompletion.browser.cjs`를 실행한다.
- **남은 확인** · 갤럭시·두 번째 기기의 뒤로가기와 HTTPS 공유는 묶음 실기기 검증에서 확인한다. 팀 도판·문안 검수, 운영 조건과 카카오 앱 실연동, 팀원 프론트 후속 인수는 각각 기존 담당자 확인 후 진행한다.
