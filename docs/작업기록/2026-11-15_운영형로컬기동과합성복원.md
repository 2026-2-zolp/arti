# 11/15 운영형 로컬 기동과 합성 백업 복원

- **검수 기준** · `dev/임준억` `dd8b5a3`의 `compose.yaml`, `frontend/Dockerfile.static`과 `frontend/nginx.static.conf`를 사용했다. 빈 DB는 `arti-ops-clean-1115`의 5230, 복원 DB는 `arti-ops-restore-1115`의 5231로 각각 시작했다. 두 환경은 DB와 미디어 볼륨을 따로 사용한다. [운영 구성과 예산 결정안](../operations/W12_운영구성과예산결정안.md)
- **프록시** · Vite에서 빌드한 정적 자산을 Nginx에서 제공했다. `/`, `/mypage`, `/admin/members`, 과거 영수증 주소의 직접 진입과 해시가 붙은 JS 자산을 확인했다. 같은 주소의 `/api/ready`는 Django의 PostgreSQL 준비 응답 200과 요청 ID를 반환했다. 미등록 API는 JSON 404, 익명 관리자 조회는 401이었다. Nginx만 `127.0.0.1`에 바인딩됐고 Django와 DB는 Compose 네트워크에서 연결됐다.
- **스키마** · 빈 PostgreSQL 17에서 별도 `migrate` 서비스가 ARTI 6개와 Django contenttypes 2개를 적용한 뒤 API가 기동했다. 복원본에는 같은 이력이 있어 마이그레이션 작업이 추가 적용 없이 정상 종료했다. 두 환경에서 `migrate --check`와 `makemigrations --check --dry-run`이 통과했다.
- **복원과 미디어** · 기존 합성 `pg_dump -Fc`를 테이블이 없는 DB에 단일 트랜잭션으로 복원했다. 계정 3개, 관람 2건, 반응 2건의 행 내용이 원본 합성 DB와 일치했다. 새 미디어 볼륨에 합성 PNG 두 파일을 풀고 앱 UID/GID 10001을 적용했다. 두 파일의 SHA-256이 원본과 일치했다. 프록시를 통해 공개 PNG는 일반 경로 200, 비공개 PNG는 일반 경로 404와 관리자 경로 200을 확인했다.
- **PC 브라우저** · 복원 주소에서 회원 2명이 각각 새로 로그인해 마이페이지에서 과거 영수증을 한 건씩 열었고 새로고침 후에도 표시됐다. 관리자 화면에는 회원별 관람기록이 한 건씩 나타났고, 관리자 상세 API가 같은 영수증 데이터를 반환했다. 반응 사유와 체류 시간도 일치했다. 다른 회원의 영수증 접근은 403으로 막혔다. 이번 검수에서 수정이 필요한 제품 결함은 재현되지 않았다.
- **검수 범위** · 로컬 HTTP, 내부 PostgreSQL과 합성 미디어 볼륨을 확인했다. 대상 호스트의 HTTPS, 외부 DB TLS, 배포 후 복귀는 운영 환경 결정 후 검증한다. 확대·축소와 실기기 검증은 보류 중이다.

## 재현 순서

1. 저장소 루트에서 Compose 2.35.1 기준으로 `compose.yaml`에 검수용 오버레이를 붙인다. 오버레이에서 `services.api.ports`는 `!reset []`로 비우고, `web`의 빌드 컨텍스트는 `./frontend`, Dockerfile은 `Dockerfile.static`으로 잡는다. `web`은 `api`가 healthy일 때 시작하고 로컬 포트만 컨테이너 80에 연결한다.
2. 검수용 DB 암호와 Django 비밀키는 Git 제외 환경에 둔다. `ARTI_ENV=production`과 `ALLOW_TEST_FIXTURES=false`로 설정한다. 빈 DB 프로젝트에서 `docker compose up -d --build --wait web`에 두 Compose 파일과 프로젝트 이름을 지정해 기동한다. `migrate` 로그와 Nginx 주소의 `/api/ready`를 확인한다.
3. 별도 프로젝트에서 DB만 먼저 시작하고 공개 스키마에 테이블이 0개인지 확인한다. 합성 덤프를 `pg_restore --exit-on-error --single-transaction --no-owner --no-acl`로 복원한다. API가 쓰는 빈 미디어 볼륨에 백업 목록의 두 파일을 풀고 해시와 소유권을 대조한다. 같은 정적 웹 이미지를 사용해 복원 프로젝트를 시작한다. [기존 백업·복원 명령](../execution-plan/2026-11-07/records/backup-restore/2026-11-09/commands.md)
4. 복원용 Nginx 주소에서 익명·회원·관리자 세션을 각각 열어 API와 화면을 대조한다. 복원 전후 DB 행 수, 미디어 해시, 회원 영수증과 관리자 목록·상세의 일치 여부를 남긴다. [시연·복구 체크리스트](../operations/2026-11-11_main_시연복구체크리스트.md)
