# 11/15 AI 도슨트 평가 하네스

- **입력** · 기존 기준선의 합성 작품·질문 12개와 보완 라운드에 저장된 대화 이력을 재사용했다. 원래 실행기에 쓰였던 DRF `APIClient`와 제품 `/api/artworks/:id/ask` 경로를 유지했다. 각 실행은 이전 회차의 모의 답변을 다음 입력으로 넘기지 않고, 보존된 이력을 그대로 재생한다. [기존 프로토콜과 실행기](../execution-plan/2026-11-07/records/docent-baseline-2026-11-09/README.md)
- **동일 입력 재생** · 합성 PostgreSQL과 루프백 HTTP 제공자로 12개를 두 번 실행했다. 24개 요청이 200을 반환했고, 사례별로 제공자에게 전송한 본문 SHA-256이 두 회차에서 일치했다. 요청한 작품, 원문, 질문, 대화 이력과 서버가 구성한 진입 맥락도 대조했다.
- **출처 참조** · 가이드·원문·요약과 맥락 없는 질문에서 작품 ID, 출처 버전, 근거 종류와 리비전을 검사했다. 모의 제공자가 끼워 넣은 다른 작품의 출처는 응답에 포함되지 않았다. 콘텐츠 버전이 다르면 409가 반환됐고 제공자 호출은 0회였다.
- **실패 뒤 재시도** · 제공자 500은 API 502, 제공자 429는 API 429 및 `Retry-After: 30`, 루프백 읽기 타임아웃은 API 504였다. 각 실패의 첫 요청은 제공자를 한 번만 호출했다. 사용자 재시도에 해당하는 두 번째 API 요청은 동일한 본문으로 200과 올바른 출처 참조를 반환했다. 429의 안내 시간을 확인했고, 모의 제공자에서 재시도 가능 상태를 재현했다.
- **검수 범위** · 작품·관람기록·반응 DB 행을 호출 전후 대조했다. 타임아웃 시험의 소켓 제한은 0.5초로 줄였다. 이번 결과는 제품 API 계약과 복구 경로의 검증이다. 실제 모델 답변의 사실성·이해도와 브라우저의 조작 검수는 후속이다. 외부 모델 호출은 0회였다.
- **회귀 결과** · PostgreSQL에서 하네스 3건과 기존 제공자 테스트 11건이 통과했다. Django 전체 177건을 실행한 첫 회차에서 기존 가입 동의 시각 검사가 한 번 실패했다. 저장 시각이 요청 전 시각보다 약 0.54초 앞서 있었다. 원인은 재현되지 않았고, 가입 동의·하네스·제공자 테스트를 묶어 재실행한 22건은 모두 통과했다.

## 실행

격리 PostgreSQL을 연결한 Django 테스트 환경에서, `backend-django` 디렉터리 기준으로 실행한다. 테스트 컨테이너를 쓰는 경우 Django와 `docs`가 위치한 저장소 전체를 같은 경로 아래에서 읽을 수 있어야 한다.

```powershell
$env:ARTI_DOCENT_REPLAY_REPORT = '1'
python manage.py test arti.tests.test_docent_harness arti.tests.test_provider --noinput -v 2
```

`ARTI_DOCENT_REPLAY_REPORT`를 켜면 프로토콜 해시, 사례 ID, 라운드, 결과 코드, 출처 참조, 제공자 요청 해시와 소요 시간이 JSON으로 출력된다. 모의 제공자의 문구와 합성 시험 정보로 결과를 분류하며 키나 요청 원문은 출력하지 않는다. GitHub Actions의 Django 전체 회귀에서도 같은 세 테스트가 발견된다. [하네스 코드](../../backend-django/arti/tests/test_docent_harness.py)

## 팀 검수 전달본

보관한 보완 라운드의 질문·답변 12건을 작품 근거, 실제 이력, 출처 버전과 함께 한 문서에 정리했다. 작성자 외 검수자는 기존 자체 점수를 보기 전에 제출표를 작성한다. 질문 세트 SHA-256, 사례별 입력·응답, 네 후속 응답의 실제 전달 이력을 원본과 대조했다. 이번 전달본은 저장 자료를 읽어 작성했으며 실제 모델 호출과 실기기 검증은 보류했다. [팀 검수용 평가표](../review/docent-2026-11-15/README.md)
