## 검증단 관점과 통과 결과

- **방문자.** Chrome 터치 에뮬레이션 360×740·390×844에서 각각 다섯 쌍 선택 → 취향 확인 → 30분 추천 → 도면 지도 → 세 작품 → 도슨트 → 영수증을 완주했다. 지도·감상·질문 실패·질문 성공·영수증의 문서 폭이 각각 화면 폭 이내였고, 지도에 도면 이미지가 표시됐다.
- **기술·시니어.** 브라우저 네트워크 지연 140ms와 도슨트 진입 시 작품 응답 지연 1.2초를 적용했다. 질문 작성 중 전송이 비활성화되고 작품이 도착한 뒤 활성화되는지 확인했다. 루프백 제공자의 첫 500이 Django 502로 전달됐다. 질문 입력이 남고 실패한 턴이 대화에 들어가지 않았다. 같은 질문을 재시도하면 응답 대기 표시와 버튼 잠금이 나타났고, 200 응답에서 서버가 같은 관람가이드 질문과 작품 출처를 반환했다. 원래 작품의 관람가이드로 돌아왔다.
- **데이터·운영.** 전용 PostgreSQL 18과 합성 계정·미디어를 사용했다. 각 화면 크기에서 영수증 최초 201·새로고침 200의 요청·응답이 일치했고, 계정당 관람과 반응이 각각 한 건이었다. DB 접속 불가와 마이그레이션 전에는 API 상태 200·DB 준비 503, 이관 뒤에는 DB 준비 200을 확인했다. 루프백 제공자가 뜨기 전에도 설정이 유효하면 `configured`가 반환됐다. 키·모델 이름·주소 노출과 진단 요청의 외부 호출을 회귀로 검사했다.
- **팀·교수·외부 평가위원.** 이번 결과는 합성 전시, 데스크톱 Chrome의 모바일 터치 에뮬레이션, 루프백 도슨트 제공자에서 얻었다. 실제 휴대폰과 승인 콘텐츠의 검증은 대기다. 화면 키보드, 브라우저 뒤로 가기, 음성 읽기, 영수증 이미지의 OS 저장·공유는 실기기 확인 항목이다.

최종 회귀는 Django 152건, 프론트 34건, 빌드·타입 검사, Django 설정·이관 변경 검사와 계획 가드레일 32건을 통과했다. Windows에서 공개 이미지 테스트가 파일을 열어 둔 채 종료되는 문제를 찾아, 테스트가 스트림을 읽고 PNG 헤더까지 확인하도록 고쳤다. 모바일 시험의 합성 데이터와 브라우저 결과는 Git 제외 경로 `data/private/mobile-rehearsal-20261111`에 보관했다.

실기기 다음 단계는 Android Chrome과 iOS Safari에서 같은 여정, 화면 키보드와 내보내기를 확인하고 작성자 외 관리자 기기에서 위치·가이드 변경이 관람 화면에 반영되는지 대조하는 것이다. 운영 쪽은 목표 환경에서 DB 준비·도슨트/작품 분석 호출·백업 복원을 확인한다.
