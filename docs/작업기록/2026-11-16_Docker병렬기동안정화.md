# 11/16 Docker 병렬 시험 기동 안정화

`fe72c92` 운영 검수에서 팀 PC 브라우저와 배포 전 검사를 함께 실행하면 Docker 기본 브리지 주소 풀이 차면서 Compose 원본 또는 모의 카카오 HTTPS 기동이 중단됐다. Windows에서 모의 HTTPS 런처를 CRLF로 복사했을 때는 Docker의 Linux `sh -ec`가 줄 끝의 `\r`을 명령으로 읽어 API가 종료 127, Nginx 준비 요청이 502였다. [기존 운영 인수 결과](2026-11-16_fe72c92_운영인수재현.md)

## 적용

- Compose 원본과 모의 HTTPS 모두 공용 시험 네트워크 함수로 실행별 브리지를 먼저 요청한다. Docker가 기본 주소 풀 부족을 보고할 때만 명시 `/28`과 동적 `/29`를 요청한다. 서브넷 중첩은 최대 여덟 번까지 다른 주소로 재시도하며 권한·이름·그 밖의 Docker 오류는 실패로 반환한다.
- 후보 마이그레이션 실패와 Nginx API 주소 변경 시험은 기존대로 명시 서브넷을 사용한다. 동적 범위 바깥의 API 주소 두 개를 유지하고 각 자원은 자기 실행의 Compose와 Docker 네트워크에 연결한다.
- 새 네트워크에 소유 라벨을 붙인다. 제거 전에 발급받은 ID로 라벨을 읽어 일치한 시험 브리지만 정리한다. 모의 HTTPS의 Gunicorn을 띄우는 셸 명령은 Linux `sh`에 넘기기 전에 CRLF를 LF로 바꾼다. [공용 브리지 함수](../../scripts/artiTestNetwork.ps1) · [운영 검사기](../../scripts/runOpsPreflight.ps1) · [모의 HTTPS 실행기](../../frontend/tests/runKakaoNginx.browser.ps1)

## 재현

```powershell
pwsh -NoProfile -File ./scripts/tests/test_arti_docker_network.ps1
```

모의 Docker 검사에서 기본 할당 1회, 기본 주소 풀 부족 후 명시 할당, 명시 서브넷 중첩 재시도와 제한, 권한 오류에서 중단, 다른 실행 소유 네트워크의 삭제 거부를 확인했다. 실제 병렬 검수는 두 PowerShell에서 저장소 루트 기준으로 각각 실행한다.

```powershell
pwsh -NoProfile -File ./scripts/runOpsPreflight.ps1 -Revision fe72c92 -HttpsPort 5625
pwsh -NoProfile -File ./scripts/runOpsPreflight.ps1 -Revision fe72c92 -HttpsPort 5626
```

검사 결과는 각 `data/private/arti-preflight-<실행ID>/result.json`에 남는다. `source-startup.networkAllocation`이 `default` 또는 `explicit`이며 모의 HTTPS 할당은 `[https-network]`에 표시된다.

## 실제 검수 결과

| 실행 | 원본 할당 | 모의 HTTPS 할당 | 복원·프록시·로그 | 정리 |
| --- | --- | --- | --- | --- |
| `arti-preflight-dea1e47b48e7` · `5625` | 기본 `192.168.240.0/20` | 명시 대체 | 통과 | 통과 |
| `arti-preflight-750942c371d7` · `5626` | 명시 대체 `10.247.225.0/28` | 명시 대체 | 통과 | 통과 |

두 원본이 동시에 기동한 시점에 둘의 브리지 ID와 소유 라벨이 각각 다른 것을 조회했다. 양쪽 모두 같은 영수증 한 건의 복원과 본인·타회원·비회원·관리자 `200/403/401/200`, 같은 Nginx의 `200→502→200`, 모의 카카오 콜백 `302/502`와 비노출 로그를 확인했다. 두 실행 전의 Docker 네트워크 ID·이름 전체를 비교해 기존 네트워크가 모두 남은 것을 확인했다.

모의 HTTPS 런처는 전 줄을 CRLF로 바꾼 임시 사본으로도 실행했다. `fe72c92` 이미지에서 Nginx 준비, Chrome의 연결 취소·만료 콜백 거절·기존 이메일 계정과 저장 V2·영수증 보존, 정상·장애 콜백과 로그까지 통과했다. 임시 사본과 시험 이미지 태그를 정리했다.
