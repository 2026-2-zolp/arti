# 11/17 관리자 통합과 시연 후보 검수

## 관리자 통합

- [PR #41](https://github.com/2026-2-zolp/arti/pull/41)은 `main` `9111fb1` 위에 동섭님 변경 두 건을 옮기고 A-04 작품명 상세 링크를 추가한 검토본 `438409d`다. 작품명 Enter 이동, 기존 행 클릭, 체크박스 선택을 PC Chrome에서 각각 실행했다. 관리자 분석·동시 편집과 관람·도슨트·영수증 Chrome을 포함한 [CI 15개](https://github.com/2026-2-zolp/arti/actions/runs/43904513574)가 모두 통과했고 `b8f4c2e`로 병합됐다.
- 일괄 확정은 PR 프론트와 로컬 `8fa748f` Django, 별도 합성 PostgreSQL로 검수했다. A 탭에서 요약 제안 작품 두 점을 체크해 확정 대화상자를 열고, B 탭에서 두 번째 요약을 수정·저장했다. A 탭의 이전 버전 전송은 `409 VERSION_CONFLICT`였고 두 작품 모두 제안 상태를 유지했다. A 탭에서 최신 자료 다시 조회 → 내용 재검토 → 다시 선택해 보냈을 때 `200`으로 두 점만 확정됐고 B 탭의 최신 요약이 유지됐다.
- 현재 시연용 DB 두 곳에서 승인 행 12건과 15건의 출처·해설을 읽기 전용으로 검사했다. 빈 값과 공백만 있는 값은 0건이었다. 각 DB는 합성 작품만 포함했다. 실제 개발 DB는 원본 볼륨을 읽기 전용으로 연결한 네트워크 없는 PostgreSQL 메모리 복제본에서 조회했다. 작품 25점 모두 출처 확인 상태였고 승인 행은 0건이었다. 원본 DB는 중지 상태를 유지했다.

## 관람 PC 재현

1. 위 PR 프론트 빌드와 별도 합성 PostgreSQL에서 V2를 켠다. [팀 PC 시연·복구 절차](../operations/2026-11-11_main_시연복구체크리스트.md)의 합성 전시 `fixture-ex01`을 사용한다.
2. V2 5쌍 비교 → 추천 → 지도 → 감상 순으로 진행한다. PR Chrome에서 좁은 화면 회귀가 통과했다. 결합 로컬 빌드에서는 3·5·7점 추천에서 후보 부족·무좌표·비공개 조건을 재현해 각각 2·4·6점으로 이어졌고 지도·영수증 순서가 일치했다. 도면 변경과 다음 작품 비공개 뒤에는 공개 작품으로 이어졌다.
3. 모의 도슨트에서 가이드·힌트·쉬운 요약과 재시도를 확인한다. 영수증은 원 계정 재로그인 후 원래 관람 ID로 회원 기록 1건, 다른 계정으로 로그인 시 저장 요청 0건, 비회원 저장 요청 0건을 확인한다. 최종 팀 재현에서는 같은 빌드로 확대 복귀·PNG와 복원 후 권한도 회신에 남긴다.
