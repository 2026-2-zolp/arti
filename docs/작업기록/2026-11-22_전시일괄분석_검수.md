# 전시 일괄 분석과 진행 패널

작품 관리에서 전시를 선택하고 전시 일괄 분석을 요청한다. 검수 완료 원문이 있는 작품의 미확정 항목을 PostgreSQL 작업으로 등록한다. 같은 전시에 진행 중인 작업이 있으면 그 작업을 보여준다. 개별 분석과 같은 제안 저장 로직을 사용하며, 확정된 항목은 건너뛴다. 작업 등록 이후 원문·도판이 바뀌거나 워커가 작업 실행권을 잃은 경우 이전 결과의 저장을 막는다.

관리자 우하단 패널은 열기·접기를 지원한다. 진행 표시의 분자는 완료와 실패를 합한 처리 건수며 실패 건수는 따로 표시한다. 개별 원형 상태는 대기·분석·감정 대기·완료 ○·실패 ×다. 먼저 처리된 제안은 작품 링크에서 검수한다. 행의 재시도는 해당 작품에만 적용된다. 전시 처리가 끝난 뒤 상단 재시도는 실패한 작품을 다시 등록한다. 원문이 그대로면 실패한 분석 항목만 다시 실행한다.

## 로컬 구성

합성 검수용 환경 파일에 `ARTI_BACKGROUND_BATCH_ANALYSIS=true`를 설정하고 Compose에서 `--profile artwork-batch`를 켠다. DB 마이그레이션은 `0026_artwork_analysis_batch`다. 기존 감정 분리도 켠 환경에서는 `--profile background-analysis`로 감정 워커를 같이 기동한다. Django를 호스트에서 실행하면 동일 환경 설정으로 `python manage.py analyze_artwork_batches --watch`를 별도 프로세스에서 실행한다.

## 검수

- 합성 전시 1곳의 4점으로 Chrome을 검수했다. 분석 중 작품 관리에서 전시 관리로 이동하고 새로고침했다. 두 번째 브라우저 탭의 운영 로그에서도 동일 작업을 열었다.
- 첫 작품의 감정이 대기 중일 때 가이드 제안 링크를 통해 작품 상세를 열었다. 실패 3건 중 한 작품만 재시도한 뒤, 상단 재시도로 남은 실패 2건만 대기열에 등록했다. 요청 본문과 워커의 실제 호출 대상 및 항목을 대조했다.
- 기존 공개 요약은 분석 전후 일치했다. 합성 PostgreSQL에서는 이미 확정한 요약·태그·감정을 유지한 채 가이드만 생성했다. 원문 변경과 워커 실행권 만료 시 오래된 제안의 저장도 차단했다. `test_batch_analysis`와 `test_emotion_jobs` 8건이 통과했다.
- `frontend/tests/adminBatchAnalysis.browser.mjs`와 기존 `adminConcurrent.browser.mjs`, 프론트 단위 테스트 80건이 통과했다. 새 흐름은 모의 모델 응답으로 검수했다.
