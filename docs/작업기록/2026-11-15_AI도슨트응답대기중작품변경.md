# 11/15 도슨트 응답 대기 중 작품 변경

- **범위** · `main` `67c74c4`에서 시작했다. PC Chrome의 프로덕션 빌드, 취향 V2, 합성 전시, 격리 PostgreSQL, 실제 Django API와 루프백 모의 제공자를 사용했다. 제공자가 질문을 받은 것을 확인한 뒤 관리자 저장이나 관람 이동을 완료하고 응답을 풀었다.
- **관리자 원문 갱신** · 첫 대화가 있는 작품에서 두 번째 질문을 보냈다. 관리자가 편집 API로 원문을 갱신하고 재승인한 후에도 수정 전에는 이전 원문을 담은 답변이 200으로 돌아왔다. Django가 응답을 내보내기 직전에 같은 자료 버전이 여전히 공개 중인지 조회하도록 수정했다. 갱신된 버전과 공개가 중단된 작품의 진행 중 답변은 답변·출처 본문 없이 409 `CONTENT_CHANGED`로 반환한다.
- **브라우저 복구** · 409 안내가 뜨면 도슨트는 해당 버전의 대화와 관찰 질문을 화면에서 내린다. 작품 화면으로 돌아가 새 원문을 읽고 도슨트에 재진입하면 질문 초안이 남는다. 같은 질문을 다시 보냈을 때 이력은 비어 있고 답변과 출처는 새 원문 버전을 사용했다.
- **다음 작품 이동** · 첫 작품 답변 대기 중 초안을 다르게 적고, 작품으로 돌아갔다 다시 진입해 복구를 확인했다. 요청이 아직 대기하는 동안 관람 버튼으로 두 번째 작품 도슨트에 들어갔다. 그때 풀어 준 첫 작품의 답변은 이전 화면과 두 번째 작품 대화에 저장되지 않았고, 두 번째 작품의 새 질문에는 그 작품의 출처만 반환됐다. 기존 관람은 완료한 작품으로 돌아가는 버튼이 없어, 이동 후 초안 저장 범위는 같은 관람의 첫 작품 체크포인트를 시험 코드로 복원해 다시 확인했다.
- **검증 경계** · 브라우저의 콘텐츠 갱신은 인증된 관리자 편집 API를 사용했다. 배포된 앱이나 실제 모델·실기기 호출은 보류했다. 모의 제공자의 대기 제어 엔드포인트는 합성 검수용 서버에서 환경 변수를 켰을 때만 동작한다.
- **결과** · 새 Chrome 시나리오 2건, 기존 모의 제공자 재시도 3건과 관람 Chrome 회귀 14건, 프론트 단위 테스트 43건, Django PostgreSQL 전체 178건과 프로덕션 빌드가 통과했다.

## 재현

[기존 브라우저 하네스](2026-11-15_AI도슨트브라우저복구.md#재현)의 격리 DB·미디어와 프리뷰 절차를 따른다. 서버 실행 전에 같은 합성 DB에 `bootstrap_admin --login-id docent-race-admin --name '합성 관리자'`로 관리자를 만든다. `ARTI_BOOTSTRAP_PASSWORD`에 이 검수만을 위한 비밀번호를 넣는다.

하네스 서버의 `docker run`에 `-e ARTI_DOCENT_RACE_TESTS=1`을 추가한다. 별도 PowerShell에서 같은 합성 관리자 비밀번호, `ARTI_DOCENT_RACE_TESTS=1`, 해당 프리뷰의 `ARTI_REVIEW_BASE`를 설정하고 `node frontend/tests/docentRetry.browser.cjs`를 실행한다. 스크립트가 편집한 자료는 해당 시나리오가 끝나면 합성 원문과 검수 상태로 복원한다. 버전은 편집 API 계약에 따라 증가한다.
