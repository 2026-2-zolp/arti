## 검수 결과

- `f9d1371f1df207c763c497f46af8f59cd1ee0d64`를 Git으로 아카이브해 Django/Gunicorn과 정적 Nginx를 빌드했다. Docker Compose v2.35.1, PostgreSQL 17.11, PC Chrome을 사용했다. `arti-ops-startup-f9d1371`에 전용 DB·미디어 볼륨을 만들고 Nginx만 `127.0.0.1:5601`에 열었다. 도슨트와 작품 분석은 `disabled`였다.
- 백업을 테이블 0개인 DB에 복원하고 별도 미디어 볼륨에 두 합성 PNG를 풀었다. 복원 전후 원본 DB 덤프와 미디어 tar의 SHA-256은 일치했다. 두 PNG의 SHA-256도 복원 직후와 API 조회 후에 일치했다. 합성 회원·관리자 비밀번호는 이 복원본에서만 시험용으로 재설정했다. [백업 생성과 복구 이력](2026-11-16_Compose기동실패와Nginx복구.md)

## 다른 PC에서 재현

1. [시연·복구 체크리스트](../operations/2026-11-11_main_시연복구체크리스트.md#1115-운영형-로컬-시연-재현)에서 새 합성 백업과 원본·복원 프로젝트 설정을 만든다. 검수할 커밋의 소스를 별도 경로에 풀어 API와 웹을 빌드한다. 커밋과 이미지 이름은 아래와 같이 함께 기록한다.

```powershell
$opsCommit = git rev-parse f9d1371
$opsSuffix = Get-Date -Format 'yyyyMMddHHmmssfff'
$opsDir = Join-Path (Get-Location) "data/private/ops-build-$opsSuffix"
New-Item -ItemType Directory -Path $opsDir | Out-Null
git archive --format=zip --output="$opsDir/source.zip" $opsCommit
Expand-Archive -LiteralPath "$opsDir/source.zip" -DestinationPath "$opsDir/checkout"
$apiTag = "arti-ops-$opsSuffix-api:local"
$webTag = "arti-ops-$opsSuffix-web:local"
$revisionLabel = "org.opencontainers.image.revision=$opsCommit"
docker build --label $revisionLabel --tag $apiTag "$opsDir/checkout/backend-django"
docker build --label $revisionLabel --tag $webTag --file "$opsDir/checkout/frontend/Dockerfile.static" "$opsDir/checkout/frontend"
docker image inspect --format '{{.Id}} {{index .Config.Labels "org.opencontainers.image.revision"}}' $apiTag $webTag
```

2. 체크리스트의 복원 명령에서 이미지를 지정하는 Compose 파일을 추가한다. `api`와 `migrate`는 `$apiTag`, `web`은 `$webTag`를 `image`에 지정한다. 백업을 빈 DB·볼륨에 복원한 후 기존의 API 이미지 빌드 단계를 건너뛰고 `docker compose @restore up -d --no-build --pull never --wait web`으로 기동한다. `@restore`는 새 프로젝트명·환경 파일·Compose 파일 목록을, `$restoreUrl`은 그 프로젝트의 루프백 웹 주소를 가리킨다.

```powershell
foreach ($service in @('api', 'migrate', 'web')) {
    $container = docker compose @restore ps -aq $service
    docker inspect --format '{{.Image}} {{.State.Status}} {{.State.ExitCode}}' $container
}
docker compose @restore exec -T api python manage.py migrate --check
docker compose @restore exec -T web nginx -t
Invoke-RestMethod "$restoreUrl/api/ready"
```

3. 위 출력의 실행 이미지 ID와 빌드 ID를 대조한다. 복원한 프로젝트의 운영 모드에서 아래 명령이 종료 1과 `Test fixtures require development/test`를 반환하는지 확인한다. 적재 전후 전시·작품·조사풀·조사항목 수를 대조하고, 회원·관리자 영수증 한 건과 미디어 접근을 실제 웹 주소로 다시 확인한다. [복원 후 계정별 접근 확인](../operations/2026-11-11_main_시연복구체크리스트.md#복원-후-영수증-접근-권한-확인)

```powershell
& {
    $PSNativeCommandUseErrorActionPreference = $false
    $result = docker compose @restore exec -T -e ALLOW_TEST_FIXTURES=true api python manage.py load_test_fixture 2>&1
    if ($LASTEXITCODE -ne 1 -or ($result -join ' ') -notmatch 'Test fixtures require development/test') {
        throw '운영 모드의 합성 자료 적재 차단을 확인하지 못했습니다.'
    }
}
```

회신에는 소스 커밋, 빌드와 실행 이미지 ID, DB·Compose·브라우저 버전, 준비 응답, 적재 차단 전후 집계, 영수증·미디어 접근 결과, 백업 SHA-256을 적는다. 새로 빌드한 환경의 이미지 ID는 그 환경에서 실행한 컨테이너와 비교한다. 다른 PC에서 이미 검수한 이미지 그대로 실행해야 하는 경우에는 이미지 파일의 SHA-256과 로드 후 이미지 ID를 함께 대조한다.
