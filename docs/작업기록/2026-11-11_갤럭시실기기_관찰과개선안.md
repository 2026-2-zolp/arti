# 2026-11-11 · 갤럭시 실기기 관찰과 개선안

준억이 **갤럭시 S24+ · One UI 8.5 · Android 16 · Chrome**에서 합성 전시를 직접 열었다. 회원가입부터 취향 조사, 추천·지도, 감상, 도슨트, 영수증 저장, 마이페이지, 저장 취향 재사용까지 확인했다. 아래는 직접 사용하면서 남긴 22개 항목과 이후 코드·기록·PC 브라우저를 GPT와 함께 확인해 정리한 제안이다. 제안은 담당과 적용 범위를 맞추기 위한 초안이다.

| 2 | 회원가입의 전체 동의 아래 이용약관과 개인정보 수집·이용 항목은 있었지만 본문을 열 수 없었다. 기존 화면인지 확인하고 싶었다. | 11/6 동섭님 통합본에도 체크박스가 있었다. 확인한 노션과 저장소에서는 연결할 원문을 찾지 못했다. 외부 공개 준비 과정에서 팀이 실제 수집·이용 내용을 정리하고, 가입 화면에서 두 본문을 읽을 수 있게 한다. |

| 5 | ‘조사 근거 다시 불러오기’를 누르자 상단에 진행 표시와 같은 이름의 버튼이 나타났다가 사라지면서 화면이 밀렸다. | 느린 네트워크에서 카드가 128px 내려갔다 복귀했다. 기존 카드와 선택을 유지하고, 필요한 복구 동작은 같은 위치에 표시한다. |
| 6 | 미리보기가 같은 태그를 아래에 한 번 더 보여준다. ‘결정’을 누르면 선택한 태그를 중심으로 정리하고, 계정 저장과 이번 관람 적용을 더 이해하기 쉽게 만들면 좋겠다. 확정 시점에 근거 갱신 버튼도 계속 보였다. | 선택을 마치면 적용할 태그와 변경만 보여준다. 이번 관람 적용을 주 동작으로 두고 계정 저장 여부는 그 자리에서 선택하게 한다. 근거 갱신은 오류나 버전 변경을 해결할 때 표시한다. |
| 7 | 화면이 빠르게 끊겨 넘어가는 느낌이 들었다. | 우선 작품 선택·확대처럼 전환의 의미가 분명한 화면에서 짧은 효과를 비교한다. 이미지 로딩 중에도 비교 영역 크기를 유지하고, 움직임 줄이기 설정을 따른다. |

## 추천 경로와 작품 감상

| 번호 | 갤럭시에서 확인한 내용과 준억의 생각 | GPT와 검토한 결과·제안 |
| --- | --- | --- |
| 8 | 추천 경로의 지도와 매핑을 더 다듬어야 한다고 느꼈다. 작품에서 본 그림이 지도 배경에도 나와 실제 설계인지 확인하고 싶었다. | 합성 시험에서 같은 이미지 파일을 작품과 도면에 지정했다. 서비스는 전시에 등록된 도면을 읽는다. 실제 도면·입구·작품 위치가 정해지면 매핑과 순서를 다시 확인한다. |
| 9 | ‘다음 작품 안내’를 누를 때마다 전체 경로 화면으로 돌아갔다. 이동에 지도는 필요하지만 매번 전체 화면을 봐야 할지 검토하고 싶었다. | 다음 작품의 썸네일·위치·순서를 먼저 보여주고, 필요할 때 전체 지도를 여는 시안을 비교한다. |
| 10 | 작품 확대 화면에 그림만 바로 나타났다. 미술관 프레임이나 서서히 커지는 효과가 어울리는지 확인하고 싶었다. | 작품 표시 면적과 확대·닫기 조작을 먼저 확보한다. 프레임과 짧은 확대 전환은 같은 그림으로 비교한다. |
| 11 | 작품해설과 가이드가 짧은 합성 텍스트라 내용 품질을 판단하기 어려웠다. | 검수된 실제 작품의 해설·요약·가이드가 준비되면 같은 화면에서 읽기와 도슨트 연결을 확인한다. |
| 12 | 음성이 재생됐지만 목소리가 기계적이고 전형적으로 들렸다. 속도를 선택하는 조작도 보이지 않았다. | 현재 브라우저 기본 한국어 TTS와 속도 1을 사용한다. 속도 선택을 검토하고, 같은 검수 해설로 기본 음성·한국어 합성 음성·직접 녹음을 들어본다. |
| 13 | 관람가이드의 ‘이 질문으로 내 생각 이야기하기’와 ‘힌트 보기’가 더 자연스럽게 이어지면 좋겠다고 느꼈다. | 관찰 질문을 먼저 읽게 하고, 힌트를 펼치거나 해당 질문을 도슨트에 이어갈 수 있게 버튼의 순서와 문구를 다듬는다. |
| 14 | 좋아요나 싫어요의 이유를 고르자 이유 칩이 같은 줄에 나타나 버튼 위치와 가로·세로 배치가 바뀌었다. | 반응 버튼 위치를 유지하고 이유는 별도 줄에 표시한다. 긴 이유와 이유 편집도 확인한다. |
| 15 | 도슨트는 어떤 질문에도 검증용 응답을 줬다. 추천 질문은 공통 목록으로 보여 작품에 고유한 질문도 있으면 좋겠다. | 합성 제공자에서 대화 연결을 확인했고 실제 응답 품질은 대기다. 공통 질문 일부를 두고, 검수된 작품 설명이나 사용자가 보고 있던 질문을 바탕으로 작품별 질문 1~2개를 제안한다. |

## 영수증, 마이페이지, 계정

| 번호 | 갤럭시에서 확인한 내용과 준억의 생각 | GPT와 검토한 결과·제안 |
| --- | --- | --- |
| 16 | 영수증에서 관람·추천 작품 수가 같았고, 반응 횟수와 제목만 나열된 작품 목록을 개선하고 싶었다. ‘취향 해석 보기’ 버튼이 기본 스타일이었고, 해석은 시험 응답이었다. 도슨트 대화를 해석에 활용하는 방향도 생각했다. 웹에서 한 줄인 ‘따뜻한 색감’은 저장 PNG에서 두 줄로 갈라졌다. | 같은 수는 화면에서 합쳐 보여주고 작품 썸네일 옆에 반응을 표시하는 안을 검토한다. 초기 시나리오에 작품별 QR이 있어 두 집계를 데이터에 유지할 이유가 있다. 해석 버튼은 공통 스타일을 쓰고, 대화 맥락을 넣을 경우 어떤 내용이 들어가는지 보여주고 포함 여부를 고르게 한다. PC에서 320·412px PNG는 한 줄이었다. 칩 내부는 한 줄, 공간이 부족할 때는 칩 전체를 넘기도록 수정한 뒤 같은 갤럭시에서 다시 저장한다. |
| 17 | 관람 완료 후 바로 전시 시작 화면으로 이동했다. 마이페이지나 이어서 둘러볼 곳으로 이동할 선택지가 있으면 좋을지 궁금했다. | 완료 지점에서 회원용 ‘내 관람기록 보기’와 ‘전시 홈’을 함께 제시하는 방향을 검토한다. |
| 18 | 마이페이지에서 과거 영수증을 열고 앱 좌상단 뒤로가기를 누르면 두 화면이 반복됐다. 휴대폰 시스템 뒤로가기를 두 번 눌러 빠져나왔다. | 과거 영수증에서 마이페이지를 새 이력으로 쌓는 동작을 확인했다. 목록에서 들어온 경우와 직접 열었을 경우를 구분해 앱·시스템 뒤로가기 흐름을 검증한다. |
| 19 | 저장된 취향을 이미 보여주는데 ‘취향 미리 확인’을 누르면 같은 태그가 다시 나왔고, 버튼이 카드와 멀리 있었다. ‘취향 수정하기’는 바로 10점 재조사로 이동했다. | ‘이 취향으로 관람 시작’ 한 번으로 진행하고 버전 확인은 내부에서 유지한다. ‘태그만 수정’과 ‘작품 다시 고르기’의 두 경로를 제안한다. |
| 20 | 좋아요 1개와 싫어요 1개를 남겼고, 마이페이지 좋아요 목록에는 좋아요가 나타났다. 목록이 상세 화면에 연결되지 않아 관람 날짜나 상세 맥락이 있으면 좋겠다고 느꼈다. | 좋아요 목록은 다시 보고 싶은 작품을 중심으로 유지하고, 항목에 관람일과 해당 관람 기록 링크를 제공하는 안을 검토한다. 싫어요는 관람기록의 작품별 반응에서 접근할 수 있도록 검토한다. |
| 21 | 비밀번호 찾기 동작과 로그인 화면의 비밀번호 찾기·회원가입 버튼을 확인하고 싶었다. | 현재 재설정 API는 501을 반환한다. 제공 상태가 화면에 명확히 보이도록 하고, 회원가입과 비밀번호 찾기의 버튼 우선순위를 다듬는다. |
| 22 | 전시 첫 화면에도 좌상단 뒤로가기 버튼이 있었다. | 공통 헤더의 기본 동작을 확인했다. 전시 목록에서 진입했을 때와 전시 QR·주소로 바로 열었을 때를 대조해 표시 여부와 돌아갈 위치를 정한다. |

**우선 작업 제안**은 조사 근거 갱신 시 밀림, 영수증 뒤로가기, 반응 버튼 재배치, PNG 줄바꿈을 수정하고, 두 작품 비교의 상하 압축형을 적용해 같은 갤럭시에서 확인하는 것이다. 감상·지도·영수증의 구성과 전환은 프론트 작업 진척을 확인한 뒤 담당을 맞춘다. 실제 작품의 추천·도슨트·음성 품질은 검수 콘텐츠를 넣고 확인한다.
