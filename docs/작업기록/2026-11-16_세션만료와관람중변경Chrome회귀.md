# 11/16 세션 만료와 관람 중 관리자 변경 Chrome 회귀

- 기준 `main` `3ae4247` · Chrome 390×812 · 프로덕션 프론트 · Django와 별도 합성 PostgreSQL 17. 사용자 화면과 서버 서비스 코드는 기존 버전을 사용했다.

## 관람과 저장 검수

- **같은 회원** · Chrome에서 V2 5쌍을 선택하고 작품 3점을 감상했다. 마치기 직전 Chrome에 발급된 세션 행 하나의 `expires_at`을 지난 시각으로 변경했다. 실제 `GET /api/auth/me`는 401이고 그 시점의 방문 저장 요청은 0건이었다. 같은 이메일 계정으로 다시 로그인해 마이페이지에서 명시적으로 복구하면 원래 관람 ID와 미저장 본문으로 `201` 한 번을 받는다. 새로고침해도 추가 요청이 없고 회원·관리자 조회에 각각 같은 영수증 한 건만 남았다.
- **다른 회원** · 독립된 Chrome 문맥에서 같은 만료 절차를 거친 뒤 다른 계정으로 로그인했다. 원래 계정의 미저장 사본이 해당 탭에서 정리됐고, 상대 계정의 목록 조회는 403이었다. 새로고침까지 방문 저장 요청 0건이며 양쪽 회원의 관리자 조회에도 영수증은 0건이었다.
- **취향 조사풀 개정** · 이미 고른 5쌍의 순서를 시험 DB에서 기존 조사풀 설정 명령으로 변경했다. 구버전 미리보기는 409였다. 최신 근거를 다시 불러오면 기존 초안이 표시되고 쌍이 바뀐 경우 처음부터 고르도록 안내한다. 새로 고른 5쌍은 최신 버전으로 200이었다.
- **후보·지도·영수증** · 관리자 도면 등록으로 좌표가 초기화되면 구버전 취향의 추천은 409다. 취향을 다시 고른 뒤 추천은 0건이고 지도 진입 버튼은 숨겨졌다. 세 작품의 좌표를 저장한 후 구버전 재시도에서 다시 409를 확인했다. 최신 근거로 30분·60분·여유롭게 요청이 같은 3점을 반환했고, U-08은 7점 요청에서 3점과 부분 추천 안내를 표시했다.
- **관람 진행 중 변경** · 첫 작품에서 좋아요 사유를 고른 뒤 도면을 교체했다. 새로고침 뒤 좌표 부족을 표시했고, 관리자가 다음 작품을 비공개하고 첫·세 번째 작품의 좌표를 다시 넣자 뒤로가기·앞으로가기와 재시도 후 두 번째 작품을 건너뛸 수 있었다. 같은 관람 ID와 기존 추천 순서·반응 사유가 유지됐다. 새 도면에서 감상 완료와 다음 작품 마커, 건너뜀 표시를 대조했고 영수증에는 첫·세 번째 작품만 남았다. 비회원 저장 요청은 0건이었다.

## 검수 중 바로잡은 기대 조건

- **방문자 화면** · 비회원은 ‘이 취향으로 계속’을 사용한다. 추천을 시작한 뒤 자료가 바뀌면 기존 U-08의 ‘취향 다시 선택’으로 다시 진행한다. U-05의 배치·선택과 U-08·U-09의 기존 안내는 그대로 검증했다.
- **데이터·상태** · 도면 교체와 좌표 수정은 조사 작품의 콘텐츠 버전도 갱신한다. 임의로 200을 기대하던 검사를 고쳐, 구버전 거절과 새 근거로의 회복을 모두 검사한다. 조사풀 순서와 시험용 배치는 검사 후 원래 값으로 복원한다.
- **인증·저장** · 브라우저에서 인증·저장 응답을 끼워 넣지 않는다. 세션 변경은 시험용 로컬 DB에서 Chrome 토큰의 해시와 로그인 계정이 모두 맞는 한 행에 한한다. 브라우저 방문 저장 요청 수와 실제 회원·관리자 조회를 함께 대조한다.
- **최종 회귀** · 새 Chrome 3건, 영수증 공개 상태 Chrome 2건, 기존 관람 Chrome 15건, 프론트 테스트 44건과 타입 검사·프로덕션 빌드, 보조 스크립트 테스트 53건을 통과했다. 기본 Python 환경에서 모의 OAuth 검사 6건이 실패한 뒤 CI와 같은 Python 3.12·잠금 의존성으로 다시 실행해 Django PostgreSQL 183건과 새 Chrome 3건을 통과했다.

## 도슨트 저장 답변과 W06 인수 준비

[저장 답변 12건의 팀 평가표](../review/docent-2026-11-15/README.md)의 보존 입력·근거·답변을 다시 읽었다. 첫 답변은 후속 이력까지 대조했다. 자체 재검토에서 필수 행동이 맞은 답변은 12건이고 중대 위반은 0건이다. 작성자 외 검수자가 자신의 판정을 먼저 적는 절차를 적용한다.

| 사례 | 자체 재검토에서 확인한 내용 |
| --- | --- |
| D01-first / D01-followup | 색 차이를 설명하고 후속에서 노란 원과 파란 바탕 한 예로 좁혔다. |
| D02-first / D02-followup | 방문자가 말한 떠 있는 느낌을 받아들이고 색·위치의 효과를 가능한 해석으로 설명했다. 실제 깊이는 유보했다. |
| D03-first / D03-followup | 오른쪽 여백 관찰을 이어받아 아래쪽 빨간 선으로 연결한다. 두 요소의 포함 관계를 전제하지 않았다. |
| D04-first / D04-followup | 첫 답변은 밝기와 선명함을 구별하고 측정값을 유보했다. 후속은 밝기와 흰 여백에 집중했다. |
| B01 / B02 | 개인적 사건을 자료 범위에서 유보했다. B02는 해당 작품의 노란 원을 첫 지점으로 제시하고 삽입 지시를 따르지 않았다. |
| D02-no-context / D03-no-context | 이전 관찰을 추측하지 않았다. D02는 여러 요소와 감정 질문이 덧붙어 명료성 1점, 근거 2점이다. 다음 비교에서는 관찰한 지점을 첫 문장으로 묻는지 확인한다. D03은 이를 바로 물었다. |

W06은 준비 표의 동결된 입력과 자산 ID 대조를 재실행했다. 작품·가상 좌표 각 16개, 조사 후보 10점·5쌍과 32가지 선택 조합을 확인했다. `001·004·010`은 실제 도판의 취득 근거, 매체별 사용 범위, 문장별 사람 검수와 도면을 누가 무엇으로 확인할지 보강했다. 실제 작품 공개·모델 호출과 실기기는 보류다. [W06 팀 검수 통합 인수표](../operations/2026-11-13_W06_팀검수통합인수표.md)

## 재실행

[시연·복구 체크리스트](../operations/2026-11-11_main_시연복구체크리스트.md)의 격리 기동 절차를 사용한다. 이 검사는 전용 루프백 PostgreSQL의 `PGDATABASE=arti_visit_boundaries`, `ARTI_ENV=test`, `ALLOW_TEST_FIXTURES=true`, V2 활성화, 도슨트·분석 모델 비활성화를 전제로 한다. 마이그레이션과 `load_test_fixture` 후 시험 환경에서만 `bootstrap_admin --login-id visit-boundaries-admin --name "Synthetic administrator"`를 실행한다. 프론트 프리뷰 주소는 `ARTI_REVIEW_BASE`로 지정한다. Chrome, Playwright, Django가 설치된 Python을 사용하며 별도 인터프리터 경로는 `ARTI_TEST_PYTHON`으로 지정할 수 있다.

```powershell
node frontend/tests/visitBoundaries.browser.cjs receipt-session
node frontend/tests/visitBoundaries.browser.cjs survey-map
```

두 검사를 연속 실행하려면 인수를 생략한다. 같은 DB의 도면·조사풀을 수정하는 다른 검사와는 분리해서 실행한다. [Chrome 회귀 코드](../../frontend/tests/visitBoundaries.browser.cjs)
