# 11/16 좁은 화면 PC 관람 회귀

- `289c110`의 사용자 화면을 PC Chrome 320·360·412px 폭, 740px 높이에서 검수했다. 다른 시험과 분리한 PostgreSQL 17·Django·Vite 프로덕션 프리뷰를 사용했다. 기본 합성 전시에 공백 없는 영문 구간이 있는 긴 작품 제목, 160×320 도판, 320×640 도면을 넣었다. [Chrome 회귀](../../frontend/tests/narrowVisit.browser.mjs) · [합성 데이터 준비](../../frontend/tests/fixtures/narrowVisit.py)
- U-05의 두 비교 카드와 선택 버튼은 같은 화면 안에 있었다. 긴 제목은 기존 한 줄 말줄임이 적용됐고, 작가·연도에서 원제목을 읽을 수 있었다. 세로 작품에는 `contain`이 적용됐으며 Enter로 크게 보기, Tab의 창 내부 포커스와 Esc로 닫은 뒤 원래 버튼 복귀가 확인됐다.
- 수정 전 긴 제목 때문에 추천 목록 U-08, 지도 목록 U-09, 감상 제목 U-10의 문서 너비가 세 화면 폭을 넘었다. U-09의 이전 작품 마커를 열었을 때 정보 카드도 넘쳤고, U-12의 본 작품 목록은 320·360px에서 제목 일부가 화면을 벗어났다. 각 제목 영역에서 긴 단어가 필요한 경우에 줄바꿈하도록 했다. 카드·지도 배치와 비교 제목 말줄임은 기존 방식을 사용한다. [스타일](../../frontend/src/styles/app.css)

## 통과 결과

- 세 화면 폭에서 제목이 해당 목록·카드의 가로 폭 안에 들어왔다. 비회원 V2 5쌍 선택 뒤 같은 3점 순서가 추천·지도·감상·영수증에 표시됐다. 세로 도면의 전체 지도 펼침 전후 지도 높이가 유지됐으며, 뒤로가기·앞으로가기·새로고침 후에도 이전 작품에서 다음 작품까지 연결한 마커와 강조선이 일치했다.
- 영수증에서 관람 시간의 항목과 값은 같은 행에 있었고 비회원 저장 요청은 각 0건이었다. 실제 생성된 PNG 크기는 320px에서 936×2428, 360px에서 1056×2365, 412px에서 1212×2302였다. 프론트 단위 44건과 프로덕션 번들도 확인했다.

## 재현

1. 별도 루프백 PostgreSQL 17에 `arti_narrow_pc_`로 시작하는 새 DB를 만든다. 해당 `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, 새 미디어 경로 `MEDIA_ROOT` 및 시험용 `DJANGO_SECRET_KEY`를 지정한다. `ARTI_ENV=test`, `ALLOW_TEST_FIXTURES=true`, `ARTI_TASTE_PROFILE_V2_ENABLED=true`, `ARTI_LLM_PROVIDER=disabled`를 사용하고 모델 서비스 URL·실제 제공자 키와 승인된 취향 조사풀 해시를 비운다.
2. 프론트와 Django의 잠금 의존성을 설치하고 저장소 루트의 PowerShell에서 아래와 같이 준비한다. `$env:ARTI_TEST_PYTHON`에는 시험용 Python 실행 경로를 지정한다.

```powershell
& $env:ARTI_TEST_PYTHON backend-django/manage.py migrate --noinput
& $env:ARTI_TEST_PYTHON backend-django/manage.py load_test_fixture
& $env:ARTI_TEST_PYTHON backend-django/manage.py shell -c "from pathlib import Path; exec(Path('frontend/tests/fixtures/narrowVisit.py').read_text(encoding='utf-8'))"
$env:VITE_API_TARGET = 'django'
$env:VITE_API_BASE = '/api'
$env:VITE_API_PROXY = 'http://127.0.0.1:5772'
$env:ARTI_NARROW_DIST = Join-Path (Get-Location) 'data/private/narrow-visit-dist'
node frontend/node_modules/vite/bin/vite.js build --config frontend/vite.config.ts --outDir $env:ARTI_NARROW_DIST
```

3. 같은 합성 환경으로 다른 셸에서 `& $env:ARTI_TEST_PYTHON backend-django/manage.py runserver 127.0.0.1:5772 --noreload`와 `node frontend/node_modules/vite/bin/vite.js preview --config frontend/vite.config.ts --host 127.0.0.1 --port 5773 --strictPort --outDir $env:ARTI_NARROW_DIST`를 각각 실행한다. 아래 명령의 PC Chrome은 루프백 검수 주소에만 요청한다.

```powershell
$env:ARTI_REVIEW_BASE = 'http://127.0.0.1:5773'
node frontend/tests/narrowVisit.browser.mjs
```

파일 저장 선택창을 시험용으로 연결해 제품이 생성한 PNG 바이트와 크기를 확인했다. 루프백 접속만 허용해 외부 웹 글꼴 요청은 차단됐다. 실제 모델 호출과 실기기 입력·OS 공유는 계속 보류했다.
