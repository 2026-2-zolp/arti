# W 계획 재정합화와 최신 CI 인수 준비

2026-11-09 / dev/임준억 / 출발7e8ec2e. [모델 운영 안정성](2026-11-09_W07_모델운영안정성.md) 다음 과업. 사용자는 W 계획/잔여 이슈 대조와 최신 CI 준비를 요청했고 로컬 커밋만 허용했다. 앞으로 보고에는 다음 한 작업을 명시한다.

## 왜·어디를·어떻게 바꿨는가

execution.json과04-issues.md에는 W04 당시 미구현/미검증 관측이 남아 최신 G4·실제 모델·브라우저 기록과 맞지 않았다.37개 기존 ID/W/AC 연결을 유지하고 [원래 관측](../execution-plan/2026-11-07/records/reconciliation-2026-11-09/before-issues.json)을 보존한 뒤, 각 이슈에 현재 확인 범위·잔여 조건·다음 W·증거 경로를 넣었다.12개는 pass AC와 실행 근거를 대조해 현 계약 범위에서 종결했다. 다른 기기 확인이 남은 F10, 실제 전시 품질이 남은 F12 등은 부분 검증으로 남겼다. F37은 기존 사용자 결정인 Git 우선/로컬 별도 인수에 맞춰 blocked·releaseRequired=false로 정리했다. 실제 고유 자료 부재나 이전 성공을 주장하지 않는다.

12-current-status.md에 W01~W12 실적/정식 상태와 대기 조건·다음 순서를 연결했다. 실행계획 README·W02 당시 예정표·W11 최초 검사표에는 최신 안내를 추가하고 작업기록 인덱스의 오래된 Actions 미실행 표현을 고쳤다. 원본 아카이브와 과거 작업기록은 수정하지 않았다. W07 planned+preparation 실적, W06 in_progress, W11 PR 대기와 정식 게이트는 유지했다.

verify_plan.py는 재정합화 항목의 누락/증거·원래 매핑·현재 표/manifest 일치·종결 SHA 조상과 별도 인수 경계를 검사한다. 기존 pass AC/폐쇄 조건·보호파일 검사를 완화하지 않았다. verify_guardrails.py는 일반 단계 가설과 최신 상태표 검사를 분리하고7개 탐침을 추가했다. 처음 잘못된 SHA None 입력에서 subprocess 예외가 발생해 형식 검증 뒤에만 Git을 호출하도록 고쳤다. 동일 SHA는1회 판정해 중복 실행을 줄였다.

CI는 기존4job·최소 권한·트리거를 유지하고 모델 job에 ARTI_WRITER_ENABLED=false만 명시했다. pytest 전체 수집과 arti.tests 전체 수집으로 새 runtime/저장 보호 시험이 자동 실행되는지 확인했다. 테스트 수를 하드코딩하거나 원격 성공으로 꾸미지 않았다. [현재 CI 준비 기록](../execution-plan/2026-11-07/records/W11/local-current-2026-11-09/README.md)에 명령·로그·로컬/원격 경계·후속 PR 인수 절차를 기록했다.

## 검증단 검토와 판정

기술/시니어는 현재 상태 누락·거짓 종결·미통과 AC·조상 SHA·새 테스트 자동 수집을 확인했다. 데이터/운영은 과거 관측 보존·Git 인수 경계·키 제외·전용 DB/컨테이너 정리를 확인했다. 방문자/콘텐츠는 실기기/사람 검수/사용 조건/실제 통로가 남은 항목을 종결하지 않았는지 확인했다. 팀/교수/평가위원은 실제 GPT·실분류모델·합성 검사·정식 인수·원격 결과를 분리했다. 동일 작성자의 관점별 자체 검토이며 실제 외부 검수자의 승인이 아니다.

이번 두 과업의 로컬 완료 기준은 통과다. G0~G4와 기존 AC 상태는 유지하고 G5/GCI/GOPS/G6/G7은 승격하지 않았다. 일반 개발 DB·API 키·유영국 승인/배치·모델 가중치/보정·제품 기능은 변경하지 않았다. 시험용 컨테이너/네트워크는 종료/제거했고 기존 볼륨은 보존했다. 원격 push/PR/클라우드 생성은 하지 않는다.
