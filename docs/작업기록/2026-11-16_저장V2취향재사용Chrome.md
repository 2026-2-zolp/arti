# 11/16 저장된 V2 취향 재사용 Chrome 검수

## 합성 검수 결과

- **환경** · `dev/임준억` `f9d1371`의 제품 빌드, PC Chrome 390×812, Vite 프리뷰, Django, 포트 5581 전용 PostgreSQL 17을 사용했다. 시험 시작점은 합성 전시 `fixture-ex01`이다.
- **계정 저장과 조사풀 변경** · 합성 작품 태그에 풍경·따뜻한 색감 3:3 동률을 만들고 브라우저에서 다섯 쌍을 선택했다. 최초 저장은 204였고 계정 취향 버전이 한 번 증가했다. 현재 조사풀의 쌍 순서·풀 버전·동률 근거 버전을 바꾼 뒤 기존 세션은 로그아웃으로 종료했다.
- **저장 취향 재사용** · 같은 계정으로 다시 로그인해 U-06에서 저장된 취향으로 시작했다. 서버는 원래 저장된 동률 순서와 `frozen_snapshot` 규칙을 반환했다. 추천 세 작품을 차례로 감상했고, 서명된 취향 근거를 포함한 저장 요청은 201이었다. 영수증의 취향 스냅숏은 저장된 계정 스냅숏과 같았다. 마이페이지에서 같은 영수증을 다시 열었다.
- **이번 관람 태그 수정** · U-06에서 태그 하나를 추가해 새 관람에만 적용했다. 두 번째 관람에는 새 관람 ID와 서명된 근거를 사용했고 두 번째 영수증은 수동 태그를 반영했다. 계정에 대한 취향 저장 요청은 처음 한 번이었다. 별도로 조회한 계정의 저장 태그·취향 스냅숏·버전은 두 관람 이후에도 처음 저장한 값과 같았다.
- **기존 회귀** · 새 Chrome 검사를 반복 실행했고 기존 관람 경계 Chrome 세 시나리오와 Django PostgreSQL 취향 V2·조사풀 테스트 23건이 통과했다. 실제 모델 호출과 실기기 검증은 보류했다.

## 저장 응답 유실과 두 탭 변경 추가 검수

- **환경** · `dev/임준억` `7eb1198`의 제품 빌드를 루프백 Vite와 Django에 연결했다. PostgreSQL 17은 포트 5611의 별도 합성 DB를 사용했다.
- **저장 후 응답 유실** · 브라우저의 첫 계정 취향 `PUT`을 Django에 그대로 전달해 `204`와 저장 버전 1회 증가를 확인한 뒤, 응답 전달만 끊었다. 실패 안내 뒤 새로고침한 화면의 **같은 요청으로 저장 재시도**는 같은 `clientMutationId`와 동일한 JSON 본문을 다시 보냈다. Django는 `204`였고 계정 스냅샷과 버전은 첫 저장 직후와 같았다.
- **두 탭 변경** · 같은 Chrome 프로필의 첫 탭이 U-06에서 기존 계정 취향 확인을 마친 뒤 `resolve`를 보낼 때 잠시 대기시켰다. 둘째 탭의 다섯 쌍 선택을 계정에 저장한 뒤 첫 탭 요청을 전달하자 Django는 `409 VERSION_CONFLICT`를 반환했다. 첫 탭에서 **계정 최신 취향 확인**으로 최신 태그를 불러오고 다시 관람을 시작하자 최신 버전과 서명된 관람 근거를 받았다. 실패와 새로 조회하는 동안 첫 탭의 관람 상태가 유지됐고, 계정의 기존 영수증 두 건도 변경되지 않았다.
- **실행 범위** · 두 상황은 아래 `saved-v2` Chrome 회귀에서 이전의 조사풀 개정·재로그인·관람 전용 태그와 함께 실행된다. 같은 전용 DB에서 연속 두 번 통과했고, 기존 관람 경계와 후보 부족 Chrome 회귀 및 Django PostgreSQL 취향 V2·조사풀 테스트 23건도 통과했다. 실제 모델 호출과 실기기 검증은 보류했다.

## 재현

Chrome, Node.js, 잠금 의존성이 설치된 Django의 Python 가상 환경과 프론트를 준비한다. 저장소 루트에서 실제 데이터가 없는 별도 PostgreSQL을 사용한다. 아래 예시는 다른 Chrome 검수와 포트·DB·미디어를 분리한다.

```powershell
$fixtureDb = docker run --rm -d --name arti-saved-v2-edges-5611 -p 127.0.0.1:5611:5432 -e POSTGRES_DB=arti_visit_boundaries_saved_v2_edges -e POSTGRES_USER=arti -e POSTGRES_PASSWORD=browser-only-saved-v2-db postgres:17-alpine
if ($LASTEXITCODE -ne 0) { throw '전용 PostgreSQL을 띄우지 못했어요.' }
for ($attempt = 0; $attempt -lt 30; $attempt++) {
    docker exec $fixtureDb pg_isready -q -h 127.0.0.1 -U arti -d arti_visit_boundaries_saved_v2_edges
    if ($LASTEXITCODE -eq 0) { break }
    Start-Sleep -Milliseconds 500
}
if ($LASTEXITCODE -ne 0) { throw '전용 PostgreSQL이 준비되지 않았어요.' }

$env:DJANGO_SECRET_KEY = 'synthetic-saved-v2-5611-loopback-test-only'
$env:ARTI_ENV = 'test'
$env:ALLOW_TEST_FIXTURES = 'true'
$env:ARTI_LLM_PROVIDER = 'disabled'
$env:ARTI_MODEL_SERVICE_URL = ''
$env:OPENAI_API_KEY = ''
$env:ARTI_TASTE_PROFILE_V2_ENABLED = 'true'
$env:PGHOST = '127.0.0.1'
$env:PGPORT = '5611'
$env:PGDATABASE = 'arti_visit_boundaries_saved_v2_edges'
$env:PGUSER = 'arti'
$env:PGPASSWORD = 'browser-only-saved-v2-db'
$env:MEDIA_ROOT = Join-Path $PWD 'data/private/saved-v2-edges-5611'
$env:ARTI_BOOTSTRAP_PASSWORD = 'Browser-Saved-V2-5611!'
$env:ARTI_TEST_PYTHON = "$PWD/backend-django/.venv/Scripts/python.exe"
$env:VITE_API_TARGET = 'django'
$env:VITE_API_BASE = '/api'

& $env:ARTI_TEST_PYTHON backend-django/manage.py migrate --noinput
& $env:ARTI_TEST_PYTHON backend-django/manage.py load_test_fixture
& $env:ARTI_TEST_PYTHON backend-django/manage.py bootstrap_admin --login-id visit-boundaries-admin --name 'Synthetic Visit Admin'
npm.cmd --prefix frontend run build
node frontend/tests/runVisitBoundaries.browser.mjs saved-v2
```

실행마다 Django·Vite 포트는 루프백에서 자동 할당한다. 같은 빌드를 반복 사용하려면 마지막 명령만 실행한다. 같은 DB의 다른 회귀와 순차 실행한다. 이 검수는 합성 태그와 쌍 순서를 복원하며 조사풀 개정 이력은 시험 DB에 남는다. 마치면 `docker stop $fixtureDb`로 이번 DB를 정리한다. [검사 코드](../../frontend/tests/visitBoundaries.browser.cjs)
