# 11/16 운영형 배포 전 검사 자동화

Compose·Nginx 로컬 검수에서 실제로 사용한 기동, 합성 백업 복원, 브라우저 콜백 장애 절차를 하나의 검사기로 연결했다. 지정 Git 커밋의 소스만 아카이브해 OCI revision 라벨을 붙인 Django·정적 Nginx 이미지를 빌드한다. Compose 실행 이미지와 빌드 ID를 대조하고 HTTPS Chrome에도 같은 이미지를 사용한다. [기존 운영형 기동](2026-11-16_운영형로컬기동점검.md) · [HTTPS Chrome 시험](2026-11-16_NginxHTTPS카카오콜백로그.md)

| 단계 | 검사 |
| --- | --- |
| `source-startup` | 운영 설정에서 PostgreSQL 준비 응답 200, 마이그레이션 종료 0과 `migrate --check`, `nginx -t`, 계정 0개와 운영 fixture 적재 차단, 도슨트·분석 비활성을 확인한다. |
| `source-receipt` | 원본에만 합성 자료와 계정을 준비하고 실제 API로 영수증과 반응을 한 건 저장한다. 회원 본인의 영수증 접근과 본문을 확인한다. |
| `candidate-migration-failure` | 후보 마이그레이션의 DB 인증만 실패시키고 API·웹 기동 차단과 공개 테이블 0개를 확인한다. 같은 시점의 원본 준비·영수증 응답은 200이며 원본 영수증 본문이 유지돼야 한다. |
| `synthetic-backup` | 실패한 후보의 DB 볼륨을 남기고 시험 컨테이너를 내린다. 원본 웹 포트를 닫고 DB 덤프와 미디어 tar의 SHA-256을 기록한다. |
| `isolated-restore` | 정상 설정으로 같은 후보 PostgreSQL 볼륨과 빈 미디어 볼륨에 복원한다. 복원 전 테이블 0개와 동일 클러스터를 확인한다. 계정 2개·관람 1건·반응 1건, 이미지 두 장의 해시 일치, 같은 이미지로 기동하는지 확인한다. |
| `restored-web-access` | 영수증 직접 주소와 JS 번들 200, 원본과 복원된 본인·관리자 영수증의 동일 ID와 본문, 다른 회원 403·비회원 401·회원의 관리자 토큰 사용 401, 미디어 200/404/200을 확인한다. |
| `nginx-api-recovery` | 후보 API만 정지하고 다른 IP로 재생성한다. 같은 Nginx와 루프백 포트에서 준비 응답 200→502→200, 정적 영수증 주소, 관리자 검색의 쿼리 필터, 회원·관리자 영수증 본문 보존을 확인한다. |
| `https-callback-logs` | 별도 루프백 HTTPS의 모의 카카오에서 취소·연결·동일 회원에 대한 로그인과 정상 콜백 302를 재현한다. 업스트림 정지 뒤 콜백 502의 `no-store`·`no-referrer`, Nginx·Gunicorn의 인증 값 비노출과 기존 일반 API 장애 로그를 검사한다. |

## 실행과 결과

Windows PowerShell 7.3 이상, Docker Desktop/Compose 2.35 계열, Node 22와 PC Chrome이 필요하다. 저장소 루트에서 실행한다. HTTPS 기본 포트는 `5623`이고 이미 사용 중이면 비는 값을 넘긴다. 원본과 복원 HTTP 포트는 Docker가 루프백에 자동 할당한다.

```powershell
npm --prefix frontend ci --ignore-scripts --no-audit --no-fund
pwsh -NoProfile -File ./scripts/runOpsPreflight.ps1 -Revision HEAD -HttpsPort 5623
```

`-Revision`은 로컬 Git 커밋을 받는다. 실패하면 명령이 비정상 종료하고 `data/private/arti-preflight-<실행ID>/result.json`에 커밋, 통과한 검사, 실패 단계와 스크립트 줄을 기록한다. HTTP 불일치에는 예상·실제 코드가 남는다. 빌드·실행 환경을 고친 뒤 같은 커밋·명령으로 실행해 새 결과와 대조한다. 결과 파일에는 계정 비밀번호·세션·인가 값, 전체 요청이나 응답, 원본 덤프가 들어가지 않는다. 검사기에서 생성한 Compose 프로젝트·볼륨·이미지와 임시 자료만 정리하며 기존 작업 환경과 Git 브랜치에는 쓰지 않는다.

### 최초 자동 검사 기록

- 처음에는 Compose 2.35.1의 `run` 명령이 `--no-build`를 받지 않아 이를 빼고 빌드된 이미지만 쓰도록 `--pull never`를 적용했다. 이어 Docker 주소 풀에서 여유 네트워크 하나만 할당할 수 있는 상황을 재현했다. 합성 백업이나 단계별 조회가 끝나면 해당 프로젝트를 정리하도록 순서를 바꿔 원본 → 복원 → HTTPS에서 각각 하나의 시험 네트워크만 사용했다.
- `0b6b087`을 아카이브한 최종 재실행 `arti-preflight-41a37f116350`이 Docker 28.1.1과 Compose 2.35.1에서 통과했다. 새 영수증 해석 마이그레이션을 포함해 원본·복원 마이그레이션 종료 0, 영수증 한 건과 동일 ID, 미디어 해시 두 건, 권한 200/403/401, 모의 콜백 302/502와 인증 값 비노출을 확인했다. 시험 컨테이너·네트워크·볼륨·태그·임시 자료 정리도 확인했다.
- 존재하지 않는 Git 커밋을 입력한 경우에는 `failedStage: build`와 `cleanup: passed`가 기록되고 임시 경로가 정리됐다.

### 후보 마이그레이션 실패와 복구

실패는 후보 `migrate`에만 다른 DB 비밀번호를 전달해 재현한다. 원본과 동시에 기동하는 후보에는 기본 주소 풀을 추가로 요구하지 않는 작은 전용 내부 네트워크를 할당한다. 실패 확인 뒤 후보 컨테이너와 네트워크를 정리하고 후보 DB 볼륨을 유지한다. 원본 백업을 완료하고 원본을 내린 뒤, 같은 후보 볼륨을 정상 설정으로 올려 복원한다. 결과 파일에는 인증 실패 여부와 종료 코드, 테이블 수, 원본 응답 코드와 동일 본문 여부를 남긴다. [수동 실패·복구 재현](2026-11-16_Compose기동실패와Nginx복구.md)

- `289c110`을 아카이브한 실행 `arti-preflight-c85630485ab4`에서 Docker 28.1.1, Compose 2.35.1, 합성 PostgreSQL 17로 전체 검사를 통과했다. 후보 기동과 마이그레이션은 각각 종료 1이었고 API·웹은 시작되지 않았다. 후보에 공개 테이블은 0개였고 원본 준비·본인 영수증 조회는 각각 200이었으며 원본 영수증 본문도 유지됐다.
- 같은 후보 DB에 복원한 뒤 마이그레이션 종료 0과 준비 200, 계정 2개·관람 1건·반응 1건, 원본과 같은 영수증 ID·본문, 회원·관리자 200과 다른 회원 403·비회원 401을 확인했다. 미디어 해시 두 건과 접근 200/404/200이 일치했고, 기존 Chrome 모의 HTTPS 콜백의 302/502 및 인증 값 비노출도 다시 확인했다.
- 두 합성 프로젝트가 남아 있을 때 임시 검사본에서 예외가 나도록 한 실행 `arti-preflight-55d1385c391a`는 `failedStage: candidate-migration-failure`와 `cleanup: passed`를 남겼다. 해당 실행 이름의 컨테이너·네트워크·볼륨·이미지와 임시 경로가 정리됐다.

### 같은 Nginx에서 새 API 주소로 복구

복원 후보의 작은 전용 네트워크에서 API 주소 두 개를 동적 할당 범위 밖에 예약한다. 첫 주소로 복원 검사를 끝내면 API만 정지하고 Nginx의 준비 요청이 502를 반환할 때까지 확인한다. 정지 중 영수증 직접 주소는 기존 정적 SPA를 반환해야 한다. 다음 주소로 API 컨테이너만 재생성한 뒤 동일 Nginx ID·시작 시각·포트와 준비 응답 200을 확인한다. [수동 API 재생성 절차](2026-11-16_Compose기동실패와Nginx복구.md#후보-api-주소-변경을-강제하는-방법)

관리자 검색 필터가 유지되는지 확인하려고 합성 회원 두 명이 존재할 때 한 회원의 이메일을 URL 인코딩해 검색한다. 교체 전에는 그 회원 한 명만 반환돼야 하며 교체 뒤에도 응답이 같아야 한다. 교체 뒤 영수증의 정적 SPA와 회원·관리자 API 본문도 비교한다. 단계가 실패하면 코드와 실패 위치를 기록하고 이 실행의 자원만 정리한다.

- `b57eb46`을 아카이브한 `arti-preflight-0750b15cba12`에서 API를 `10.247.91.153`에서 `10.247.91.154`로 교체했다. 같은 Nginx ID·시작 시각·포트에서 준비 응답은 200→502→200이었고, 정지 중과 복구 후 정적 영수증 SPA는 모두 200이었다. 관리자 검색은 같은 회원 한 명만 반환했고 회원·관리자 영수증 응답의 본문도 유지됐다. 기존 모의 HTTPS 콜백 검사와 전체 정리도 통과했다.
- 임시 이미지에서 Nginx를 시작 시점에만 업스트림 주소를 해석하도록 바꾼 대조 실행 `arti-preflight-5a32d17a6dc9`에서는 API 정지 뒤 502 대신 504가 계속 반환돼 `nginx-api-recovery`에서 중단됐다. 종료 코드가 실패였고 실행 전용 컨테이너·네트워크·볼륨·이미지 태그와 임시 경로가 정리됐다.

복원 화면의 회원·비회원 조작과 실제 운영 주소·앱 등록은 인수 절차에서 각각 확인한다. 이번 검수에서 실제 모델과 실기기는 보류했다. [팀 PC 체크리스트](../operations/2026-11-11_main_시연복구체크리스트.md#팀-pc-재현-순서)
