## 재현과 변경

- **관리자 회원 목록** · 모델 import 누락으로 `/api/admin/members`가 `NameError`와 500을 반환하는 것을 PostgreSQL API 검사에서 재현했다. 모델을 연결하고 관람 횟수·최근 관람일을 한 집계 쿼리로 조회한다. 인증을 포함해 2쿼리이며, 기존 최대 100명 제한과 이메일·닉네임 검색을 유지한다.
- **관리자 관람기록** · A-06이 일반 회원용 `listVisits`를 호출해 관리자 세션으로 상세 기록을 조회할 수 없었다. 관리자 전용 `/api/admin/members/:id/visits`를 추가하고 프론트를 연결했다. 미존재 회원은 404, 관람 없는 회원은 빈 목록이다. 일반 회원·비회원·회원 토큰을 관리자 헤더에 넣은 요청은 차단한다. 일반 회원용 경로의 본인 제한은 유지한다.
- **조회 실패와 회원 전환** · 회원 목록·상세 각각 로딩, 실패·재시도, 빈 결과를 구분했다. 새 회원을 선택하면 상세 상태를 새로 만들고 이전 회원의 늦은 응답을 폐기한다. 이메일 선택 버튼으로 키보드에서도 상세를 열 수 있다. 사용자 화면의 공통 오류 스타일은 변경하지 않았다.
- **재해석 중 기존 내용 보존** · 기존 구현은 재요청 직후 성공한 해석을 화면에서 제거했다. 합성 브라우저 검사에서 `.receipt-ai`가 사라지는 것을 재현했다. 성공 내용과 요청 실패 상태를 분리해, 처리 중·실패 후에도 마지막 해석과 탭 캐시를 유지한다. 초기 해석 실패는 기존처럼 재시도를 제공한다.
- **PNG 최신 내용 반영** · 기존 저장 버튼은 최초 PNG를 계속 재사용했다. 해석이 성공해 내용이 바뀌면 저장 컴포넌트를 새로 만들어 PNG를 다시 준비한다. 재요청 중·실패 시에는 기존 PNG를 계속 저장할 수 있고, 새 PNG 준비 중에는 버튼을 잠근다. 실패 안내나 로딩 문구는 이미지 본문에 넣지 않는다.

## 통과 기준과 근거

- **API·DB** · Django 전체 174건 통과. 새 7건은 관리자 목록·검색·집계·권한, 선택 회원 범위와 폐쇄 전시의 저장 snapshot, 잘못된 관리자 토큰, AI 503·504·잘못된 응답 뒤 기록 보존, 성공 시 해석만 교체, 타인/변조 요청 차단, 비회원 DB 저장 0건을 포함한다. `arti-main-review-1114`의 임시 코드 사본에서 별도 PostgreSQL 테스트 DB를 사용했다. 최초 전체 실행은 참조 계약 fixture 누락으로 1건 오류였고, 사본에 의존 파일을 갖춘 뒤 전체 통과했다.
- **프론트** · 자동 검사 40건과 타입 검사를 포함한 프로덕션 빌드 통과. 관리자 조회 요청이 사용자 경로 대신 관리자 경로·헤더를 사용하는 회귀를 추가했다.
- **브라우저** · 합성 API와 Chrome에서 관리자 목록·상세 실패 후 재시도, 빈 기록·검색 결과, 회원 전환 중 늦은 응답 폐기를 확인했다. 영수증은 320·360·412px 회원·비회원에서 재해석 실패·재시도와 첫 해석 실패, 캐시 복원, 가로 넘침을 검증한다. 실제 PNG 바이트·높이를 대조해 실패 중 원본 유지와 성공 후 긴 새 문안 포함을 확인한다. 서버 권한·저장은 별도 PostgreSQL 검사로 검증하며, 이 모의 API 화면 검사를 실제 외부 AI·OS 공유 통과로 보지 않는다.
- **배포용 빌드 최종 결과** · `127.0.0.1:5217`에서 관리자 검사와 영수증 6개 조건이 모두 통과했다. 영수증 조건은 기존 해석이 있는 320px 비회원·360px 회원·412px 비회원/회원, 첫 요청인 360px 비회원/회원이다. 각 조건에서 실패와 재시도, PNG 보존·갱신, 새로고침 후 성공 캐시 복원을 확인했다. 관리자 모의 장애는 개발 모드의 효과 재실행에도 실패를 유지하도록 명시적 복구 전환으로 제어한다.
