# 2026-11-18 배포용 Compose·Nginx와 이전 이미지 복귀

- 원격 `main`과 로컬·원격 `dev/임준억`을 `aea8f9a226d69963597f8f79bbc48021823f0767`에서 대조했다. 브랜치를 빠르게 동기화하고 기존 작업 파일 여덟 개의 해시를 확인했다.
- 배포용 Compose는 웹만 호스트 루프백에 열고, 마이그레이션은 지정한 배포 이미지로 운영자가 한 번 실행한다. 처음에는 Compose 병합 후 API·마이그레이션·메일 워커의 개발용 `build`가 남았다. 세 서비스에 `!reset`을 직접 지정하고 정규화된 Compose에서 빌드 정의와 API·DB 호스트 포트가 제거되는지 확인했다. 운영 설정의 합성 fixture 적재는 거절된다.
- 외부 HTTPS Nginx 템플릿과 내부 정적 Nginx를 분리했다. HTTPS 프록시가 정적 화면과 API를 같은 출처에 제공한다. 재설정·카카오 콜백 경로에는 정상·장애 응답에서 `no-store`·`no-referrer`를 유지하고, 해당 경로의 요청 값을 액세스·오류 로그에 남기지 않는지 합성 표식으로 검사한다.
- 복귀 리허설의 제품 코드는 `aea8f9a`, 이전 호환 코드는 `99c36f5`, 스키마 불일치 대조는 `63aafe8`이다. 이전 이미지의 마이그레이션 파일과 연결한 DB의 적용 목록을 대조하는 읽기 검사기를 추가했다. 이력이 다른 경우 이전 API를 올리는 단계 전에 복귀를 중단한다.

## 최종 합성 검수

- `arti-deploy-check-7569ec4a947b`에서 루프백 인증서 검증, 배포용 Compose 기동, 두 Nginx의 설정 검사, 메일·카카오 비활성 상태와 보호 헤더를 확인했다. 후보가 저장한 영수증 한 건을 기준으로 삼았다. `63aafe8`은 마이그레이션 이력 비교에서 종료 코드 3으로 차단됐다.
- 후보 API 장애에서 준비 응답 `502`와 정적 영수증 주소 `200`을 확인했다. 웹 서버를 중지한 경우에도 HTTPS 진입점은 보호 경로 `502`의 헤더를 유지했다. 해당 경로의 합성 표식은 로그에 남지 않았고 일반 장애는 남았다.
- 이전 Django·정적 Nginx를 띄운 뒤 같은 HTTPS 프록시에서 준비 응답이 `200`으로 돌아왔다. 이미지 revision과 다른 웹 번들을 확인했고, DB 클러스터·볼륨·마이그레이션 이력·미디어 해시를 전후 대조했다. 같은 영수증과 관람·반응 각 1건, 본인·관리자 `200`·다른 회원 `403`·비로그인 `401`이 유지됐다.
- 검수 전용 자원 정리를 확인했다. 합성 결과는 `data/private/arti-deploy-check-7569ec4a947b/result.json`에 있다.
