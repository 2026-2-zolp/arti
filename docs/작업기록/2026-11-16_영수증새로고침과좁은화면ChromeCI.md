# 11/16 영수증 새로고침과 좁은 화면 Chrome CI

- PR #37 `Visit Chrome (boundaries)`의 세션 만료 회귀에서 마이페이지를 새로고침한 뒤 `Network.getResponseBody`가 목록 응답 본문을 잃었다. 같은 계정과 다른 계정 분기에서 같은 본문 읽기 방식이 쓰였다. 실제 화면에서 나온 목록 GET의 HTTP 200을 확인하고, 저장 결과의 전체 본문은 같은 계정으로 별도 API 요청을 보내 확인한다. [영수증 관람 회귀](../../frontend/tests/visitBoundaries.browser.cjs)
- 같은 계정은 새로고침 후 관람 카드 한 장에서 원래 영수증 ID로 진입하고 영수증이 렌더링되는지 확인한다. 원래 관람 ID와 작품 목록, 저장 요청 1건과 관리자 재조회도 대조한다. 다른 계정은 빈 관람 목록, 미저장 초안 정리, 원래 회원 기록 조회 403, 저장 요청 0건과 두 회원의 저장 기록 각각 0건을 확인한다.
- `Visit Chrome (narrow layout)`을 PR·수동 실행에 추가했다. 전용 PostgreSQL `arti_narrow_pc_ci`에서만 기존 긴 제목·세로 도판·세로 도면 시험 데이터를 적재한다. 모델을 비활성화한 로컬 Django와 Vite 프리뷰에서 320·360·412px 취향 비교, 지도 왕복과 영수증 PNG를 검사한다. [워크플로](../../.github/workflows/ci.yml) · [좁은 화면 검수 기준](2026-11-16_좁은화면PC관람회귀.md)
- 두 검사를 동시에 실행하니 지도 `<details>`의 `open`이 먼저 바뀌고 React가 세 번째 마커를 표시하기 전 개수를 읽는 상황도 재현됐다. 펼친 마커가 표시될 때까지 기다린 뒤 개수와 지도 높이, 작품 순서·이동선을 확인한다. [좁은 화면 회귀](../../frontend/tests/narrowVisit.browser.mjs)

## 로컬 검수

- 워크플로에서 추출한 Bash 실행 단계의 구문과 Chrome 매트릭스 11개를 대조했다. 프론트 프로덕션 번들을 별도 경로에 빌드하고, 합성 PostgreSQL 17에 영수증 경계 검사와 좁은 화면 검사의 DB·미디어를 각각 준비했다.
- 기존 `Visit Chrome (boundaries)`를 같은 합성 DB에서 연속 두 번 실행했다. 두 실행에서 같은 계정의 같은 관람 ID·영수증 1건, 다른 계정의 저장 요청 0건, 취향 조사·도면 갱신이 모두 통과했다. 이어 3·5·7점에서 후보 부족을 재현한 부속 검사도 통과했다.
- 좁은 화면 실행은 Windows Git Bash로 워크플로 단계를 재현했다. 로컬 포트와 빌드 경로를 분리하고, 남은 시험용 Django 프로세스를 정리한 뒤 5784·5785에서 320·360·412px 전 구간과 PNG가 통과했다. `MSYS2_ENV_CONV_EXCL=VITE_API_BASE`를 적용해 `/api`가 파일 경로로 변환되지 않게 했다.
- 이번 연결은 로컬에서 검수했다. 실제 모델 호출과 실기기 검증은 계속 보류했다.
