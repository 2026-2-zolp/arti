# 11/16 관리자 동시 편집 Chrome PR CI 연결

- 원격 `main` `fd2362c`로 대조했다. 기존 관리자 수정 `6a71317`을 보존하고 그 위에 워크플로 연결만 추가했다. `Admin Chrome (concurrent editing)`은 PR과 수동 실행에서 다른 Chrome 검사와 함께 실행한다. Chrome 매트릭스는 10개이며 `main` 푸시의 네 검사 구성은 유지한다. [CI 워크플로](../../.github/workflows/ci.yml)
- 새 항목은 PostgreSQL 17의 `arti_admin_concurrent`에 합성 전시를 적재하고 합성 관리자 두 명을 각각 생성한다. 공통 Vite 프리뷰와 루프백 Django에서 실제 API를 사용한다. 모델 제공자는 비활성으로 두고, Chrome은 준비 응답의 PostgreSQL 및 AI 비활성 설정과 합성 작품을 확인한 뒤 편집 테스트를 시작한다. [관리자 동시 편집 재현](2026-11-16_관리자해설도면동시편집.md)
- 기존 관리자 분석 실행기와 영수증 공개 상태·해석 회귀의 진입점은 유지했다. 분석·해석 모의 응답과 별도의 합성 DB를 사용하며, 영수증 해석은 기존 모의 서버 준비 헤더를 계속 확인한다. [기존 추가 Chrome 연결](2026-11-16_추가Chrome회귀PRCI.md)

## 로컬 재검수

워크플로 YAML에서 합성 자료 적재와 각 Chrome 실행 단계를 꺼내 Bash 구문 검사를 했다. Windows Git Bash에서 루프백 포트와 Python 실행 경로를 이 시험에 맞춰 실행했다. 별도 PostgreSQL 17 컨테이너에 매트릭스별 DB와 미디어 경로를 각각 만들었으며, Git Bash가 Vite의 `/api` 환경값을 Windows 파일 경로로 바꾸지 않도록 `MSYS2_ENV_CONV_EXCL=VITE_API_BASE`를 적용했다.
