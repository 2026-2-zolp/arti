# 11/16 영수증 Chrome 회귀 PR CI 연결

- **기준** · `main` `f9ea086`의 [작품 비공개·전시 종료 검수](2026-11-16_작품비공개와전시종료후영수증.md)를 사용했다.
- **연결** · ARTI CI의 Chrome 실행에 `Receipt Chrome (visibility)`를 추가했다. PR과 수동 실행에서 독립 PostgreSQL 17·합성 전시·합성 관리자를 준비하고 `receiptVisibility.browser.cjs`를 실행한다. 기존 도슨트 3개 검사 이름과 모의 제공자 확인 방식을 유지한다. 영수증 검사는 제공자를 비활성화한 Django와 루프백 Vite를 사용한다. [CI 설정](../../.github/workflows/ci.yml)
- **통과 기준** · 작품 비공개와 전시 종료 각각에서 첫 저장의 실제 `201` 응답을 브라우저가 받기 전에 끊는다. 다시 저장·새로고침·뒤로가기 후 머무르기는 같은 본문과 영수증 ID로 `200`을 받아야 한다. 회원·관리자 조회에서 영수증이 한 건이고 첫 작품의 21초·좋아요·선택 이유가 보존돼야 한다.
- **로컬 검수** · 워크플로에서 초기화·실행 Bash 명령을 읽어 Windows Git Bash에서 실행했다. 단계의 Bash 구문 검사와 프로덕션 빌드가 통과했다. PostgreSQL에 두 시나리오가 각각 관람 1행·반응 1행으로 남았고 합성 전시는 실행 후 공개 상태로 복원됐다. 도슨트 재시도, 작품·자료 변경, 가이드·요약 검사도 각각 별도 합성 DB에서 통과했다.
- **원격 실행** · PR #27에서 `Receipt Chrome (visibility)`를 포함한 8개 검사가 통과해 `main` `ee189e8`에 병합했다. GitHub 로그에서 비공개·종료 시나리오가 각각 실행됐으며 병합 후 `main` 검사 4개도 통과했다. 실제 모델 호출과 실기기는 보류했다.
