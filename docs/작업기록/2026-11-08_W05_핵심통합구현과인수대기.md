## 왜 이 작업을 했는가

W04는 실제 PostgreSQL과 React 조회/추천까지였으며 관리자 저장·회원·영수증은 아직 새 API로 연결되지 않았다. 기존 구현에는 검수 전 자료 공개, confirmed 요약 덮어쓰기, 취향 빈도 소실, 동일 관람 중복 저장, 만료 회원의 guest 강등, U10→U11 맥락 단절이 있었다. 이 동작들을 새 스택으로 그대로 옮기지 않고 확정 계약에 따라 경계를 수정했다. 기존 Express를 먼저 다시 고치거나 React 화면을 전면 재설계하지 않았다.

## 검증단과 보완 루프

기술·팀/교수·관람객 관점의 독립 AI 검토를 사용했다. 실제 팀·교수의 승인을 받은 것으로 기록하지 않는다.

- PostgreSQL 첫42검사에서 fixture의 확정/질문 사전조건과 기존501 기대를 수정했다. 실제 구현 경계에 맞게 검사한 뒤 통과했다.
- 기술 검토에서 잘못된 중첩 입력500·관리자 역사 조회·회원 AI rate 우회·분석 동시성·재시도 정규화·guest 해석 입력·provider502/504 처리를 지적했다. 보완과 회귀 추가 후 전체51검사를 통과했다.
- 관람객 검토에서 같은 시간 새 관람의 UUID, mode/history, 콘텐츠 변경 안내, 실제 진입 질문, pending 입력, 계정 경계, 읽기 상태 복귀를 보완했다. 늦은 해석 응답과 중복 요청도 차단했다.
- 실제 브라우저에서 guest3점 관람과 회원3점 저장/재진입·AI 실패 분리를 확인했다. DB1건과 사유/초 보존도 확인했다.
- 만료 복구 시험에서 미완료 작품 dwell이 저장 입력에 섞이는400을 발견했다. 실제 builder를 완료 작품으로 제한하고0점/부분 관람 시험을 추가했다. 기존 실패 payload는 고정 원본으로 남겼고, 임의 수정해 성공으로 꾸미지 않았다.
- 새 복구 시험 중 IAB 확인창 제어가 멈춰 최종 복구 성공은 관측하지 못했다. 코드 검토의 지적 해소와 브라우저 인수 완료는 구별했다.

## 자료 인수 판단

사용자가 로컬 고유 자료는 아직 미확정이며 Git부터 확인하도록 요청했다. Git 메타데이터40점의 .png 경로와 실제 .jpg를 ID/해시로 대응해 모두 복원했고, 해설 checkedAt=null을 확인했다. 이는 검수 전 AI 초안이므로 전시 draft/작품 source_check/좌표 null로 가져왔다. approved 시험 seed를 그대로 사용하지 않았다.

이 복원은 광권님 로컬 arti.db·uploads의 추가 수동 수정이 없다는 확인이 아니다. 당시 실제 인수 또는 명시적 제외·보존 결정이 필요했고, 아래 후속 결정으로 이번 범위를 확정했다. 유영국 전시와 작품을 별도로 등록할 구조는 있지만 실제 자료 선정/공식 근거/사람 검수 완료는 아니다.

## 당시 보류 해소 절차와 커밋 조건(아래 최종 결과로 종결)

1. 새 시험 관람으로 만료→동일 회원 재로그인→명시 복구→persisted:true→pending 제거→소유자 재조회/DB1건을 실제 UI에서 확인한다.
2. 관리자 편집/충돌/재승인 및 부족 풀/404/offline 화면의 최종 증거를 보완한다.
3. AC17 자료 인수 범위를 결정하고 증거를 연결한다.
4. 관련 자동검사·타입/빌드·검증단·문서 정합성을 재확인한다. G4 통과 후 이 기록을 완료 결과로 보강하고 W05 로컬 커밋을 남긴다.

현재 후속 모델/AWS/CI/CD 단계로 넘어가지 않았다. 기존 W01~W04 커밋과 보호 아카이브38개, 동섭 원문은 유지한다. 실제 팀 DB·개인 대화·키는 Git에 복제하지 않는다.

최종 자동검사는 PostgreSQL51건·프론트13건·타입·빌드·migration 일치까지 종료코드와 로그를 확인했다. 검증 서비스를 종료하고 볼륨을 보존했으며 시험회원 세션을 폐기·계정을 비활성화했다. 당시 W05/G4와 커밋을 보류했으며 아래 재시험 후 해제했다.

## 후속 보완·G4 최종 통과

사용자가 Git 기준 인수 및 로컬 고유자료 원본보존 후 별도인수를 명시했다. [AC17 결정](../execution-plan/2026-11-07/records/W05/data-intake-decision.md)에 실제미수령/unknown/백업완료미확인과 후속 export·해시·차이대조·dryrun·검수 절차를 기록했다. 기존 자료와 아카이브는 변경하지 않았다.

브라우저 native confirm 뒤 입력정지를 해결하기 위해 Confirmation.tsx를 추가하고 App/각 확인 호출부/app.css를 수정했다. 명시확인은 유지하면서 취소우선 focus·Tab/Escape·actor/visit/path변경취소를 넣었다. 복구는 새1점관람으로 시험해 취소시pending유지→명시확인후성공/pending제거→역사reload·DB1건을 확인했다. 이전400payload를 고쳐 성공시킨 것이 아니다.

추가 검토에서 U08 작품목록만 실패하면 무한로딩되는 경로와 A04 확정실패 catch누락을 발견했다. 독립오류/retry와 충돌 후 검토선택해제·최신조회·재검토를 구현했다. no-suggestion선택차단, A05 배정작품있는방 삭제차단, 원문 출처를 과장하지 않는 표시, 영수증 키워드의 한국어 LABELS도 보완했다. 실제 관리자409→재조회→다시검토→1점확정 및 원문변경 비공개404→재승인/재확정→provider503확정보호를 확인했다.

목록만503→버튼retry성공, 실제Vite연결중단→오류안내/재시도→서비스재시작 HMR자동회복, pool부족/후보0/404/메일미발송도 관측했다. 후자는 자동재연결이며 수동retry회복으로 과장하지 않는다.

최종 PostgreSQL51·실제프론트helper/reducer13·타입·빌드·migration일치·Compose가 통과했다. 기술/관람객/팀·교수범위 검증 역할의 추가 필수 지적이 없고 AC11~17을 근거와 연결해 G4통과로 기록했다. [최종판정](../execution-plan/2026-11-07/records/W05/gate-review.md). 시험세션4/계정2정리·서비스종료·볼륨보존. 실제모델/W06자료/AWS/CI/CD실행/실기기는 남아 있다.

CI는 기존검사를 PR마다 재현해 팀통합회귀를 막는 효과가 크다. CD는 AWS 운영결정 이후 적용한다. [CI/CD검토](../operations/CI-CD_적용검토.md)는 별도 검토이며 workflow/배포를 실행한 기록이 아니다.

G4 통과 후 실제 로컬 커밋 `631a70b96ea015921445c87370276f2588f7c10c`를 생성했다. 원격 푸시는 하지 않았다. 이어 원격 대상 fetch·fast-forward/포함 이력·민감정보 제외·확인 후 실행 절차를 [푸시 검토 준비](../operations/원격푸시_검토준비.md)에 기록했다.
