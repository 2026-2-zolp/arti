# 11/15 관리자 전시 등록·공개와 도면 반영 검수

- **기준과 환경** · `main` `d347de7`에서 시작해 `dev/임준억`의 수정 빌드를 검수했다. PC Chrome 1440×1024 관리자 화면과 375×812 관람자 화면을 별도 브라우저 세션으로 열었다. 격리된 Django·PostgreSQL에 취향 V2를 켜고 새 합성 전시를 등록했다. [11/15 개발 로드맵](../operations/2026-11-15_즉시개발과시연로드맵.md)
- **발견과 수정** · A-04의 새 작품에 외부 이미지 주소를 입력하지 않은 상태로 저장하면 Django가 400을 반환했다. 새 작품 양식에서 `imageUrl`이 빠져 있었고, 서버는 이 필드를 빈 문자열로 받을 수 있다. 양식의 초기값에 빈 문자열을 넣은 뒤 같은 화면에서 이미지 없는 작품 4점을 등록했다. [작품 등록 양식](../../frontend/src/pages/admin/A04Artworks.tsx) · [관리자 편집 계약](../../backend-django/arti/editing.py)
- **등록·공개** · A-03에서 준비 중 전시를 등록하고 A-04에서 작품 3점을 검수 완료, 1점을 검수 대기로 저장했다. A-05에서 합성 PNG 도면을 올리고 각 작품의 위치를 지정했다. 준비 중 전시의 공개 목록·직접 조회와 도면 접근이 차단됐다. 운영 중으로 전환하자 관람자 목록에 전시가 나타나고 도면 바이트가 업로드 파일과 일치했다. 검수 대기 작품은 좌표가 있어도 공개 직접 조회와 추천에서 제외됐다.
- **도면 교체와 좌표 저장** · 같은 600×400 크기의 두 번째 도면을 선택해 확인 창을 취소했을 때 기존 추천 3점이 유지됐다. 교체를 확정하자 이전 도면 공개 경로는 404가 됐고, 작품 좌표가 초기화돼 신규 추천은 0점이었다. 두 작품을 다시 놓았을 때는 2점, 나머지 작품도 놓았을 때는 3점이 추천됐다. 관리자 새로고침 후 최종 마커 3개를 확인했다.
- **관람자 반영** · 입구를 (10, 20)에서 (90, 88)로 옮기고 세 작품을 재배치하자 신규 추천이 A→B→C에서 C→B→A로 바뀌었다. C 마커를 멀리 끌어 옮기면 B→A→C, 되돌리면 C→B→A였다. 새 비회원 세션에서 취향 5쌍을 선택하고 V2로 30분 추천을 받아 같은 순서를 확인했다. 새 도면 파일, 전체 지도 마커 순서, 입구→C 및 C→B 구간의 시작·끝 좌표를 관리자 저장 값과 대조했다. 검수 범위는 좌표를 수정한 뒤 시작한 새 추천과 지도다.
- **자체 검수** · 프론트 프로덕션 빌드, 프론트 테스트 43건, PostgreSQL 도면 관리 테스트 6건, 기존 관람 브라우저 회귀 12건이 통과했다. 확대·축소와 실기기 검증은 보류 상태다.
