# 11/14 영수증 저장 응답 유실 검수

- 원격 `main` `82da7ad`와 로컬 `5a0028c`를 기준으로 격리 Compose의 합성 전시, Django, PostgreSQL 17, 프로덕션 프론트로 시험했다.
- 첫 저장을 업스트림에 전달해 실제 201 응답을 받은 뒤 Playwright가 브라우저 연결을 끊었다. 화면은 저장 실패를 표시했고, 다시 저장하기 전 회원 조회에서 이미 같은 기록 한 건이 확인됐다.
- 화면의 ‘다시 저장’은 방문 ID와 저장 본문을 그대로 보냈다. 서버는 같은 영수증 ID와 내용을 200으로 반환했고, 성공 표시 뒤 탭의 미저장 항목이 사라졌다. PostgreSQL에서도 시험 방문의 관람 행 1건과 반응 행 1건, 이유 ‘합성 반응’, 체류 21초를 확인했다. 제품 코드 변경은 필요 없었다.
- 재실행은 합성 전시를 적재한 루프백 Django를 Vite 프록시에 연결하고 `ARTI_REVIEW_BASE`와 `PLAYWRIGHT_MODULE`을 지정한 뒤 `node frontend/tests/receiptResponseLoss.browser.cjs`를 사용한다. 검사는 실제 합성 계정을 생성하고 첫 응답 유실을 브라우저에서 모의한다.

## OAuth와 가입 문안 확인

- PR #13의 기존 이메일 계정 연결 및 연결된 카카오 계정 재로그인 구현이 `main`에 포함돼 있다. 격리 기본 환경에서는 상태 API가 비활성으로 응답했다. 카카오와 가입 계약의 Django 테스트 19건이 통과했다. 팀 앱 담당·키·고정 HTTPS 콜백, 실제 연결·재로그인, 해제·복구·탈퇴 절차는 후속이다.
- U-04의 약관 필수 동의와 두 전문 보기, Django의 약관 버전 `2026-11-14-draft.1` 및 동의 시각 저장이 반영돼 있다. 운영 주체·연락처·보유와 파기 기간, 이용자 요청 절차, 외부 AI·호스팅 처리 조건은 공개 문안 확정 전에 팀 확인이 필요하다. 도슨트 미전송 질문의 탭 저장과 카카오 회원번호의 처리 범위도 최신 전문 검토에 포함한다. [가입 안내와 카카오 로그인 준비안](../operations/2026-11-14_가입안내와OAuth준비.md)
