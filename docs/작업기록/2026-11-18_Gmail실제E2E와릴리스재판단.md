# 2026-11-18 Gmail 실제 E2E와 릴리스 재판단

## Gmail 재설정 실제 검수

- `arti-gmail-trial`의 Git 제외 설정에서 앱 비밀번호의 표시용 공백 세 칸을 제거했다. 그 외 값은 사용자가 입력한 설정을 사용했다. 설정 검사, API 재기동, 루프백 HTTPS 인증서와 페이지 보호 헤더, Gmail STARTTLS 인증을 확인했다.
- 기존 회원과 구분하려고 발송 계정의 Gmail `+` 별칭으로 합성 ARTI 회원을 만들고 영수증 한 건을 저장했다. Chrome에서 재설정 요청 `204`를 확인한 뒤 그 회원 요청 한 건만 Gmail에 발송했다. 같은 계정의 INBOX를 읽기 전용으로 열어 해당 요청의 토큰 ID로 정확히 한 통을 대조했다. [Gmail 별칭](https://support.google.com/a/users/answer/9282734?hl=en)
- 받은 링크를 시험 Chrome의 루프백 컨텍스트에서 열어 URL에서 토큰 조각이 제거되는 것을 확인했다. 변경은 `204`, 링크 재사용은 `400`, 이전 세션과 이전 비밀번호는 각각 `401`이었다. 새 비밀번호로 로그인한 뒤 마이페이지에서 이전과 같은 영수증 ID 한 건을 열었고 상세 조회는 `200`이었다. HTTPS 인증서는 CLI에서 검증했다. Chrome 자동화에서는 자체 서명 인증서를 이 시험 컨텍스트에 허용했다.
- 합성 비밀번호 재설정 Chrome 회귀에 기존 영수증 1건 복구와 다른 회원의 접근 `403`을 추가해 통과했다. CI 실행기는 합성 편지함을 사용한다. 프런트 단위 검수 56개, OpenAI 비용 입력 정규화 3개와 W06 준비 검증도 통과했다.
- 실제 시험의 제품 기준은 `63670aa`다. 수신함·회원·영수증의 식별 값과 토큰을 제거한 결과만 `data/private/arti-gmail-https-1118/live-e2e-result.json`에 남겼다. 로컬 Gmail 시험 API에서 재설정은 활성, 대기열은 0건, 정기 워커는 정지 상태다. 운영 적용 전에는 공유 HTTPS 수신과 반송을 확인하고 발송 운영 담당을 정한다. [시험 환경과 발송 설정](2026-11-18_GmailHTTPS와프로젝트잔여작업.md)
