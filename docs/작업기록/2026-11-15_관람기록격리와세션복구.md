# 11/15 관람기록 격리와 세션 복구 검수

- **환경** · `main` `cca8204` 이후 로컬 도슨트 변경 `bb689a9` 위에서 PC Chrome 1280×800, 프로덕션 프론트, 별도 Django·PostgreSQL 합성 환경을 사용했다. 두 회원과 두 공개 전시의 ID를 구분했다. 텍스트·분석 모델은 비활성으로 기동했다.
- **계정·전시 경계** · 회원 A는 `fixture-ex01`에서 V2 5쌍과 3점 추천으로 관람했고, 회원 B는 별도 전시의 작품 한 점을 저장했다. 상대 계정의 목록과 영수증 상세는 양방향 403이었다. 전시에 속하지 않은 작품의 저장과 A의 V2 서명을 B 계정으로 보낸 요청은 400이었다. A의 완료된 관람을 같은 ID로 두 번째 전시에 다시 저장하려는 요청은 409였고 두 계정 목록에는 각각 자기 영수증 한 건이 남았다.
- **실제 세션 만료** · A가 마지막 작품에서 관람을 마치기 직전, 시험 DB에서 해당 세션의 `expires_at`을 과거로 옮겼다. 영수증에서 `GET /api/auth/me`가 401을 반환했고 관람 저장 요청은 0건이었다. 현재 탭에는 원래 계정·전시·관람 ID, 감상한 작품 순서, V2 취향과 서명을 담은 미저장 사본이 남았다.
- **원래 계정 복구와 다른 계정 로그인** · 복구 버튼에서 A로 재로그인한 뒤 마이페이지에서 명시적으로 복구했다. 미저장 사본과 동일한 본문을 한 번 전송해 201을 받았고, 저장된 기록 한 건과 사본 삭제를 확인했다. 별도 브라우저 세션에 동일한 미저장 사본을 넣고 B로 로그인한 경우 B의 목록만 보였고 A의 사본은 삭제됐다. 저장 요청은 0건이었다. 이 삭제는 공유 브라우저에서의 기존 계정 분리 계약이다.
