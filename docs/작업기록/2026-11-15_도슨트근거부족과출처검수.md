# 11/15 도슨트 근거 부족과 혼합 출처 검수

- **기준과 재현** · `main` `cca8204`의 Django API에 기존 고정 질문 B01을 보냈다. 모의 제공자가 근거 부족 표시와 다른 작품에서 가져온 문장을 함께 반환해도 API는 `llm` 응답과 현재 작품 출처를 내보냈다. 승인 원문이 공백일 때 자유 질문·원문 진입·일반 관찰 질문에서 제공자가 호출됐다. 근거 부족 표시를 문자열로 보내도 받아들였다. [고정 질문과 평가 기준](../execution-plan/2026-11-07/records/docent-baseline-2026-11-09/protocol.json) · [U-11 응답 계약](../execution-plan/2026-11-07/records/W02/contracts.md)
- **근거 부족 응답** · 현재 요청에 써도 되는 원문·확정 요약·확정 가이드가 없으면 제공자 호출 0회로 HTTP 200, `mode=refusal`, `sourceRefs=[]`와 서버 안내를 반환한다. 확정 가이드에서 시작하면 선택한 가이드와 그 리비전을 사용할 수 있다. 제공자가 `insufficientEvidence=true`를 보낸 경우에도 같은 안내를 쓰고 제공자의 문장과 출처를 버린다. 표시를 보낸 경우에는 불리언을 검증하고, 기존 `answer` 전용 응답도 처리한다. 잘못된 값은 502로 반환한다.
- **출처 검수** · 현재 작품의 다른 자료 종류·리비전 99, 실제로 DB에 있는 다른 합성 작품, 가짜 작품 ID를 함께 넣었다. 정상 응답에서는 서버가 선택한 현재 작품의 원문·가이드·요약 리비전만 반환했다. 근거 부족 안내에는 참조가 없다. 자료 버전 불일치나 생성 중 비공개 전환은 기존 409 동작을 검증했다.
- **브라우저** · 합성 전시의 카드 비교·추천·지도·작품에서 도슨트로 들어갔다. 근거 부족 응답은 ‘안내’ 말풍선으로 표시됐다. 새 관찰 질문이 이어졌을 때 앞선 안내는 요청 이력에 포함되지 않았고, 현재 작품의 원문 참조만 반환됐다. 뒤로가기에서 같은 작품으로 돌아왔다.
- **실행 범위** · PostgreSQL의 Django 전체 시험 181건, 프로덕션 빌드, PC Chrome 도슨트 시나리오 9건이 통과했다. Chrome에서 502·429·타임아웃 재시도, 근거 부족 안내와 혼합 출처, 자료 갱신, 작품 이동, 가이드 질문·힌트·쉬운 요약을 확인했다. 생성에 성공한 요청은 루프백 모의 제공자를 사용했다. 실제 모델의 근거 부족 판정 정확도와 답변 문장별 근거 일치는 승인 자료를 받아 평가할 항목이다. 실제 모델 호출과 실기기는 보류했다. [Django 실행기](../../backend-django/arti/tests/test_docent_harness.py) · [Chrome 실행기](../../frontend/tests/docentRetry.browser.cjs) · [남은 작업](../operations/2026-11-15_즉시개발과시연로드맵.md)
- **외부 자료 사용 방향** · 같은 작품을 다룬 소장기관 기록, 작가 재단 자료, 연구 도록을 팀이 먼저 대조해 등록한다. 원문 링크·기관명·확인일과 함께 작품 ID, 자료가 뒷받침하는 사실의 범위를 기록한다. 출처가 엇갈리면 기관별 설명과 확인이 필요한 항목을 표시한다. 작품 밖 일반 배경은 ‘참고 자료’로 제공하고, 제작 당시 사건이나 작가 의도처럼 근거가 없는 질문에는 확인할 수 없다고 안내한다. 도슨트의 실시간 웹 검색은 이번 검수 범위에서 보류한다.
