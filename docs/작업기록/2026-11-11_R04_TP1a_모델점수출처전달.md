# R04 TP1a — 모델 점수 출처의 선택적 전달과 검증

2026-11-11 / `dev/임준억` / 착수 기준 `d2975bf`. [이전 상세계획](2026-11-11_R04_동점구현상세계획.md) 다음 작업이다. 사용자가 TP1a 실행을 승인했고 프론트는 동섭님 종합본 수령 후 다시 확인하기로 했다. 일반 개발 DB 변경·공개 활성화·원격 푸시는 하지 않는다.

## 왜 이 작업을 했나

동점에 모델 점수를 보조로 쓰려면 같은 입력·모델·보정 정의에서 나온 점수인지 먼저 확인해야 한다. 이전 응답은 모델 이름과 점수만 있어 그 조건을 증명할 수 없었다. TP1a에서는 출처의 전달과 입력 결합까지만 만들고, 저장·승인된 서명 등록·동점 적용은 후속 단계로 남겼다.

## 변경 전과 후

| 대상 | 변경 전 | 변경 후 |
| --- | --- | --- |
| FastAPI 분석 | 모델명·점수만 반환 | nullable `tagEvidence`에 실제 원본 이미지 바이트·점수·고정 모델/processor artifact·보정/계산 정의의 hash 결합 |
| CLIP 로더 | 모델/processor 기본 revision 로드 | 선택적 40자리 revision과 완전한 기존 snapshot일 때 같은 로컬 경로로 로드. 전후 파일 hash 일치와 전체 로딩 성공 후에만 근거 게시 |
| 출처 미확정 | 구분할 필드 없음 | 기존 점수 동작 유지, 근거는 null. 부동 revision·임의 로컬 경로·불완전/중복 형식 cache를 추정하지 않음 |
| Django 전달 검증 | 근거 필드 처리 없음 | 실제 전송 바이트·점수·모델 및 세 checksum 확인. absent/null은 호환, 잘못된 근거는 정제된 502 |
| 기존 저장 응답 | 감정 결과에 공급자 dict 병합 | 새 근거가 감정 JSON에 우회 저장되지 않도록 제외. 태그의 기존 scores 형식 유지 |

변경 파일은 `ai-service/app/provenance.py` 신규와 `config.py`, `analyzer.py`, `image_fetch.py`, `main.py`, Django `arti/model_service.py`, `arti/providers.py`다. 모델·Django 시험 파일을 각 1개 추가했다. `.env.example`에 빈 `ARTI_CLIP_REVISION`과 한국어 안내를 추가하고 [모델 운영 안내](../operations/모델서비스_로컬운영.md)를 보강했다. 실제 env는 건드리지 않았다.

`providers.py` 조정은 계획에 없던 최소 호환 보완이다. 전달 검증 결과를 기존 코드가 통째로 저장할 수 있어, TP1b 전에 새 근거가 저장되는 것을 차단했다. models/migrations·점수 계산·8태그·보정값·추천 3/5/7·프론트·pool·기존 확정 데이터는 수정하지 않았다.

## 검증 루프와 자체 검토

1. 제한된 환경의 ASGI 시험이 1건 뒤 멈춰 중단했다. offline 설정을 유지한 채 로컬 시험 소켓이 허용된 프로세스로 재실행했다. OS 설정이나 의존성을 변경하지 않았다.
2. 모델 시험 34건 통과 후 기술/시니어 관점에서 cache 완전성·runtime 버전 누락·부분 로딩·파일 변경을 추가 검토했다. tokenizer/config/weight 4종 변경과 요청별 보정값 복사본을 보강해 최종 38건을 통과했다.
3. 방문자/운영·데이터 관점에서 구형 응답 유지, 다른 이미지·낡은 점수·모델 불일치·잘못된 checksum·경로 필드 차단과 기존 저장 형식 보존을 확인했다. Django SimpleTestCase 23건을 통과했고 DB 생성/접근은 없다.
4. 임시 FastAPI/Uvicorn과 fake scorer를 띄우고 Django의 실제 HTTP 수신 경로로 교차 확인했다. DB cursor 접근 금지 상태에서 0회, 두 공급자 저장 형식도 유지했다. 시험 서버는 종료했다.
5. 기존 스크립트 53건 통과. 팀/교수/외부 평가위원 관점에서는 이를 실제 모델 품질·사람 검수·동점 기능 완성으로 보고하지 않도록 범위를 분리했다. 같은 작성자의 역할별 자체 검토이며 독립 검수는 아니다.

모델 38건 중 신규 15건, Django 23건 중 신규 5개 시험 메서드다. 실 가중치·GPT 호출·모델 다운로드는 없다. 기존 Starlette TestClient/httpx 사용중단 경고 1건은 남아 있으며 이 과업에서 의존성을 바꾸지 않았다. 출처 hash는 무결성 확인이지 인증 서명이나 사람 승인 판정이 아니다.

[실행 기록과 A1~A4 판정](../execution-plan/2026-11-07/records/taste-tie-implementation-results-2026-11-11/TP1a/README.md)에 명령·건수·합성 HTTP 응답·소스 경계를 연결했다. 기존 계획과 계약은 시점별 아카이브로 보존하고 실제 진척은 새 실행 기록에 남긴다. 공식 W/G/AC 통과 상태를 승격하지 않았다.

## 결과와 다음 단계

TP1a의 모델/전달부 기술 기준만 통과했다. 일반 `arti-dev` DB·컨테이너·실제 env·공개풀은 변경하지 않았다. 로컬 커밋만 남기고 원격 푸시는 하지 않는다.

다음은 **TP1b**다. 기존 행을 null/0으로 호환하는 추가 필드·migration, 점수/근거/revision의 원자 저장, 실패·동시 수정·기존 확정 보호를 구현하고 격리 PostgreSQL에서 검증한다. 일반 개발 DB에 migration을 적용하지 않는다. TP2 서버 사전검증/저장 충돌 보호와 TP3 프론트는 그 이후이며, 실제 cached 모델 근거와 전체 브라우저 인수는 TP4에 남아 있다.
