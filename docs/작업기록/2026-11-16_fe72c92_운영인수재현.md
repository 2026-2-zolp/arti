## 복원 세션 분기

동일 커밋에서 실행 전용 서브넷을 명시한 임시 검사본 `arti-preflight-1a83b5d8c823`으로 재현했다. 원본·후보 PostgreSQL의 클러스터 식별자가 다름을 확인한 뒤 합성 세션 검사와 폐기는 후보에서만 했다.

- 복원 직후 원본에서 발급한 회원·관리자 토큰은 후보에서 각각 200으로 같은 영수증을 열었다. 후보에서 발급한 토큰은 원본에서 각각 401이었다.
- 후보의 합성 세션 5건을 폐기했다. 폐기 직후와 후보 API 재시작 후, 기존 회원·관리자 토큰 4개는 모두 401이었다. 후보의 세션 0건을 확인한 뒤 재로그인하자 두 역할 모두 200으로 같은 영수증을 열었다.
- 원본 회원·관리자 토큰은 계속 200이었다. 원본과 후보의 영수증은 각 1건이며 동일 ID·본문과 미디어 파일 두 개의 해시가 유지됐다. 이번 실행의 합성 Compose 자원 정리도 통과했다.

## 운영 담당이 정할 사항

- 교내 PC 로컬과 제한 HTTPS 중 주소·접근 범위를 결정한다. 빌드 커밋·이미지 식별자·DB 및 미디어의 백업 시각과 해시·보유 종료일·복원 담당을 한 회신에 적는다. 배포 주소를 채택하면 해당 주소의 TLS·미디어 접근·직접 재진입·카카오 로그를 검수한다. [운영 구성과 예산 결정안](../operations/W12_운영구성과예산결정안.md)
- 복원 대상에서 기존 세션을 유지할지 재로그인시킬지 전환 전에 결정한다. 기존 세션 행은 DB 덤프에 포함된다. 유지하면 만료 전 기존 회원·관리자 토큰으로 같은 기록을 확인한다. 재로그인을 택하면 승인된 복원 대상을 식별한 뒤 해당 대상만 폐기하고, 재시작 후 기존 401·새 로그인 200·원본 조회 유지까지 확인한다. [합성 세션 재현 절차](2026-11-16_합성복원세션검수.md)

## 후속 개발 후보

- 합성 런처가 기본 브리지 풀 포화를 구분해 표시하고, 실행 전용 명시 서브넷으로 재시도하도록 보완한다. Compose 원본과 모의 HTTPS에 모두 해당한다. 기존 프로젝트가 실행 중일 때도 두 검사가 병렬로 기동하고 시험 자원만 정리되는지 통과 기준을 둔다.
- Windows에서 Docker `sh -ec`에 전달하는 시작 명령의 줄바꿈을 LF로 정규화한다. 모의 HTTPS 런처의 임시 CRLF 사본은 API가 종료 127로 내려가 Nginx 준비 요청이 502였다. 같은 `true &&` 명령의 줄바꿈만 바꾼 대조 시험은 LF 0, CRLF 127이었다.
- 복원 세션 정책 검증을 격리 preflight에 선택 항목으로 연결한다. 원본·후보 클러스터 ID 일치 차단, 기존 세션 조회, 후보 폐기 후 재시작·재로그인, 원본 유지 여부를 상태 코드와 건수로 남긴다.
