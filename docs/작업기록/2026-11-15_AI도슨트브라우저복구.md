# 11/15 AI 도슨트 브라우저 장애 복구

- **관람 흐름** · PC Chrome의 360×812 화면에서 비회원 취향 V2 5쌍 → 30분 추천 3점 → 지도 → 첫 작품 해설 → AI 도슨트 → 같은 작품 복귀 → 나머지 작품 → 영수증을 장애별로 반복했다. 프로덕션 프론트 빌드가 격리 PostgreSQL의 합성 전시를 읽는다. 브라우저는 실제 Django API를 사용하고, Django의 제공자 어댑터는 같은 컨테이너의 루프백 HTTP 서버만 호출했다.
- **오류와 복구 기준** · 모의 제공자 500은 API 502, 제공자 429는 API 429와 `Retry-After: 30`, 제공자 응답 지연은 실제 읽기 타임아웃을 거쳐 API 504를 냈다. 오류가 나도 입력의 앞뒤 공백까지 보존되고, 성공했던 대화는 유지된다. 실패한 질문은 대화 이력에 먼저 들어가지 않는다. 다시 시도할 때 작품과 관람 ID, 자료 버전, 해설 진입 맥락, 질문, 이전 성공 이력이 동일해야 한다. 모의 제공자도 실패·재시도 요청의 본문을 바이트 단위로 비교한다.
- **429 수정** · 수정 전 Chrome에서 서버 대기 중에도 다시 시도가 가능했다. 프론트는 Django가 준 초 단위 대기를 적용하고, 입력은 편집할 수 있게 두면서 보내기·다시 시도·힌트·추천 질문 요청을 잠근다. 마감 시각은 같은 탭의 세션에 저장해 새로고침과 작품 이동에도 적용한다. 시간이 지나면 전송을 다시 허용하며 사용자가 직접 요청해야 한다. 테스트는 Playwright 시계로 대기 중 Enter와 만료 직전·직후를 확인한다. [RFC 6585 §4](https://datatracker.ietf.org/doc/html/rfc6585#section-4) · [Playwright Clock](https://playwright.dev/docs/clock)
- **제품 가드레일** · 제공자 오류 본문이 화면에 노출되지 않는지, 임의의 작품 출처 대신 서버가 현재 작품의 원문 버전·리비전을 돌려주는지, HTML처럼 보이는 응답 문자열이 화면에서 태그로 실행되지 않는지 검사한다. 타임아웃 뒤 새 입력을 쓰고 이전 질문을 재시도하면 새 입력이 남아야 한다. 복구된 답변은 한 번 표시되고, 같은 관람 ID로 세 작품의 순서가 영수증까지 이어져야 한다. 자료 변경 거절과 고정 질문의 가이드·요약 출처는 기존 API 및 브라우저 회귀에 연결한다. [OWASP 프롬프트 인젝션 방어](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) · [API 평가 하네스](2026-11-15_AI도슨트평가하네스.md)
- **검수 범위** · 브라우저 회귀는 관람 흐름과 장애 대응을 검사한다. 실제 모델의 사실성·근거 부족 응답·쉬운 재설명과 프롬프트 인젝션 저항은 승인된 자료로 사람 평가가 필요한 항목이다. 실제 모델 호출과 실기기 검증은 보류했다. [OpenAI 평가 모범 사례](https://developers.openai.com/api/docs/guides/evaluation-best-practices) · [OpenAI 워크플로 평가](https://developers.openai.com/api/docs/guides/agent-evals)
- **결과** · 도슨트 Chrome 3개 관람 시나리오, 기존 관람 Chrome 14건, 프론트 단위 43건, PostgreSQL의 도슨트·제공자 14건과 프론트 프로덕션 빌드가 통과했다. Chrome에서 재현한 영수증은 비회원 표시까지이며, 회원 저장과 자료 변경 후 초안 복구는 기존 관람 회귀에서 확인했다.

## 재현

저장소 루트에서 PowerShell과 Docker를 사용한다. 별도 합성 PostgreSQL과 미디어 볼륨을 사용하며, 로컬에 Chrome과 Playwright를 준비한다. Playwright를 다른 작업 디렉터리에 설치한 경우 `PLAYWRIGHT_MODULE`에 그 설치 경로를 지정한다.

```powershell
$project = 'arti-docent-browser-1115'
$env:ARTI_DB_PASSWORD = 'docent-browser-postgres-test-only'
$env:DJANGO_SECRET_KEY = 'synthetic-docent-browser-django-key-only'
docker compose -p $project up -d --wait db
docker build -t arti-docent-browser-api:local ./backend-django
$mount = (Get-Location).Path + ':/repo:ro'
$api = @('--rm', '--network', "${project}_default",
  '-e', "PGPASSWORD=$env:ARTI_DB_PASSWORD", '-e', 'DJANGO_SECRET_KEY',
  '-e', 'ARTI_ENV=test', '-e', 'ALLOW_TEST_FIXTURES=true',
  '-e', 'ARTI_TASTE_PROFILE_V2_ENABLED=true',
  '-v', $mount, '-v', "${project}_media_data:/app/media",
  '-w', '/repo/backend-django')
docker run @api arti-docent-browser-api:local python manage.py migrate --noinput
docker run @api arti-docent-browser-api:local python manage.py load_test_fixture
docker run @api -p 127.0.0.1:4056:8000 arti-docent-browser-api:local python manage.py shell -c 'from arti.tests.docent_browser_server import serve; serve()'
```

별도 PowerShell에서 프록시와 프리뷰를 실행한다.

```powershell
$env:VITE_API_TARGET = 'django'
$env:VITE_API_PROXY = 'http://127.0.0.1:4056'
npm --prefix frontend run build
npm --prefix frontend run preview -- --host 127.0.0.1 --port 5239 --strictPort
```

세 번째 PowerShell에서 `node frontend/tests/docentRetry.browser.cjs`를 실행한다. 포트를 바꿨으면 `ARTI_REVIEW_BASE`에 프리뷰의 루프백 주소를 지정한다. 시험은 `X-Arti-Docent-Mock` 응답 헤더를 확인하고 해당 로컬 주소 밖의 브라우저 요청을 차단한다.
