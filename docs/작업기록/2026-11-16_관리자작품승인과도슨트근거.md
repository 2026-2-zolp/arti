# 관리자 작품 승인과 도슨트 근거 검수

- 기준은 `main`의 `9111fb1`과 로컬 이미지 분석 수정 `85eede8`이다. 합성 전시와 PostgreSQL, 모의 제공자를 사용했다. 관리자 등록·수정에는 기존 편집 API를 직접 호출했고, 관람 쪽은 같은 작품의 공개 목록·상세와 도슨트 API로 검수했다.
- 수정 전에는 A-04의 화면 검사를 건너뛴 직접 등록·수정 요청이 빈 출처나 해설을 포함해도 200으로 처리됐다. Django에서 `approved`로 저장하려는 경우 해설과 출처가 모두 있어야 한다는 조건을 검사한다. 누락이나 공백만 있는 값은 `400 VALIDATION_ERROR`로 처리하고, `pending`과 `source_check`는 검수할 내용을 아직 모으는 상태로 저장할 수 있다. 출처 서술과 참고 URL은 기존처럼 별도 필드다.
- 승인 작품의 출처·원문 변경은 별도 승인 전까지 공개 목록·상세와 도슨트에서 제외한다. 이전 편집 버전의 승인 요청은 409로 처리한다. 최신 원문을 승인하면 해당 원문과 출처가 공개되며, 쉬운 요약과 가이드 질문·힌트는 별도로 검토해 확정한 뒤 공개된다. 이전 관람 화면의 `contentVersion`을 보낸 질문은 `409 CONTENT_CHANGED`를 반환한다. 미공개 작품, 오래된 버전, 미확정 요약·가이드 진입은 모의 제공자를 호출하지 않았다.
- 공개된 같은 합성 작품에 세 경로로 같은 질문을 보냈다. 모의 제공자는 각각 최신 원문, 확정 요약, 확정 가이드 질문을 받았다. 세 응답의 참조가 현재 작품 ID와 `sourceVersion`, 자료별 `revision`에 일치했다. 가이드 질문은 브라우저가 보낸 문구 대신 서버에 확정 저장된 문구를 사용했다.
- 맞춤 해설 API(`POST /api/artworks/:id/explanation`)는 생성 중 원문이 바뀌면 이전 해설을 200으로 내보냈다. 도슨트 자유 질문과 같은 공개 상태·콘텐츠 버전 검사를 응답 직전에 적용했다. 생성 중 변경은 `409 CONTENT_CHANGED`, 재승인 전 다시 요청하면 404로 처리한다.
- Django PostgreSQL 전체 194개와 최종 승인·도슨트 집중 회귀 3개가 통과했다. PC Chrome의 기존 가이드 질문·힌트·쉬운 요약 회귀도 통과했다. 502 후 자료가 바뀐 경우 409를 받은 뒤 입력을 보존하고 최신 근거로 다시 질문해 관람을 이어갔다. [Chrome 회귀 재현](2026-11-15_AI도슨트가이드와요약복구.md#재현)

## 재현

백엔드 잠금 의존성이 설치된 Python과 운영 자료가 없는 별도 PostgreSQL에서 실행한다. `ARTI_ENV=test`, `ALLOW_TEST_FIXTURES=true`, `ARTI_LLM_PROVIDER=disabled`를 설정하고 `OPENAI_API_KEY`와 `ARTI_MODEL_SERVICE_URL`은 빈 값으로 둔다. 테스트가 합성 작품을 적재하고 제공자 응답을 모의한다.

```powershell
& $env:ARTI_TEST_PYTHON backend-django/manage.py test arti.tests.test_integration --noinput
```
