# 11/17 관리자·계정·지도·모델 후속 검수

## 1. 관리자 AI 운영 로그

- 운영 로그 Chrome이 Django 분석 API를 직접 호출하도록 변경했다. 요약 생성 성공·가이드 `502`가 섞인 `200` 응답과 가이드 단독 `502`를 같은 화면에서 확인했다. 요청 두 건은 부분 실패 한 건과 AI 요청 오류 한 건으로 집계됐다. 비활성 태그·감정 항목과 모의 제공자의 상세 오류 문구는 로그에 표시되지 않았다.
- PR의 **Admin Chrome (operations log)**을 전용 합성 DB에 연결했다. 후속 사용량은 요청 한 건과 실제 모델 호출 수를 구분하고, 응답별 입력·출력 토큰과 미수집을 표시하는 방안부터 모의 검수한다. 비용·관리자 키 설정은 과금 출처와 운영 권한이 정해진 뒤 연결한다.

## 2. 비밀번호 재설정

- PR의 **Account Chrome (password reset)**을 별도 합성 DB와 메모리 메일함에 연결했다. 등록·미등록 이메일의 응답, 메일 수신 1건, 이전 비밀번호 로그인 `401`, 기존 세션 만료와 다른 회원 세션 유지를 확인했다. 새 비밀번호로 재로그인한 뒤 회원 ID가 같았다.
- 실제 발송 단계는 팀 발신 주소, HTTPS, SMTP, 주기적 발송 작업과 가입 주소 확인 기준이 필요하다. 준비 뒤 시험 편지함으로 수신·반송·복구, 회원 및 영수증 유지부터 검수한다. [시험 배포 순서](../operations/비밀번호재설정_로컬검수와배포준비.md#시험-배포에서-켤-때)

## 3. A-05 지도

- 전시실 세 곳과 작품 일곱 점을 합성 도면에 배치했다. 같은 방의 작품 간에는 이동선이 표시됐다. 방 사이가 끊겼을 때 A·B 각각에서 가까운 문을 표시하고, 도착 쪽 문 후보 두 개 중 가까운 후보를 강조했다. 연결 문을 추가하자 미리보기가 연결됐고, 저장과 새로고침 뒤 관람자 지도가 반영됐다. 수평 SVG 선은 선 길이와 스트로크로 검수한다.
- 팀 PC가 독립 재현하면 가까운 문이 실제 통행 가능 여부와 일치하는지 확인한다. 현장 도면을 받으면 출입 제한·일방통행·다른 방의 우회 경로를 우선 확인한다. 직접 관람 운영 적용은 팀 회신 뒤 결정한다. [팀 PC 검수](../operations/2026-11-17_PR50_팀PC검수.md)

## 4. 카나나와 Luna 비교

- 고정한 원문 `L01`~`L03`의 해시를 검증하고 모델별 요약·가이드 두 회씩 총 12쌍의 평가 실행표를 생성했다. X/Y 배정을 대조하고 원문 변조 시 실행표 생성이 중단되는지 확인했다. 3B와 예비 1.3B의 공식 개정을 기록했다.
- 실제 비교는 WSL 실행기 준비와 고정 3B의 초기 로딩 한 건부터 진행한다. 여유가 부족하면 1.3B를 별도로 검토한다. 실제 호출이 재개되면 같은 원문으로 근거·수정 시간·지연·메모리를 기록하고 평가표를 채운다. [실행표와 고정 개정](../operations/2026-11-17_도슨트모델과관리자운영검토.md#원문-비교-실행표-준비)

## 5. 카카오 OAuth

- 기존 이메일 계정 연결 기준으로 팀 앱 소유자, HTTPS 경로, ID 일치·중복 차단·로그·이메일 로그인 복귀를 첫 연동 인수표에 정리했다. 팀 앱이 준비되면 콘솔과 콜백을 확인한 뒤부터 시작한다. [첫 실제 시험 인수표](../operations/카카오로그인_첫연동가이드.md#4-첫-실제-시험-인수표)

프런트 빌드와 새 CI 두 명령, 전체 지도·직접 관람 Chrome을 각각 합성 환경에서 통과했다. 워크플로 매트릭스는 로컬에서 대조했다. GitHub Actions 실행, 실제 메일 발송·모델 호출·카카오 로그인·실기기와 PR #50 병합은 후속 확인 범위다.
