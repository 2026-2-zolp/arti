# 11/17 작품 확정·폐기·철회와 관람 연결

- 제품 기준은 PR #46 병합 커밋 `2236ded`다. 합성 PostgreSQL과 PC Chrome, 루프백 모의 제공자로 검수했다. [PR #46](https://github.com/2026-2-zolp/arti/pull/46) · [main 검사](https://github.com/2026-2-zolp/arti/actions/runs/43941432659)
- A-03 전시명에서 A-04 작품명으로 Enter 진입하고 관람가이드 제안을 확정했다. 위치가 없을 때 추천 0점이었고, A-05 도면을 올려 좌표를 저장한 뒤 추천과 U-09에서 같은 작품과 지점을 확인했다. U-10의 관찰 질문에서 U-11을 열어 응답의 작품 ID·원문 버전·가이드 개정 번호를 공개본과 대조했다.
- 다시 생성한 제안을 폐기한 뒤 확정 질문·힌트와 작품 좌표, 추천 목록, 공개 내용 버전과 도슨트 근거가 유지됐다. 이미 열어 둔 U-11에서 같은 근거로 다시 질문해 200을 받았다.
- A-04 검수 상태를 ‘출처 확인’으로 바꾼 뒤 공개 목록과 추천은 0점이었고, 개별 상세와 도슨트 요청은 404였다. 이전 빌드에서 첫 404 뒤 작품 화면으로 돌아가는 안내가 없어 회귀 검사가 실패했다. 수정본 U-11은 이전 작품·답변을 화면에서 내리고 질문 초안을 보존한다. 추가 전송을 막고 ‘작품으로 돌아가기’를 제공하며, 복귀한 U-10에서 ‘이 작품 건너뛰기’로 이어지는 것도 확인했다.
- 같은 통합 회귀의 실행 조건은 기존 관리자 분석 Chrome과 같다. 별도 합성 DB에서 V2를 켜고 프론트 빌드 후 `node frontend/tests/adminAnalysis.browser.mjs`를 실행한다. 별도 환경의 도슨트 502·429·504 재시도와 근거 부족 회귀, 합성 W06 인수 두 건, 프론트 47건과 빌드를 확인했다. [관리자 Chrome](../../frontend/tests/adminAnalysis.browser.mjs) · [실행 조건](2026-11-16_관리자분석중작품변경Chrome.md)
