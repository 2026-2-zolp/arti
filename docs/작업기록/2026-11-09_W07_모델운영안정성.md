# W07 모델 운영 안정성과 저장 보호

2026-11-09 / 출발b8fac09 / dev/임준억. 팀원 답변과 독립적으로 진행할 과업 중 모델 서비스 안정성부터 수행했다. 앞선 [독립 검수 준비](2026-11-09_W06_독립검수준비와사용범위확인.md)와 실제 모델 기동·40점 평가를 다시 사람 승인으로 해석하지 않는다.

## 배경과 변경 전후

FastAPI 직접 요청은 로딩을 기다리거나 여러 추론이 겹칠 수 있었다. 일부 모델만 게시된 초기화도 준비 완료 판단과 섞일 여지가 있었다. ai-service/app/runtime.py의 단일 로딩/추론 슬롯과 health/ready 구분을 추가하고 analyzer.py는 모든 구성요소가 성공한 뒤 게시하게 했다. main.py는 로딩503·과부하429와 상태·busy 시간을 제공한다. 로딩 실패/시작 실패 후 슬롯이 남지 않고 다음 요청은5초 backoff 후 재시도한다.

Django의 providers.py는 요청 안에서 결과와 실패를 모두 공유한다. 이전에는 태그 실패 후 감정에서 같은 upstream을 반복할 수 있었다. model_service.py는429를 RATE_LIMITED로 보존하고, timeout30초·연결/잘린 응답을 정제한다. editing.py는 실제 재시도 대기 정보를 보존하되 기존 부분 성공·suggested 저장·원문 승인/확정 보호·버전 충돌 정책은 유지한다.

새 tests/test_runtime.py와 Django tests/test_model_operations.py는 이벤트·실제 로컬HTTP·PG를 사용해 로딩/동시 요청/실패·복구/timeout·늦은 응답·버전 경합을 검증한다. 원래 test_model_service.py에는 잘린 HTTP 전송 검사를, test_api.py에는 작성 비활성 차단과 독립된 가짜 writer 조건을 보완했다. [운영 기준](../operations/모델서비스_로컬운영.md)과 [검증 근거](../execution-plan/2026-11-07/records/W07-preparation/model-operations-2026-11-09/README.md)를 추가했다.

## 검증 루프와 결과

처음 새 pytest 상대 import와 전용 임시폴더 상위 경로 오류를 수정해22개를 통과했다. 검토에서 로더 완료 시점 경합·스레드 시작 실패를 보완해 Windows23개를 통과했다. Linux 작성 비활성 조건에서 기존 write 시험의 환경 의존2건을 발견해 활성 조건 명시·비활성 모델 호출 차단을 추가한 뒤 Torch 없는 Linux24개가2.62초에 통과했다. Starlette/httpx deprecation warning은 남아 있으며 성공과 구분한다.

PG96개가 먼저 통과했고 잘린HTTP 응답 처리 검사를 추가해 최종97개가47.183초에 통과했다. 지연 HTTP timeout504/429/503에서 값·검수상태·버전은 그대로였고, 늦은 응답 뒤에도 불변이며 다음 요청은 성공했다. upstream 호출은 요청별1회였다. 다른 DB연결에서 버전 변경 후 성공 응답을 보내도 API409로 옛 분석값을 저장하지 않았다. 기존 PostgreSQL cross-connection advisory lock 검사도 포함했다.

실제 고정 CLIP/mDeBERTa·오프라인 CPU4스레드로 별도 프로세스를 실행했다. cold/loading503, 동시2건200+429, caller20ms timeout 뒤 실제 계산 완료까지429, 완료 후200을 확인했다. 실제 Django 추론 진행 중 프로세스를 끊으면502, 중단 상태는503이었으며 재기동 후8태그/6감정 응답으로 복구했다. 최종 모델 준비5.81초/재기동9.53초, 동시 성공4.93초/거절4ms, peak RSS1261.04MiB였다. 이는 제한된 단일 실측이고 품질/운영 SLA가 아니다.

추론 단계의 DB 없는 실제 모델 시험과 저장 단계의 PG+지연HTTP 시험을 분리해 기록했다. native 시험 이후 HTTPTransportError 정규화를 더했으므로 sourceHashes 차이와 별도 회귀 근거도 남겼다. 모델 runtime/추론 소스는 같은 최종 코드다. 유료GPT·유영국 자료·보정값은 사용/변경하지 않았고 일반 arti-dev16점 상태 해시가 이전 격리 기록과 동일했다. 프론트/브라우저는 이번에 바꾸거나 재시험하지 않았다.

## 검증단 판정과 한계

기술/시니어는 단일 슬롯·경합·프로세스 로컬 범위·late 응답을, 데이터/운영은 값/상태/버전 보존·관측/재시작·원본/비밀값 보호를, 방문자/콘텐츠는 무한대기/가짜성공을 만들지 않는지 확인했다. 팀/교수/평가위원은 실제 추론·가상장애·최종 품질의 주장을 분리했다. 동일 작성자의 관점별 자체 검토이며 실제 외부 승인은 아니다.

로컬 단일 프로세스 운영 기준은 통과했다. native 계산을 caller timeout으로 강제 취소하지 않고 완료까지 슬롯을 유지한다. 영구 정체는 운영자가 프로세스를 재시작해야 한다. 다중 worker 전역 제한·watchdog·분산 queue·외부 배포 용량은 이번 범위가 아니다. 새 운영에서는 legacy Kanana write를 비활성으로 두며 /write를 함께 켰을 때 자원 보호를 보장하지 않는다.

W06/W07/G5의 정식 품질/검수 상태는 유지한다. 다음 독립 기술 과업은 W11 PR CI 검증과 W12 운영 결정안이다. 실제 라벨이 들어오면 콘텐츠/품질 평가를 이어간다. 로컬 커밋만 남기고 푸시하지 않는다. 시험 컨테이너는 종료하고 볼륨은 보존하며 일반 개발 API는 재생성하지 않는다.

최종 계획 검사: 오류0/보호38개, guardrail25개, W02계약 오류0을 확인했다.30초를 관리자 전체 요청의 총기한으로 오인하지 않도록 모델 HTTP 경계의 제한임을 운영 안내에 명시했다.
