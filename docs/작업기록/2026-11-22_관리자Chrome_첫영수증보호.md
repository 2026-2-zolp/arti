# 관리자 Chrome 회귀와 첫 영수증 보호

2026-11-22. 기준 커밋은 `1a450e7`이다. 합성 데이터와 격리된 PostgreSQL로 확인했다.

## 관리자가 작품을 비공개로 바꿀 때

- 검수 완료 작품이 검수 대기나 출처 확인 상태로 바뀌면 일반 관람 화면에서 즉시 숨긴다. 승인된 원문이나 도판 변경으로 출처 재검수가 필요해지는 경우에도 같은 규칙을 적용한다.
- 비공개 전환 후 72시간 동안 서버가 영구 삭제를 보류한다. A-04는 보류가 끝나는 한국 시각을 표시한다. 회원이 비공개 전에 같은 작품과 관람 ID로 받은 서명된 작품 정보가 첫 영수증 저장의 근거가 된다.
- 유예 중에 비공개 초안을 다시 수정해도 기한을 늘리지 않는다. 유예 후에도 영수증, 대화, 취향 조사, 관람 순서 등 연결된 기록이 있다면 삭제를 차단한다. 처음부터 비공개로 새로 작성한 미연결 초안은 관리자가 삭제할 수 있다.
- 회원에게 관람 증빙을 발급할 때 같은 작품 행을 잠근다. 비공개 전환과 증빙 발급이 동시에 들어오면 먼저 처리된 상태를 기준으로 응답한다. 영수증 제출과 삭제는 전시 행 잠금으로 직렬화한다.

## 검수

- PostgreSQL 17의 Django 관련 테스트 19개를 통과했다. 비공개 직후 삭제는 `409`, 회원 첫 저장은 `201`, 같은 관람 ID로 두 번 재시도하면 `200`이었다. 영수증 ID와 작품 스냅샷이 일치했고 DB에는 영수증 1건과 좋아요 1건이 남았다. 본인은 조회할 수 있고 다른 계정은 `403`이었다.
- 작품 비공개와 전시 종료 각각을 PostgreSQL 17과 Django에 연결한 Chrome에서 검증했다. 서버가 처음 `201`을 반환한 뒤 응답을 끊고, 다시 저장·새로고침·뒤로가기를 거쳐 `200` 세 번과 동일한 영수증 ID를 확인했다. 회원·관리자 목록에도 한 건이었고, 감상 시간·반응·사유를 확인했다.
- `Admin Chrome (catalog controls)`를 PR CI에 연결했다. 로컬에서는 빌드한 프론트와 실제 Django·PostgreSQL을 연결해 전시·작품 삭제 취소의 요청 0건, 이전 버전 `409`와 최신 버전 `204`, 비공개 도판 확대·닫기 후 포커스, 지도 저장 전 요청 0건과 저장 후 1건을 확인했다. 새로고침과 V2 관람자 지도에서 남은 구조물만 표시됐다.
- 프론트 테스트 78개, 프로덕션 빌드, 계획·계약 검사도 통과했다.

Chrome 재현에는 [CI의 합성 DB와 관리자 준비 단계](../../.github/workflows/ci.yml)를 사용한다. 관리자 검사는 저장소 루트에서 `node frontend/tests/adminCatalog.browser.mjs`로, 영수증 검사는 별도 합성 환경에서 `node frontend/tests/receiptVisibility.browser.cjs`로 실행한다. GitHub Actions의 새 작업 결과는 PR을 열 때 확인한다.

## 운영 반입 순서

마이그레이션 `0024_artwork_receipt_protection`은 비공개 작품의 마지막 수정 시각이 최근 72시간 이내인 기존 행에 수정 시각 기준 유예를 채운다. 해당 행에는 전환 이력이 따로 남아 있지 않아 최근 수정 건을 보수적으로 보호한다. 앞으로는 작품이 비공개로 바뀐 시점이 기준이다.

합성 DB에 0023을 적용한 상태에서 최근 비공개 작품, 오래된 초안, 승인 작품을 만든 뒤 0024로 올렸다. 세 행을 보존했고 최근 비공개 작품에만 유예 시각이 생겼다. `makemigrations --check --dry-run`도 통과했다.

실제 배포 시에는 운영 백업과 복원 확인 후 API 이미지 전환 전에 PostgreSQL 마이그레이션을 적용하고, 스키마 확인 뒤 API를 교체한다. CD의 스키마 검사 단계에서 이 변경을 먼저 확인한다.
