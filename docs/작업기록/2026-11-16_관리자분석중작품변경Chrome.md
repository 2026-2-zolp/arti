# 관리자 분석 중 작품 변경 Chrome 회귀

## 결과

- `dev/임준억`의 `eb5d1b9` 기준으로 관리자 Chrome 두 탭을 같은 합성 작품에 연결했다. Django·PostgreSQL과 루프백 HTTP 분석 모의 제공자를 사용했다. 관리자는 실제 로그인하고 합성 작품의 생성·이미지 업로드·원문 저장·요약 확정을 제품 API로 처리했다.
- 첫 탭이 이전 원문을 바탕으로 보낸 분석을 대기시킨 뒤, 둘째 탭에서 새 원문과 요약을 저장했다. 원문 버전이 증가하고 검수 상태와 확정 요약이 재검토 상태가 된 것을 확인했다. 둘째 탭에서 새 원문을 검수하고 요약을 다시 확정했다.
- 이전 원문의 공급자 응답을 풀자 첫 탭은 `409 VERSION_CONFLICT`를 받았다. 작품 상세를 다시 조회한 응답은 둘째 탭의 최신 저장 결과와 일치했다. 기존 화면의 **분석 다시 시도**는 같은 구버전으로 요청해 `409`를 반복했다.
- `409 VERSION_CONFLICT`에서 **최신 작품 다시 불러오기**를 표시하고 최신 상태를 받기 전까지 분석 버튼을 비활성화하도록 관리자 작품 상세를 수정했다. 확인을 취소하면 첫 탭에 입력한 미저장 수정이 유지된다. 확인하고 다시 불러오면 둘째 탭에서 저장한 최신 상태가 표시되고 분석 버튼을 다시 사용할 수 있다.
- 최신 상태에서 **AI 다시 분석**을 눌러 `200`을 확인했다. 모의 제공자에 전달된 이전·최신 원문을 각각 SHA-256으로 대조했다. 새 태그·감정 제안이 반영됐고, 둘째 탭에서 확정한 요약과 원문 버전은 유지됐다. 시험 중 실제 모델 호출과 실기기 검증은 보류했다.
- 실제 Chrome 회귀의 반복 실행, 프론트 타입 검사와 테스트 44개, PostgreSQL 분석·태그 저장 테스트 21개가 통과했다.

## 재현

1. 전용 루프백 PostgreSQL에 `arti_admin_analysis` 또는 `arti_admin_analysis_<suffix>` 형식으로 합성 DB를 준비한다. `PGHOST=127.0.0.1`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, 합성용 `DJANGO_SECRET_KEY`와 별도 `MEDIA_ROOT`를 지정한다.
2. `ARTI_ENV=test`, `ALLOW_TEST_FIXTURES=true`, `ARTI_LLM_PROVIDER=disabled`를 지정하고 `ARTI_MODEL_SERVICE_URL`은 빈 값으로 둔다. 일회용 시험 관리자 비밀번호 `ARTI_BOOTSTRAP_PASSWORD`를 설정한 뒤 같은 환경에서 저장소 루트에서 실행한다.

```powershell
& $env:ARTI_TEST_PYTHON backend-django/manage.py migrate --noinput
& $env:ARTI_TEST_PYTHON backend-django/manage.py load_test_fixture
& $env:ARTI_TEST_PYTHON backend-django/manage.py bootstrap_admin --login-id admin-analysis-admin --name 'Synthetic Analysis Admin'
$env:VITE_API_TARGET = 'django'
$env:VITE_API_BASE = '/api'
npm.cmd --prefix frontend run build
node frontend/tests/adminAnalysis.browser.mjs
```

`ARTI_TEST_PYTHON`에는 백엔드 잠금 의존성을 설치한 Python 경로를 넣는다. 시험 스크립트는 제품 프론트 빌드를 Vite 프리뷰에서 열고, Django와 모의 제공자를 자동 할당한 루프백 포트에서만 실행한다. 별도 빌드는 `ARTI_BROWSER_DIST`에 지정할 수 있다. 합성 관리자와 기반 자료를 이미 적재한 DB에서는 마지막 시험 명령만 실행하면 된다.
