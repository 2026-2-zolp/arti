# 카카오 계정 연결·재로그인 모의 검수

## 검수 결과

- **환경** · PR #34의 작업본 `f9d1371`에서 PC Chrome, 루프백 HTTPS Vite, Django와 전용 합성 PostgreSQL 17을 연결했다. Chrome에서 카카오 인가 페이지 요청을 가로채고 서버의 토큰·JWKS 응답을 모의로 제공했다. 기존 Django 테스트의 RSA 서명 자료를 재사용해 실제 콜백의 PKCE·nonce·서명 검증 경로를 실행했다. HTTPS 인증서는 시험마다 임시 생성했다.
- **취소와 연결** · 합성 이메일 회원이 로그인한 상태에서 카카오 연결을 취소하면 안내 뒤 마이페이지로 돌아갔고, 기존 회원 토큰과 미연결 표시가 유지됐다. 다시 연결하면 연결됨이 표시됐다. 제품 로그아웃은 204였고 이전 토큰으로 회원 조회하면 401이었다.
- **오래된 완료 탭** · 같은 브라우저의 두 탭에서 차례로 로그인을 시작했다. 앞선 탭의 완료 요청은 `400 KAKAO_INVALID_FLOW`로 거절됐고 그 시점에는 세션 토큰이 없었다. 최신 탭에서 완료하자 마이페이지로 돌아가며 새 세션이 발급됐다.
- **계정과 관람 기록** · 카카오 재로그인 전후 회원 ID, 저장된 V2 취향의 태그·스냅샷·버전을 대조했다. 마이페이지에서 같은 영수증을 열었고, 목록에는 기존 영수증 한 건만 있었다. 영수증 상세 응답과 화면에 표시된 관람 작품도 확인했다.
- **HTTPS 경계** · Chrome에서 흐름 쿠키의 `Secure`·`HttpOnly`·`SameSite=Lax`·경로 `/`를 확인했고 완료 후 쿠키는 삭제됐다. 콜백 응답에 `Cache-Control: no-store`와 `Referrer-Policy: no-referrer`가 있었고 완료 URL에는 상태 프래그먼트만 남았다.
- **회귀** · 같은 합성 DB에서 Chrome 경로를 연속 두 번 실행했고 기존 Django PostgreSQL 카카오 테스트 11건도 통과했다. 이번 HTTPS 검수는 PC의 Vite 루프백 환경에서 진행했다. 운영 Nginx와 등록된 HTTPS 주소의 연결, 실제 카카오 앱·실제 모델·실기기는 후속 확인 범위다.

## PowerShell 재현

잠금 의존성이 설치된 백엔드 가상 환경과 프론트, Docker와 PC Chrome을 준비한다. 아래 명령은 저장소 루트에서 실행한다. 5591은 이 시험용 PostgreSQL 포트이며, 브라우저 프리뷰는 기본값으로 루프백 5593을 사용한다.

```powershell
docker run --rm -d --name arti-kakao-browser-1116 -p 127.0.0.1:5591:5432 -e POSTGRES_DB=arti_kakao_browser -e POSTGRES_USER=arti -e POSTGRES_PASSWORD=synthetic-kakao-browser-db postgres:17-alpine
for ($dbCheck = 0; $dbCheck -lt 20; $dbCheck++) {
    docker exec arti-kakao-browser-1116 pg_isready -h 127.0.0.1 -U arti -d arti_kakao_browser
    if ($LASTEXITCODE -eq 0) { break }
    Start-Sleep -Milliseconds 500
}
if ($LASTEXITCODE -ne 0) { throw '카카오 검수용 PostgreSQL이 준비되지 않았어요.' }

$env:ARTI_ENV = 'test'
$env:ALLOW_TEST_FIXTURES = 'true'
$env:ARTI_LLM_PROVIDER = 'disabled'
$env:ARTI_MODEL_SERVICE_URL = ''
$env:OPENAI_API_KEY = ''
$env:ARTI_KAKAO_CLIENT_ID = ''
$env:ARTI_KAKAO_CLIENT_SECRET = ''
$env:ARTI_KAKAO_CALLBACK_URL = ''
$env:DJANGO_SECRET_KEY = 'only-synthetic-kakao-browser-regression-1116'
$env:PGHOST = '127.0.0.1'
$env:PGPORT = '5591'
$env:PGDATABASE = 'arti_kakao_browser'
$env:PGUSER = 'arti'
$env:PGPASSWORD = 'synthetic-kakao-browser-db'
$env:MEDIA_ROOT = Join-Path $PWD 'data/private/kakao-browser-1116'
$env:ARTI_TEST_PYTHON = (Resolve-Path 'backend-django/.venv/Scripts/python.exe').Path
& $env:ARTI_TEST_PYTHON backend-django/manage.py migrate --noinput
if ($LASTEXITCODE -ne 0) { throw '검수 DB 마이그레이션에 실패했어요.' }
& $env:ARTI_TEST_PYTHON backend-django/manage.py load_test_fixture
if ($LASTEXITCODE -ne 0) { throw '합성 전시를 불러오지 못했어요.' }
$env:VITE_API_TARGET = 'django'
$env:VITE_API_BASE = '/api'
npm.cmd --prefix frontend run build
if ($LASTEXITCODE -ne 0) { throw '프론트 빌드에 실패했어요.' }
node frontend/tests/kakaoAuth.browser.mjs
```

브라우저 실행기가 Django 모의 서버·HTTPS 프리뷰를 시작·종료하고 시험 인증서를 정리한다. 고정 포트가 이미 사용 중이면 `ARTI_KAKAO_BROWSER_PORT`에 별도 루프백 포트를 지정한다. DB에 합성 전시가 준비돼 있으면 마지막 브라우저 명령으로 다시 실행한다. 검수가 끝나면 `docker stop arti-kakao-browser-1116`으로 전용 DB를 종료한다.
