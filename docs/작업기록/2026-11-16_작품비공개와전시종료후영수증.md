# 11/16 작품 비공개·전시 종료 후 첫 영수증 저장

- **기준** · `main` `bd9c321`. 격리 PostgreSQL에 합성 전시 `fixture-ex01`을 적재했다. PC Chrome과 실제 Django API를 연결했고 도슨트·분석 제공자는 비활성화했다.
- **기존 재현** · 감상을 마친 작품을 비공개로 바꾸면 작품 조회는 404, 회원 영수증 첫 저장은 400이었다. 전시 상태를 종료로 바꾸면 공개 전시 조회와 첫 저장이 모두 404였다. 영수증 화면이 현재 공개 전시·작품 조회를 기다려 종료된 전시에서는 새 영수증을 만들 수 없었다.

## 변경

- 공개 작품을 감상할 때 Django가 회원·관람 ID·전시·작품에 묶인 영수증 근거를 발급한다. 현재 공개 목록에서 빠진 작품은 **그 관람에서 발급한 서명이 있을 때만** 첫 저장에 포함한다. 서명에는 작품 식별자·제목·작가·연도·태그와 당시 전시 제목·장소를 담는다. 기존 취향 근거와 같은 72시간 유효 기간을 사용한다.
- 앱은 작품 감상을 마칠 때 영수증에 필요한 정보와 근거를 탭에 보존한다. 전시 조회가 404가 된 지도에서는 ‘지금까지 관람으로 마치기’로 완료한 작품만 영수증에 싣는다. 새로고침이나 영수증 복귀는 탭의 동일 저장 본문을 재사용한다.
- 비공개 작품·종료 전시의 공개 조회는 404로 유지된다. 회원 영수증의 비공개 작품 스냅샷에는 서명 당시의 기본 정보만 남는다. 도판·해설·이미지 경로는 들어가지 않는다. 공개 변경 전에 근거를 발급받지 못한 이전 관람은 서버에서 비공개 작품의 첫 저장을 계속 거절한다. 이미 저장된 영수증은 기존 재시도·조회 규칙으로 복구한다.

## 검수

- **작품 비공개** · V2로 추천받은 첫 작품을 감상한 뒤 관리자가 비공개로 변경했다. 새로고침과 브라우저 앞뒤 이동 후 나머지 2점을 감상했다. 회원 영수증에 총 3점과 첫 작품의 체류 21초·좋아요·이유가 남았다.
- **전시 종료** · 첫 작품 감상 뒤 관리자가 전시를 종료했다. 앞뒤 이동·새로고침·지도 재시도 후 ‘지금까지 관람으로 마치기’로 종료했다. 첫 작품과 체류 21초·좋아요·이유가 남았고, 미감상 작품은 포함되지 않았다.
- **저장 응답 유실** · 두 경우 모두 서버의 첫 `201` 응답을 Chrome에 전달하기 전에 연결을 끊었다. ‘다시 저장’·새로고침·뒤로가기 후 ‘머무르기’가 모두 같은 관람 ID·요청 본문·영수증 ID로 `200`을 받았다. 회원·관리자 조회와 PostgreSQL에서 시나리오마다 관람 행 1건과 반응 행 1건을 확인했다.
- **권한과 기존 흐름** · 서명 위조, 다른 계정·관람·작품에서 재사용하는 요청을 거절한다. 비회원은 화면에서 영수증을 이용하며 회원 저장은 발생하지 않는다. 실제 모델 호출과 실기기 시험은 보류했다.
- **회귀 결과** · PostgreSQL Django 전체 183건, 프론트 44건과 프로덕션 빌드, 기존 Chrome 관람 15건과 저장 응답 유실 1건을 통과했다. 마이그레이션 변경은 없다.

## 재현

- 합성 전용 DB와 미디어 볼륨에서 Django 마이그레이션과 `load_test_fixture`를 실행한다. `ARTI_TASTE_PROFILE_V2_ENABLED=true`, `ARTI_LLM_PROVIDER=disabled`로 띄우고 분석 모델 URL은 비운다. 합성 관리자 `receipt-snapshot-admin`을 `bootstrap_admin`으로 준비한다.
- 격리 Django에 연결된 루프백 프론트 URL을 `ARTI_REVIEW_BASE`에, 합성 관리자 비밀번호를 `ARTI_BOOTSTRAP_PASSWORD`에 지정한다. `node frontend/tests/receiptVisibility.browser.cjs`를 실행한다. 시험은 합성 표식을 검사하고 편집한 공개 상태를 각 시나리오 뒤에 복원한다.
