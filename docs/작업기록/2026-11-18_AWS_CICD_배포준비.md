## 11/19 DuckDNS 첫 기동 파일 준비

- `arti-exhibit.duckdns.org`를 기본 후보로 두고, 계정·인스턴스 ID를 입력하면 서울의 대상 ECR·EC2·SSM에 맞춘 IAM 정책, GitHub 환경 값과 호스트 전달 묶음을 생성하도록 했다. 출력에는 비밀번호와 배포 활성화 값이 없다. 모의 ID로 정책 범위와 압축 파일의 경로·LF 개행을 확인했다. 잘못된 주소와 기존 출력 디렉터리는 거부됐다.
- 격리 로컬 Nginx에서 최초 인증서 발급용 HTTP 설정을 검수했다. ACME 파일은 `200`, 없는 파일은 `404`, 일반 요청은 고정 HTTPS 주소로 `308`이었다. 시험 인증서를 적용하니 지정 DNS 이름으로 TLS 연결이 됐고, 첫 릴리스 전 upstream `502`에서도 카카오 콜백·비밀번호 재설정의 `no-store`와 `no-referrer`가 유지됐다. 실제 DuckDNS 등록·AWS 리소스 생성·공인 발급은 대기 상태다. [DuckDNS 기준 첫 설정](../operations/2026-11-19_DuckDNS_AWS_첫설정.md)
