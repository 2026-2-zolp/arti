## PR #53 병합 후 로컬 배포 검수

- 호스트의 HTTPS 첫 HTML을 기동 중인 웹 이미지의 `index.html`과 비교한다. 예전 화면이 HTTP 200을 반환하는 경우를 모의 검수에서 전환 실패로 처리했고 이전 이미지와 릴리스 기록이 유지됐다. Linux 스크립트 테스트 86건과 ShellCheck를 통과했다.
- `pwsh -NoProfile -File scripts/runDeployRollback.ps1 -Revision c9a87fa -PreviousRevision 7245761 -IncompatibleRevision 63aafe8`로 별도 Compose·Nginx에서 검수했다. 새 이미지와 복귀 이미지 모두 HTTPS 응답이 각 컨테이너의 HTML과 일치했다. 준비 API 200→502→200, 복귀 후 같은 DB·미디어와 영수증 ID 한 건, 본인·관리자 200, 다른 회원 403, 비회원 401을 확인했다. 결과는 로컬 `data/private/arti-deploy-check-c979a249c50b/result.json`에 있다.
- 첫 배포 가이드에 완료된 릴리스의 digest를 읽어 최초 관리자 계정을 만든 뒤, 합성 전시를 등록하고 외부 팀 PC에서 검수하는 순서를 연결했다. 실제 AWS와 공용 HTTPS 상태는 팀 계정과 주소가 정해진 뒤 확인한다. [최초 관리자와 외부 PC 검수](../operations/2026-11-18_AWS_CICD_첫배포.md#첫-실행과-복귀)
