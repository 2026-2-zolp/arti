## 이미 있는 자산과 그 한계

- React/TypeScript/Vite 사용자·관리자 주요 화면, API 클라이언트가 있다. 프론트 빌드 성공은 실제 관람 완주를 보장하지 않는다.
- Express API·SQLite 저장·인증·추천·회원 기록과 38개 테스트가 있다. 테스트 성공은 프론트의 생성 가이드 덮어쓰기 등을 놓칠 수 있어 실제 화면 계약 회귀가 추가로 필요하다.
- Python/FastAPI 모델 서비스와 태그 평가 자료가 있다. 조사 폴더의 AI 소스는 일부만 가져온 것이므로 완전한 실행 배포본이 아니다.
- 규칙 기반 추천은 합리적인 기준선이다. 검수한 관찰 질문도 매번 생성할 필요가 없다. 테스트의 fake AI는 외부 호출 없이 분기를 검증하는 정상 자산이다.
- source/summary/guide/emotion/tag의 서로 다른 검수 상태를 하나의 “AI 완료” 불리언으로 합치지 않는다.

## 태그 평가를 읽는 기준

노트북 저장 출력 기준(이번 조사 재실행 아님): WikiArt 대상 분류55장 중 풍경53/55, 인물50/55. 40장·6인 태깅 비교에서 primary hit는 서비스90%, leave-one-out88%. 태그별 LOO F1은 풍경69/인물88/추상75/빛78/강렬한색감53/차가운색감53/따뜻한색감69/부드러운색감62(%). 부드러운색감의 사람간 일치도 κ≈0.26으로 낮다. 같은 40장에서 임계값 보정을 했으므로 외부 검증으로 과장하지 않는다. 6감정 11장 결과도 추천 정확도로 사용하지 않는다. 자세한 셀 출력은 [노트북 추출](../../../research/ai-validation-extract.md) 참조.

표의 문제는 현 기준선에 대한 관측이다. 수정 후에는 ID를 유지하고 증거·상태를 갱신한다. 실행 미확인 항목을 완료/재현으로 승격하려면 재현 로그가 필요하다.
