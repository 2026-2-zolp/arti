# 프로젝트·준억님 역할의 맥락

## 제품의 중심

ARTI는 미술 초보 관람객이 현장 QR로 진입해 취향과 시간을 고르고, 작품 추천·지도 안내·작품 감상·질문·영수증까지 이어가는 모바일 웹이다. 핵심 가치는 긴 해설을 더 많이 보여주는 것보다 **작품을 직접 관찰하도록 돕는 Guided Looking과 근거 있는 추가 대화**에 있다. 관리자에게는 작품·원자료·출처·AI 초안·검수·위치 관리가 필요하다.

첫 적용 전시는 10/12 회의에서 선택한 **유영국 「산은 내 안에 있다」**다. 코드의 고흐 등 유명 작품 12점 시드는 해당 전시 데이터가 아니다. 실제 전시 자료·작품 위치·이용 가능한 이미지 확보 여부는 별도 확인이 필요하다.

노션의 회의 준비안·개인 메모와 실제 회의 결과는 다를 수 있다. 빈도 가중 방식, 저장 범위, 최종 API는 11/3 메모만으로 전부 확정되지 않는다.

## 준억님이 인수한 일

11/5 23:41 개인톡에서 광권님이 요청한 항목은 ① 챗봇 추가·성능 평가 ② 해설/관람가이드 생성 주체 확인 ③ 백엔드 DB 구조 확인 ④ TypeScript 백엔드 유지 여부(AI는 Python) ⑤ 8태그 성능 확인 ⑥ 팀 기술 설명 준비다. 준억님은 확인해보겠다고 답했다. 이번 사용자 정정에 따라 **모두 착수 전 확인·구현 과제**로 본다.

따라서 준억님의 우선 역할은 챗봇 화면 하나를 추가하는 것에 그치지 않는다. 최신 프론트와 광권님 API 사이의 경계를 정리하고, AI가 실제 자료와 검수 상태를 지키며 응답하는지 증명하고, 원래 스택으로 옮길 때 그 동작이 유지되도록 하는 일이다.

| 영역 | 준억님 중심 작업 | 협업 상대·확인점 |
| --- | --- | --- |
| 통합 | 필드·상태·오류·추천 입력·저장 계약 작성 및 회귀 검증 | 동섭: 최신 ZIP 의도와 화면; 광권: 백엔드·모델의 실제 규격 |
| AI | 생성 주체·호출 경로·출처·실패 표시·대화 맥락·작은 평가셋 | 광권: 모델/평가 입력 파일·실행 조건 인계 |
| 스택/DB | Django/DRF·PostgreSQL 전환 계획과 호환성 검증 | 팀: 제출 설계와 바뀐 추천 방식의 변경 기록 |
| 데이터 | 공식 자료→초안→검수→노출 흐름 확인 | 작품 자료 수집·사람 검수 담당은 팀 내 지정 필요 |
| 기술 설명 | 현재/목표/검증 결과를 구분한 설명 | 수업 목표 진척률을 실제 완료율로 발표하지 않음 |

OAuth, 고도화된 추천, 새로운 데이터 수집을 준억님 혼자 모두 맡기로 확정된 근거는 없다. 위 표는 인수 흐름에 맞춘 작업 제안이다.

## 작업 범위의 경계

우선 한 전시, 모바일 관람 완주, 10점 5쌍 취향 선택, 8태그 추천, 검수된 작품 정보, 관찰 질문·추가 대화, 기록을 연결한다. 여러 미술관 확장, 실내 실시간 측위, 작품별 QR, 대규모 벡터 검색 인프라, 자동 수준 판정, 파인튜닝, 멀티에이전트는 현재 선행조건으로 추가하지 않는다.

추천의 결정적 계산, 검수된 고정 질문, 화면의 태그 라벨·시간 옵션은 유지할 수 있다. 삭제할 대상은 파일명에 mock이 있는 모든 코드가 아니라, 실제 데이터·AI인 것처럼 보이게 하는 시드·숨은 대체 응답·저장 불일치다.
