## 게이트를 통과시키는 기준

- **G0 계약:** 최신 프론트와 서버 필드 비교표가 있고, 빈도/선택 원본·공개 검수·저장·AI 실패 방식에 모순이 없다. 미정은 담당과 확인 방법을 적는다.
- **G1 현재 통합:** 임의 시드와 실제 자료를 구별하고 핵심 완주가 가능하다. 취향/시간 변경 추천 재계산, 가이드 저장 보존, 미검수 공개 차단, 저장 실패 재시도 필수. 일부 저장 정식 DB 모델은 T06으로 옮길 수 있지만 실패를 성공으로 표시하면 통과하지 못한다.
- **G2 실제 AI:** 키 없는 규칙 응답을 실제 모델 성공으로 세지 않는다. 공식 자료에 있는 질문·없는 질문·관찰 질문·후속 질문·강제 실패를 확인한다.
- **G3 전환:** 호환 API와 참조 ID 보존, 필요한 데이터 이전, 인증·권한, 재시작 영속성 확인. 실패 시 이전 기준선으로 돌아갈 수 있다.
- **G4 데이터:** 출처·검수 상태·이미지·위치와 추천 태그를 확인한다. 40장 보정 성능과 대상 전시 평가를 분리한다.
- **G5 사용자:** QR/진입부터 영수증까지 실제 모바일 화면에서 성공·실패 모두 확인. API 테스트만으로 대체하지 않는다.
- **G6 설명:** 목표/실제/미구현이 구분되고 결과 수치가 로그를 가리킨다.

## 첫 작업 회차의 구체적인 순서

1. 이 기준선과 최신 원본을 비교한 뒤 통합 브랜치 기준점을 기록한다.
2. front types/client와 backend types/schemas/catalog/admin/visits를 맞대어 계약표를 만든다. 우선 생성 가이드 필드, 승인 상태, 추천 입력, visitId를 확정한다.
3. 조사 audit을 정식 회귀 사례로 옮긴다. 이 스크립트 자체는 경로/내부 reducer에 결합되어 있어 최종 테스트로 그대로 복사하지 않는다.
4. 가이드 덮어쓰기 → 미검수 공개 → 추천 무효화 → 영수증 저장/실패 → 대화 격리 순으로 고친다. 매 수정마다 해당 회귀와 인접 흐름만 검사한다.
5. 핵심 완주를 브라우저에서 확인하고 남은 장애를 기록한다. 이 시점에 Django 전환 첫 범위를 고정한다.

11/9~10의 90%, 11/16~17의 100%는 자료에 적힌 수업 목표이지 현재 달성률이나 이번 계획의 확약이 아니다. 시간이 부족하면 고급 알고리즘·부가 기능을 줄이고, 검수·저장·실제 AI 여부와 목표 스택 전환을 숨겨서 완료로 처리하지 않는다.

## 보류·중단 기준

실제 모델 키가 없으면 G2를 대기 상태로 두고 T05를 진행한다. 평가 이미지가 없으면 저장된 수치를 재실행 결과로 쓰지 않고 자료 수집·핵심 흐름을 진행한다. 공식 작품 자료가 부족하면 추정 해설을 대량 생성하지 않고 승인 자료가 있는 작품으로만 증명한다. 모델·알고리즘 교체는 기존 기준선보다 어떤 실패가 개선되는지 작은 비교를 거친다.
