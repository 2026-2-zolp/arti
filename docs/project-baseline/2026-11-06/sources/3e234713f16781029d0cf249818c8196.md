## 1. 이번 회의에서 정리된 것

- <b>핵심 사용자:</b> 이전 회의와 동일하게 <b>미술 감상 초보자</b>를 중심으로 유지.
- <b>중심 경험:</b> 추천·코스 자체보다 <b>작품 앞에서 관찰하고 생각하는 과정을 돕는 Guided Looking</b>을 핵심 경험으로 더 구체화.
- <b>AI 개입 방식:</b> 처음에는 감상 포인트와 추천 질문을 적극적으로 제시하고, 사용자가 익숙해지면 질문을 조금씩 열어 <b>스스로 작품을 보는 감각을 기르는 코치형 경험</b>으로 확장하는 아이디어에 공감.
- <b>작품 설명:</b> DB에 충분한 근거 자료를 저장하는 것과 사용자에게 보여주는 설명량은 분리. 화면에는 사용자의 수준·질문·관람 맥락에 맞춰 필요한 내용만 가공해 제공.
- <b>데이터 방향:</b> 가능하면 우리가 임의로 작품을 모아 가상 전시를 만드는 것보다 <b>실제로 열렸거나 열리고 있는 전시의 작품 목록·공식 자료를 활용</b>하는 방향이 적절하다는 데 공감.
- <b>MVP 규모:</b> 성격이 다른 <b>실제 전시 2개 정도를 후보로 찾아보고, 전시당 약 20점 전후를 시작 기준</b>으로 검토. 작품 수는 실제 데이터 확보 가능성과 전시 규모를 확인한 뒤 조정.
- <b>추천 동선:</b> 실내 GPS·3D 내비게이션까지 구현하는 의미가 아니라, <b>추천된 작품을 어떤 순서로 감상하면 좋을지 보여주는 관람 순서</b> 수준으로 우선 이해.
- <b>조사 순서:</b> 작품별 상세 조사부터 시작하지 않고, 먼저 <b>ARTI에 적용하기 좋은 실제 전시 후보와 공개 데이터 범위</b>를 찾은 뒤 대상 전시를 정하고 작품 데이터를 수집하기로 함.

## 2. 핵심 논의

### Guided Looking · 작품을 ‘설명’하기보다 ‘보게 하기’

- 동섭님은 이전 회의에서 나온 Guided Looking 방향에 동의하며, <b>AI가 먼저 감상 포인트와 질문을 제시하는 방식</b>을 중심으로 가져가자는 의견을 제시.
- 예: “배경색은 어떤 느낌인가요?”, “인물의 표정이나 시선은 어디를 향하고 있나요?”처럼 먼저 관찰할 지점을 알려줌.
- 이후 몇 작품을 함께 본 뒤에는 “이번 작품에서는 무엇이 먼저 눈에 들어오나요?”처럼 질문을 열어 사용자의 자율적인 관찰을 유도하는 방식이 제안됨.
- 즉 ARTI를 <b>답을 알려주는 도슨트 → 작품을 보는 방법을 길러주는 관람 코치</b>에 가깝게 설계하는 방향.
- 다만 <b>언제 AI 개입을 줄일지, 사용자의 감상 수준을 어떤 기준으로 판단할지</b>는 추가 구체화가 필요.

### Egographica 벤치마킹

- 동섭님이 [Egographica](https://app.egographica.art/agents/kentacobayashi)를 공유하고 실제 화면을 함께 확인.
- 작가별 AI 에이전트와 대화하는 구조이며, 인터뷰 등을 바탕으로 사용자의 질문에 답하는 형태로 파악.
- 처음에는 화면의 항목이 ‘추천 질문’과 유사해 보였지만, 확인 결과 <b>ARTI가 구상하는 ‘AI가 먼저 관찰을 유도하는 Guided Looking’과는 결이 다름</b>.
- 따라서 유사 서비스·벤치마킹 사례로는 참고하되, ARTI의 차별점은 <b>대화 자체보다 작품을 관찰하게 만드는 선제적 질문과 관람 흐름</b>에서 찾는 방향.

### 작품 설명 범위 · 광권님 ‘황소’ 자료를 기준으로 검토

<mention url="https://app.notion.com/p/3e434713f16780bfb06cc65b4ce15c0a" />

- 광권님은 이중섭의 <b>〈황소〉</b>를 직접 조사해, 작품 하나를 설명하려면 어느 정도 자료가 필요한지 예시를 준비.
- 자료에는 <b>작품 재료·크기, 연관 작품, 그림 속 대상의 묘사·상징성, 작가의 시대·생애, 작가의 철학·화풍</b> 등 여러 층위가 포함됨.
- 특히 이 자료의 목적은 <b>사용자 화면에 모든 내용을 그대로 보여주자는 것이 아니라, AI가 설명을 생성할 때 참고할 DB 원자료의 범위를 정해보자는 것</b>으로 재확인.
- 광권님은 실제 조사 시 시대 맥락과 작품 속 상징을 특히 중요하게 본다고 설명했으며, 최종 범위는 팀의 구현 역량에 맞춰 정하자는 의견.

### 작품 DB 카테고리

<mention url="https://app.notion.com/p/3e434713f16780ce8e39e3aaad578595" />

현재 논의된 기본 틀은 다음과 같음.

1. <b>작품 기본정보</b> — 작품명 / 작가 / 제작연도 / 재료 / 크기 등
2. <b>시각적 관찰 요소</b> — 대상 / 색 / 선 / 형태 / 구도 / 표정·자세 / 질감 등
3. <b>작품 해석·상징</b> — 의미 / 상징 / 제작 의도 등 + 근거·출처
4. <b>작가·시대 맥락</b> — 작품 이해에 필요한 작가 생애와 시대 배경
5. <b>작가의 작품세계·화풍</b> — 반복 소재 / 스타일 / 관심사
6. <b>연관 작품·연작</b> — 관련 작품이나 같은 시리즈
7. <b>출처</b> — 각 정보가 어디에서 나온 것인지 추적 가능하도록 저장

- 핵심은 작품마다 무엇을 넣을지 제각각 정하는 것이 아니라 <b>최소 공통 필드·수집 기준을 정해 DB의 일관성을 확보하는 것</b>.
- 정보가 확인되지 않는 작품은 임의로 채우지 않고 <b>미상 / 확인되지 않음</b> 등으로 명시.
- 위 카테고리를 그대로 최종 스키마로 확정한 것은 아니며, 실제 데이터를 수집해보며 줄이거나 보완하기로 함.

### DB 원자료와 사용자 설명은 분리

- DB에는 가능한 범위에서 충분한 정보를 보관하되, <b>사용자가 처음부터 긴 설명을 읽게 하지는 않음</b>.
- 사용자 화면에서는 짧은 안내와 질문으로 시작하고, 사용자가 원하는 만큼 추가 질문을 통해 정보를 단계적으로 제공하는 흐름이 적절하다는 의견.
- 정리하면 다음 구조를 우선 검토.

<b>신뢰 가능한 원자료·출처 → 구조화된 작품 정보 → ARTI가 사용자 상황에 맞춰 질문·설명 생성</b>

- 예를 들어 시각적 특징은 Guided Looking 질문 생성에, 작가·시대 맥락은 추가 설명에, 작품 해석은 근거와 함께 심화 질문에 활용하는 방식.

### AI로 자료를 수집할 때의 원칙

- 광권님은 <b>정해둔 카테고리를 AI에 주고 자료를 수집·정리해 DB에 넣는 방식</b>을 제안.
- 방향 자체에는 공감했지만, AI에게 “이 작품 조사해줘”라고만 한 뒤 답변을 바로 DB에 저장하면 출처 추적과 사실 검증 문제가 생길 수 있다는 의견이 나옴.
- 따라서 다음 방식이 더 적절하다고 정리.

<b>공식 미술관·전시 페이지 등 신뢰 가능한 자료 확보 → AI가 해당 자료 안에서 필요한 카테고리를 추출·정리 → 사람이 출처와 내용을 확인 → DB 저장</b>

- 즉 <b>AI 자체를 정보 출처로 삼기보다, 주어진 자료를 읽어 구조화하는 작업자로 사용</b>.
- 이후 ARTI가 DB의 구조화된 정보를 다시 초보자에게 맞는 질문·설명으로 가공하는 구조.

### 성현님 조사 · The Met Open Access

- 성현님은 <b>The Metropolitan Museum of Art Collection API / Open Access CSV</b>를 데이터 후보로 공유.
- 작품 기본정보, 작가, 제작 시기, 재료·기법, 크기, 문화권·시대, 이미지, 태그, 소장 정보 등 다양한 메타데이터를 확보할 수 있어 <b>기본 작품 DB를 채우는 소스</b>로 활용 가능성이 있음.
- 다만 Guided Looking에 필요한 <b>작품 해석·작가의 작품세계·세부 맥락까지 API 하나로 모두 해결되지는 않으므로</b>, 공식 작품 상세 페이지·전시 자료 등 다른 출처와 함께 사용하는 방향을 검토.

## 3. 추가 기능 아이디어

### 나만의 ‘아트 영수증’

- 광권님 제안.
- 관람 중 <b>어떤 작품에 오래 머물렀는지, 어떤 작품과 많이 대화했는지, 어떤 색감·주제에 반응했는지</b> 등을 바탕으로 관람 종료 후 개인 기록을 보여주는 아이디어.
- 예: “오늘 가장 오래 머문 색감”, “가장 깊게 대화한 작품”, “오늘의 전시 바이브” 등.
- 팀에서도 <b>전시를 보고 끝나는 것이 아니라 관람 경험을 한눈에 남길 수 있다는 점</b>에서 반응이 긍정적이었음.
- 디자인이 잘 나오면 이미지 저장·SNS 공유 같은 확장도 검토 가능.
- 아직 표시 항목과 계산 기준은 미정.

### 작품과 어울리는 AI 음악

- 광권님이 실제 경험한 전시에서 착안.
- 해당 전시는 취향에 따라 작품과 <b>미리 생성해둔 AI 음악</b>을 함께 추천하는 방식이었음.
- ARTI에서도 작품 감상 시 선택적으로 어울리는 음악을 제공하는 아이디어가 제시됨.
- <b>신선한 차별점</b>이라는 의견과 동시에, 전면에 내세우면 “작품 감상 서비스인지 음악 서비스인지” 정체성이 섞일 수 있다는 우려도 있었음.
- 따라서 넣더라도 Guided Looking을 방해하지 않는 <b>선택형 보조 기능</b>으로 검토하고, 우선순위는 핵심 기능 이후로 두는 편이 적절하다는 분위기.
- 광권님도 두 아이디어 중에는 <b>아트 영수증에 더 무게</b>를 둠.

## 4. MVP 전시·작품 범위

### 실제 전시를 우선 활용

- 가상으로 작품을 직접 모아 전시를 구성하는 것도 가능하지만, 팀이 미술 큐레이션 자체를 새로 설계해야 한다는 부담이 있음.
- 실제 전시의 작품 목록을 사용하면 <b>전문가가 구성한 전시 맥락을 그대로 활용할 수 있고, 발표 때 대상 범위를 설명하기도 쉬움</b>.
- 현재 진행 중인 전시에 한정하지 않고, 작품 목록과 공식 자료가 남아 있다면 <b>과거 실제 전시도 후보</b>가 될 수 있음.

### 전시 수와 작품 수

- 회의 중 20점, 20\~30점, 더 많은 작품 수 등 여러 예가 나왔으며 <b>정확한 수량은 확정하지 않음</b>.
- 우선은 성격이 다른 <b>전시 2개 정도</b>를 찾아 비교하는 방향.
- 예: 특정 작가전 1개 + 특정 시대·사조·주제전 1개.
- 작품은 <b>전시당 약 20점 전후를 시작 기준</b>으로 생각하되, 실제 전시 구성과 데이터 수집 난이도에 따라 조정.
- 따라서 다음 단계는 작품 수를 먼저 고정하는 것이 아니라 <b>사용하기 좋은 실제 전시를 찾고 작품 목록·공개 데이터를 확인하는 것</b>.

## 5. 아직 결정이 필요한 것

- <b>Guided Looking 단계화:</b> 몇 작품·어떤 행동을 기준으로 AI 질문을 줄이거나 바꿀지.
- <b>DB 카테고리 최종안:</b> 현재 6개 영역 + 출처를 그대로 사용할지, 실제 수집 후 통합·축소할지.
- <b>사용할 실제 전시:</b> 국내/해외, 작가전/주제전 중 어떤 전시를 최종 MVP에 넣을지.
- <b>작품 수:</b> 전시당 20점 전후는 출발점이며 실제 데이터 확보 후 확정.
- <b>취향 영수증 세부 지표:</b> 머문 시간·질문 수 외에 무엇을 기록하고 어떤 방식으로 결과를 만들지.
- <b>AI 음악:</b> MVP 포함 여부 및 구현한다면 어느 위치에서 선택형으로 제공할지.
- <b>추천 동선 로직:</b> 단순 추천 순서를 어떤 정보·취향과 연결해 만들지.
