# 👋 처음 시작하기 — 팀원용 GitHub 안내

새 Django 개발 실행은 [현재 실행 안내](개발실행-Django.md)를 따릅니다. 아래는 Git 사용 안내입니다.

[← ARTI 메인으로](../README.md) · [그림으로 보는 PR](개발-PR-흐름.md)

처음 GitHub를 쓰더라도 **본인 브랜치 열기 → 코드 수정 → PR 만들기** 세 가지만 익히면 됩니다.

## ① GitHub 초대 수락하기

1. `2026-2-zolp` 조직 초대를 수락합니다.
2. [arti 저장소](https://github.com/2026-2-zolp/arti)가 보이는지 확인합니다.
3. [메인 README](../README.md)에서 현재 개발 범위와 폴더 역할을 확인합니다.
4. 각자 사용할 브랜치는 **미리 준비**되어 있습니다. 새로 만들지 않아도 됩니다.

| 팀원 | 본인 브랜치 |
| --- | --- |
| 임준억 | `dev/임준억` |
| 김광권 | `dev/김광권` |
| 지성현 | `dev/지성현` |
| 김동섭 | `dev/김동섭` |

## ② 내 컴퓨터에 저장소 받기

터미널 또는 VS Code 터미널에서:

```bash
git clone https://github.com/2026-2-zolp/arti.git
cd arti
git fetch origin
git switch --track origin/dev/김광권
```

마지막 줄의 `김광권`을 **자기 이름**으로 바꿉니다. 이미 동일한 로컬 브랜치를 만든 적이 있다면 `git switch dev/자기이름`으로 이동합니다.

## ③ 코드 작업 전에 최신 내용 받기

```bash
git switch dev/김광권
git fetch origin
git merge origin/main
```

이 예시도 본인 브랜치 이름으로 바꿉니다. 다른 팀원이 `main`에 합친 최신 코드를 반영하는 단계입니다.

## ④ 작업을 저장하고 올리기

```bash
# 직접 코드 수정·실행·테스트 후
git status
git add -A
git commit -m "feat: 작품 추천 화면 구현"
git push -u origin dev/김광권
```

`git status`를 먼저 확인하여 비밀 키나 불필요한 파일이 포함되지 않았는지 확인해 주세요.

## ⑤ PR 작성하기

GitHub의 **Pull requests → New pull request**를 엽니다.

```text
base: main            ← 합쳐질 팀 공통 브랜치
compare: dev/김광권   ← 내가 수정한 브랜치
```

PR 제목 예시: `feat: 작품 추천 화면 구현`

PR 본문은 **변경 내용 / 확인 결과 / 참고사항**만 간단히 작성하면 됩니다. 팀원 검토 후 `main`에 병합합니다.

다음 작업을 시작할 때는 개인 브랜치로 돌아와 `git fetch origin`, `git merge origin/main`을 다시 실행합니다.
