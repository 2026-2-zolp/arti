# 개발·운영 결정과 계약

2026-11-08: W02 개발 계약은 [실제 코드 기반 확정 규격](records/W02/contracts.md), [개발 결정](records/W02/decisions.md), [검토 판정](records/W02/gate-review.md)을 따른다. 아래 표의 W02 결정 항목은 이 기록에서 닫았으며, 팀 최종 UX 합의/운영 미결은 구분해 유지한다.

## 결정의 범위

사용자가 **코드 출발점 ae0e58e**를 확정했다. 과거ZIP은 참고자료다. 최신 요구의 U10맥락 연계는 아직 미구현이며 이번 과업에 반영한다. U05/06의 최종 합의는 대기 중이고 현 방식을 임시유지한다.

기본 기술 계획은 React 유지 + Django/DRF 서비스API + PostgreSQL + Docker다. W02에서 개발 결정을 기록한다. AWS RDS/S3/EC2는 후보이며 선택을 사용자/팀의 최종합의로 꾸미지 않는다.

후속 근거 없이 모든 설명을 실시간 개인화로 바꾸지 않는다. 검수된 고정 가이드와 실시간 대화의 역할을 구분한다. 현재 40점 해설이 official source인 것처럼 LLM근거로 쓰지 않는다.

## 팀·관람객 관점으로 고정할 최소 사례

- U05/06 임시기준은 현 전시앞10점의 최대5독립쌍 선택→태그확인/수정→회원 저장취향 재사용이다. 이는 현재동작 설명이며 최종선정풀·부족처리·빈도가중의 정답을 승인한 뜻은 아니다. UI표현/배치 검토는 가능하나 선택원본·빈도·저장·요청규격 변경은 D03/fixture를 갱신한다.
- 회원은 서버저장·재조회, guest는 가입없이 관람/도슨트/영수증과 DB미저장 안내가 기본이다. guest서버보존·회원이관을 원하면 계약변경한다. 관람완료와 저장완료를 구분한다.
- 이해수준은 취향태그로 단정하지 않는다. 같은 작품의 “쉽게 설명”/“더 깊게 설명” 요청에 따른 실제응답을 평가한다. 새설문/자동진단은 도입하지 않는다.
- tagCoverage0은 approved+position 후보집계0이다. 전시전체 소재부재·자료미준비를 혼동하지 않는 안내와 운영체크를 정한다.
