# AC17 인수 범위 결정 — Git 우선, 로컬 고유 자료 별도 인수

2026-11-08 KST / 결정자: 임준억 / 이번 W05에 적용.

사용자 결정: **“이번 인수는 Git 자료 기준으로 하고, 로컬 고유 자료는 원본 보존 후 별도 인수하는 걸로 기록하자.”** 따라서 AC17은 이번 Git 기반 인수 경계에 한해 통과 판정한다. 로컬 자료가 없다는 확인이나 실제 팀 DB 이전 완료를 뜻하지 않는다.

## 이번에 실제 확인·이전한 것

- 코드 출발점은 동섭 통합본 `ae0e58ebc338c17da6d4d17616fd802f03ba3bb6`이며 W04까지의 로컬 이력을 보존했다.
- Git의 `ai-service/evaluation/tag_eval_set.json`, `evaluation/images`, `backend/scripts/capture-descriptions.json`을 명시 exporter로 묶었다. 40점 모두 해시를 확인했다. 메타데이터의 .png와 실제 .jpg 차이는 같은 작품 ID의 유일한 후보만 대응하고 manifest에 원경로·보정·해시를 기록했다.
- 해설 checkedAt=null인 AI 초안이다. 원문을 공식 검수본으로 승격하지 않고 **전시 draft / 작품 source_check / 위치 null**로 새 PostgreSQL에 적재했다. 기존 시험 seed의 approved·임시 좌표를 승계하지 않았다.
- importer는 dry-run·파일 해시·중복/덮어쓰기 거부·실패 롤백을 검사했다. [Git 자료 관측](data-and-browser-db.json), [PostgreSQL 검사](postgres-tests.log). 비공개 bundle과 DB·업로드 복사본은 ignored 영역/별도 시험 볼륨에 두고 Git에 넣지 않는다.
- 기존 Git 이미지·해설·시드와 보호 아카이브38개는 수정하지 않는다. 회원·세션 전체 이전은 이번 범위에 넣지 않았다.

## 원본 보존과 별도 인수

광권님 PC의 실제 `arti.db`·uploads는 **아직 받거나 변경하지 않았다**. 원본을 삭제·덮어쓰기·변환하지 않고 제공자 측에 보존하는 정책으로 기록한다. 제공자 PC에서 백업 완료 여부를 확인한 것은 아니다. Git으로 복원되지 않는 수동 검수/태그/분석/좌표/도면의 존재 여부는 계속 unknown이다.

별도 인수 시에는 (1) 쓰기를 멈춘 일관된 DB export와 대응 uploads 복사본·해시 manifest 확보, (2) 원본 읽기 전용 보관, (3) Git 재생성본과 ID/검수/분석/파일 차이 대조, (4) 고유 자료만 별도 개발 DB에서 dry-run, (5) 데이터/파일/FK·검수 상태·좌표 round-trip 확인, (6) 제공자 확인 후 채택 순으로 진행한다. 실제 회원 개인정보·세션·비밀번호 자료는 별도 필요성/정책 확인 없이 가져오지 않는다.

유영국 전시를 새로 등록하고 작품/원문/출처/좌표를 연결할 공간은 있다. 현재 40점은 유영국 검증 데이터가 아니다. 선정 자료 확보·사람 검수·배치와 W06 데이터 준비가 남아 있다. 이번 결정으로 W06/W07 및 출시 인수 기준을 자동 통과시키지 않는다.
