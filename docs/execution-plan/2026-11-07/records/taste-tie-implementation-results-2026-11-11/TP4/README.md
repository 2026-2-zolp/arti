# TP4 격리 통합 인수 검증

기준 커밋 `c192974`의 프론트와 실제 Django API를 별도 PostgreSQL 17에 연결했다. 캐시 모델 실추론은 FastAPI에서 한 번 실행했다. 도슨트의 외부 응답은 루프백 OpenAI 호환 테스트 제공자로 구성했다. 이 제공자가 받은 질문·관람가이드 맥락을 검사하고 Django가 구성한 출처 참조를 브라우저 응답과 대조했다.

| 기준 | 검증 결과 |
| --- | --- |
| P4-01 | Chrome에서 10점·다섯 쌍 선택과 v2 확인부터 지도, 세 작품 감상, 관람가이드 도슨트, 영수증까지 완주했다. 동일 요청의 최초 201·재시도 200·재시작 뒤 조회 응답을 대조했다. [브라우저 여정](browser-journey.md) |
| P4-02 | 같은 격리 데이터의 3/5/7점 v1 응답 전체를 `9234371`의 추천 구현과 대조했다. v2의 동일 가중치와 서버 동점 우선순위도 확인했다. [추천 대조](recommendation-diff.json) |
| P4-03 | 기존 고정 CLIP 캐시로 분석한 입력·artifact·processor·런타임·보정·점수 해시를 PostgreSQL 저장 근거와 대조했다. [모델 출처](real-provenance-smoke.json) |
| P4-04 | 일반 환경의 8개 모델과 미디어·활성 풀·원본 16점·컨테이너 식별자를 읽기 전용으로 전후 대조했다. [보존 결과](ordinary-before-after.json) |
| P4-05 | 프론트, Django, 모델 계약, 계획·자료 검사 4개 작업에 해당하는 로컬 명령을 실행했다. [로컬 검사 결과](local-ci-results.json) |
| P4-06 | 동일 격리 DB에서 v2 활성 → 비활성 → 재활성으로 Django를 재시작했다. 기존 계정과 영수증을 대조하고 중단 전에 발급한 근거의 첫 저장·재시도를 확인했다. [비활성화와 복구](rollback-results.json) |

추가 대조에서 체류 시간이 같은 작품의 ‘가장 오래 본 작품’이 PostgreSQL JSON 키 순서에 따라 바뀌는 문제를 찾았다. 서버 응답과 브라우저의 영수증 계산 모두 관람 순서를 동점 기준으로 사용한다. 해당 동점 회귀를 추가한 뒤 최초 응답과 재시도·재조회가 일치했다.

검증 범위와 판정은 [검증 기록](validation.json)에 있다. 다음은 실제 작품·태그의 독립 검수와 공개 대상·사용 범위에 대한 인수 판단이다.
