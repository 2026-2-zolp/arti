# R02 시연 인벤토리·R05 실제 도슨트 응답 기준선

2026-11-09 KST / 시작a94ebd8 / GPT gpt-6-luna 기존 설정 유지. [필수 시연 흐름·잔여 결함 표](../../../../operations/2026-11-09_필수시연흐름과잔여결함.md)를 작성하고, 합성 작품의 실제 도슨트 응답을 측정해 answer 지시문만 보완했다. 실제 유영국·사람 이해도·브라우저 전체 재시험/G5는 아니다.

## 입력·방법·기준 고정

[protocol.json](protocol.json)과SHA256을 유료 호출 전에 고정했다. 가상 작품1개(파란 바탕·노란 원·오른쪽 흰 여백·아래 빨간 선),4상황의 실제2턴8회 + 자료 밖/삽입 지시문2회 + 맥락 제거 비교2회 = 초기12회다. 원본 작품 이미지·유영국 미검수 설명·개인 대화는 보내지 않았다. 별도 합성13작품 PG를 사용했다.

같은 제품 `/api/artworks/:id/ask` 경로를 DRF APIClient로 실행해 PostgreSQL의 공개/확정·entry 버전을 검사하고 실제GPT HTTP를 호출했다. 브라우저/Nginx를 통과한 새 시험은 아니다. 첫 응답은 실제 GPT 출력이며 다음 턴 history에 그대로 넣었다. 두 라운드는 같은 작품·질문 시나리오지만 첫 응답을 새로 생성하므로 다음 턴 history는 서로 다르다. 엄격히 같은 전체 payload의 통제실험이 아니며, 맥락 제거 비교도 history와entry를 함께 제거해 각각의 효과를 분리하지 않는다. 유료 평가모델·자동 재시도·상시 CI·새 평가 플랫폼은 추가하지 않았다.

필수 기준은 계약·출처/workId·저장 보호, 사실/관찰/자료 명령 경계의 큰 위반0, 상황별 요구 행동 충족·해당 자체 루브릭 평균>=1.5/2, 개별 호출25초 이내다.0~2 자체 점수는 정확도나 인간 평가가 아니다. 실패를 평균으로 상쇄하지 않는다. 모델/키/응답 스키마/토큰 cap/timeout/검수 정책은 유지했다.

## 재현·보존

[probe.py.txt](probe.py.txt)는 실제 실행한 키 없는 제품경로 probe다. 입력 protocol과 라운드별selection을 읽어 첫/다음 턴을 실행하고, 실제upstream 모델·사용량·payload SHA만 수집한다. Authorization/key·계정환경을 출력하지 않는다. DB/ENV는 `data/private`의 별도 수동 실행기로 준비했고 일반 Compose를 재생성하지 않았다. 새 반복은 기존 출력과 protocol을 덮어쓰지 않는 새 디렉터리·새DB·별도 호출 상한을 먼저 준비해야 한다. 이 파일은 자동 CI에 등록하지 않았다.

`baseline-selection.json`/`targeted-selection.json`, `protocol.sha256`, `summary.json`, `flow-inventory.json`, `django-regression.log`, `validation.json`을 함께 보존한다. `verify.py`는 저장된 계약·연속성·동일 입력/상태·호출/사용량·평가 근거·프롬프트 범위를 재검사하며 API를 호출하지 않는다. 시험용DB/네트워크 종료와 모델키 임시 전달파일 제거는 cleanup 기록으로 확인한다.

평가 방법 참고: [OpenAI 공식 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)의 과업별 평가·고정 사례·사람 판단과의 구분을 사용했다. 별도 Evals 플랫폼이나 신규 하네스 구축은 하지 않았다.
