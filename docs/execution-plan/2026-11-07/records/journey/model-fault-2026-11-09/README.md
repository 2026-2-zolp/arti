# 격리 브라우저 모델 장애·복구 여정

2026-11-09 KST / 출발37a2484 / dev/임준억. 전용 Compose arti-fault-browser-20261109(API4033/UI5193)·별도 PG17/미디어·합성13작품/시험 관리자1명을 사용했다. 실제 React IAB→Django→HTTP 장애 서비스→PostgreSQL을 점검했다. 장애 서비스는 합성 응답이며 CLIP/mDeBERTa나 실제 GPT가 아니다. 실제 native 로딩/중단 검증은 앞선 [모델 운영 기록](../../W07-preparation/model-operations-2026-11-09/README.md)과 구분한다.

## 발견·수정 루프

1. 수정 전503은 일반 실패 문구만 보였지만 입력은 유지됐다. 이어 성공 응답에서 analyzedAt가 없어서 AiPanel의 `.slice()`가 예외를 내고 빈 화면이 됐다. before-recovery-error.json/PNG에 보존했다. 실제 모델 결과를 그대로 저장하는 경로와 필수 시각을 가정한 화면의 계약 누락이었다.
2. providers.py는 감정 분석에 서버 시각을 붙이고 AiPanel은 이전 자료의 누락 시각을 안전하게 표시한다. test_model_operations의 복구 성공 응답에 파싱 가능한 시각을 검증했다.
3. AiPanel은 기존에 전체 AI 필드를 덮어썼다. adminAnalysis.ts로 새로 만든 필드만 합치고 kept/실패 필드·요청 중 바뀐 필드·다른 작품·더 최신 저장 버전을 보존한다. 확정 요약/가이드의 미저장 편집값이 실제 복구 성공 뒤에도 남았다. 호출을 시작하기 전에 이미 편집한 미확정 필드의 의도적 재생성까지 모두 보존한다는 계약은 아니다.
4. ApiError가 제한된 정수 Retry-After를 보존하고 화면에503/429/504/502별 행동·alert·재시도 버튼을 제공한다. 자동 반복 호출은 추가하지 않았다. useRef의 진행 플래그와 disabled 버튼으로 연속 요청을 막고 근거 없는1분 안내를 제거했다.
5. 첫 타입 검사에서 legacy DTO의 선택적 version을 직접 비교한 오류가 나와0 기본값으로 처리했다. 회귀3개는 kept 입력·요청 중 편집/구버전/다른 작품·오류 안내/시각 누락을 검증한다. 최종 프론트23개·타입·빌드 통과.
6. Docker 바인드 마운트의 변경 감지가 되지 않아 전용 Vite를 재시작하고 reload하여 최신 코드를 확인했다. 최초 seed는 시험 API에 없는 경로를 읽어 실패해 stdin으로 전달했다. 실제 제품 문제와 시험 구성 오류를 구분했다.
7. 첫 전체 PG 회귀가 브라우저 장애 모델 주소를 상속해1건 실패했고89개 실행 후 중단했다. 대상 시험 프로세스에만 SIGINT를 보내 정리하고 ARTI_MODEL_SERVICE_URL/유료 키를 명시적으로 비운 시험 프로세스로 재실행했다. 최종97개48.354초 통과. model-events의 중간 추가 timeout 호출은 이 잘못 구성한 회귀에서 발생한 것이며 브라우저 중복 요청으로 세지 않는다. 마지막 slow 구간은 회귀 주소 분리 후1회다.

## 자체 검증단 판정과 경계

기술/시니어는 렌더링 실패·선택 필드 병합·동기 중복 방지·서버 시각·버전 보호를, 방문자/콘텐츠는 기다림/재시도·편집 손실·확정/제안 구분을 점검했다. 데이터/운영은 전용 DB·확정값/행 수·늦은 응답·모델 재기동과 키 제외를 대조했다. 팀/교수/평가위원은 합성 장애/실모델·실제 화면/API 저장·정식 품질을 구분했다. 동일 작성자의 관점별 자체 검토이며 외부 사람 승인은 아니다.

이번 격리 장애·복구 기술 기준은 통과다. 브라우저502(추론 중 프로세스 강제 중단)·클라이언트90초 abort·실기기·실제 유영국/실모델 품질은 이번 실행 범위가 아니다.502 안내는 회귀로 확인했고 native 중단·저장 보호는 선행 별도 근거가 있다. 일반 arti-dev·유영국 승인/좌표·키·모델 가중치/보정은 변경하지 않았다. 시험 컨테이너를 종료하고 볼륨은 보존한다. G5/GCI/운영 게이트 승격·원격 push는 없다.
