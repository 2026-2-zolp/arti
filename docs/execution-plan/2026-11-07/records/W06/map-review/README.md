# 관리자 지도·배치 연결 검증과 전시 구성 계획

2026-11-09 / 기준f181b23 / [전시 구성·남은 W 계획](../../../../../operations/2026-11-09_유영국전시구성과동선검토.md), [작업기록](../../../../../작업기록/2026-11-09_W06_지도관리확인과후속계획.md).

## 범위와 실제 실행

도면 업로드·방/입구/작품 배치의 관리자→API→PostgreSQL→추천 연결을 조사하고 같은비율 교체의 초기화 안내를 보완했다. 기존 W05/G4를 재작성하거나 유영국의 실제 출품/배치를 승인하지 않는다.

시험은 독립Compose프로젝트 `arti-w06-map-review`의 PostgreSQL17, Python3.12 이미지, Django test runner의 새시험DB, 테스트별TemporaryDirectory 미디어를 사용했다. 원본/기존 개발볼륨을 초기화하지 않았다. 원래 /app 읽기전용bind와 중첩미디어 마운트가 충돌한 시작실패는 새이미지/중첩bind제거로 수정했다.

| 검사 | 결과/한계 |
| --- | --- |
| 전체 Django arti.tests | 최종69검사 통과. 기존63+새지도6. PostgreSQL 실제DB, 실모델 없음 |
| 새지도6검사 | 도면 재조회/공개조건·교체/다전시격리·구버전409·방/입구/위치·삭제/권한·추천연결. 실제600×400 합성PNG, 실제작품 없음 |
| frontend npm test | 최종20통과(기존17+도면작업 지연응답3). 실제 확인창 클릭/React DOM시험은 아님 |
| frontend npm run build | TypeScript+Vite빌드 통과 |
| 실제 브라우저·현장 | 이번 미실행. 새확인창의 분기는 코드검토, 실제도면/유영국배치는 대기 |

새 시험환경에서 먼저 `docker compose --env-file .env.compose -p arti-w06-map-review up -d --wait db`로 PostgreSQL을 기동한다. 이번 실제 실행은 `up -d db` 후 DB가 준비된 것을 시험 연결로 확인했다. 실행 명령은 `docker compose --env-file .env.compose -p arti-w06-map-review build api` 후 같은프로젝트의 `run --rm --no-deps api python manage.py test arti.tests --noinput`. 비공개env 내용은 기록하지 않는다. 프론트는 frontend에서 `npm test`, `npm run build`를 실행했다.

## 추가 관점의 검토

사용자가 EVALUATOR/SENIOR 추가에 동의해 계획·시나리오에 반영했다. 기술검토 에이전트에는 SENIOR 관점을, 범위검토 에이전트에는 EVALUATOR 관점을 함께 요청한다. 실제 외부 평가위원/교수/시니어의 승인으로 표현하지 않는다. 검토 지적과 보완 결과는 아래에 누적한다.

## 판정

이번 지도기능 조사·좌표초기화 안내 보완·후속 계획의 부분 과업을 검증한다. W06 전체/AC18·AC19/G5, 실제브라우저/유영국출품·권리·배치·사용성·보행시간·실모델 품질은 통과하지 않는다. 운영자 도면 입력이 가능하다는 사실만으로 배치근거 확인까지 완료했다고 하지 않는다.

다음 작업은 합성자료 DB·미디어 백업/복원 검증과 핵심3점 콘텐츠 검수 준비다. 실제 도면을 받으면 인수근거를 정리하고, 확보 전에는 시연용 구성안을 실제 전시장과 구분해 검토한다. 실제 적재 기능/공개 상태 변경은 이후 작은 단계로 진행한다. 원격푸시 없음.

## 검토 지적·보완 결과

- 기술+SENIOR: 실제관리자→PG→추천 연결6검사의 범위 적정. 등록/조회/수정 표현과 새DB기동 명령을 보완했다. 추가로 전시A 도면 요청 중B전시 전환 뒤 늦은응답이 작품목록을 덮는 필수 문제를 발견했다. 도면편집기를전시ID로분리하고 수명/작업ticket가드·동시작업차단을 추가했다. A→B/재활성 지연성공·중복업로드/삭제와옛finally·늦은삭제실패3회귀 및 전체front20/빌드를통과했다.
- 방문자: 교체 뒤 구도면draft가 남는 필수 문제를 발견했다. 업로드/삭제 성공 시임시위치/선택/옛마커를 비우고 저장좌표0점이어도draft가있으면확인하도록 수정했다. 재검토에서해결확인. 입구/방소속 재확인 안내도반영.
- 팀/교수+EVALUATOR: 부분과업과유영국실배치/권리/최적보행/모델품질을분리하고 남은W의의존관계를 유지해 필수계획지적없음. 후속브라우저에서 취소→기존상태보존,확인→초기화→재배치→추천회복을확인하도록 추가한다.

후속 브라우저 PS09에는 동일비율교체, 미저장위치만있는경우, 업로드/삭제대기중전시전환, 취소보존, 재배치후추천회복을 포함한다. 이번지연검사는생산가드의비동기동작검사이며 실제브라우저클릭결과가아니다.

최종 기술/SENIOR 재검토에서 전시별작업수명·ticket보호·지연3회귀가 적정하며 필수지적이해결됐음을확인했다. 방문자도draft지적해소를확인했다. 부분과업은인수가능, 실제브라우저 PS09와W06전체는대기다.

전용시험컨테이너와네트워크는 `docker compose --env-file .env.compose -p arti-w06-map-review down`으로종료했다. `--volumes`는사용하지않았고 이번전용postgres_data/media_data볼륨도보존했다. 원래프로젝트볼륨/자료는건드리지않았다.
