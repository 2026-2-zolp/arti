# 사용자 피드백을 포함한 편향 완화 계획

2026-11-09 사용자 요청으로 검토·계획에 반영한다. 이번 작업은 평가와 설계이며 새 피드백 UI/API/DB를 구현하지 않는다.

## 필요성과 적용 경계

팀의 다수결은 평가 기준 중 하나이고 관람자 전체의 정답이 아니다. 실제 사용자의 피드백은 팀 외 관점을 확보하고 실패 사례를 찾는 데 유효하다. 그러나 추천받아 본 작품만 평가하고 만족/불만이 강한 사람이 주로 응답하면 선택·노출 편향과 기존 모델의 선호 강화가 생길 수 있다. 좋아요를 라벨 정답으로 자동 적용하지 않는다.

근거: [Google PAIR의 피드백 패턴](https://pair.withgoogle.com/guidebook-v2/patterns)은 기대와 다른 AI 동작에 의견을 전달할 통로를 제안한다. [Schmit·Riquelme 2018 연구](https://proceedings.mlr.press/v84/schmit18a.html)는 추천과 사용자 반응 간 순환을 무시한 추정의 한계를 다룬다. [평가자별 라벨 보존 연구](https://aclanthology.org/2021.law-1.14/)는 주관적 판단을 단일 라벨로 합치면서 발생할 수 있는 관점 손실을 다룬다. 이 연구가 ARTI의 피드백 효과를 실증한 것은 아니며 아래 적용은 프로젝트에 대한 설계 제안이다.

## 구분할 피드백

| 대상 | 질문/사유 예시 | 개선에 사용할 범위 |
| --- | --- | --- |
| 작품 선호 | 마음에 들어요/안 들어요, 이유 | 개인 취향. 기존 reaction/reason을 태그 정오로 재해석하지 않음 |
| 태그 적합성 | 이 작품에 이 태그가 어울리나요? 맞음/다름/모르겠음 | 다중 의견과 불확실성. 다름만으로 삭제/정답 변경하지 않음 |
| 추천 유용성 | 취향에 맞음/너무 비슷함/추천 이유가 납득 안 됨 | 추천 품질·다양성 개선. 작품 사실성 판단과 분리 |
| 해설·가이드·도슨트 | 도움됨/사실 의심/너무 어려움/질문 반복/맥락 놓침 | 콘텐츠·프롬프트 오류 분류. 만족도가 사실성을 보증하지 않음 |

추천 경로나 감상 질문을 가로막지 않는 선택적 피드백으로 설계한다. 답변/가이드 뒤의 작은 평가와 사유 선택을 우선 검토하며 매 작품 평가를 강제하지 않는다. 기존 콘텐츠 검수/사용권 확인을 대체하지 않는다.

## 후속 구현에 필요한 계약 초안

대상 종류·작품/전시 ID·태그 또는 응답 ID·콘텐츠 revision·모델/프롬프트/설정 버전·구조화된 평가/사유·시간을 연결한다. 노출 위치/추천 버전과 응답 여부를 구분할 최소 이벤트도 검토하되 개인정보·저장기간·동의 범위를 먼저 결정한다. 전체 대화/자유서술/계정 식별정보를 기본 수집하지 않는다. 현재 guest 미저장 정책을 이번 문서로 바꾸지 않는다.

중복/반복 입력을 제한하고 한 사람의 반복 클릭이 다수의 의견처럼 계산되지 않도록 한다. 무응답은 부정 평가로 계산하지 않는다. 보고할 때 노출 수·평가 수·응답률과 표본 부족을 함께 표시한다. 회원과 guest 수집 방식, 보관/삭제 및 민감한 자유서술 정책은 구현 전에 확정한다.

## 반영 루프와 W 연결

1. W06: 태그 정의·독립 라벨·확신 없음·의견 분포를 보존. AI 점수는 첫 판단 후 공개한다.
2. W07: 기존40점 고정 점수/평가자 민감도 결과로 기준선 확보. 모호한 사례는 별도 목록으로 유지한다.
3. W05 후속: 위 최소 계약과 guest 정책을 확정한 뒤 선택적 피드백 기능 구현을 별도 과업으로 검토한다. 현재 제품 기능으로 표시하지 않는다.
4. W07/W10: 피드백은 검토 대기 사례로 모아 노출 편향·중복을 확인하고, 필요하면 독립 검수/자료 사실 확인을 거친다. 수정 후보는 별도 버전으로 평가하며 원래 고정 평가 입력을 덮어쓰지 않는다.
5. 통과한 수정만 명시적으로 적용한다. 클릭 즉시 태그 승인/모델 재학습/추천 가중치 전체 변경은 하지 않는다.

규모에 맞춰 구조화된 사유와 검토 목록부터 시작한다. 대규모 온라인 학습·밴딧·RLHF 플랫폼 구축은 현재 범위가 아니다. 피드백은 편향을 없애는 장치가 아니라 추가 관점을 관찰하고 오류를 찾는 장치다. 실제 사용자 유용성/효과는 W10에서 별도로 확인한다.
