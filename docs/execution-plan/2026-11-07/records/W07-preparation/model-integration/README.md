# W07 선행 기술 구현 — Django 분석 서비스 연결

2026-11-09. W05/G4 통과 후 W06 사람 검수 대기 중 진행한다. execution.json의 preparatoryWork에 선행 가능 범위와 완료 조건을 분리했다. W07의 기존 W06 의존성과 AC20~22·G5 정식 통과 조건은 유지한다.

## 구현과 실행

기존 providers.generate는 GPT 텍스트 작업만 연결했다. 이제 tag/emotion은 별도 ARTI_MODEL_SERVICE_URL의 FastAPI /analyze를 호출한다. editing.py는 같은 관리자 요청의 태그·감정에 분석 결과를 공유하므로 두 번 추론하지 않는다. GPT/요약·가이드 설정과 독립이며 Kanana /write는 호출하지 않는다.

서버 환경변수 ARTI_MODEL_SERVICE_URL은 기본 빈 값(비활성)이다. 호스트 Django와 FastAPI를 실행한다면 FastAPI의 실제 주소를 지정한다. Compose API에서는 127.0.0.1이 호스트 PC가 아니므로 호스트 실행 서비스라면 http://host.docker.internal:8001 같은 접근 가능한 내부 주소를 지정하고 API를 재생성한다. 일반 arti-dev 설정과 컨테이너는 이번 작업에서 변경하지 않았다. 모델 서비스 실행은 ai-service/README.md를 따른다. 모델 다운로드/실행과 메모리 여유를 확인한 뒤 활성화한다. 서비스 주소는 운영자가 신뢰하는 내부 주소만 사용한다.

MEDIA_ROOT 안의 업로드 원본을 제한 크기로 읽어 base64 전달한다. 이미지 URL을 모델 서버가 임의 다운로드하도록 넘기지 않는다. URL만 있는 작품은 연결 오류로 알려 로컬 파일 인수를 먼저 요구한다. showImage=false는 공개 표시 정책이므로 관리자 승인 원문의 분석용 파일과 구분한다.

8개 태그와 6개 감정 전체의 유한한 0~1 점수, 모델명, 입력 사용 여부를 검사한다. 파일 누락/경로 이탈/초과 크기, 리다이렉트, 이미지 실패 후 텍스트 대체, 잘못된 점수는 성공 처리하지 않는다. 요청 timeout은 30초이며 느린 최초 모델 로딩을 성공으로 위장하지 않는다. 모델 서비스 /health의 modelsLoaded로 사전 로딩 여부를 확인할 수 있다. Django /api/ready는 기존처럼 API/DB 준비 상태이며 모델 준비 완료를 뜻하지 않는다.

기존 승인 원문 제한·낙관적 버전 충돌·확정 항목 보호·부분 성공 정책은 유지한다. 분석 결과는 suggested이며 자동 confirmed/approved로 바꾸지 않는다. 모든 작업이 실패하면 DB 버전/기존 값이 보존된다. 실패한 부분만 있으면 기존 정책에 따라 성공한 부분만 저장한다.

## 검증단 자체 검토 기준

- 기술/시니어: 실제 로컬 HTTP 계약, 한 번의 분석 공유, 완전한 점수 검증, timeout·redirect 차단.
- 데이터/운영: 경로 이탈/외부 이미지 요청 차단, 비밀값 없는 환경 예시, 일반 DB 미변경, 실패 시 값·버전 보존.
- 방문자/콘텐츠: 미검수 자동 노출이나 감정의 정답화 없음. 생성은 검수 전 제안.
- 팀/교수/평가위원: 연결 구현과 실제 모델 품질을 구분. 가상 분석 응답 회귀를 모델 성능 증거로 사용하지 않음.

동일 작성자의 관점별 자체 검토이며 실제 팀원·교수의 승인이 아니다. 판정 범위는 선행 연결 구현이다. 실모델 cold/warm·메모리·정확도 및 실제 유영국 여정은 다음 단계이며 W06/07/G5 완료로 올리지 않는다.
