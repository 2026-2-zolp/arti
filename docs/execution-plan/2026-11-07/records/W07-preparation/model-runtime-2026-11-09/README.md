## 결과와 통과 범위

Windows CPU 4스레드, 논리 CPU8/메모리31.51GiB 환경에서 공개 가중치를 고정 revision으로 내려받고 네트워크 비활성 상태로 로딩했다. CLIP은 3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268, mDeBERTa는 8adb042d524ecd5c26d3e3ba0e3fbcf7e2d0864c다. 사용하지 않은 HF 캐시 snapshot을 실제 실행 revision으로 기록하지 않도록 결과를 다운로드 메타데이터와 대조했다. 모델 응답의 로컬 경로는 공개 모델 ID로 정리했다.

- HTTP 준비 약0.59초, 다운로드 제외 모델 준비 약5.67초. 단일 기동이며 OS 파일 캐시 영향이 있을 수 있다.
- 핵심001/004/010을 각2회, 실제 Django 제공자→HTTP FastAPI→CLIP/mDeBERTa로 호출해 6회 성공했다. 파일 SHA와 입력 원문을 고정하고 각 요청에서 tag/emotion 결과를 공유했다.
- 호출은 Django 별도 프로세스 기동을 포함해1.70~2.19초. 30초 제한 내이며 반복 응답은 동일했다.
- 0.2초 간격으로 수집한 서버·자식 프로세스 RSS 합계 최대1260.87MiB(약1.23GiB). Django 호출자·전체 시스템 메모리는 제외하며 운영환경 필요량으로 일반화하지 않는다.
- usedImage/usedText는 모두 true, tagSource는 image다. 점수 전체 유한0~1, 모델명/반복 동일성을 확인했다.

초기 기본 HF 자동 다운로드는 파일 전송이 정체돼 추론 전에 시험 서버를 종료했다. 성공한 로딩 시간에서 이 준비 실패를 제외하되 숨기지 않는다. 공개 파일 GET은 정상200이라 revision별 파일 다운로드 후 오프라인 경로를 사용했다. 파일 확보는 CLIP bin 약70초, mDeBERTa safetensors 약68초가 걸렸다. 다운로드와 첫 서버 준비를 섞어 cold-start 성능으로 주장하지 않는다.

실제 연산 의존성은 기존 전용 venv에 추가했으며 버전은 JSON에 기록했다. Kanana는 비활성이고 유료 API 호출은 없다. 모델 서비스 가상 회귀17개는0.54초에 통과했다. 최초 pytest 기본 임시경로 권한 오류2개는 전용 basetemp로 재실행해 해소했다. Starlette/httpx deprecation warning1개는 남아 있다. 모델 loader의 slow processor 기본값 경고와 torch.jit deprecation은 관찰됐으나 이번 요청은 성공했다. 이 측정에서 제품 코드는 변경하지 않았다.

## 자체 검토와 한계

기술/시니어 관점: 실제 모델 호출·버전·revision·입력 해시를 확인했다. 운영 관점: 일시 서버를 종료하고 일반 arti-dev 설정/DB/미디어를 바꾸지 않았다. 방문자/콘텐츠 관점: 검수 전 초안을 실측 입력으로 썼으나 결과는 DB 적재/승인하지 않았다. 팀/교수/평가위원 관점: 3점의 기술 성공·반복 안정성과 정확도/효과를 구별했다. 동일 작성자의 관점별 자체 검토다.

이번 선행 기술 측정은 통과다. 3점은 탐색에 이미 사용한 calibration 후보여서 held-out이 아니며, W06 승인·AC22 전체품질/G5 완료 근거로 쓰지 않는다. 일반 개발 앱의 provider 활성화·관리자 저장 여정은 별도 단계다. 실행문은 일회 측정 증거이고 정식 하네스 추가가 아니다.
