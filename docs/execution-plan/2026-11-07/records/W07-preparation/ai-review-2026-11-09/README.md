# 색감 오류 검토·점수 표시·피드백 계약

2026-11-09 / 기준9f22c6f. 앞선 [40점 기준선](../tag-baseline-2026-11-09/README.md) 이후의 개발 검토다. 모델·라벨 튜닝이나 제품 피드백 UI 구현 단계는 아니다.

- [고정 불일치18건](error-cases.json): vivid FP8건, cool FP7/FN3건. 원시 점수·팀 표수·이미지SHA를 연결한다.
- [시각 검토와 태그 정의안](tag-guidelines.md): 18개 원본 대조. 높은 채도/강렬함, 국소 색/주요 색 인상의 차이를 후속 확인 가설로 구분한다.
- [표시·피드백 최소 계약](display-feedback-contract.md), [JSON](presentation-contract.json): 모델은 연관 점수, 사람 의견은 명시된 판단 분모/건수, 불확실성/무응답은 별도로 표시한다.
- [검사 결과](validation.json): 점수의 확률화·0건/소수응답·모르겠음·노출 분모·자동학습/승인·버전 누락의 경계를 확인한다. scripts/ai_review.py는 이 개발 검토 자료용 검사/예시 생성기이며 제품 API가 아니다.

## 이번 과업 통과 기준

1. 동결 원시점수 해시와18건·표수를 추적하고 제품 원본/팀 라벨을 바꾸지 않는다.
2. 오류원인 가설·정의 제안·실제 사람 승인/정답을 구별한다. 원본18장의 자체 시각 검토는 독립 사람 검수가 아니다.
3. 모델 점수와 확률, 의견 비율과 응답률, 검수 상태를 혼합하지 않는 예시가 있다.
4. 소수/0건·모르겠음·무응답을 처리하고 피드백 자동학습/자동승인을 막는다. guest·보관/식별 미결정은 명시한다.
5. 관련 자동 검사·계획 보호 검사를 통과하고 원격 푸시 없이 작업기록을 남긴다.

이 기준은 개발 검토의 완료 기준이다. 태그 정의의 팀 합의·실제 사용자 비율 표시 정책·새 UI 인수나 W06/07/G5 통과 기준을 대신하지 않는다.

기술/시니어는 분모·입력 검증과 변조 검사를, 데이터/운영은 대상 버전·자동승인 차단·guest 정책 보존을, 방문자/콘텐츠는 숫자가 정답/감정으로 오인되지 않는지 확인한다. 팀/교수/평가위원은 팀 기준과 불일치를 객관적 오답으로 단정하지 않는지, 유영국 도상 중복·개발자료 한계를 구분하는지 검토한다. 동일 작성자의 관점별 자체 검토다.

다음은 태그 정의안을 독립 라벨링에 사용할 수 있게 팀 검토하고 유영국의 의견 분포를 확보하는 일이다. 검수 대기 중에는 합성/격리 자료의 전체 여정 검증을 진행할 수 있다. 피드백 기능은 최소 수집·guest·보관 정책을 결정한 뒤 별도 구현하며 지금은 기존 reaction과 의미를 섞지 않는다.
