# 점수·비율 표시와 피드백 최소 계약 v1

2026-11-09 개발 검토안. [기계 판독 계약](presentation-contract.json), [분모 예시 검증](validation.json). 제품 UI/API/테이블 변경은 포함하지 않는다. 일반 관람 흐름을 방해하지 않고 세부 점수는 관리자/상세에 한정하는 방향이다.

## 숫자 표시

| 종류 | 예시 | 의미/금지 표현 |
| --- | --- | --- |
| 모델 | 모델 연관 점수0.740 · AI 제안 | 정답확률74%/취향일치확률74%로 변환 금지. 현재 태그는 보정 점수이며 감정도 객관적 확률이 아님 |
| 사람 의견 | 판단5명 중3명 선택 ·60% | 표본/유효 판단 수와 함께 표시. AI 점수와 평균 내 단일 신뢰도로 만들지 않음 |
| 모르겠음 포함 | 판단4명 중3명 ·75%, 모르겠음1명 별도 | 분모가 전체응답5가 아님을 명시. 기존40점 통계는 기존 체크형 라벨 규칙을 그대로 유지하며 새 의미로 소급 해석하지 않음 |
| 답변 유용성 | 판단10건 중8건 도움됨 ·80% | 응답자 중 비율. 노출20건/응답10건이면 응답률50%를 별도 기록. 무응답은 부정이 아님 |
| 소수 응답 | 2건 중2건 도움됨 | 일반 사용자 집계는 유효10건 미만이면 건수 우선/퍼센트 숨김을 잠정 제안. 10건도 통계적 신뢰를 보증하는 기준이 아니며 제품 적용 전 결정 |
| 평가 성능 | 기존40점 팀 라벨 기준 Macro-F1 71.7% | 개별 작품의 정확할 확률이나 유영국 성능으로 표시하지 않음 |

감정6개를 합계100%의 구성비로 그리지 않는다. 모델 점수와 사람 의견·검수 상태를 별도 항목으로 둔다. ‘확정’은 해당 콘텐츠/버전의 관리자 상태이며 사실 전체·저작권·모델 신뢰도까지 인증하는 표시가 아니다. stale은 과거 확정과 구분하고 현재 검수 상태가 없는 항목을 확정으로 꾸미지 않는다.

## 피드백 최소 계약

작품선호·태그적합성·추천유용성·텍스트유용성을 서로 다른 targetKind로 보존한다. targetId/targetRevision/modelConfigVersion/rating(positive·negative·unknown)은 필수 초안이며 텍스트평가는 응답ID와 source/content revision, 추천은 recommendation generation이 대상 버전에서 추적 가능해야 한다. 작품선호처럼 모델 없는 대상은 modelConfigVersion을 명시적인 not_applicable 값으로 구분한다.

positive/negative의 의미는 대상 종류에 따라 다르다. ‘좋아하지 않음’을 ‘태그 틀림’으로 바꾸지 않는다. 구조화된 사유는 색감/태그해석/과다태그/추천다양성/사실의심/난이도/반복/맥락단절 등을 대상별로 제한하는 방향이며 자유서술은 기본 수집하지 않는다. 오류신고와 불확실성은 승인 대기로 연결할 뿐 자동 정답이 아니다.

누적 데이터에는 노출/응답/판단 가능 건수를 분리한다. 같은 대상 버전에 대한 중복은 한 사람의 다수 의견으로 세지 않도록 한다. 회원/비회원 식별·중복 방지·보관/삭제/동의 방식은 구현 전에 확정한다. 새 device fingerprint를 만들거나 전체대화/계정정보를 기본 저장하지 않는다. 현재 guest DB미저장 정책은 유지한다.

피드백은 검토 목록→필요한 독립 확인→변경 후보→고정 평가/회귀→명시 적용으로 연결한다. 클릭 즉시 DB 태그 확정·모델 재학습·전역 추천 가중치 변경은 금지한다. 사용자가 피드백을 제출했다고 즉시 개인화/수정됐다고 안내하지 않는다.

후속 구현은 W05 후속으로 별도 범위를 정한다. W06 라벨은 첫 판단에 모델 수치를 숨기고, W07은 평가·설정 비교를, W10은 실제 초보 관람자 유용성·응답 편향을 확인한다. 이번 계약검토로 W06/W07/G5를 완료시키지 않는다.
