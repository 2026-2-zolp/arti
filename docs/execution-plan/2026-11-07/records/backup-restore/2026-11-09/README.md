# 합성 DB·미디어 백업/복원 시험

2026-11-09 / [자료대기계획3](../../../../../operations/자료대기중_실행계획.md). 원본을 건드리기 전에 새 환경으로 DB와 대응 미디어를 함께 복원할 수 있는지 확인했다. 운영/AWS 복구나 팀원 고유자료 인수 완료가 아니다.

## 실행과 통과 근거

arti-backup-src / arti-backup-dst의 별도 신규 PostgreSQL17·미디어 볼륨을 사용했다. 소스만 migration 후 합성 fixture를 적재했다. 전시2·작품13·계정2·세션1·관람1·반응1, 미디어3개(작품 공개/비공개·도면)를 만들고 공개/미검수, 요약·가이드 확정/제안 상태를 섞었다. 이 수치는 실제 유영국 전시가 아니다.

소스 앱 쓰기가 없는 상태에서 pg_dump와 미디어 tar/파일별 SHA256을 한 세트로 생성했다. 비어 있는 대상 DB에 pg_restore, 비어 있는 대상 볼륨에 미디어를 복원하고 서비스 UID10001 소유권을 적용했다. [결과 JSON](result.json)의 소스 이전/복원본/소스 이후/복원 DB 재시작 후 논리 DB 해시와 파일별 해시가 전부 같다. 관계·관람 snapshot/반응·검수 상태는 ORM으로 직접 대조했고, 공개 작품 필터·보호 이미지·누락404는 API로 확인했다. 관람 영수증 API 완주는 이번 시험에 포함하지 않았다. 복원본 공개 이미지 하나를 잠시 같은 볼륨 내 보류 디렉터리로 옮겼을 때 manifest가 누락을 검출하고 API404가 발생했으며 finally에서 복구 후 해시 일치를 확인했다. 공개 작품과 공유하는 이미지까지 일괄 비공개가 된다는 주장은 하지 않는다.

## 수정 루프와 실제 한계

첫 시험에 migration 선행이 빠져 실패해 명시 migration 단계를 추가했다. 검증문이 잘못된 fixture ID를 참조한 것은 실제 fixture-art13으로 바로잡았다. 미디어를 /tmp로 옮기면 볼륨 경계 EXDEV가 나므로 같은 미디어 볼륨의 임시 디렉터리로 바꾸었다. tar 복원 후 root 소유권이면 앱 쓰기에 문제가 생기므로 목적지 UID10001 복구를 절차에 포함했다. 이들은 제품 결함으로 꾸미지 않고 시험/복원 절차 보완으로 기록한다.

원본 arti-w04/arti-w05 및 다른 볼륨·팀원 로컬 자료는 수정/삭제하지 않았다. 시험 컨테이너/네트워크는 종료하고 볼륨은 보존한다. 덤프·세션/계정행·미디어 tar는 Git 제외 data/private/backup-20261109에만 둔다. Git에는 집계/해시와 키 없는 실행 증거만 남긴다. 합성3개 파일의 바이트가 같은 작은 PNG이므로 대용량/서로 다른 포맷/성능 복구 시험으로 일반화하지 않는다.

## 후속 자료 인수 시 적용 절차

1. 대상 이름/볼륨과 데이터 소유자를 확인한다. 실제 자료 인수 전 앱 쓰기를 멈춰 DB/미디어의 일관된 시점을 만든다. 기존 볼륨에 restore하지 않는다.
2. 별도 보존 위치에 PostgreSQL custom dump, 미디어 tar, 파일별 manifest와 전체 archive 해시를 한 세트로 보관한다. 실제 개인정보가 포함될 수 있어 Git·공유 로그에 올리지 않는다.
3. 새 빈 DB/볼륨을 준비하고 같은 PostgreSQL 메이저 버전/애플리케이션 버전으로 복원한다. 먼저 SQL/파일을 검토하고 기존 데이터에 clean/덮어쓰기를 적용하지 않는다.
4. 경로 탈출/심볼릭링크 없이 미디어를 복원한다. 서비스 UID10001의 디렉터리/파일 소유권을 복구하고 hash·누락을 대조한다. 현재 제품 미디어는 평면 파일 경로다. 향후 중첩 경로가 생기면 이번 평면 archive 스크립트를 그대로 쓰지 않는다.
5. 논리 데이터 집계/관계·파일/도면·확정/제안·공개 API를 대조하고 재시작 후 다시 확인한다. 실패 시 대상만 조사하고 원본은 보존한다. 통과한 복원본을 실제 개발 데이터로 채택할지는 별도 인수 결정으로 남긴다.

실행 명령의 핵심은 pg_dump -Fc → 새 DB의 pg_restore --no-owner --no-acl, 읽기 전용 소스 미디어 mount → 새 빈 목적지 복원이다. 세부 실행문 텍스트와 [Compose 명령](commands.md)은 이 폴더에 보존한다. 이번은 고정된 합성 시나리오이며 범용 운영 복원 도구를 도입한 것은 아니다.

논리 DB 해시는 Exhibition/Artwork/Account/Session/Visit/VisitReaction 여섯 도메인 모델의 pk 정렬 행 값에 한정한다. migration 테이블·시퀀스·전체 DB 구조의 동등성 해시가 아니다.
