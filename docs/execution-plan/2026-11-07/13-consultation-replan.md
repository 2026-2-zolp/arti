## 4. 도슨트 개선은 무엇을 할 것인가

컨설팅 발표 취지는 **작품·진입 해설/질문·사용자의 실제 발언을 이어받아 현재 필요한 설명을 조절**하는 것이다. 질문이 전문적이라는 이유만으로 사용자의 숙련도를 고정하거나 정신/성격/능력을 추정하지 않는다. 아트 영수증 interpret의 ‘이해 수준 추정 금지’를 전역 해제하지 않는다.

| 관측 가능한 대화 신호 | 목표 응답 | 불합격 예 |
| --- | --- | --- |
| 어렵다/모르겠다/용어 의미 질문 |용어 풀이·짧은 문장·눈앞의 한 특징/예시 연결 |같은 문장 반복, 수준 낙인, 근거 없는 쉬운 이야기 추가 |
| 왜 그런가/맥락을 더 알고 싶다 |승인 근거 안에서 조형 이유·맥락을 확장, 사실과 가능한 해석 구분 |자료 밖 작가 의도/사건 단정, 다른 작품 사실 혼입 |
| 구체 관찰을 말함 |실제 관찰을 짚고 다음 관찰 또는 추가 질문으로 연결 |말하지 않은 감정/관찰 추정, 매번 처음부터 설명 |
| 첫 질문·신호 부족·요청 변경 |쉬운 기본 설명과 짧은 확인, 현재 요청을 우선해 조절 |과거 한 발언으로 숙련/초보 고정, 근거 없이 상세 정보 확대 |

실행은 **현재 코드의 실응답 기준선 측정이 먼저**다. 새 분류기·모델 전환·DB 사용자 수준 컬럼부터 만들지 않는다. 부족한 시스템/작업 지시와 현재 맥락 전달만 최소 보완하고, 직접 선택 버튼은 여전히 선택적 보조안이다. 기존 모델/질문·원문/버전/프롬프트 해시·호출/토큰/비용 상한을 실행 전 기록한다. 키 값은 기록하지 않는다.

첫 시험은 승인된 합성1작품의4상황과 근거 밖/지시문 경계2건부터 시작하고, 수정 후 핵심3점의 실제 검수 자료로 확대한다. 필요한 맥락 유무 비교를 같은 입력·모델 조건으로 남기되 자체 AI 평점을 실제 방문자의 이해 효과로 발표하지 않는다. 실제 평가자가 없으면 ‘응답 정책/근거 검증’까지만 완료로 표현한다. 정상·실패를 합산해 높은 평균으로 상쇄하지 않는다.

## 5. 실제 데이터와 추가 전시의 채택 조건

16점은 수량만으로 부족/충분 판정하지 않는다. 현행 선택풀은 준비된 작품을 ID순10점으로 자르는 계약이다. 큐레이션안이 다르면 ID변경·숨김으로 맞추지 않고 명시적 계약 변경과 회귀를 한다. 없는 인물 태그를 억지로 양성 처리하거나 사용자 취향을 몰래 교체하지 않는다. 감정6항목은 텍스트 해석/분위기 정보이며8태그 F1과 다른 평가다. 감정·선호를 작가 의도나 객관적 정답으로 제시하지 않는다.

비교 전시는 (1)실재 전시/컬렉션 근거 (2)작품별 ID·이미지·내용/사용 범위 (3)유영국보다 태그 대비를 보여줄 근거 (4)지도/배치 또는 명시적 시연 재구성 (5)검수·인수 책임과 마감 공수 (6)주 전시 회귀·준비에 방해 없음이 있어야 채택한다. 정확히30/40점·현재 개최 중 조건은 합의가 아니다. 채택 전에는 전시2개 기능·데이터 적재를 새 필수로 만들지 않는다. 채택 시 별도 전시ID·검수·평가 입력으로 격리한다.

## 6. 운영과 협업의 경계

기술 준비는1GB 후보/2GB 권장, 모델은 별도/사전 분석이 전제다. 실제 계정·총예산·모델 위치·TLS/주소·종료일이 없으면 임의 생성하지 않는다. 저가 한 호스트에 정적 웹·API·PG를 두는 안을 우선 검토하고 RDS/RunPod/ECS/Bedrock·AWS Core 설치를 필수 선행으로 만들지 않는다. 준비한 정합 백업·고정 모델 revision/cache·비밀/업로드 보호를 재사용하고 실제 대상에서 재확인한다.

`89cdc6b`의 [push CI42556157089](https://github.com/2026-2-zolp/arti/actions/runs/42556157089)는4job 성공이다. 이 최신 사실을 반영하되 W11/AC07/GCI는 PR 이벤트와 인수 조건 전까지 유지한다. 사용자·타인브랜치·main을 강제 갱신하지 않는다. 코드 재개 전 최신 통합본으로 작업 브랜치/담당 파일을 정하고, 공통CSS·API/DTO·환경 변경은 변경요약과 회귀 결과를 연결한다. 과거 개인 브랜치의 전체 덮어쓰기로 합치지 않는다.

팀 검토 요청은 **링크+현재 동작/문제+질문1~2개+회신 필요 시점**으로 전달한다. 판정은 수정/유지/보류와 근거·작품ID/화면·검수자/날짜를 남긴다. 무응답을 승인/부정 라벨로 바꾸지 않는다. 회의록의 역할을 실제 수행 완료나 새 개인별 확정 공수로 만들지 않는다.
