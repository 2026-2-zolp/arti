# 과업지시서 — 동섭 통합본 인수·리팩토링

## 목적

ARTI의 한 전시 관람을 **진입→취향→시간→추천→지도/작품감상→맥락 있는 도슨트→영수증/기록**으로 연결한다. 핵심 가치는 공식 근거와 사람 검수에 기반해 작품 관찰을 돕는 Guided Looking이다. 첫 적용 대상은 유영국 「산은 내 안에 있다」다.

계획수립 당시 준억님은 최초 GitHub 개설 이후 구현 착수 전이었다. 이전 카톡의 API연동/하네스 표현·공유일정은 실제완료 증거로 사용하지 않는다. 사용자 확정 출발점 ae0e58e를 정식확보·재현했고 실제코드계약/회귀기반을 단계별로 검토한다. 현재상태는 execution.json을 따르며 계약/회귀 통과가 실제제품기능·실모델 완료를 뜻하지 않는다.

## 적용 기준

1. **코드 출발점:** ae0e58e 전체 저장소. 광권 bb83a86와 기존 ZIP은 비교 근거.
2. **인수 맥락:** 동섭님 1107 문서. 실제 구현 선택·합의 필요·미검증을 구별.
3. **요구/완료 기준:** 기존 회의·설계·사용자 최신 요구와 이 계획.
4. **변경 관리:** 새 합의·코드 변경은 커밋·결정 기록과 함께 반영.

## 포함 범위

- React·TypeScript 화면 유지, 새 backend와 타입/상태/오류 일치.
- 서비스 API는 Django/DRF 전환을 기본 계획으로 둔다. W02에서 개발 결정에 근거를 남기고, 대안이 필요하면 그 영향까지 기록한다. 팀 최종 채택이 확인됐다고 쓰지 않는다.
- PostgreSQL과 Docker 기반. AWS 운영까지 고려하되 RDS·S3·EC2 조합은 후보.
- 공식 데이터 적재와 원자료 검수, AI 산출물별 검수·공개 제한.
- 사용자 취향·도슨트 맥락·기록 저장·인증·관람 격리.
- 로컬 태그/감정 모델 재사용, 챗봇·요약·가이드의 외부 API 연계와 실제 평가.
- GitHub Actions CI/CD, AWS 시험환경·복구·최종 모바일 인수.

여러 미술관 확장·실시간 실내측위·대형 벡터DB·파인튜닝·멀티에이전트 제품기능·Kubernetes를 선행 요구로 넣지 않는다. 테스트 fake AI·라벨/시간상수·검수된 정적 질문·결정적 추천 계산은 유지 가능한 자산이다.

## 사용자 요구를 반영할 U-10

두 탭(작품해설/관람가이드)을 유지한다. 공식원문 기본+선택 요약, 짧은 도입+관찰질문+접힌 힌트, 확정 가이드만 공개·일반팁 구분. 두 탭에서 도슨트로 넘어갈 때 작품뿐 아니라 보던 질문/해설과 필요한 대화 맥락을 전달한다. 돌아오면 탭·확장·힌트·스크롤을 복원한다. **화면 이동으로 감상을 처음부터 다시 시작시키지 않는다.**

기존 코드에 일부 UI가 이미 있다. 구현된 두 탭·최대8태그·guide필드 반영을 다시 만드는 것이 아니라 남은 연결과 회귀를 수행한다.

## 인수와 책임

11/7 카톡상 준억님은 코드 인수·백엔드/AI 전반·리팩토링 중심이며, 다른 팀원은 잠시 코드 작업을 멈추고 광권님은 유영국 작품선정/자료확보, 동섭님·성현님은 UI/UX·여정과 U05/06 합의를 검토하는 흐름이다. 실제 완료·새 합의는 별도 확인한다. 외부 메시지 발송이나 브랜치 덮어쓰기를 자동 수행하지 않는다.

유영국 20~40점은 검토 규모이며 의무 숫자가 아니다. 먼저 검수 가능한 일부로 흐름을 증명하고 최종 시연 범위를 정한다. 유영국 작품이라는 사실과 실제 해당 전시 출품 여부는 따로 확인한다.

## 계획 운영

기존 Express를 Postgres/OAuth/전체RAG까지 완성한 뒤 Django로 다시 만들지 않는다. 재현·계약 확보 후 선택 대상 API에서 결함을 해결한다.

AWS 예산/계정·Actions 권한·실제 AI 키가 없다고 로컬 개발 전체를 막지 않는다. 해당 외부 작업을 blocked로 두고 독립 작업을 진행한다. 기준 통과를 미룰 수는 있어도 생략할 수는 없다.

개발·배포 준비와 공개 릴리스의 기준을 분리한다. 실모델이 없어도 fixture 기반 CD시험을 할 수 있지만 실제AI·전시·모바일 인수 없이 서비스 완료/공개릴리스로 처리하지 않는다.

공수는 W01의 데이터/실행 상태와 W02의 개발 범위 이후 산정한다. W12에서 운영비·리소스 공수를 별도 산정한다. 이전 로컬 DB/Docker 추정을 Django전체/AWS/CI/CD까지 포함한 총견적으로 쓰지 않는다. 수업 목표 완료율·카톡 공유 약속을 실제 달성률로 쓰지 않는다.
