## 순서와 누락 검토

- **데이터·운영** — 세 회신 접수, 내용 승인, 이미지 사용 범위, 풀 활성화는 별도 판정이다. 교내 프로젝트 사용 의사만으로 외부 URL·PDF·영상에 사용 범위를 넓히지 않는다. 실제 작품 인수가 지연되면 합성 AWS smoke와 로컬 기술 검증을 이어간다. 3점은 도슨트 우선 표본이다. 5·7점 동선을 확인하려면 전시에서 그 수만큼 추천 가능한 작품과 좌표가 필요하다.
- **기술·시니어** — W11 판정 문서와 첫 검수 기록의 원본은 `4bc1e84`·`8eaab21`이다. 인수한 근거 문서에서 PR CI와 병합 후 CI를 확인할 수 있다. 코드 rollback과 DB·미디어 복원은 따로 시험한다. 60초 관리자 분석 예산과 일반 API·프록시·worker 제한은 실제 호스트에서 다시 측정한다. GitHub의 AWS 배포 OIDC와 사용자 카카오 로그인의 권한과 실패 경계를 따로 둔다.
- **방문자·프론트** — ①·⑤와 기존 PNG 한 줄은 확인한 빌드를 근거로 유지한다. ②와 새 영수증 하단 저장, 질문 도슨트 진입, 다음 작품 이동은 새 빌드에서 묶는다. U-05 비교·확정 UI, 피드백 표시·가이드 힌트·음성 속도, 좋아요 상세는 현재 UX 목록에 연결한다. 핵심 실패를 우선 처리하고 나머지는 공수와 담당에 따라 채택한다.
