# 통합·리팩토링 과업지시서

## 1. 목적과 배경

ARTI는 미술 초보 관람객이 현장 QR로 진입해 취향·시간을 선택하고 작품 추천·지도·감상·질문·영수증까지 이어가는 모바일 웹이다. 첫 적용 전시는 유영국 「산은 내 안에 있다」이며, 핵심은 **공식 자료에 근거해 작품을 직접 관찰하도록 돕는 Guided Looking과 추가 대화**다.

각자 AI와 작업하면서 React 프론트, Express/SQLite API, Python/FastAPI 모델이 만들어졌다. Express 채택이 팀의 숙련도·의도적인 최종 설계에 근거했다는 사실은 확인되지 않는다. 제안·설계의 Django/DRF·PostgreSQL·Docker와 차이가 있고, 프론트·API·저장 상태도 일치하지 않는다. 준억님은 이제 구현을 시작하는 상황이다.

이 과업은 목업을 한꺼번에 삭제하거나 기술을 늘리는 작업이 아니다. 현재 자산을 검증하면서 **하나의 관람 흐름·데이터·AI·배포를 일관되게 연결하는 작업**이다.

## 2. 기대 결과

1. 한 전시에서 취향10점·독립5쌍 → 취향 확인/수정 → 시간 → 추천 → 지도/작품 감상 → 질문 → 종료/기록이 연결된다.
2. 취향 입력 변경, 실패, 재진입, 계정 전환에도 이전 결과나 다른 관람 데이터가 섞이지 않는다.
3. 공식 원문·검수 요약·관찰 가이드·대화 응답의 의미와 검수 조건이 명확하다.
4. 실제 AI·규칙 응답·실패를 구별하고, 승인 자료만 근거로 사용한다.
5. 선택한 스택에서 DB·이미지·모델의 실행 경계가 명확하며 Docker·AWS·CI/CD로 재현할 수 있다.
6. 다른 팀원이 코드 실행·작품 등록·검수·배포·복구를 문서대로 수행할 수 있다.

## 3. 포함 범위와 경계

| 포함 | 수행 수준 |
| --- | --- |
| 최신 React 프론트 통합 | 현재 사용자/관리자 화면을 기반으로 상태·계약·오류를 수정. UI 전면 재디자인 제외 |
| API·인증·권한·저장 | 추천·작품·관리자·관람 기록의 계약과 저장 일관성 |
| 기술 스택 정리 | Django/DRF 권장안의 채택/대안 결정을 기록한 후 단계 전환. PostgreSQL·Docker 계획 포함 |
| 실제 작품·출처 | 검수 가능한 작은 파일럿에서 시작, 최종 시연 코퍼스 확정 |
| AI | 로컬 태그/감정 추론 자산, 실제 LLM, 근거·유보·대화·지연·실패 평가 |
| 배포 | AWS 최소 구성, Docker, GitHub Actions CI/CD, 로그·복구·비용 확인 |

여러 미술관 플랫폼, 실내 실시간 위치 추적, 자동 감상 수준 판정, 파인튜닝, 멀티에이전트 제품 기능, Kubernetes, 대규모 벡터 검색은 선행 요구로 추가하지 않는다. 벽/통로 데이터가 없으면 지도 선을 최적 보행 경로로 부르지 않는다. 임베딩·TSP/Dijkstra 등 원설계와 바뀐 부분은 설계 변경 기록으로 설명한다.

검증단은 작업 품질을 점검하는 역할이다. ARTI 제품에 멀티에이전트 기능을 넣는다는 뜻이 아니다.

## 5. 책임 제안

준억님은 통합 경계·AI·DB/스택·검증·기술 설명을 중심으로 인수한다. 동섭님에게 최신 화면 의도, 광권님에게 API·모델·평가 입력의 인계를 확인한다. 작품 수집·사람 검수·배포 계정 관리 담당은 지정이 필요하다. 이것은 담당 제안이며 새 업무를 팀원이 수락한 기록이 아니다. 외부 메시지를 자동 발송하지 않는다.

## 6. 일정과 공수

우선 의존성·통과 기준으로 진행한다. 기존 대화의 DB8~16시간, Docker4~8시간, 모델 컨테이너 추가4~12시간은 **개발용 추정**이며 실제 측정·확약이 아니다. Django API 전체 이전·AWS·CI/CD·모바일 검증이 포함된 총공수로 사용하지 않는다. W02에서 선택한 범위·AWS 예산·실행 자원·자료 확보 상태를 기준으로 다시 산정한다.

수업의 90%/100% 목표를 실제 완료율로 기록하지 않는다. 필수 검수·저장·근거·배포 검증을 생략해 날짜를 맞추지 않는다.

## 7. 변경과 완료 관리

각 변경은 W-ID·F-ID·AC-ID를 연결한다. 실험은 작은 입력으로 수행하고 새로운 근거가 있을 때만 확장한다. 명세 변경은 이유·영향·대안·승인/결정 주체를 기록한다. 증거 없는 완료 표시, 오류 숨김, 검증 기준의 임의 하향은 금지한다. 문서 수정이 서비스 통과를 대신하지 않는다.
