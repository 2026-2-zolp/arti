# ARTI 통합·리팩토링 실행 문서
작성 기준: 2026-11-06 KST / 버전 1.0 / 준억님 구현 착수 전

이 문서는 실제 작업을 위한 **현재 실행 기준**이다. 기존 [조사 아카이브](../../project-baseline/2026-11-06/README.md)는 조사 당시의 관측·판단을 보존하며 수정하지 않는다. 두 문서의 계획이 다르면 이 실행 문서의 최신 결정 기록을 따른다. 과거 조사 결과를 소급 수정하지 않는다.

1. [과업지시서](01-assignment.md): 왜·어디까지 작업하는가.

3. [검증단·통과 기준](03-quality-gates.md): AC별 증거를 제출하고 통과할 때까지 수정하는 방법.
4. [이슈 추적표](04-issues.md): 기존 F01~F21과 새 F22~F33의 현재 추적 상태.
5. [계약·기술 결정](05-contracts-and-decisions.md): 유지할 규격·제안·미결 사항.
6. [AWS·Docker·CI/CD 절차](06-operations.md): 개발 이후까지 이어지는 실행·배포 범위.
7. [증거·결정·인수인계 양식](07-records-and-handoff.md): 작업과 검증을 기록하는 방법.
8. [문서 자체 검증 기록](08-document-review.md): 이번 문서 제작의 검사·수정 기록.

## 현재 상태

- **사용자 확인:** 준억님은 첫 GitHub 개설 이후 실제 구현하지 않았다. 현재 프론트 기준은 제공 ZIP이고, 광권님 코드는 dev/김광권 기준이다. PostgreSQL 선택에는 추후 AWS 운영 고려가 있었다. GitHub Actions CI/CD를 포함한다.
- **과거 실행 증거:** 프론트 빌드·Express 타입 검사·38테스트 통과와 조사 audit이 있다. 현재 작업 공간 재실행·실모델·모바일·AWS 검증을 대신하지 않는다.
- **권장안:** React 유지, Django/DRF로 서비스 API 정리, PostgreSQL, Docker, 로컬 모델의 FastAPI 분리 활용. Django·AWS 서비스 조합·인증 방식은 팀 최종 합의가 확인된 상태가 아니다.
- **수행 범위:** 이번에 만드는 것은 실행 문서와 검증 체계다. 서비스 구현·GitHub 설정·AWS 리소스 생성·배포는 수행하지 않는다.

문서 게이트 GD는 두 검토 역할의 수정·재검토와 자동검사 후 통과했다. [검토 기록](08-document-review.md)에 지적·수정·결과를 남겼다. 개발 게이트 G0~G7은 전부 미실행이다. 문서 통과가 서비스 통과를 의미하지 않는다. 현재 실행 상태의 기계 판독 기준은 [execution.json](execution.json)이다.

## 바로 시작할 첫 작업

**W01: 정식 통합 작업 공간과 재현 기준 확보.** 현재 C:/Proj/26-2-zolp 루트는 조사 디렉터리이며 정식 Git 체크아웃으로 확인되지 않았다. research 사본을 그대로 서비스 소스로 취급하지 않는다. 정식 저장소를 격리된 작업 경로에 확보하고 최신 ZIP·고정 SHA 대비 변경 목록을 만든다. 자세한 순서는 [W01](02-procedure.md#w01-기준선과-재현-공간) 참조.

문서를 읽다가 결정 미확정·키 없음·권한 없음이 발견되면 해당 과업만 대기 상태로 두고, 의존하지 않는 과업을 진행한다. 실패를 통과로 바꾸거나 기준을 사후에 낮추지 않는다.
