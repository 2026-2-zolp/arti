# 실행 문서 자체 검증 기록

기준일: 2026-11-06 KST / 판정: **GD 문서 인수 통과**.

이 판정은 실행 문서의 정합성·절차·검증 체계에 한정한다. 서비스 구현 게이트 G0~G7은 모두 미실행이다. 기존 빌드·38테스트는 역사적 증거이며 이번 문서 작성에서 다시 실행하지 않았다.

## 검증단

- 작성자: 과업지시서·계약·운영 절차 작성, 출처 대조, 구조 검사.
- 범위/정합성 검토 역할(scope_review): 사용자 요구·ARTI 범위·사실/권장 구분·실행 기준의 누락 검토.
- 기술/운영 검토 역할(technical_review): API/데이터·전환 경계·AWS/모델·CI/CD·종결 의존성 검토.

두 검토 역할은 별도 AI 보조 검토자다. 실제 팀원 동의·작품 검수·사용자 테스트·AWS 실행을 대신하지 않는다. 각 역할에서 필수 수정 제시→반영→재검토를 수행했고 모두 남은 필수 지적 없음으로 판정했다.

## 검증 루프 기록

### R0 — 작성 중 정리

- Express 전체 완주를 Django 전환 선행으로 강제하지 않도록 변경. 재현/계약 확보 후 선택 스택에서 해결한다.
- 기존 “Django 복귀” 단정과 최신 대화의 차이를 구분. 채택 결정은 W02에 남긴다.
- W04 이후 AWS 첫배포를 준비해 최종 시점에만 환경 문제를 발견하는 일을 줄인다.
- 문서 GD와 서비스 G0~G7을 분리한다.

### R1 — 최초 독립 검토와 수정

| 지적 | 수정 |
| --- | --- |
| F01이 계약/캐시 검사만으로 닫힐 수 있음 | AC13에 실제 빈도·사용자 수정·기대 계산·원본 저장/재조회 추가. 추천목록이 반드시 달라야 한다는 조건 배제 |
| F08의 10점5쌍 런타임/부족처리 누락 | AC16 보강, F08에 AC16·W05 연결 |
| 출처 변경 후 기존 확정 AI의 재검수 실행 기준 누락 | AC11에 stale/확정해제·공개/근거 제외·재검수 후 재노출, F29에 AC11·W05 연결 |
| 초기 AWS 배포가 인증/검수 전 공개될 수 있음 | W08 접근제한·시험fixture 경계, F33 기본계정·자동시드 차단, AC10/23/26 보강 |
| 비밀번호재설정 기능 미완성을 일반 인증 검사로 종결 가능 | AC16에 실제동작 또는 명시적 UI제거/비활성 검증 |
| 최종 인수의 필수 이슈 범위가 모호 | releaseRequired 명시. F21은 고급기능 의무 제외, 변경/제한 설명은 필수 |

### R2 — 수정 후 재검토와 논리순환 해소

- F09 종결에 AC31을 요구하고 AC31이 F09 종결을 요구하는 순환 발견.
- F09의 개별 종결 기준을 AC18·AC29로 변경하고 AC31은 최종집계로 분리.
- 검증기에 required 이슈의 AC31 종결의존 금지, AC31 통과 전 필수 이슈 종결, AC의 실제 작업 누락 검사를 추가.
- 범위 검토와 기술 검토 모두 수정 확인 후 인수 통과 판정.

### R3 — 자동 검사와 잘못된 상태 거부 시험

[verify_plan.py](verify_plan.py): 고유ID·task/gate DAG·이슈/작업/AC 연결·증거 없는 통과·로컬링크·아카이브 해시/목록 검사. 초기 생성 시 결과파일 링크가 아직 없다는 자체검사 오류를 고쳤고, 최종 검사 오류0.

[verify_guardrails.py](verify_guardrails.py): execution.json을 실제 수정하지 않고 메모리상의 잘못된 후보7개를 검사기에 공급했다. 증거없는 pass, AC31 종결순환, 열린 필수이슈가 있는 최종pass, 구현과업누락, 작업순환, AC미통과 task완료, 검토증거없는 gate통과를 **7/7 모두 거부**했다. 서비스 테스트가 아니라 문서 검증기의 방어 시험이다.
