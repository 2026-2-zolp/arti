## 2. 현재 상태

### 2-1. 백엔드·AI — 광권님 최신본 + 1가지 변경

광권님 `dev/김광권`(`bb83a86`, 11/03)의 `backend`, `ai-service`, `docs`를 그대로 가져왔습니다. 함께 들어온 주요 기능은 다음과 같습니다.

- 취향 태그 8개 통일, 태그 점수 기반 추천
- AI 태그 기준값 보정(팀 6명 다수결 라벨)
- 전시별 태그 작품 수 API `GET /exhibitions/:id/tag-coverage`
- 작품 관람가이드 칸: 쉬운 설명 `guideIntro`, 질문별 힌트 `guidedHints`, 검수 상태 `guideStatus`
- 로컬 모델 Kanana로 요약·가이드 초안 만들기 (Claude API 키가 없을 때, 관리자 [AI 분석] 때만)
- DB 자동 변환: 칸 추가, 예전 태그 변환(`calm`→풍경, `emotion` 삭제)

**제가 바꾼 것 (1가지): 기존 관찰 질문을 자동으로 '확정'하지 않음**

| 파일 | 변경 |
|---|---|
| `backend/src/db.ts` | 새 칸을 만들 때 "관찰 질문 있는 작품은 확정"으로 바꾸던 줄 삭제 |
| `backend/src/seed.ts` | 시드 작품의 `guideStatus`를 `'none'`으로 |
| `backend/test/ai.test.ts` | 위 규칙에 맞게 테스트 2개 수정 (백엔드 테스트 38개 통과) |

이유: 자동 확정되면 [AI 분석]이 "확정된 가이드는 덮어쓰지 않는다" 규칙 때문에 쉬운 설명·힌트를 새로 만들지 않습니다. 관리자가 검토해서 확정하는 흐름을 지키기 위해서입니다.

## 7. 실행 방법 메모

서버 3개를 각각 다른 터미널에서 켭니다.

| 서버 | 위치 | 명령 | 주소 |
|---|---|---|---|
| AI 분석(태그·감정·Kanana) | `ai-service` | `.venv\Scripts\activate` → `uvicorn app.main:app --port 8000` | http://localhost:8000/health |
| 백엔드 | `backend` | `npm run dev` | http://localhost:4000/api |
| 프론트 | `frontend` | `npm run dev` | http://localhost:5173 |

- ai-service는 관리자 [AI 분석]에만 필요합니다. 사용자 화면만 볼 때는 백엔드와 프론트만 켜도 됩니다.
- Kanana 모델(약 4GB)은 **처음 한 번만 내려받고**, ai-service를 켤 때마다 첫 [AI 분석]에서 메모리에 올립니다(첫 분석만 오래 걸림, 메모리 약 9GB). 메모리가 부족하면 ai-service를 켜기 전에 `ARTI_WRITER_ENABLED=false`를 설정하세요. 요약·가이드만 꺼지고 태그·감정 분석은 됩니다.
- 백엔드는 Kanana를 최대 5분 기다리고(`WRITER_TIMEOUT_MS`), 실패하면 10분 동안 부르지 않습니다(코드 고정). 바로 다시 시도하려면 백엔드를 재시작하세요.
- `backend/.env`의 `ANTHROPIC_API_KEY`가 있으면 Kanana 대신 Claude를 씁니다.
- DB는 백엔드를 켤 때 자동으로 새 형식으로 바뀝니다. 처음부터 다시 만들려면 `backend/data/arti.db`(와 `-shm`, `-wal`)를 지우고 백엔드를 켜세요.
