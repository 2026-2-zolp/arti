# 유영국 핵심 3점 검수와 인수 기준

TP4에서 격리 여정을 기술 검증했다. 이 문서는 실제 작품의 태그, 작품 식별, 해설과 이미지 사용 조건을 팀이 확인하는 순서다. [기존 16점 블라인드 절차](../yoo-2026-11-09/README.md)의 태그 정의와 원본 해시를 재사용한다. [취향 조사 5쌍 검수](../taste-survey-2026-11-10/review-protocol.md)는 별도 과업이다.

## 1차 · 독립 태그 검수

- 저장소 루트에서 `python scripts/build_yoo_core3_review.py`를 실행하면 `data/private/independent-review-20261111/core3-blind.zip`이 생성된다. 팀에는 ZIP만 먼저 건넨다. 작품 제목·해설·출처·모델 결과·기존 답변은 ZIP에서 제외했다.
- 검수자가 각자 작업하고 원본 응답을 먼저 고정한다. 기존 절차대로 3명 이상을 목표로 하고 프로젝트 범위 안에서 제3자 관점을 확보한다. 인원과 사전 노출을 기록하고, 노출 응답은 독립 응답과 구분해 해석한다.
- `python scripts/yoo_labels.py 응답.json --core3`으로 묶음 버전·ID·이미지 해시·완료 상태를 확인한다. TEST는 실응답에서 제외한다. 초안과 미응답은 보존하되 완료로 세지 않는다. 모르겠음과 미응답을 비해당에 합치지 않는다.
- 작품·태그별 해당/비해당/모르겠음/미응답 수와 유효 분모(해당+비해당)를 기록한다. 2/3처럼 분자·분모를 함께 제시하고 동점·불일치·유효 응답 부족은 보류한다. 모델 비교는 독립 응답 고정 후 진행한다. 핵심 3점은 기존 탐색에 사용됐으므로 이 검수로 모델 일반화 성능을 주장할 수 없다.

## 11/16 회신 접수 사전 확인

- 회신 원문과 첨부는 비공개로 보존한다. 준억은 작품별 회신에 실제로 확인된 정보만 아래 형식에 옮긴다. `imageSha256`은 회신이 가리키는 실제 파일, `wordingSha256`은 검수자가 본 문안의 SHA-256이다. 문안 해시는 줄바꿈을 LF로 통일해 계산한다. 회신에서 어느 파일이나 문안을 봤는지 확인할 수 없다면 기존 자료의 해시를 대신 넣지 않고 광권·회신자에게 확인한다.
- `python scripts/yoo_core3_receipt.py <비공개-회신.json>`으로 접수 행을 확인한다. `recordable`은 해당 행의 필수 항목과 현행 자료 연결이 맞다는 뜻이다. `pending`은 보류 의견이나 불일치·누락을 뜻하며 `issues`에서 이유를 확인한다. 미지정·미등록 필드나 매체는 원문 배열의 행 번호만 `unassigned…Entries`로 보고한다. 여러 검수자의 회신은 각각 기록하고 이견과 승인 여부는 담당자가 판단한다.
- 도판이 첨부된 회신은 `python scripts/yoo_core3_receipt.py <비공개-회신.json> --image <비공개-도판파일>`로 검사한다. 회신에 적힌 해시가 일치해도 실제 파일 해시가 다르면 문안·매체 인수는 대기다. 11/18 비공개 보관본의 001·004·010 해시는 인수 목록과 3/3 일치했다. 광권님은 원 취득처를, 준억은 매체별 사용 조건을 확인한다.
- 검수에 쓴 Markdown 문안이 첨부되면 같은 명령에 `--wording <비공개-문안.md>`를 붙인다. 줄바꿈을 LF로 맞춘 뒤 대조한다. 다른 버전이면 문안 인수는 대기이며, 이미 확인된 도판 사용 근거는 해당 매체 행에 보존한다.
- 작성자 외 문안 검수자는 작품별 질문의 전제를 먼저 확인한다. **001**은 붉은 자국이 반드시 끊긴다는 전제 없이 이어짐·끊김을 모두 살핀다. **004**는 제목의 괄호 뜻을 추정하기 전에 확인된 자료를 찾는다. **010**은 아래쪽 선의 관찰과 물로 읽는 감상을 구분한다. 이 항목은 회신용 확인 기준이며 문안 해시는 기존 검수본을 가리킨다.
- 결과의 `handoff.pendingContentFields`는 현행 문안에 대한 확인이 남은 필드다. 해설·쉬운 요약·질문·힌트가 모두 `confirmed`이고 현행 도판의 해당 매체도 `confirmed`일 때 `handoff.media`의 그 매체가 `ready-for-review`로 나온다. 준억과 매체 담당은 표시된 회신을 원문과 대조한 뒤 원 취득 근거와 실제 도면까지 연결해 적용을 검토한다. [합성 인수 검수](../../작업기록/2026-11-16_W06_회신과시연연결검수.md)
- `content.field`는 `description`(해설), `summary`(쉬운 요약), `question`(가이드 질문), `hint`다. `usage.medium`은 `campus_demo`(교내 제한 시연), `presentation`(결과물 PDF·발표), `recording`(녹화), `external_url`(외부 URL)이다. `decision`에는 `confirmed`(확인), `revise`(수정), `hold`(보류)를 적는다. 문안에는 검토한 구절과 사실·관찰·해석의 근거를, 매체에는 근거 URL 또는 회신과 접근 대상·기간·권리 표기를 이어서 기록한다. 취득 URL·제공자와 도면 근거는 위 회신 양식에서 각각 확인한다.

아래는 입력 형식만 보여주는 합성 예시다. 실제 회신 판정에는 해당 회신에서 확인한 SHA-256과 근거가 필요하다.

```json
{
  "recordId": "yyk-intake-20261109-001",
  "imageSha256": "실제로 검토한 도판의 SHA-256",
  "wordingSha256": "실제로 검토한 문안의 SHA-256",
  "content": [
    {"field": "hint", "judgedText": "합성 구절", "evidence": "합성 관찰 근거", "reviewer": "시험 문안 검수자", "reviewedOn": "2026-11-16", "decision": "confirmed"}
  ],
  "usage": [
    {"medium": "campus_demo", "evidence": "합성 근거", "scope": "합성 대상·기간·표기", "reviewer": "시험 사용 검수자", "reviewedOn": "2026-11-16", "decision": "confirmed"}
  ]
}
```

`e2f8127` 기준으로 합성 회신 6종을 확인했다. 도판 해시가 없거나 다른 작품이면 해당 문안·사용 행 모두 보류했다. 문안 해시가 없거나 다르면 문안만 보류했다. 매체 미지정은 어느 사용 행에도 배정하지 않았다. 교내 제한 시연 회신은 발표·녹화·외부 URL 행에 영향을 주지 않았다. 검수자·수정 의견을 보존하고 명시 보류와 중복 행은 대기로 보고했다. `python -m unittest discover -s scripts/tests -p test_yoo_core3_receipt.py -v`로 재현할 수 있다. 실제 도판의 사용 범위, 사람 검수, 서비스 반영·공개 상태는 기존 대기 판정을 유지한다.
